# 救助三步程序——逐案评估、工具匹配、条件设计

## R — 原文 (Reading)

> 要想让最后的贷款发挥作用，借款人必须具备偿付能力。如果不是这样（比如它们的资产价值低于它们的负债），那么央行的贷款可以展期，但不能防止失败。
>
> — 本·伯南克，第五章 全球金融危机

---

## I — 方法论骨架 (Interpretation)

救助决策最忌"救/不救"的直觉二选一，正确做法是一套三步程序。第一步是分类：先回答目标主体是流动性困难还是资不抵债——有真实价值可抵押、只是账期错配的，放贷有用；资本窟窿已破的，放贷只是延缓死亡，补资本的事必须由能承受损失的一方（财政、母公司）来做。

第二步过三问（LTCM 范式）：无序倒闭是否会危及整个系统？道德风险能否最小化——钱主要出自私人、股东出局、管理层担责？有没有明确的法律授权框架——缺框架的救助必然招致临时性与公平性批评。

第三步定结构：设计损失吸收安排，让最可能亏钱的一层（通常是财政或母公司出的股本金）垫在下面吸收预期损失，放贷方在"足额收回"的底线内放心冒险——一笔垫底资金因此能撬动数倍的信贷投放。涉及跨主体救助时，还要先做传染评估：信心传染、实质业务冲击、对方自身的挤兑结构。

## A1 — 书中的应用 (Past Application)

### 案例 1: LTCM 纾困三问——私人注资而非公共救助（第三章）
- **问题**: 1998年9月，杠杆1:30的对冲基金LTCM濒临倒闭，纽约联储要不要出手？
- **方法论的使用**: 逐条过三问：无序倒闭可能冲击整个金融体系（对照1990年放任德崇证券倒闭的后果）；道德风险可最小化——14家私人机构注资36亿美元、股东出局、管理层离场、美联储未出一分公共资金；法律框架一问暴露了缺口（无正式处置程序），答案被记入十年后的预案清单。
- **结论**: 系统性成立、私人出资结构可行，于是召集市场自救而非公共救助。
- **结果**: LTCM得以更有序解散，道德风险受控；当年拒绝参与注资的贝尔斯登，十年后自己成了求援者——程序中"私人出钱"条款的最好注脚。

### 案例 2: AIG 救、雷曼不救——同一程序在相反案例上的执行（第五章）
- **问题**: 2008年9月两家机构同时告急，为何结局相反？
- **方法论的使用**: 第一步分类见分晓：AIG有可抵押的盈利保险子公司（真实价值在，流动性工具够得着）；审查雷曼账簿后确认已严重资不抵债，不满足美联储贷款"足额抵押"的法律要求，美国银行拒绝无注资收购。第二步第三问同样卡住：财政部当时无权做资本注入。
- **结论**: 不是"救AIG不救雷曼"的双重标准，而是同一分类程序的两次执行——最后贷款人只能救流动性困难，不能替代财政的资本重组。
- **结果**: 雷曼9月15日破产、恐慌全面爆发；作者的反事实判断是信任已失、技术性延命也难阻恐慌，真正的分水岭是10月才有国会授权的TARP资本注入。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 集团/平台面对一家现金流断裂的核心供应商或生态伙伴，纠结"过桥贷款、收购产能还是任其倒闭"。
2. 政府部门或行业协会面对某系统性机构的求援，需要一套能对外解释"凭什么救它、凭什么这些条件"的决策框架。
3. 用户被质问"为什么救了A不救B"——需要用分类程序说明两案的可比变量（可抵押价值、系统性、道德风险约束）。
4. 用户要设计一笔救助的资金结构：谁垫底吸收损失、贷款方底线在哪、私人出资比例多少、股东与管理层如何处置。

### 语言信号 (用户的话里出现这些就应激活)

- "该不该救""bailout""出手相救还是让它倒"
- "流动性困难还是资不抵债""过桥贷款""救助条件"
- "道德风险""moral hazard""系统性风险""损失吸收""凭什么救它"

### 与相邻 skill 的区分

- 与 `bagehot-stigma-design` 的区别: f11 解决"工具设计好了但该用的人不敢用"的机制摩擦；本 skill 解决"要不要救、救的结构"的决策本身。决策找本 skill，落地摩擦找 f11。
- 与 `panic-contagion-template` 的区别: f09 是系统级诊断（处于哪一环、会不会蔓延）；本 skill 是对单一主体的逐案分诊与结构设计。先诊断后决策。
- 与 `political-feasibility-engineering` 的区别: f17 处理救助的政治面包装（叙事、替罪羊对冲）；本 skill 处理经济结构（分类、三问、损失吸收）。政治可行性是本程序三问之外的附加维度。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **分类：流动性困难还是资不抵债**
   - 完成标准: 基于资产负债表证据（有无可抵押的真实价值、亏损是账期错配还是资本窟窿）输出分类结论。
   - 判停条件: 若已资不抵债且无收购方/注资方，放贷类工具全部止步——转入讨论"补资本的一方（财政/母公司/收购者）是否存在且愿意"。

2. **过三问（LTCM 范式）**
   - 完成标准: 三问各有书面答案——无序倒闭的系统性影响（含对照放任案例）、道德风险最小化方案（私人出钱、股东出局、管理层担责）、法律/授权框架是否存在。

3. **定损失吸收结构**
   - 完成标准: 明确最坏情形下各层谁亏多少——垫底的预期损失由谁吸收、贷款方能否守住"足额收回"底线、垫底资金能撬动多少倍信贷。

4. **双路径传染评估**
   - 完成标准: 对"救"与"不救"两条路径各做一遍传染链分析（信心传染→实质业务冲击→对方挤兑结构），不能只评估救的代价。

5. **写明退出与追责条款**
   - 完成标准: 退出触发条件、追责与回收安排在出手前成文——救助的临时性必须事前声明，否则道德风险约束形同虚设。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 无系统性维度的单笔坏账核销或投资止损——那是普通的风控决策，走三步程序是仪式化浪费。
- 用户问的是"恐慌整体到哪一步了"（f09）或"纾困工具为什么没人用"（f11）——三个问题层层相邻但处方不同。
- 目标主体资不抵债且用户期待"放贷救活"——本 skill 的第一步结论恰恰是放贷无效，勿为了迎合期待而跳过分类。

### 作者在书中警告的失败模式

- 分类正确但结构缺位仍会失败：雷曼的偿付性判断没错，但缺国会授权的资本注入（TARP 10月才到位），窗口期内"不够早、不够大"。
- 缺法律框架的救助必然事后挨打：LTCM 三问中"有无明确框架"答案为否，暴露的缺口直接写成2008年预案清单的第一条。
- 危机初期把小概率灾难按基准情景对待："很可能得到控制"式的乐观评估使救助工具启用过晚——模糊期的观望偏向与恐慌的指数动力学正面相撞。

### 作者的盲点 / 时代局限

- "救雷曼也无法阻止恐慌"的反事实（信任已失、延命无益）缺乏判决性检验，作者以决策者身份自辩，书中自己承认该判断至今有争议。
- 法律授权缺口在2008年9月雷曼时点已明知，TARP 却到10月才到位——作者将归因偏向国会约束，对自身窗口期把握的复盘不充分。
- "救助加剧财富不平等"（机构股东受保、房贷人自担）的内在张力全书未正面处理——这是 BOOK_OVERVIEW 指出的最强反对意见之一。

### 容易混淆的邻近方法论

- `bagehot-stigma-design`：白芝浩原则（惩罚性利率、良好抵押品、有偿付能力）是本 skill 第一步分类的操作标准；但"工具没人用"的污名问题是 f11 的领地——分类时用白芝浩，落地时防污名。
