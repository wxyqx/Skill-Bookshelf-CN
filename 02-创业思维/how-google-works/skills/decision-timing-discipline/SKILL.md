# 决策时机与授权（响铃、80/80、马背原则、PIA）

## R — 原文 (Reading)

> "对于决策者而言，最重要的任务就是：设立最后期限，进行决策工作，按最后期限完成。" / "我们只需坐在马背上（这通常只是打比方），快速环视四周，然后继续上路。"
>
> — 施密特、罗森伯格，第四章《该响铃时就响铃》/《马背原则》

---

## I — 方法论骨架 (Interpretation)

这是一套"何时拍板"的纪律，把决策沿两个维度分开处理：重要性与信息完备度。

- **少做决策与授权**：管理者的产出不是决定数量——把专家/创始人得心应手的事交出去，只保留产品发布、并购等少数关键项；授权时把决策权和期限一起交出去（"决定权归你们，明天出结论"）。
- **80/80 时间律**：80% 的时间给带来 80% 收入的核心业务，防止注意力被光鲜的新业务吸走；注意力分配必须显式核算，不能靠感觉。
- **响铃**：对重要决策设最后期限；超过一定限度后，更缜密的分析并不带来越好的决策，争论只会产出乏善可陈的折中；足够重要的决策反而要每天开会——高频碰头既标记重要性，又省去重复背景。
- **PIA**：出手前三问——还有耐心吗？信息还有增量吗？备选方案在哪？守门员在对方射门时原地不动，扑救成功率反而翻倍：能等就等，别被行动偏误绑架。
- **马背原则**：日常可逆项不必跳下马做 50 页分析，骑在马上快速环视四周就继续上路；前提是律师等支持职能必须嵌为团队一员。

响铃之前保持耐心，响铃之时果断行动——这组张力由决策者本人拿捏，别成为紧迫感的奴隶。

## A1 — 书中的应用 (Past Application)

### 案例 1: 比尔·坎贝尔在财捷响铃
- **问题**: 财捷一项重要产品决策久拖不决——负责高管搜集了大量资料，数据没有说服力，就再做一轮研究，还是无济于事，于是继续挖掘数据。
- **方法论的使用**: 刚上任的比尔·坎贝尔下令设期限，强制决策落地："不管你的决策是对是错，赶紧做点实事吧。"
- **结论**: 超过一定限度后，分析不再提升决策质量；决策者的职责是设期限、响铃、让团队行动——机会成本是创意精英本可去做更重要的事。
- **结果**: 拖延被终结，"该响铃时就响铃"成为原则的出处案例（c56）。

### 案例 2: 谷歌法律部的马背原则
- **问题**: 传统法务习惯回顾过去、规避风险，与互联网时代"速度甩开规则变化速度"的要求正面冲突——连谷歌运动场指示牌都有 1/4 版面是免责声明。
- **方法论的使用**: 法律总顾问肯特·沃克提出马背原则：不必每次跳下马花几周拟 50 页法律声明，骑在马背上快速环视四周就继续上路；律师为决策者提供周密指引而非免责文书，法律部改招通才并嵌入业务团队。
- **结论**: 带着不完全信息行动——多数决策不需要万全分析，重大并购与合规问题除外。
- **结果**: 马背原则成为谷歌法律部的标准工作方式（c59）。

### 案例 3: 埃里克的 80/80 错配
- **问题**: 1997 年埃里克任诺勒 CEO，核心业务 NetWare 与更有趣的新产品 NDS 目录服务争夺他的时间。
- **方法论的使用**: 比尔·盖茨建议"把 80% 的时间花在 80% 的收入上"；埃里克自以为照做了，实际仍把过多精力投向光鲜的新业务。
- **结论**: 管理者往往低估新产品上市后的赢利周期，企业赢利靠核心业务——注意力分配必须显式核算，不能靠感觉。
- **结果**: 埃里克事后承认错配，这条教训成为 80/80 时间律的出处（c60）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 一个重要决策拖了几个月，双方都有数据、谁也说服不了谁，每次开会都是"再调研一轮"。
2. 会议议而不决：讨论充分、反对意见也都摆过了，但没人愿意说"就按 A 定了"，总有人提议下次再议。
3. 高管被琐事决策淹没（一天十几个会全是等他拍板），真正重要的业务反而没时间；该不该授权、授给谁、授多大。
4. 时间分配自检：日程里核心业务的占比与其收入占比严重失衡，新业务"有趣"成了投入的隐性理由。
5. 谈判或机会窗口前纠结"现在出手还是再等等"；法务/合规/风控环节把上线节奏拖死。

### 语言信号 (用户的话里出现这些就应激活)

- "议而不决 / 拖了三个月 / 再议 / 再调研一轮 / analysis paralysis"
- "该谁拍板 / 要不要授权 / deadline 又拖了 / 没人拍板"
- "时间不够用 / 该抓哪头 / 新业务还是核心业务 / 80/80"
- "现在出手还是再等等 / PIA / 耐心 信息 备选方案"
- "马背原则 / horseback / 带着不完全信息行动 / 法务太慢"

### 与相邻 skill 的区分

- 与 `real-consensus` 的区别：那个管"讨论的质量"（异议是否真实现形、败方是否挺身支持），本 skill 管"讨论什么时候结束"（时限与拍板）。口诀：点头而不执行→ real-consensus；讨论充分了但不拍板→ 本 skill。实际决策会先走共识流程、再由本 skill 响铃。
- 与 `hippo-resistance` 的区别：河马迟迟不拍板或事事自己拍，本质是权力结构问题，归 hippo；本 skill 提供的是时限与授权结构，不处理发言权重。
- 与 `ship-iterate-fail-well` 的区别：马背原则管"行动之前要不要等完美信息"，交付-迭代管"行动之后怎么走"（用真实反馈修正）——两者衔接：先上马，再迭代；别用"等数据"拖延马背原则，也别拿"先上路"跳过迭代复盘。

## E — 可执行步骤 (Execution)

1. **给决策分类定级**
   - 完成标准：沿"可逆性 × 影响面"归入三类——重大不可逆（并购级，走 PIA）、重要且紧迫（设响铃）、日常可逆（走马背）；类别依据写得出来。
2. **检查授权结构与时间分配**
   - 完成标准：先问"这件事需要你拍吗"——专家/一线得心应手的事连期限一起交出去（"决定权归你们俩，明天出结论"），只在严重误判时插手；同时自检 80/80：核心业务在你日程中的占比与其收入占比是否失衡，失衡当周调整。判停条件：决策本就该由别人做→交还后跳到步骤 4。
3. **对重大项过 PIA 再定响铃**
   - 完成标准：三问有答案——还有耐心吗？信息还有增量吗（同一议题两轮研究无增量即封盘，别让"再挖一轮数据"成为拖延的合法形式）？备选方案在哪？结论落在两个动作之一：信息仍有增量→继续耐心收集；无增量→设最后期限；足够重要→每天同一议题开会（如 AOL 谈判连续 6 周每天下午 4 点，期满必须定）。
4. **按期限响铃并执行**
   - 完成标准：到点必须拍板，决策记录写明依据与被放弃的备选，不出现"再议"；期限来临前保持灵活，别当紧迫感的奴隶——最后一刻的新信息若有实质增量，先处理信息再响铃。
5. **日常可逆项走马背**
   - 完成标准：快速环视（把关键风险点过一遍）→发出带"不完全信息"声明的决定→预留回滚条件→事后补分析；不要求 50 页文书，但支持职能（法务/合规）须提前嵌入团队而非事后救火。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **必须立即执行的紧急事故**——没有决策空间，按指挥链行动；事后复盘才是分析对象。
- **重大并购与强合规事项**——书里明确这类仍需详细分析，马背原则不适用于"错了就死"的不可逆项。
- **价值观/道德底线审查**——不能拿"上马就走"跳过（对照"这是作恶"叫停机制）。
- **纯信息查询与日常琐事**——"中午吃什么"不需要 PIA，硬套框架是仪式化。

### 作者在书中警告的失败模式

- ce36 数据挖掘式拖延：决策没有截止日期时，"永远在收集信息"是风险最小策略，但信息边际收益趋零、拖延成本线性增长（财捷案例的反面）。
- ce37 紧迫感的奴隶与行动偏误：守门员几乎总扑向一边，原地不动成功率反而翻倍；反向错误是把期限神化、拒绝最后一刻仍有价值的新信息。
- ce59 80/80 错配：埃里克自以为执行了 80/80，时间实际流向光鲜新业务——注意力流向新奇是默认设置，必须显式核算。
- ce39 律师式规避风险：1% 的不确定性被放大成数周分析与 50 页免责文书——法务的风险函数里没有"错失机会"这一项。

### 作者的盲点 / 时代局限

- BOOK_OVERVIEW 批判指出"共识"决策与"少做决策"的张力（谁的时间够用）本书未调和；80/80 与 70/20/10 在"核心 vs 新业务"的分配上互相呼应，但新业务何时升级为核心业务的判定标准书中缺席。
- "合规率容忍五成"与守门员数据等论据是转述与经验之谈；在强监管行业（金融、医疗）不可直接移植，马背原则需要按监管红线重画边界。

### 容易混淆的邻近方法论

- 精益创业 / MVP：精神相近但对象不同——精益管产品验证，本 skill 管决策时机；且本书独有参数（每天开会、80/80、PIA、合规率容忍五成）在精益话语里没有对应物。
- 泛论"授权赋能"：本书独特处是授权与限期绑定——决定权交出去的同一句话里必须含期限，否则只是甩锅。
