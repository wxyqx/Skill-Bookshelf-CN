# 招聘质量律（羊群效应 / 宁缺毋滥 / 宁"漏聘"不"误聘"）

## R — 原文 (Reading)

> "招聘中有一条黄金法则是不可违背的，那就是：宁缺毋滥。如果质量和速度不可兼得，那质量一定要放在首位。" / "我们宁愿'漏聘'（也就是没有招聘那些应该招聘的人），也不愿意'误聘'（也就是把那些不该招入企业的人招进来）。"
>
> — 施密特、罗森伯格，第三章《宁缺毋滥》/《宁可"漏聘"，也不"误聘"》

---

## I — 方法论骨架 (Interpretation)

三个事实决定了这套律法。**其一，招聘是管理者最重要的工作，且职级越高越要亲自抓**——多数公司恰恰相反，高管越高越不管招聘；物色人才像刮胡子，不每天下功夫别人看得出来。**其二，质量是复利**：A 级人才互相吸引（羊群效应），B 级人才不仅招 B 还会引来 C 和 D——标准打折一次，人才密度就开始指数衰减，且早期员工的错误被放大得最狠。**其三，错误不对称**：漏聘（错过该招的人）损失有限且可再遇；误聘（招进不该招的人）要付解雇成本、团队污染与双方折磨。所以拿不准时不录，质量与速度冲突时质量永远优先。

两个自检问题暴露招聘漏洞：把业绩最差的 10% 换成新员工，团队会更好吗？团队里有没有你根本不想挽留的离职者？

推论：没有匹配的空缺也要招最优秀的人（先为人造位，"人浮于位"）；同时警惕另一种人——把"解雇他们就行了"挂在嘴边的人，那只是逃避招聘责任的借口。

## A1 — 书中的应用 (Past Application)

### 案例 1: 桑德伯格因"不是工程师"被拒
- **问题**: 埃里克想把时任顶尖高管的谢丽尔·桑德伯格招入麾下，破不破例？
- **方法论的使用**: 两位创始人坚持"非工程师不招"的画像标准，宁可放过这个级别的人选也不松动。
- **结论**: 质量标准可以极端到放弃顶尖人才——标准即身份。
- **结果**: 桑德伯格最终仍以其他途径加入谷歌工作 6 年多；标准后来有所松动——极端执行既守了标准也漏了人才（c05）。

### 案例 2: "你很棒，我们就招你了"——主动营造羊群
- **问题**: 如何系统性吸引 A 级人才，而不只是被动筛选？
- **方法论的使用**: 用"你很棒，我们就招你了"的招聘语传递高标准信号；乔纳森洽谈候选人时把团队的**全部**简历交给对方看，而非只秀佼佼者。
- **结论**: 高标准本身就是招募手段——优秀的人想和优秀的人共事。
- **结果**: 谷歌早期以此吸引全球求职者，A 撑 A 的羊群滚大（c42）。

### 案例 3: 凯文·希斯特罗姆——"漏聘之痛"的自曝
- **问题**: 自学成才的市场专员凯文申请转入只收计算机科学学位的 APM 项目，高管们破不破例？
- **方法论的使用**: 包括乔纳森在内的高管按条文拒绝，没有为具体的人破例。
- **结论**: 规则挡住了一个高出标准的人——漏聘同样有代价。
- **结果**: 凯文离职创办 Instagram，以 10 亿美元卖给脸谱网；作者自嘲"凯文，好样的！"（c46）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 关键岗位空缺数月，压力之下出现一个"能力一般但能马上到岗"的候选人。
2. 面试完感觉"还行但说不上哪里特别好"，团队意见五五开，要不要发 offer。
3. 复盘连招错人（试用期就走/表现不达标），分不清是标准问题还是流程问题。
4. 高管太久没亲自读简历、面试，把招聘整体交给 HR/猎头。
5. 团队讨论"先招进来，不合适再换人"的兜底策略。

### 语言信号 (用户的话里出现这些就应激活)

- "宁缺毋滥 / 先随便招一个顶着 / 空缺太久了要不要将就"
- "招错人怎么办 / 误聘 / 招进来不合适再换"
- "A 玩家 / A-player / 羊群效应 / A 撑 A"
- "这个候选人还行但不出彩 / 拿不准 / 五五开"
- "hire slow / quality over speed / 别降标准"

### 与相邻 skill 的区分

- 与 `talent-portrait` 的区别：本 skill 管"标准多高、拿不准怎么办"（质量律与取舍）；那个管"画像里有什么维度、怎么测"（学习型动物/机场测试/光圈）。先守律，再选人。
- 与 `hiring-ops` 的区别：本管"要不要这个人"的判断标准；那个管"由谁、按什么流程定"（委员会/30 分钟/信息包）。质量律是 ops 的目的，ops 是质量律的保障。
- 与 `retention-playbook` 的区别：招错的人不能用"招进来再慢慢看"处理，也不能指望留才手段补救入口错误；那本书管入职后的留与汰。
- 与 `expel-villains-protect-stars` 的区别：品行恶棍最好在招聘入口拦截（画像/品行测试），但已入职恶棍的清除是那个 skill 的事。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **把质量律显式化**
   - 完成标准：向决策方复述两条硬规则——宁缺毋滥无例外；漏聘与误聘代价不对称。把"空缺一个月"与"误聘一人"（解雇成本+团队污染+重招时间）的真实成本并列写出。
   - 判停条件：若争议其实是"看什么维度选人" → 转 `talent-portrait`；若是"由谁按什么流程定" → 转 `hiring-ops`。
2. **用两个自检问题校准现状**
   - 完成标准：回答"把业绩最差的 10% 换成新员工，团队会更好吗"（会=招聘环节有漏洞）与"团队里有没有你不想挽留的离职者"（有=该放手），结论写入本次招聘决策的背景。
3. **拿不准时的默认动作**
   - 完成标准：每位拿不准的候选人默认 no-hire，并写下"若误聘，最坏情形是什么"一段；"漏聘的惋惜"可以记录进人才库，但不得作为复议录用的理由。
4. **检查标准的执行人与通道**
   - 完成标准：确认最高负责人亲自读简历/主持面试/填反馈（"物色人才好似刮胡子"）；听到"招错了大不了解雇"时追问其招聘投入（解雇不是招聘缺位的对冲）；对顶尖人才保留"人浮于位"通道——先招进来再造位置。每个录用决策记录一句"此人是否强于团队现有水准，强在哪"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **大批量、可快速培训的劳动密集型岗位**——本书质量律以创意精英型岗位为默认模型，照搬"宁缺毋滥"可能拖垮交付。
- **已到 offer 与薪酬谈判细节**——那是谈判问题，不是录用标准问题。
- **用"解雇"兜底的激进试错式扩张**——先修招聘，不放行；把解雇当常规工具会制造恐慌文化。

### 作者在书中警告的失败模式

- B 级人才繁殖 B、C、D：标准打折一次，人才密度以复利方式衰减，早期员工的错误被放大得最狠（ce23）。
- 以解雇为乐的管理者："解雇他们就行了"只是不愿在招聘上下功夫的人规避责任的借口（ce30）。
- 对称提醒：规则压过判断导致的漏聘同样有代价——凯文·希斯特罗姆与 Instagram 的教训（ce26，与 `talent-portrait` 共用）。

### 作者的盲点 / 时代局限

- "不计成本招最好的人"以搜索业务的垄断性利润引擎为前提（幸存者偏差）；同期采用相似人才策略的雅虎、AOL 并未复制成功——质量律的收益依赖后续的挑战与资源供给。
- 全书以工程师为默认员工模型（创始人一度"非工程师不招"），对强合规、劳动密集行业的可移植性书中未讨论。
- 书中未给"现金流只够 6 个月"式约束的过渡方案；"换路径不换标准"（合同工买时间+扩大漏斗）是下游推演，不是书中原文。

### 容易混淆的邻近方法论

- "hire slow, fire fast"（Netflix 等）：口号相近；本书独特在不对称框架的精确化、两个自检问题与"没有空缺也要招"的人浮于位通道。
- Topgrading 式 A-player 招聘：本书多出两条——显式的"宁漏聘不误聘"取舍，与对"以解雇为乐者"的防范。
