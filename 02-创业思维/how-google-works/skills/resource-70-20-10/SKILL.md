# 70/20/10 资源配置原则

## R — 原文 (Reading)

> "将70/20/10作为我们的资源配置原则，即将70%的资源配置给核心业务，20%分配给新兴产品，剩下的10%投在全新产品上。" / "投入过多与投入不足同样不可取……过度投资会让人产生固执的偏见。" / "'创意喜欢限制'……资源上的稀缺，是激发创意的催化剂。"
>
> — 施密特、罗森伯格，第六章《创新：缔造原始的混沌·70/20/10原则》

---

## I — 方法论骨架 (Interpretation)

这不是风险管理教科书里的"投资组合分散"，而是一条给创新兜底的组织资源律：把预算和人力切成固定三份——七成养活当下的核心业务（它是印钞机，断了就没有明天），两成投给已经初步成功、需要放大的新兴产品（有用户信号，不是纯赌），一成留给没有任何成功迹象的疯狂构想。

真正反直觉的是 10% 这一档的两个设计细节。第一，**刻意不给多**：投入过多与投入不足同样有害——资源砸得越重，人越不甘心放弃、越只能看见项目积极的一面，客观性随投入量递减。第二，**稀缺本身是工具**："创意喜欢限制"，预算紧、时间短会逼团队用巧劲，富余的预算反而滋养平庸的执行。所以给 10% 项目的时候，同时要给它设边界。

配套纪律是同一比例用在注意力上：把 80% 的时间花在贡献 80% 收入的核心业务上（80/80 时间律）。资源分三档，管理者的心思也要分三档，不能让新业务的诱惑把核心业务挤到失血。

## A1 — 书中的应用 (Past Application)

### 案例 1: 谢尔盖切分前 100 项目清单
- **问题**: 2002 年公司变大后，"前 100 项目清单"式的管理开始失灵，作者担心"说不"的文化渗入、好构想被预算流程牺牲。
- **方法论的使用**: 谢尔盖把清单上的项目分成三组——约 70% 属搜索引擎与广告核心业务，约 20% 属初步成功的新兴产品，约 10% 属全新产品——比例由此定案。
- **结论**: 用固定比例给"说好"的文化兜底：10% 的格子天生为疯狂构想留着，不必每个项目都去说服预算会。
- **结果**: 70/20/10 成为谷歌长期的资源分配原则（c77）。

### 案例 2: 苹果牛顿——过度投资捂死了创意
- **问题**: 苹果牛顿的手写识别几乎只认识研发者自己的字迹，为什么没人拦住它上市？
- **方法论的使用**: 作者归因于投入规模——产品"下了血本"，测试小组"削足适履"给出合格结论，管理层听到了顺耳的答案。
- **结论**: 投入越多越难舍弃；耗资百万美元的构想比几千美元的构想要难以放弃得多。这正是 10% 上限存在的理由。
- **结果**: 牛顿惨遭滑铁卢，成为资源配置克制原则的反面教材（c78）。

### 案例 3: 谷歌图书——相机加节拍器起家
- **问题**: 拉里要把人类出版过的约 1.3 亿本书数字化上网，听起来需要天文数字的预算。
- **方法论的使用**: 不动用工程师团队和大预算，先用买来的数码相机、三脚架加节拍器，让玛丽莎翻书拍照，估算每本书的数字化耗时——验证可行后再立项。
- **结论**: "没有什么比过度投资更能损害创意的发展"；限制激发创意，小预算实验反而是最快的路。
- **结果**: 谷歌图书立项，谷歌街景用同样的土法验证并最终覆盖 800 万英里道路（c79）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 做年度预算/季度人力分配：核心业务、成长中的新产品、探索性项目同时在抢资源。
2. 某个探索性项目不断加码，团队开始"只报好消息"，纠结要不要继续投。
3. 想给创新留出资源，又怕被"明年必须见效"的逻辑砍掉。
4. 一人公司/独立开发者规划自己的 2000 小时：主业、有信号的新方向、疯狂尝试各占多少。
5. 业务线负责人抱怨"新项目吸走了我的人"，或反向抱怨"核心业务养活了所有异想天开"。

### 语言信号 (用户的话里出现这些就应激活)

- "预算/人力怎么分 / 资源配置 / resource allocation / 组合"
- "核心业务 vs 新业务 vs 探索 / 70/20/10"
- "要不要给这个新方向加码 / 再投一笔试试"
- "已经投了这么多，放弃可惜 / 沉没成本"
- "创意喜欢限制 / constraint / 稀缺"

### 与相邻 skill 的区分

- 与 `focus-user-think-10x` 的区别：那个决定"方向该多大"（10 倍思维、登月目标），本 skill 决定"钱和人怎么切"——先有大方向，再谈配比。10% 格子里的项目通常就是那个 skill 筛出来的。
- 与 `twenty-percent-time` 的区别：20% 时间是"人的自由时间"制度，自下而上；70/20/10 是"组织资源"的分配纪律，自上而下。前者不需要预算审批，后者年年要拍板。
- 与 `ship-iterate-fail-well` 的区别：迭代管"单个项目的节奏与止损"，本 skill 管"项目群之间的配比"；10% 项目止损后资源回流 70%，两个 skill 在这个接口上衔接。

## E — 可执行步骤 (Execution)

1. **三分类：把候选项目切成核心/新兴/全新**
   - 完成标准：每个项目归入且只归入一档，判据是"现在养家的是谁 / 有没有初步成功的用户信号 / 是否仍是疯狂构想"；三档清单拿出来能被任何人复核。
2. **按 70/20/10 定配比**
   - 完成标准：预算与人力比例落位，70% 那份保证核心业务不缺血；20% 只给有初步成功信号者，纯想法不得挤占；比例写进资源配置决议。
   - 判停条件：核心业务尚未跑通（没有养家的 70%）→ 不机械套用比例，本 skill 只保留"探索项目克制投入"的原则，回到生存优先。
3. **给 10% 档刻意设上限与边界**
   - 完成标准：10% 项目有预算上限和时限；并回答"如果它需要一连串加码才能成立，我们能否在半个周期内发现"——过度投资会制造只见积极面的偏见（牛顿之鉴）。
4. **用小实验代替大预算启动探索**
   - 完成标准：每个 10% 项目先给"相机+节拍器"级别的最小验证（可用土法估算可行性），拿到信号再谈加码。
5. **配对 80/80 注意力律并定期回流**
   - 完成标准：管理者自检时间分配（约 80% 时间在核心业务）；每季度用数据复查三档——新兴转核心、探索转新兴、死掉的探索回流 70%，配比重排一次。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **生存期组织**：核心业务没有正现金流时，"10% 给疯狂构想"是奢侈品——先解决养家问题，比例会变形为 100/0/0，这不丢人。
- **单项目内部排期**：backlog 里功能做先做后，是优先级问题不是组合配置问题，套 70/20/10 是滥用。
- **强合规/重资产行业的硬性迁移**：制药、航空等行业的"探索"受监管流程约束，比例可借鉴，但"快速试错"的部分要先过合规边界。

### 作者在书中警告的失败模式

- 苹果牛顿：过度投资让团队对致命缺点闭目塞听，测试被"削足适履"做合格——赌注越大，承认失败的账面与心理成本越高（ce47）。
- 诺勒的时间错配：新业务的诱惑挤占核心业务，80% 的时间没花在养家的业务上——70 那一档被抽血同样致命（ce59）。
- 沉没成本谬误与承诺升级：以"已经投入多少"而非"未来回报多少"决定继续，掌权者用组织的钱保卫自己的声誉（ce50，与 `ship-iterate-fail-well` 共用）。

### 作者的盲点 / 时代局限

- 幸存者偏差：70/20/10 能运转的前提是 70% 那档真是一台印钞机（AdWords）；非暴利企业照搬比例，可能先饿死核心。书中的从容来自搜索业务的垄断性利润，这一点作者没有明说。
- 比例是经验值而非定律：书中未给出该比例在其他行业/规模下的校准方法，照抄数字不如学它的两个机理（克制 + 稀缺）。

### 容易混淆的邻近方法论

- 风投组合/探索-利用（explore-exploit）理论：结论方向相同；本书独特在 10% 的克制机制（投入过多同样有害）与"创意喜欢限制"的稀缺观。
- OKR 资源对齐：OKR 管目标聚焦，70/20/10 管资源切分；谷歌两者并用但互不替代。
