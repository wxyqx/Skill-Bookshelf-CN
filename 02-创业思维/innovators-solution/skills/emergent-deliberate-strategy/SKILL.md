# 应急/谋划战略流程的情境匹配

## R — 原文 (Reading)

> 英特尔公司从DRAM生产商转化为微处理器公司，却是由资源分配的过程决定的。英特尔的卓越的战略转变并不是高管层有意识的明确战略的结果，而是通过中层管理人员在资源分配中所作的日常决策实现的。
>
> — 克里斯坦森 & 雷纳, 第8章 战略开发流程的管理

---

## I — 方法论骨架 (Interpretation)

每家企业始终同时存在两种战略流程：**谋划型**（deliberate，有意识、分析性、自上而下、有始有终）与**应急型**（emergent，中层、工程师、销售财务人员日常决策的累积涌现）。成败不在于选哪一种，而在于让合适的流程主导合适的情境。

用三问测谋划型是否可行——三条全中才可用谋划型，否则用应急型：
1. 成功所需的所有重要细节是否已知，且实施者了如指掌？
2. 全员能否从各自角度一致理解并行动？
3. 外部不可预料的政治/技术/市场力量是否可控？

切换规则：未来不明、取胜策略未现时，应急型主导——先行动后学习、低成本试错、禁止大额承诺；一旦制胜策略清晰浮现，果断砍掉分散注意力的项目、切换谋划型无情执行。

防"健忘症"：成功企业会把谋划型流程制度化并习惯性套用到下一个破坏性业务上，需有意识地把流程重置回应急模式。

## A1 — 书中的应用 (Past Application)

### 案例 1: 英特尔从 DRAM 转向微处理器
- **问题**: 高管仍把 2/3 研发预算投给 DRAM，但 DRAM 毛利率已被日本厂商压到垫底。
- **方法论的使用**: 生产调度员每月按单位毛利率排产能，产能被有序转移给毛利最高的微处理器——实际战略由日常资源分配涌现，高管末期才"走出旋转门再走进来"追认。
- **结论**: 实际战略是资源分配流程的输出而非输入；战略转型常常先由应急流程实现。
- **结果**: 英特尔成功转型微处理器公司，1984 年财务危机后正式放弃 DRAM。

### 案例 2: 神童通信与苹果牛顿——该探索时砸钱执行
- **问题**: 在线服务/掌上设备市场萌芽，前景不明，却按谋划型流程大额投入。
- **方法论的使用**: 作者指出其错误不在进入太早，而在策略可行性未明前就采用谋划型流程、按既定计划执行。
- **结论**: 破坏性新市场初期无法满足谋划型三条件，应用应急型流程。
- **结果**: 神童通信投入 10 亿美元、苹果牛顿耗资 3.5 亿美元，策略被证明错误时已耗尽资源；奔迈是唯一在原计划失败后转应急流程、再随市场成熟的赢家。

### 案例 3: 沃尔玛小镇开店——应急型涌现为谋划型
- **问题**: 山姆·沃顿决定第二家店不开在大城市，而建在阿肯色州附近的小镇。
- **方法论的使用**: 出于后勤与管理效率的日常决策后来演化成"在小镇建折扣店"的辉煌战略；高效策略浮现后被正式化并加以利用。
- **结论**: 应急型流程涌现的策略在被识别后可转化为谋划型战略。
- **结果**: 形成竞争对手难以抢占的小镇市场战略。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 公司试水一个前景不明的新业务（AI 应用、新市场、新模式），在"按计划大投入"与"先小步试错"之间拿不准。
2. 某个新业务已经跑出清晰的赢利模式，但团队仍在同时资助一堆分散项目，需要判断何时收手聚焦。
3. 成功企业要把一套成熟的战略规划流程（年度预算、ROI 论证、详细预测）套用到一个破坏性新业务上，担心水土不服。
4. 复盘发现新业务"计划做得很漂亮却失败"，想知道问题是否出在流程用错。

### 语言信号 (用户的话里出现这些就应激活)

- "这事该按计划一把投入，还是先小步试错？"
- "现在走一步看一步，是不是太没章法？"
- "模式好像已经跑通了，还要不要继续多头下注？"
- "我们该不该用同一套规划流程管所有新业务？"
- "emergent / deliberate strategy / 探索期 vs 执行期"

### 与相邻 skill 的区分

- 与 `good-money-bad-money` 的区别: 本 skill 判断战略流程该用应急还是谋划；后者诊断资金背后的投资者期望结构（对成长/利润的耐心）如何扭曲选择。
- 与 `resource-allocation-audit` 的区别: 本 skill 关注流程模式的情境匹配；后者审计资金/产能流向与中层筛选标准，回答"真实的战略是什么"。
- 与 `executive-engagement-rules` 的区别: 后者决定高管是否亲自介入；本 skill 决定用哪种战略流程。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **识别当前情境的确定性水平**
   - 完成标准: 明确新业务是否已有可行的取胜模式、关键细节是否已被验证。

2. **用三问检验谋划型可行性**
   - 完成标准: 逐条回答"细节是否已知且实施者了如指掌 / 全员能否一致理解行动 / 外部力量是否可控"，给出三问的通过情况。
   - 判停条件: 三条中任一为否，即判定需应急型主导，跳到步骤 3。

3. **设计应急型探索动作**
   - 完成标准: 给出小规模、多场景、低成本试错的方案，并明确"禁止大额承诺"的红线。

4. **设置流程切换触发器**
   - 完成标准: 写出"取胜模式清晰浮现"的可观测信号，以及届时切换到谋划型、砍掉分散项目的具体动作。

5. **检查"健忘症"风险**
   - 完成标准: 确认是否在把成熟的谋划型流程习惯性套用到新业务，并给出重置回应急模式的动作。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户问的是纯项目排期、预算编制或执行效率问题，情境已明确——此时谋划型本就适用，无需本 skill。
- 用户纠结的是资金方的耐心与期望结构——应使用 good-money-bad-money。
- 用户问的是具体产品功能或技术选型，与战略流程模式无关。

### 作者在书中警告的失败模式

- **该探索时砸钱执行（萌芽期误用谋划型战略）**（ce13）：未来不明却过早采用谋划型流程大规模投入（神童通信 10 亿美元、苹果牛顿 3.5 亿美元），策略被证明错误时已耗尽资源。
- **该执行时仍继续摸索（成功后"健忘症"）**（ce14）：取胜策略已明朗却仍不聚焦、继续分散摸索；或把制度化的谋划型流程照搬到下一个破坏性业务。
- **实际战略被资源分配过滤器扭曲**：中层按"像过去成功案例"包装创意，谋划型流程会压制应急试错。

### 作者的盲点 / 时代局限

- 三条件与"切换测试"多为否定式/纠偏式规则，正面指导依赖对理论的熟练运用；"取胜策略清晰浮现"的判定在实践中带主观性。
- 案例集中于 2003 年前美国大企业；精益创业、敏捷等方法已部分替代发现式规划，对已内建快速迭代机制的组织，本框架的增量价值需重新评估。
- "该探索还是该执行"的边界在快速变化行业中可能瞬时切换，静态三问未必跟得上。
- 作者承认可预测性存在未消除的不确定性来源。

### 容易混淆的邻近方法论

- 明茨伯格"应急战略"：本 skill 正是把该概念操作化为三条件与切换规则。
- 精益创业 MVP：同属探索路径，本 skill 补上"何时切换到执行"的判据。
