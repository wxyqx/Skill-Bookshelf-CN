# 雇用产品提问法（任务理论市场细分）

## R — 原文 (Reading)

> 客户是在"雇用"产品去完成某项特别的"任务"……到底谁才是快餐连锁店早点的真正竞争者呢？……从顾客的角度来说，早点奶昔的竞争对手是无聊、百吉饼、香蕉、甜甜圈……当企业将产品定位于客户所在的情境中，而不是定位于客户本身时，他们就能成功降低产品推广过程中的不确定性了。
>
> — 克里斯坦森 & 雷纳，第3章《客户希望购买什么样的产品》

---

## I — 方法论骨架 (Interpretation)

客户不是在购买产品，而是在"雇用"它完成某项任务。所以市场细分不该问"谁买"（人口、客户属性、产品类别、消费心态），而该问"买来完成什么任务"。任务的功能、情感、社会三个维度共同决定购买条件；真正的竞争对手是完成同一任务的其他方案——包括"什么都不做"。

要发现任务，去观察购买情境：购买的时间、场景、同行者、同购的东西；再追问"不买它时你用什么替代"。替代品集合才是真实的竞争集合（奶昔清晨的任务对手是百吉饼、香蕉和无聊本身，而不是其他连锁店的奶昔）。

一条产品线只应主打一个任务。向身兼多个任务的客户问"该改良什么"，只会得到互相冲突的"四不像"答案，陷入功能军备竞赛。配套一条否决测试：若价值主张是让客户去做他本来不做、优先级不高的事，判为低胜算，直接否决——客户不会因为新产品出现就"改变任务"。开发新品时应封存基于产品/客户属性的历史细分数据，因为它只揭示相关性而非因果。

## A1 — 书中的应用 (Past Application)

### 案例 1: 快餐店奶昔研究——顾客"雇用"奶昔打发通勤无聊
- **问题**: 某快餐连锁改进奶昔（更浓、更巧克力、更便宜、加健康概念）却无效，为什么？
- **方法论的使用**: 不按消费心态细分，而是观察"顾客雇奶昔做什么"。研究员在餐厅连续观察后发现，清晨近一半销量是长途通勤者单杯打包带走。他们追问替代品：百吉饼弄碎屑、香蕉吃太快、三明治油手且会凉、甜甜圈不顶饿——真对手是"无聊"，而奶昔能用一只手、不脏手地撑过约20分钟。晚间则是父母"通情达理"地安抚孩子，该任务下奶昔常常失败。
- **结论**: 同一产品身兼两个互斥任务，改良方向必须按任务分别设计。
- **结果**: 清晨任务给出清晰改良路径（更浓、拌果粒、设自助机加快购买）；成为全书任务理论的招牌案例，并指向"零消费"新市场。

### 案例 2: 盛田昭夫亲察任务，开创12个破坏性业务
- **问题**: 索尼如何连续为破坏性新产品找到立足点？
- **方法论的使用**: 1950-1982年由盛田昭夫与5位伙伴观察和询问"人们想完成什么任务"，再为破坏性产品寻找立足点（便携晶体管收音机、可移动黑白电视、Walkman、3.5英寸软盘等）。他们不做基于属性的量化细分。
- **结论**: 破坏性立足点靠亲察任务获得，量化属性细分只能发现延续性机会。
- **结果**: 12个新市场破坏业务成就索尼黄金时代；80年代初盛田退出、公司改聘MBA人才用量化属性细分评估市场后，18年再无破坏性创新，PlayStation、Vaio都被作者归入延续性产品。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 要为一款产品做市场细分，手头只有按年龄/收入/产品类别切分的传统数据，想换一种能发现破坏性机会的切法。
2. 产品功能越加越多却说不清在帮客户完成什么，团队正陷入"竞品有的我们也要有"的功能竞赛。
3. 需要重新定义真实竞争对手与竞争集合（含"什么都不做"）。
4. 评估一个新产品的价值主张，怀疑它是在"让客户改变任务"。

### 语言信号 (用户的话里出现这些可能激活)

- "我们的市场到底该怎么细分？"
- "客户为什么会买这个？"
- "谁才是我们真正的竞争对手？"
- "下一步该加什么功能？"
- "Jobs to be done? Who do we hire/fire?"
- "客户其实需要这个"（需警惕，可能是改变任务的信号）

### 与相邻 skill 的区分

- 与 `nonconsumer-screening` 的区别: 本 skill 是任务理论总纲，用来发现任务与竞争集合；对方把"任务问题"专门用来甄别零消费人群是真机会还是无任务伪机会。
- 与 `new-market-disruption-pattern` 的区别: 对方把任务理论作为四要素模式里"目标客户"这一要素来塑造新市场破坏计划；本 skill 是细分方法本身。
- 与 `three-stone-tests` 的区别: 对方判断"这个构想是不是破坏性"；本 skill 回答"这个市场上客户要完成的任务是什么、竞争集合是谁"——常作为对方的前置输入。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **封存属性细分假设**
   - 完成标准: 明确列出当前在用的属性分类（人口/产品类别/客户规模），并声明本轮暂时不用它们做决策依据；注明这些数据只揭示相关性。

2. **观察购买情境**
   - 完成标准: 收集并按"购买时间、场景、同行者、同购品"四要素整理真实购买记录或观察数据，形成若干可辨识的"情境簇"而不是人群标签。

3. **追问替代品集合**
   - 完成标准: 对每个情境簇问"不买它时你用什么替代"，列出替代方案清单，务必包含"什么都不做/自己凑合"这一项；由此确定真实竞争集合。

4. **提取任务并拆维度**
   - 完成标准: 用一句话写出该情境要完成的任务，并分别标注其功能、情感、社会维度上的要求；确认这些要求能解释观察到的购买选择。

5. **单任务聚焦与功能取舍**
   - 完成标准: 明确该产品主打的唯一任务，据此把现有功能分为"服务该任务/与该任务无关"两类，给出砍掉与新增的具体建议。
   - 判停条件: 若同一产品被要求同时服务两个互斥任务 → 拆分产品或拆分产品线，避免"四不像"。

6. **否决测试**
   - 完成标准: 检查价值主张是否要求客户"去做他本来不做、优先级不高的事"；若是，判定低胜算并给出否决或重塑建议（回到客户已在雇的方案上找立足点）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 纯定价、渠道推广、组织设计问题——任务理论不直接回答这些（渠道可参见 `channel-motivation-test`）。
- 客户任务本身就是标准化、规格明确的采购（如按规格招标的通用元器件），此时属性/规格细分可能已足够，任务洞察的边际价值低。
- 只是想给现有产品做 bug 修复或明确的功能补强，且任务已清楚。

### 作者在书中警告的失败模式

- **按产品/客户属性细分，做出没人满意的"全能型"产品**：沿用产品类别、人口属性做细分会让企业陷入功能军备竞赛，最终产出无法帮客户完成任务的"瑞士军刀式"产品或四不像（ce03）。
- **试图让客户改变任务**：产品价值主张是让客户做他们原本不做、优先级很低的事，指望新产品创造新习惯；客户不会因新品出现就改变任务，胜算极低（ce04）。

### 作者的盲点 / 时代局限

- 样本集中于 2003 年前的美国上市大企业，任务理论对平台/生态型组织、双边市场、非上市耐心资本与扁平小团队的适用性未经验证。
- 观察法依赖研究者的定性判断，"任务"的边界可被事后叙事影响，缺乏可复现的量化检验；同一现象不同观察者可能切出不同任务。
- 认为"技术进步恒快于需求吸收"是前提假设；个案支撑的结论（如索尼18年熄火）受案例选择影响。
- 任务理论的实操成本高（需大量现场观察），在被压缩的时间与预算下容易被简化回属性细分。

### 容易混淆的邻近方法论

- 与"消费心态/生活方式"细分：后者按心理标签分类，本 skill 按情境中的任务分类；同样的人在一天里不同情境的任务可以完全不同。
- 与"以客户为中心"口号：本 skill 要求定位在客户所处的**情境条件**，而非客户本身。
