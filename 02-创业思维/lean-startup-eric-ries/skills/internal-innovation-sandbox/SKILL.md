# 内部创新沙盒：让大公司既保护创新又保护母体

## R — 原文 (Reading)

> "传统观念认为当公司变得更大时，丧失创新、创意和增长的能力在所难免。我认为这种想法是错的。新创企业成长之际，创业者可以建立一个组织，学习如何在满足现有顾客要求与寻找新顾客之间求得平衡……我还相信，即使是大型成熟企业，只要他们愿意调整管理哲学，他们也可以转换到我所说的'管理组合'的思考方式。"
>
> —【作】埃里克·莱斯，第12章

> "在我的经验中，不管是新创企业还是企业内部的新创团队，都要具备三种架构特征：稀少但稳定的资源，开发业务的独立权，以及与绩效挂钩的个人利益。……要记住，组织架构只是先决条件，它不能保证成功。但是，错误的架构却几乎一定会导致失败。"
>
> —【作】埃里克·莱斯，第12章

> "我们常把企业内部的创新挑战框定在这个问题之上：即如何在组织机构中保护内部创新团队不受干扰？而我想要重新框定并反过来提出问题：如何在新创团队中维护上级组织机构？……所以把创新团队藏起来的常规建议其实是种误导。"
>
> —【作】埃里克·莱斯，第12章

> "长期而言，公司会不断面临各种威胁，我们的挑战是如何在公开、开放的环境中建立向创新团队下放权力的机制，这是公司通向可持续创新文化的必由之路。我建议的解决方案是为创新建立一个沙盒系统，它能控制创新的冲击力，但不会限制创新团队使用的方式。"
>
> —【作】埃里克·莱斯，第12章

> "事实上，大型企业内部的创新者应该把创业工作看做一条可行的职业之路。能够使用精益创业方法领导团队的经理人，就该有一个简单明确的'创业企业家'角色，作为他们名片上的头衔，不一定非要离开公司去施展才能……"
>
> —【作】埃里克·莱斯，第12章

## I — 方法论骨架 (Interpretation)

大企业创新失败的主因不是缺点子，而是缺一套让创新团队和母体业务**同时存活**的机制。本书给出的方案是一整套互锁的制度设计：

1. **大公司不必然丧失创新能力，培养创业企业家是高级管理层的职责**：管理创新可以做得到，但它需要新的管理法则——高管的工作不是亲自创新，而是营造让内部创业者涌现并对之问责的流程（Intuit 的 SnapTax 即为范例）。
2. **三种架构特征是先决条件**：①**稀少但稳定的资源**——预算总量小，但必须绝对安全，中途被砍 10% 对新创团队可能是致命打击；②**独立的开发权**——在有限范围内自主开发并推销，跨部门全职运作、不过层层审批；③**与绩效挂钩的个人利益**——不限于财务（非营利/政府机构可用公开认可与使命感替代，丰田"主查"即首席工程师的最终决定权）。注意：架构只是先决条件，不能保证成功；但错误的架构几乎一定导致失败。
3. **反向框定：保护的是母体，不是把创新藏起来**：正确的问题不是"如何保护创新团队不受上级干扰"，而是"如何在新创团队中维护上级组织机构"。黑匣子式秘密项目（IBM 博卡拉顿）即便偶尔一次成功，也极少带来持续创新，且让没被知会的经理人感到被蒙骗、滋生政治角逐。
4. **创新沙盒七规则——控制冲击力，不限制方式**：①任何团队都可在沙盒内做真正对比测试（只影响沙盒内产品/某细分市场）；②一组团队从头到尾观察整个实验；③实验限时（功能实验一般几周）；④实验不得影响沙盒外顾客（以主流顾客群百分比计）；⑤每项实验用含 5~10 个（不能超过）可执行指标的统一标准化报告评估；⑥所有团队、所有产品用相同指标评估；⑦建实验的团队必须实时监测指标与顾客反应，有重大情况马上停止。沙盒起步要小（如只放一个定价页），顾客是真实的，团队最好有"主查"式身份明确的领导者，且**无需事先批准**即可开发、营销、部署。
5. **管理组合四阶段与创业企业家头衔**：企业须同时管理开发、成长、优化、成熟四类工作（任何公司任何时候都同时在四个阶段上运作）；产品随阶段在团队间交接，员工可跟产品走也可留下再创业。内部创新者应拥有"创业企业家"这个名片头衔，通过创新核算担责并获得升职奖励；沙盒应逐渐扩大而非把团队"搬回"日常运作，扩张须评估团队能否在母体中"自谋生路"。
6. **三重科学质询审内部改变建议**：每项建议都过同一套严格问询——我们能用理论预测这个改变的结果吗？能先在小团队内培育这种改变以观后效吗？能衡量其影响力吗？——让自下而上的改进与精益创业手段同构。

## A1 — 书中的应用 (Past Application)

### 案例 1: 财捷 SnapTax 与"自由岛"（ch02，主线案例）
- **问题**: 拥有 7700 名员工的财捷要推出与自家主力产品 TurboTax 直接竞争的颠覆式新品——按克里斯坦森的预言，这类企业最擅长服务老客户，最挣扎于突破性创新。
- **方法论的使用**: 高级管理层刻意营造流程：上司开辟"自由岛"让团队尽情发挥；最初小组只有 5 个人、没有高额预算和大笔营销投入；团队自己与潜在顾客无数次对话后找到"手机拍 W-2"的点子，先推只针对加州简单退税情形的早期版本。
- **结论**: 让团队实现创新的不是基因、运程或星座，而是刻意营造的机制——管理创新可以做得到，培养创业企业家是高级管理层的职责。
- **结果**: 2011 年全美推出后 3 周内被下载 35 万多次；团队领导人是从公司内部组建的"创业企业家"，而非外聘明星。

### 案例 2: 咨询客户的定价实验乱象与沙盒解法（ch12）
- **问题**: 一家 B2B 收入为主的公司想对消费者细分市场做低价实验，企业销售团队则担心低价"吞噬或削弱"与既有企业客户的关系；此前的定价实验由多个团队先后负责、改了不同部分、用虚荣指标，导致会议上各部门各取数据、主持人"不得不基于看似最合理的论调作决定"。
- **方法论的使用**: 用沙盒规则重构实验：起初沙盒中只需要有定价页；实验只影响沙盒内范围、限时、用 5~10 个可执行指标的统一标准化报告评估、所有团队用相同指标。
- **结论**: 争执的根源不是人不和，而是缺一套既控制冲击力又放权实验的支持体系；沙盒让"基于数据的决定"重获公信力。
- **结果**: 实验边界清晰、母体业务被保护，团队在公开开放的环境中获得了下放权力的机制。

### 案例 3: IMVU 的三重科学质询与自下而上创新（ch11/ch12）
- **问题**: 组织长大之后，改进建议满天飞：什么该试、什么不该试，没有判据；创新者也会从"激进的局外人"变成"现状的代言人"。
- **方法论的使用**: 对每项内部改变建议实行三重质询——用理论预测结果、先在小团队内培育观后效、衡量影响力——与精益创业手段同构；同时以导师制等制度把工作风格传给新成员。
- **结论**: 很多在 IMVU 开拓的精益创业技巧并非作者发明，"而是由企业员工把自己的创造力和才干注入工作之中，构思、发挥和执行的"——机制让创新自下而上地涌现。
- **结果**: 每当建议得以实施，新的做法既提升个人认知，也提高了公司的生产效率。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 在大公司/大机构里为创新业务争取独立资源：团队总被业务部门抢人抢预算、中途砍款，想问"该给创新团队什么样的架构和保障"。
2. 要给内部实验"立规矩"：既想放权让团队大胆试，又怕搅乱主营业务和客户关系，需要划实验边界、定统一的实验与汇报规则。
3. 要设计内部创新的考核、头衔与交接：创新负责人做完产品就被塞去管运营、没人愿意再开新东西；或创新全靠"秘密项目"躲在别的楼里偷偷搞，从没出过第二个成功产品。

### 语言信号 (用户的话里出现这些就应激活)

- "内部创新""创新沙盒""管理组合""内部创业者""创业企业家""自由岛""主查/首席工程师"
- "给创新团队独立资源/单独预算""独立开发权""创新考核""内部实验的规矩""怎么给内部创新定边界"
- "秘密项目/黑匣子创新""创新团队和业务部门抢资源""做完产品就转岗""大企业怎么做创新"

### 与相邻 skill 的区分

- 与 `bml-validated-learning` 的区别：后者管创新业务本身怎么跑验证循环；本 skill 管**承载它的组织机制**（架构、边界、激励、交接）。问"实验怎么做"归后者，问"团队有什么权、受什么限"归本 skill。
- 与 `lean-startup-five-principles` 的区别：后者答"精益创业适不适用于我们"的总判断；本 skill 是已决定采用后**在大机构里落地成制度**的设计图。
- 与 `innovation-accounting` 的区别：沙盒内的团队用什么核算框架向管理层汇报归后者；"报告必须标准化、统一指标、5~10 个上限"这类**沙盒制度条款**归本 skill。
- 与 `actionable-vs-vanity-metrics` 的区别：指标怎么设计、同期群/对比测试怎么做归后者；本 skill 只规定"所有团队用同一组可执行指标"的制度约束。
- 与 `five-whys-adaptive-org` 的区别：出事故后追根因、调组织速度归后者；本 skill 是事前把创新运行的"宪法"写好，不处理事故诊断。

## E — 可执行步骤 (Execution)

1. **给创新团队配齐三种架构特征**：逐项检查资源（少而稳、有书面承诺防中途砍款）、开发权（划定独立工作范围、跨部门全职、免层层审批）、个人利益（股权/奖金与长期表现挂钩，或用公开认可替代）
   - 完成标准：三项各有明确书面安排；任何一项缺失（尤其资源稳定性）即视为架构错误，先补齐再开跑。
2. **反向框定，安抚母体**：把问题从"怎么护着创新团队"倒转为"怎么让上级组织和业务部门不被蒙在鼓里"——让实验公开可见，给经理人事先知情与申诉渠道
   - 完成标准：母体相关部门知道实验的存在与边界；团队不再被要求保密；"如果创新可以藏着掖着，还有什么不能"的信任裂痕已被显式处理。
3. **建立沙盒七规则并从小起步**：成文规定——实验只影响沙盒内产品/细分市场、全程有人观察、限时（功能实验几周级）、顾客影响面以主流顾客百分比封顶、5~10 个可执行指标的统一标准化报告、全体团队同一指标、指标异动即熔断停止
   - 完成标准：七条全部成文且可执行；沙盒初始范围足够小（如一个定价页、一类顾客）；指定了"主查"式身份明确的领导者。
4. **授权跑实验并按创新核算汇报**：团队无需事先批准即可开发、营销、部署；沙盒顾客是真实顾客；以统一标准化报告汇报基准线与引擎调整
   - 完成标准：至少一轮实验在无事先审批下完成；汇报用的是与全公司相同的可执行指标，而非各部门自选数据。
5. **按管理组合四阶段安置人与产品**：为开发/成长/优化/成熟四类工作分别匹配团队；产品交接时员工可跟产品走或留下再创业；落实"创业企业家"头衔与升职奖励；规划沙盒逐步扩大及团队"自谋生路"评估
   - 完成标准：四阶段归属清单成文；每个创新负责人有头衔与利益挂钩安排；交接方案含去留选择；沙盒扩张计划中写明母体承受力评估。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户问的是创新业务**本身**怎么跑验证、怎么挑实验、怎么衡量进展——那是循环与工具层的事，转 `bml-validated-learning`、`mvp-design-patterns`、`innovation-accounting` 等。
- 用户还在判断"精益创业适不适合我们这种组织"——总纲判断转 `lean-startup-five-principles`。
- 用户的问题是出了事故后的根因分析与流程取舍——转 `five-whys-adaptive-org`。

### 作者在书中警告的失败模式（按家族速查）

- **e20 IBM 博卡拉顿黑匣子（F10）**：设在佛罗里达州博卡拉顿、与主线业务完全分离的创新据点即便取得一次性成功，也"极少带来持续的创新"——躲避上级组织机构会造成长期的负面结果，IBM 正因此在黑匣子开发的新市场（如个人电脑）丧失领导地位。
- **e21 黑箱激励（F10）**：某高利润科技企业以管理层颁发的神秘大幅升职加薪奖励创新团队——没有客观标准让团队自我衡量，大家缺乏信心，于是没人真冒险，都把精力集中在"有可能获得高级管理层批准的项目上"。
- **e23 "放慢节奏、寻找天才"的迷思（F11）**：面对创新困境，指望"某些人生来就知道该做哪些正确的事"的天才或放慢节奏是歧途——SnapTax 团队靠的是刻意营造的流程，"不是他们的基因、运程或星座"。
- **e19 折中陷阱（F9）**：在"放开创新"与"保护现状"之间各让一步的折中仲裁，会惩罚中间立场、奖励表演极端——沙盒规则必须成文且统一，不能靠会上的折中角力临时裁断。

### 作者的盲点 / 时代局限

- 主案例（财捷、IBM、丰田主查、IMVU）多来自 2000 年代前后的美国科技与制造业；沙盒假设实验成本低、可在线切流，硬件、强监管、长交付周期行业需大幅变通（书中亦承认法律/品牌/组织政治等现实约束）。
- "公开沙盒优于秘密团队"的论断以西方大企业政治生态为语境；书中也承认三种架构特征本身就需要高级管理层的支持来创建——若高管不背书，整套机制无从落地，这一点书中着墨有限。

### 容易混淆的邻近方法论

- **克里斯坦森《创新者的窘境》/"另起炉灶"式独立子公司**：同样诊断颠覆式创新难题，但莱斯明确反对"与主线完全分离"的黑匣子路线，主张公开沙盒加再整合——分离式团队极少带来持续创新。
- **谷歌式 20% 自由时间/秘密实验室**：那是放权给个人自发项目；沙盒是一套成文的边界规则（限时、限影响面、统一指标、熔断），强调制度化的问责而非自由放任。
- **常见的"创新大赛/黑客松"**：一次性活动不等于持续机制；沙盒要求真实顾客、统一可执行指标和认知阶段性目标，活动式创新通常缺这些约束。
