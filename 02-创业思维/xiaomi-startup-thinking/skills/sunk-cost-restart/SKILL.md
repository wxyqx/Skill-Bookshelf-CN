# 方向性错误推倒重来——沉没成本当学费，重做目标必须是终结性产品

## R — 原文 (Reading)

> 我们在这款产品上的研发费用已经投入了4000多万元，开发团队经过讨论，一致同意，之前的4000多万元研发费用就当交学费了，整个项目推倒重来。
>
> — 雷军/徐洁云，《小米创业思考》第六章 互联网七字诀（快篇）

---

## I — 方法论骨架 (Interpretation)

错误分两类：执行不足（流程、工艺、细节打磨不够）可以靠迭代改善，越改越好；产品方向/定义层面的根本性错误（核心体验本身不达标、起点就错了）继续打磨只会加大损失——修补是在错误的地基上加盖楼层。判定的关键是设一个"重做判定点"：当测试结果触及产品定义底线（而非进度延误或成本超支）时，不进入修补流程，直接评估推倒重来。

判定为方向错误后，两步收尾：已投入的费用立即改记账为"学费"——它的价值已经兑现为"确认此路不通"的认知，不再是待收回的投资；随后重组团队重做，且重做目标必须是"终结性产品"——不是修补版的第二款，而是要终结某个旧格局的产品（红米二代以 4460 万台终结了山寨机业态）。另外注意：方向性错误不只在产品层，路径选择错误（如技术路线一步登天）同样适用"改道而非硬扛"的逻辑。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 红米一代 4000 多万元研发费打水漂，二代 4460 万台终结山寨机
- **问题**: 2012 年立项红米做"国民手机"，第一代产品内部测试体验不理想，此时已投入 4000 多万元研发费。
- **方法论的使用**: 团队讨论判定问题出在产品本身而非执行，触及产品定义底线；一致同意 4000 多万元当作学费，整个项目推倒重来，不进修补流程。
- **结论**: 方向性错误的唯一止损方式是重做，沉没成本在判定瞬间即转为认知资产。
- **结果**: 重做的红米二代 2013 年 799 元上市，单款销量 4460 万台，山寨机业态迅速消亡——重做目标被设定为终结性产品并达成。

### 案例 2: 澎湃 SoC——路径错误的改道而非放弃
- **问题**: 2014 年组建松果公司造芯，不到 20 人直攻最高难度的手机 SoC，3 年多烧约 10 亿元后业务陷入僵局，S2 迟迟未出。
- **方法论的使用**: 复盘结论是错误估计难度、选择了错误的前进路径——路径/方向错误比投入决心缺失更致命；止损方式不是放弃方向，而是判定当前路径不可行、改道：从 ISP 影像芯片、充电芯片等易成败的细分芯片做起，以战养战。
- **结论**: 方向性判定同样适用于技术路径层——错路继续加注是损失，改道保留方向。
- **结果**: 2021 年起澎湃 C1/P1 等细分芯片在高端机量产交付，能力与业务同步爬坡。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 项目投入数百万/数千万后内测口碑平平，团队主张"再打磨两个版本就好"，用户判断不了是执行问题还是定义问题。
2. 决策者明知产品方向可能不对，但被"已经投了这么多钱、停了没法向老板/股东交代"的心态绑架，在找止损的判定依据。
3. 技术路线选错（如直接攻坚最难方案）陷入僵局，在评估改道、收缩还是继续硬扛。

### 语言信号 (用户的话里出现这些就应激活)

- "沉没成本、都投了 X 万了、打水漂、交学费"（sunk cost）
- "推倒重来、从头再做、scrap and rebuild、start over"
- "内测/口碑不行，继续修还是砍掉、要不要止损"（kill the project / cut losses）

### 与相邻 skill 的区分

- 与 `downturn-remediation` 的区别: 那是公司级系统性能力落后的危机补课（交付/创新/质量三抓手）；本 skill 针对单一产品/项目方向性错误的取舍判定，范围小而决断重。
- 与 `speed-four-abilities` 的区别: "改善快"属于方向正确时的执行迭代；本 skill 恰恰要先判定方向是否正确——方向错时迭代是负动作。
- 与 `new-business-three-pits` 的区别: 那是进入新业务前的风险自检；本 skill 是已投入后的事中止损判定。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **判定错误类型**
   - 完成标准: 明确写出问题是否触及产品定义底线（核心体验/目标用户价值不成立），并列出证据；若是可迭代的执行细节缺陷，则给出迭代清单并退出本 skill。
   - 判停条件: 若为执行缺陷（性能优化、工艺改进、交互细节），转迭代流程，不推倒重来。

2. **冻结修补投入**
   - 完成标准: 修补预算与排期冻结成文，团队停止在错误地基上继续加盖。

3. **沉没成本计为学费并复盘归档**
   - 完成标准: 财务与心理上完成"学费"记账，产出教训清单（错在哪、判定依据、下次立项的检查项）并作为新项目输入。

4. **重组团队设定终结性重做目标**
   - 完成标准: 新项目目标不是"修补版"，而是定义"要终结什么"（如红米二代终结山寨机）；若同时存在技术路径错误，先改道到与能力匹配的难度阶梯再重做。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 仅执行层面的缺陷：性能不达标、工艺不稳、交互细节差——方向正确时这些必须迭代，推倒重来是浪费。
- 早期低成本试错：试错本身就是设计，快速放弃是常态，谈不上"沉没成本当学费"的重决策。
- 纯产品线裁撤：因战略收缩砍掉产品线是资源配置问题，不是"重做"决策。

### 作者在书中警告的失败模式

- 路径选择错误比决心缺失更致命：澎湃芯片不到 20 人直攻最高难度 SoC，"先干了再说"替代难度/资源/节奏评估，投入越多僵局越深——方向判定必须包含技术路径维度。
- 重做之后仍可能在别的维度再犯：红米命名本身后来被判定为"轻率消耗小米品牌资产"，2019 年 Redmi 独立纠偏——重做决策要连同命名/品牌等架构决策一并审视。
- 以"稳定压倒一切"为拖延辩护：明知问题显形却迟迟不做决定，用修补动作掩盖判定恐惧（与低谷章"片面求快"教训同源）。

### 作者的盲点 / 时代局限

- 幸存者叙事：红米二代、澎湃改道等"重做后成功"的案例入选，重做后仍失败的项目未被记录，重做成功率无从得知。
- "4000 万当学费"的叙事依赖创始人权威与团队共识，书中未给出可授权、可复制的判定机制，普通管理者难以复制这种"一致同意"。
- 决策口径为自述：投入金额与测试结论均出自作者单方叙述，附录为品牌传播文本，细节经叙事化修剪。

### 容易混淆的邻近方法论

- downturn-remediation：公司级补课 vs 单品重做判定。
- speed-four-abilities：方向正确时的迭代提速 vs 方向错误时的止损重做，两者以"错误类型判定"为分界。
- new-business-three-pits：事前自检 vs 事中止损。
