# 一次只做一件事（集中精力）

## R — 原文 (Reading)

> "卓有成效如果有什么秘诀的话，那就是善于集中精力。卓有成效的管理者总是把重要的事情放在前面先做（first things first），而且一次只做好一件事（do one thing at a time）。"
>
> — 彼得·德鲁克，第5章·要事优先（L1257）

> "正因为管理者面对的事务太多太杂，才特别需要专心。一次只做好一件工作，恰恰就是加快工作速度的最佳方法。越能集中我们的时间、努力和资源，我们所能完成的工作也就越多。"
>
> — 彼得·德鲁克，第5章·要事优先（L1273）

> "一般的管理者喜欢同时着手几件要事，结果对每一件事，他们都无法获得足够的最低整块时间。只要任何一件事情受阻，全部事情也都跟着受阻了。"
>
> — 彼得·德鲁克，第5章·要事优先（L1287）

---

## I — 方法论骨架 (Interpretation)

"要事优先"有两半：重要的先做，以及一次只做一件。后半常被忽视，却是德鲁克最反直觉的推论——越集中，完成得越多；并行不是效率，而是所有要事一起卡住的根源。

机制有三条。一，贡献多而时间少：管理者的重要工作极多、可自由支配的时间极少，唯一出路是集中。二，重大贡献需要长整块时间（第2章的门槛：写报告初稿要 6~8 小时、科学实验要 5~12 小时；低于门槛的时间"所花的时间就是浪费，再做就得从头开始"）。三，人不是能同时抛接多个球的多功能工具：杂技演员最多抛 10 分钟，普通人甚至三件事都绝无仅有（莫扎特是例外，不能拿例外当方法）。

配套是三件"一事无成"的自毁习惯，要做镜像操作：低估任务所需时间（改为估算宁可有余、把"意料之外"计入计划）；喜欢赶工（改为按部就班、不赛跑）；同时开工几件要事（改为一段时期只有一件要事，其余搁置）。

操作定义：在一段时间内，把本人的时间精力以及整个组织的注意力，都集中在同一件要事上；完成后才启动下一件。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 制药公司总裁 11 年的三件大事
- **问题**: 一家规模极小、业务限于国内的制药公司，如何在强手林立的世界制药业里翻身？
- **方法论的使用**: 这位总裁 11 年任期内只做三件大事，每件都集中数年：最初几年集中推动研究计划、搜罗研究人才（不到 5 年，公司在两项新计划上高居领先）；中期集中把公司做成国际性企业（判断健康保险与大众医疗服务将刺激药品用量，配合某国健康保险打入国际市场）；最后五年集中制定"医疗公用事业化"的新策略。他不追求什么都做，每次只专心做好一件。
- **结论**: "他之所以能取得如此成就，就是因为他能每次专心只做好一件事。"要在任期内做成一件这样的工作已非易事，而他在十多年里做出了三项重大决策。
- **结果**: 公司从国内小厂成长为实力强大、人力雄厚的世界性大公司；"他们所用的时间总比别人少得多"。

### 案例 2: 杂技演员与莫扎特——能力边界的参照系
- **问题**: 人是否真的能同时处理多件事？
- **方法论的使用**: 德鲁克承认人有"多功能工具"的一面，但给出边界：最好的杂技演员双手抛七八个球也只能玩 10 分钟，时间久了所有球都得掉下来；能在同一时间交替做两件事的人已属少数，同时处理三件"恐怕就绝无仅有"；莫扎特能同时作曲数首且首首杰作，但巴赫、韩德尔、海顿、威尔第一流的作曲家都只能同一时间专心于一曲。
- **结论**: 对一般管理者而言，"想像莫扎特一样同时做好几件事是不太可能的"——例外不能当作方法。
- **结果**: 这条能力边界成为"一次只做一件事"的直接依据。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户同时推进两三个项目/要事，现在全部延期，问"先救哪一个"。
2. 用户日程排满、频繁切换任务，每天很累但重要的事没有任何实质进展。
3. 老板/组织把多个"最高优先级"任务同时压给用户或团队，用户问怎么接。
4. 用户读完时间管理内容后试着"多线程"处理要事，结果每件都浅尝辄止。

### 语言信号 (用户的话里出现这些就应激活)

- "我同时在推三个项目，全都卡住了 / everything is stuck, all delayed"
- "多线并行是不是更高效 / multitasking, parallel projects"
- "我应该先做哪个？/ which one first"
- "重要的事一直没时间动 / important work never gets done, no deep work time"

### 与相邻 skill 的区分

- 与 `priority-and-posterior`（f15）的区别：f15 解决"选哪件、敢不敢定不做的"（取舍与勇气）；本 skill 解决"选定了之后一次推几件"（并行度与配额）。先 f15 排序，再本 skill 串行执行。
- 与 `consolidate-free-time`（f05）的区别：f05 处理时间资源侧——记录、清理、把零碎自由时间并成整块；本 skill 处理任务侧——每件要事的最低整块时间配额与串行推进。碎片太多要先 f05，任务太多才是本 skill。
- 与 `abandon-yesterday`（f14）的区别：f14 是"删掉不该继续的过去"（减存量）；本 skill 是"同一时间只让一件要事占用你"（串行）。减不掉的原因常是舍不得昨天——那种情形先走 f14。
- 与 `time-diagnosis-questions`（f03）的区别：f03 砍掉根本不需要做的事（取消/授权）；本 skill 假定都是要事，处理的是它们的排列方式。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **列出要事清单并估算每件的"最低整块时间"**
   - 参照书中门槛量级（如深度写作类初稿需连续 6~8 小时、实验类 5~12 小时）为每件要事估算所需连续时间。
   - 完成标准: 每件事有一个连续时间区间，而不是总工时。
2. **核算可用整块时间**
   - 从日历估算未来 2–4 周真正能连续支配的时间总量（可借用 f05 的记录结果）。
   - 判停条件: 若平均每件要事都拿不到门槛的一半 → 确认问题在并行本身，进入第 3 步；若总时间够但全部被切成碎片 → 转 f05 处理。
3. **选定唯一当前要事，其余明确搁置**
   - 用 f15 的优先次序选出 1 件（不是 2–3 件）作为当前唯一要事；对其余写下"本次不做"及搁置风险（搁置≈取消，时机有代价）。
   - 完成标准: 能说出本周"我在不做"的清单，且每项有接手/重启的安排。
4. **给唯一要事足额连续时间并防守**
   - 在日历上占定连续块（如半天或 90 分钟单元拼接），并预设被蚕食时的回收机制。
   - 完成标准: 日历上出现具体时段；有至少一条防守规则（关通知、免打扰时段等）。
5. **修正三件自毁习惯**
   - 时间估算宁可有余（把意外计入）；不赶工（按部就班）；不启动新的"要事"直到当前件完成。
   - 完成标准: 计划里有明确缓冲；当前要事完成前不接第二件要事（拒绝或排期）。
6. **完成后才定下一件**
   - 视情况变化重定优先次序，再启动下一件唯一要事。
   - 完成标准: 有"启动下一件"的时点判断，而不是自动顺延旧清单。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 值守型/响应型岗位（客服、运维值班、急诊分诊）：这类工作本质上要求并行响应，"一次只做一件事"只适用于其中的"要事"，不适用于事务性队列。
- 无时间自主权岗位（BOOK_OVERVIEW 强制边界，承接 ce04–ce10 的时代声明）：若连续时间完全不可得，替代动作是先争取哪怕每天 30–60 分钟的稳定连续段，或与 f05/f03 连用先清理时间；若结构上完全不可行，应如实说明本 skill 暂不适用，而不是让用户自责。
- 用户的问题其实是"该不该做这件事"（取舍），不是"一次做几件"——用 f15 或 f24。

### 作者在书中警告的失败模式

- **同时着手几件要事（ce20）**：三件典型自毁——低估所需时间（以为万事顺利）、喜欢赶工（赶工使进度更落后）、多要事并行互相拖累。预警信号：手头同时有多件"第一位"的任务；日程排得刚好、没有任何余量。
- **把集中当口号不设防守**：集中的自由时间会持续被"新的问题、新的紧急事件"瓜分——德鲁克强调这是持续对抗，不是一次性安排（与 f05 的防守机制衔接）。

### 作者的盲点 / 时代局限

- 秘书/助理与高管语境（BOOK_OVERVIEW 批判节）：书中"整块时间"在大公司高管与秘书支持下才现实；对基层执行岗，需按上文替代动作降级执行。
- 案例是 1966 年前美国大企业的轶事（制药公司总裁为匿名案例，无对照组）；证据等级声明：本书证据以作者顾问观察与轶事为主，无对照实证。
- "同时处理三件事绝无仅有"是基于 1960 年代经验的能力断言；个体差异与今日工具支持的异步协作使其强度需保留（德鲁克自己也承认莫扎特式例外）。
- 女性的时间约束在书中零着墨（性别化石），照护责任等现实约束需在本 skill 之外处理。

### 容易混淆的邻近方法论

- 流行时间管理（碎片利用、微任务、多线程技巧）：德鲁克的立场相反——低于门槛的碎片时间对重要工作等于零价值；重点不是"塞得更满"而是"串得更纯"。
- 与"敏捷并行/矩阵分工"：组织层面的并行属于分工设计问题，本 skill 管的是个人与团队注意力的串行纪律。
