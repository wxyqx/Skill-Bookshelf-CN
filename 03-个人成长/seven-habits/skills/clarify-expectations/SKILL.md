# 一开始就明确期望

## R — 原文 (Reading)

> "几乎所有的人际关系障碍都源于对角色和目标的期望不明或者意见不一致。……期望不明确会导致误会、失望和信用度的降低。"
>
> — 史蒂芬·柯维，第六章（人际关系的本质）·明确期望

> "很多期望都是含蓄的，从来没有明白地说出来过，但是人们却想当然地认为这些事是心照不宣的。实际情况并非如此。如果没有明确的期望，人们就会变得感情用事，原本简单的小误会也会变得很复杂。"
>
> — 史蒂芬·柯维，第六章（人际关系的本质）·明确期望

> "正确的做法是一开始就提出明确的期望，让相关的每一个人都了解。要做到这一点需要投入很多的时间和精力，不过事实会向你证明，这样做会省去你将来更多的麻烦和周折。"
>
> — 史蒂芬·柯维，第六章（人际关系的本质）·明确期望

---

## I — 方法论骨架 (Interpretation)

关系里的多数爆炸，不是坏人造成的，而是两套从未对表的期望相撞。柯维的诊断词是"含蓄期望"：每个人心里都有一份从未说出口、却默认对方应当知道的角色说明书——妻子默认丈夫记得纪念日，老板默认下属"该懂"报告要什么格式。冲突发生时，双方各自翻开自己那份说明书，都觉得自己有理。

这条原则的操作是三句话：

1. **时机前置**：在合作开始（或下次冲突复盘时）主动把角色、目标、标准、时限摆上桌面；此时是谈判，事中是审判。
2. **识别含蓄期望**：问自己"有哪些要求我从没说出口，却默认对方应该懂"——把它们逐条说出来。说清要投入时间，但省去更大的事后代价。
3. **期望要具体到可检验**："帮我做好那件事"不是期望；"谁、在什么时间、交付什么、按什么标准"才是。做到了这一点，后续的分歧就从"你根本不在乎"降级为"我们对标准的理解不同"——前者伤关系，后者只是技术问题。

## A1 — 书中的应用 (Past Application)

### 案例 1: 16 岁女儿的双赢用车协议（cases.md c20，bound to f12；p16 引"协议从一开始就明确了双方对彼此的期望"）
- **问题**: 青春期女儿用车，父母担心安全与车况，女儿要自由——反复口头要求只会升级为权力斗争。
- **方法论的使用**: 父女把彼此期望从一开始就白纸黑字写清：女儿遵守交规、负责清洁保养；父母提供汽车、汽油、保险；每周日碰面评估，达标可用、不达标停用。
- **结论**: "协议从一开始就明确了双方对彼此的期望"，评估的是约定本身而不是父女谁赢。
- **结果**: "协议让我们三个人都得到了解放"，女儿实现自我管理。

### 案例 2: 职责描述的对峙对话（L4661-4673）
- **问题**: 员工与老板互相等待对方界定工作职责——"我等你拿给我""我以为是你在等我说清楚"，双双僵住。
- **方法论的使用**: 柯维用这组对话演示目标期望不明确如何损害交流与信任：双方都援引"从最开始你说的是……"，各有各的版本。
- **结论**: 谁来完成什么样的工作必须在开端说清，否则小事也会升级为"你说过/你从没说过"的人格审判。
- **结果**: 该组对话成为第六章"明确期望"一节的立论场景。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 新合作启动：新员工入职、接手新客户、合伙开工、项目立项——想在开始前对齐角色与目标。
2. 冲突复盘：新婚夫妇为"过年回谁家"爆发第一次大吵、婆媳为带孩子方式翻脸——发现双方都在引用从未言明的"心照不宣"。
3. 交付反复不符：给下属或外包的要求说了几遍，交来的总是"不是我想要的"。
4. 关系长期积累怨气："我以为你早该知道"式的失望越攒越多。

### 语言信号 (用户的话里出现这些就应激活)

- "你说过……/你从没说过……"（you said / you never said）
- "我以为他应该知道""心照不宣""这种事还用说吗"
- "职责不清/权责不明""下属做的总不是我想要的"
- "对齐预期/明确期望/clarify expectations"

### 与相邻 skill 的区分

- 与 `stewardship-delegation`（f18）的区别：授权场景中"预期成果"只是五要素之一，f18 处理把整项任务连同责任交给对方；本原则覆盖一切关系（夫妻、婆媳、客户）的期望对表，不限于授权。给下属布置任务总返工 → f18；跨关系的心照不宣冲突 → 本 skill。
- 与 `emotional-bank-account`（f08）的区别：明确期望本身是情感账户七种存款之一；但 f08 是余额总诊断（先查提款记录），本 skill 是其中一种定向投资动作。关系全面冷却 → f08；冲突源明确指向期望不明 → 本 skill。
- 与 `no-involvement-no-commitment`（p08）的区别：期望的**明确**不等于期望的**强加**——共同目标要执行者参与拟定（p08），明确期望是把参与产出的共识落到可检验的条目上。对外包与一次性合作可单方开价再协商，对家庭与团队须走参与。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **盘点含蓄期望**
   - 完成标准：与用户分别列出双方的隐性期望清单（"我从没说出口但默认对方知道的要求"），每条至少落到角色、事项、标准之一；先自查己方，不先数落对方。

2. **归因分级**
   - 完成标准：把当前冲突标注为"期望不明"或"期望不一致"——前者是没说清，后者是说了但真分歧；两者的处理不同（前者补沟通，后者进入协商）。
   - 判停条件：若拆解后发现冲突实为账户透支（长期积怨、恶语相向），先转 emotional-bank-account 修复，再回来对表。

3. **对表会谈**
   - 完成标准：产出一次对表记录：双方各自的期望逐条摊开，重合项确认，分歧项进入协商；每条最终写成"谁、在什么时间、交付/做到什么、按什么标准"。

4. **落地为可检验形式**
   - 完成标准：家庭场景用书面或口头约定+定期回顾（参照用车协议的每周碰面），工作场景写入协议或任务单；含"情况变化时如何重新对表"的条款。

5. **设回顾点**
   - 完成标准：约定首次回顾日期（建议 2-4 周），检查期望是否仍符合实际，修订而非翻旧账。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **探索性工作前期**：方向未验证的项目细节期望定得越死，返工越多；此时只对齐目标与决策节奏，细节随发现演进。
- **单方强加的"明确"**：把明确期望做成强势方下达的清单，让弱者签字——柯维的期望明确以双方了解为前提，配合 p08 的参与；单方版本只会加速关系破产。
- **用旧账倒推期望**：冲突后拿着今天的标准审判昨天的行为；对表只对过去未言明事项做确认与豁免，对未来做约定。

### 作者在书中警告的失败模式

- 含蓄期望的代价："人们就会变得感情用事，原本简单的小误会也会变得很复杂，原本很小的事情也会导致严重的冲突和人身攻击，最终不欢而散。"
- "你说过/你弄错了/你连提都没提过"式循环（L4687-4697）：期望不明把技术分歧升级为人格指控。
- 事前怕麻烦：柯维承认明确期望"需要投入很多的时间和精力"，跳过它省下的时间会在冲突中连本带利还回去。

### 作者的盲点 / 时代局限

- **原则中心论不可证伪**："几乎所有人际障碍源于期望不明"是全称诊断，任何冲突都可回溯出期望落差，命题在书内不可检验（BOOK_OVERVIEW 批判节）。
- **权力不对等的盲区**：在雇佣关系悬殊、家务分工性别化的场景中（书中案例均为 80 年代中产家庭与组织），"明确期望"可能被强势方用来固化对自己有利的分工；skill 层面应检查期望本身的正当性，而不只是清晰性。
- **文化变量**：含蓄沟通在某些文化语境中承担维系体面的功能，全部显性化并非无代价，书中未讨论。

### 容易混淆的邻近方法论

- 项目管理的需求对齐/SOW：同形但域不同——柯维把"明确期望"推广为全关系域（含家庭与亲密关系）的第一障碍诊断，且强调含蓄期望的心理机制，不只是交付条款。
- `win-win-agreement` / `stewardship-delegation`（g22/f18）：协议五要素中的"预期结果"就是明确期望的授权场景实现；本原则是其一般形式。
