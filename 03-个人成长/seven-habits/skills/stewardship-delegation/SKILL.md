# 责任型授权五要素（Stewardship Delegation）

## R — 原文 (Reading)

> "责任型授权的关注重点是最终的结果。它给人们自由，允许自行选择做事的具体方法，并为最终的结果负责。起初，这种授权方式费时又费力，但却十分值得。"
>
> — 史蒂芬·柯维，第五章·责任型授权（fulltext.txt L4111）

> "这种授权类型要求双方就以下五个方面达成清晰、坦诚的共识，并做出承诺：预期成果、指导方针、可用资源、责任归属、明确奖惩。"
>
> — 史蒂芬·柯维，第五章·责任型授权（fulltext.txt L4113-4129 撮要）

> "不加约束的放任，其最终结果只能是扼杀人们的能动性，让人们回到初级的指令型要求上：'告诉我你想要我做什么，我照做就是了。'"
>
> — 史蒂芬·柯维，第五章·指导方针（fulltext.txt L4121）

> "信任是促使人进步的最大动力，因为信任能够让人们表现出自己最好的一面。……授权的大原则不变，权限却因人而异。"
>
> — 史蒂芬·柯维，第五章（fulltext.txt L4167、L4175）

## I — 方法论骨架 (Interpretation)

授权只有两种：**指令型**（盯方法——"做这个、做完告诉我"，自己为结果负责）与**责任型**（盯结果——对方自选方法、为结果负责）。指令型是多数人的默认，代价是自己成为瓶颈；责任型前期费时费力，但产生杠杆（1 小时撬动 10-100 倍成果）并培养责任感。

责任型的骨架是五要素的**成对共识**——不是单方面交代，而是双方都说清楚并承诺：

1. **预期成果**: 要什么结果、何时要；方法不计。
2. **指导方针**: 原则、限制性规定、已知的坑——约束但不下指令，防"不加约束的放任"。
3. **可用资源**: 人力、财物、技术、组织支持，包括"我可以帮什么"。
4. **责任归属**: 业绩标准、时间表、由谁评估（理想是自我评估）。
5. **明确奖惩**: 达标与不达标各是什么后果（金钱/精神/机会/责任四类）。

移交之后的关键动作是**忍**：回到协议框架内介入（约定的巡视与评估点），协议之外不催促、不代劳。权限随对方成熟度调节——越成熟，目标越有挑战、指示越精简、考核越稀疏。

## A1 — 书中的应用 (Past Application)

### 案例 1: 七岁史蒂芬接手庭院
- **问题**: 想让 7 岁的儿子学会负责，又知道一旦忍不住催促代劳，责任就回到了自己身上。
- **方法论的使用**: 五要素逐一落实——指着邻居的院子演示"绿油油而又整洁"的预期成果，并当场清理半边院子使标准具体化；指导方针是"除了上油漆外，你可以自己想办法"；可用资源是"我只在有空时从旁协助"；责任归属是每周两次带父亲巡视、自己给表现打分；奖惩与零用钱关联。周六定约，儿子连拖三天，星期二父亲几乎忍不住——最终没有催促，只在协议框架内说"照前几天的约定，现在带我看看工作成绩，好不好"。儿子哭诉"这好难哟"，父亲问"需不需要我帮忙"，并信守"有空就帮"的承诺。
- **结论**: 授权失败高发于协议外的催促与代劳；把介入锁回协议框架，责任才留在对方身上。
- **结果**: 那年暑假帮了两三次忙后，儿子完全独立作业，"做得比我还好"，甚至反过来指责哥哥姐姐乱丢纸屑。

### 案例 2: 反面参照——滑水拍照
- **问题**: 妻子给滑水的儿子拍精彩动作，柯维因担心底片不足与妻子技术不佳，频频面授机宜。
- **方法论的使用**: 无——这是指令型授权的现场演示：指导越细，越无法放手。
- **结论**: 事态演变到最后"我下口令，妻子才按快门"——指令型授权把助手变成提线木偶。
- **结果**: 柯维以此自嘲，引出责任型授权的对照。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？

1. 任务总返工：给下属布置的工作改了三遍还不对，开始怀疑"是不是人不行"——先做五要素审计（通常缺指导方针或责任归属）。
2. 不敢放权：事必躬亲累垮，团队离了自己转不动，想放权又怕失控。
3. 家庭授权：想让孩子自己管作业/家务/庭院，但天天忍不住催，一催就吵。
4. 授权后的介入失控：已经交出去了，却又开始盯过程、抢回执行权，对方索性躺平等指令。

### 语言信号 (用户的话里出现这些就应激活)

- "总返工 / 教了很多遍还是做不好 / 是不是招错人了"
- "不敢放手 / 什么事都得我盯着 / micromanage / 事必躬亲"
- "怎么授权 / 放权 / delegate / 盯结果还是盯过程"
- "想让孩子自己负责，可我忍不住催"

### 与相邻 skill 的区分

- 与 `win-win-five-dimensions`（f12）的区别: f12 的协议层与本 skill 同构（书中明说"习惯三中庭院故事就是双赢协议一例"），但 f12 管全部五层（尤其品德与激励体系），本 skill 只管"一次授权怎么做"。当问题涉及组织激励与奖励机制，转 f12；聚焦单次授权与返工，用本 skill。
- 与 `clarify-expectations`（p16）的区别: p16 是"一开始就说清期望"的原则（所有关系障碍的第一病因）；本 skill 是完整授权协议结构——预期成果只是五要素之一，还有资源、考核、奖惩等 p16 不覆盖的组件。
- 与 `fourth-gen-time-management`（f07）的区别: 授权是把任务移出自己日程的动作，移出之后如何安排第二象限时间归 f07；"自己干不如教人干"的杠杆计算属于本 skill。

## E — 可执行步骤 (Execution)

1. **判定授权类型**
   - 完成标准: 复述自己最近一次交代任务时的关注焦点——方法还是结果；确认当前属于指令型还是责任型。
2. **起草五要素**
   - 完成标准: 五要素各写成一句话——预期成果（结果+时限，明确"方法不计"）、指导方针（限制性规定+已知难点，不下指令）、可用资源（含"何时可以找我"）、责任归属（标准+时间表+自我评估方式）、明确奖惩。
   - 判停条件: 若写不出"结果"只能写出"步骤"，说明自己还没想清楚要什么——退回重想，不要先派活。
3. **达成共识并承诺**
   - 完成标准: 对方能用自己的话复述五要素（尤其预期成果与责任归属）；单方宣读不算共识。
4. **移交后按协议介入**
   - 完成标准: 协议外不催促、不代劳；只在约定巡视/评估点介入；对方情绪性求助时按"可用资源"条款提供支持（庭院案例的"需不需要我帮忙"）。
5. **按成熟度调权限**
   - 完成标准: 每周期评估一次——不成熟则目标调低、指示加详、考核加密；成熟则反向调整，并记录在案。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 合规、安全、法定流程（发票签批、危险作业规程）——流程本身即指令型，责任型授权无空间。
- 危机灭火期——先集中控制，事后复盘授权结构。
- 对方明确表示"只要告诉我做什么"的临时性、一次性配合——此时指令型反而尊重对方意愿；但要警惕这常常是被指令型管理驯化出来的结果。

### 作者在书中警告的失败模式

- **用唠叨、威胁、吼叫换取"整洁的房间"**: 只盯产出（金蛋），用地位差强推，牺牲孩子的责任感与关系本身（鹅）——"不盯就不做、靠奖惩驱动"是授权失败的产能诊断（ce05）。
- **不加约束的放任**: 把责任型误解为甩手不管，对方回到"你让我做什么我做什么"的初级状态（L4121 原文警告）。
- **指令型的自我强化**: 滑水拍照——指导越细，助手越不动脑，最终自己成为一切动作的发令者（L4101-4105）。

### 作者的盲点 / 时代局限

- "信任是促使人进步的最大动力"预设对方有基本能力与安全感；对新手+高压 deadline 的组合，书中未给出过渡期设计（只说"需要对人员进行必要的培训"）。
- 关键案例（7 岁庭院、培训六个月压到五周）是作者单源叙述，无第三方验证；"1 小时撬动 10-100 倍"是修辞性杠杆，非实测数据。
- 五要素共识的达成依赖双方地位大致对等的谈判空间；在雇佣权力严重不对等时，"协议"可能只是形式，此批评与全书原则中心论不可证伪的局限一致。

### 容易混淆的邻近方法论

- 情境领导理论（Hersey-Blanchard）——"按成熟度调风格"与 L4175 高度相似；柯维的差异在五要素协议的成对共识与信任论根基。
- OKR/目标管理——形似于"预期成果"，但 OKR 通常缺奖惩制度与可用资源的成对约定。
- RACI 责任矩阵——只分配责任角色，不处理预期成果的演示、指导方针与自我评估。
