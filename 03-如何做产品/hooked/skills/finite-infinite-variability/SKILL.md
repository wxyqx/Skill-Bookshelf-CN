# 有限 vs 无穷的多变性

## R — 原文 (Reading)

> "'有限的多变性'会使产品随着时间的推移而丧失神秘感和吸引力，而'无穷的多变性'是维系用户长期兴趣的关键。"
>
> — 第4章 牢记并分享（L1522）

> "给产品附加'无穷的多变性'则有助于人们保持持久的兴趣。例如，单人通关游戏中包含的是'有限的多变性'元素，而联机多人游戏则包含'无穷的多变性'，因为整场游戏怎么玩全由玩家自己说了算。"
>
> — 第4章 有限的多变性 vs 无穷的多变性（L1488）

> "诸如YouTube、Facebook、Pinterest和Twitter这样的网站都存在一个特性，那就是利用用户提供的内容来制造源源不绝的新意。……蕴含'无穷的多变性'的产品赢得用户忠心的胜算要更大，所以那些在多变性上不具备优势的产品必须经常更新换代才能跟上时代的步伐。"
>
> — 第4章 有限的多变性 vs 无穷的多变性（L1492）

---

## I — 方法论骨架 (Interpretation)

"内容要常更新"是常识，这个框架问的是更深一层的结构问题：**不可预测性由谁制造？** 如果答案是"只能靠我们持续上新"——内容被消费后即变得可预见，用户的热情随剧情揭晓而消退——那这个产品具有有限多变性，冷却不是运营失误而是结构宿命，唯一的活法是好莱坞式的工作室模式：不停制造新亮点，并把"哪部作品会火"的不确定性计入成本结构。

如果不可预测性来自其他参与者——对手玩家的出招、其他用户的创作、潮流的演变——产品就获得了无穷多变性：用户自己互相制造新鲜感，供给不依赖你的内容团队。魔兽世界八年不衰（队友的表现不可预知）与 Dribbble 常看常新（设计师社区随潮流生长）是这条判据的两个独立例证，Zynga 小镇系列的换皮速朽则是反面。

由此得出两个可直接使用的推论：一是把"用户会不会腻"从焦虑变成可判定问题——数一数变量的制造者有几个人；二是商业模式被这个属性决定——消耗型内容该按内容公司定价与排期，平台生态才值得押注网络效应。

## A1 — 书中的应用 (Past Application)

### 案例 1: Zynga 小镇系列的破产
- **问题**: 农场小镇爆红后，Zynga 如何延续成功？
- **方法论的使用**: 用多变性结构审视其后续产品：新游戏"其实是新瓶装老酒，只是借用了'农场小镇'的外壳"——机制外壳被复制却未注入新的不可预测性，玩家可预见一切后续体验。
- **结论**: 有限多变性在重复中耗尽；依赖单一爆款的工作室模式又要求持续押中新品，失败一次即资本逃离。
- **结果**: "玩家的热情很快消失，投资商也纷纷撤资"，股价跌去 80%（L1478–1484）。

### 案例 2: 魔兽世界与 Dribbble——无穷多变性的两个来源
- **问题**: 什么样的产品能多年不失魅力？
- **方法论的使用**: 作者找了两条互相独立的证据线：魔兽世界靠联机团队作战——"团队其他成员在游戏中的表现就成为不可预知的因素"；Dribbble 靠设计师用户生成内容——潮流与设计范式变化时网页随之更新，"动态发展的网站始终会给他们带来新的惊喜"。
- **结论**: 无穷多变性的两个来源是对手与创作者，共同点是让"他人"制造不可预测性。
- **结果**: 魔兽问世 8 年仍拥有一千多万固定玩家（L1488–1490），成为"结构决定生命周期"论证的正例。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 内容型产品规划：付费专栏、课程、连载、播客面临"完读即走"，想知道要不要转向社区化/共创。
2. 生命周期评估：游戏、玩具型 App 增长见顶，要预判"会不会腻"是运营问题还是结构问题。
3. 商业模式选择：在工作室模式（持续上新+发行体系）与平台生态（UGC+网络效应）之间做投资决策。
4. 老用户流失诊断：活跃度下滑被归因于"没做好运营"，需要检验是否新鲜感结构耗尽。

### 语言信号 (用户的话里出现这些就应激活)

- "用户会不会腻 / 新鲜感过了就走了 / 玩腻了"（users get bored, novelty wears off）
- "内容更新压力太大 / 追不上热点 / 做内容做不动了"（content treadmill, constant updates）
- "有限/无穷多变性 / variability / 要不要做 UGC / 怎么让产品常看常新"（finite vs infinite variability, user-generated content）

### 与相邻 skill 的区分

- 与 `f12-three-variable-rewards` 的区别：f12 选酬赏通道（社交/猎物/自我），f13 检查所选酬赏的"变量"能否长期存续——先选通道再查变量，混用会把"类型"和"存续"答成一个问题。
- 与 `f02-habit-zone-frequency-first` 的区别：f02 判断行为能否成为习惯（使用侧：频率×用途）；f13 判断兴趣能否长期维持（供给侧：变量来源）。一个管进不进习惯区间，一个管能在区间里待多久。
- 与 `f15-five-stored-values` 的区别：f15 靠资产沉淀留人（不依赖新鲜感），f13 靠不可预测性留人（依赖体验）；UGC 平台两者兼得但概念不同——诊断流失时要分清用户是"腻了"还是"没沉淀"。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **列出产品的酬赏供给来源**
   - 完成标准: 明确回答"用户每次体验的差异由谁制造"，来源写明四选一或组合：设计者（上新）、用户自己（进度/成长）、其他用户（UGC/对战）、外部世界（潮流/数据）。

2. **判定有限/无穷**
   - 完成标准: 用"使用 N 次后用户能否预测下一次体验"检验，给出判定与理由；有 ce07 警兆（老用户活跃度系统性低于新用户、"再玩一次"的理由消失）的记为证据。
   - 判停条件: 若判定为有限多变性且全部变量靠设计者上新，显式标记"工作室模式"，并把持续上新的成本结构写进结论——不得继续假装在做习惯产品。

3. **有限多变性的出路三选一**
   - 完成标准: 在三个选项中给出明确选择与理由：a) 叠加无穷层——引入互动、共创、对战，让他人制造变量；b) 接受工作室模式——按内容公司的成本结构定价、排期与组织；c) 放弃习惯定位——承认低频工具/一次性消费属性，改打可感知用途。

4. **验证判断**
   - 完成标准: 用数据复核——新老用户活跃度对比、回访理由衰减曲线、换皮警兆（新品与旧品只有皮肤差异、社区出现"换皮"共识、收入集中于单一 IP）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 工具型产品：计算器、词典、查询工具的价值就在可预测，"用完即走"是正当的，不该为多变性强加社交或随机化。
- 酬赏类型尚未确定时：变量是酬赏的属性，先过 f12 选通道，否则无从判定"什么在变"。
- 把"多变"理解为"多"：加大奖励数量或频率不改变可预见性，这不是本框架的解法。

### 作者在书中警告的失败模式

- Zynga 换皮破产（ce11）：复制机制外壳而不注入新的不可预测性；警兆——新品与旧品只有皮肤差异、玩家社区出现"换皮"共识、收入集中于单一 IP。
- 可预测后即失去魅力（ce07）：孩子能预知小狗的下一个动作后便觉得没以前好玩——大脑一旦掌握因果关系即把行为转为自动处理，没有新变量注入，注意力流向下一个未知对象。
- 爆品陷阱（ce21）：有触发、有酬赏、无投入的产品，多变性耗尽后无任何转换成本，热度自然衰减。

### 作者的盲点 / 时代局限

- 算法推荐的工业化晚于本书：推荐流让用户无须投入即可获得个性化多变酬赏，"投入→储存价值→依赖"的链条在算法主导产品中被部分短路；本书的"猎物酬赏"形态仍是时间序信息流与人工设计的截半图（阶段 0 批判节）。
- 军备竞赛后果未考虑：当所有产品都变量化（抽卡、开箱、算法流），单产品的边际多变性被稀释、用户渴望阈值整体抬高——作者未做博弈论式推演。
- "多巴胺叙事"的科学简化：间歇强化的定性结论成立，但"变数越大多巴胺越多"的表述在后续神经科学中已显过粗（阶段 0 批判节）。

### 伦理红线（酬赏/多变性设计专用）

**多变性设计不得用于绕过用户自主权、不得制造强迫性使用**：以拉长使用时长为唯一目的的随机化（抽卡、开箱、无限滚动叠加随机奖励）对未成年人与易感人群构成成瘾设计——"生产致瘾产品等同蓄意伤害"（L476）；为产品补多变性时，优先选择用户真实受益的变量（共创、对战、新知），落地前过 f18 操纵矩阵。

### 容易混淆的邻近方法论

- "内容为王/勤更新"的运营常识：本框架的判据是变量制造者结构而非更新勤奋度——勤更新恰是有限多变性产品的宿命成本，不是解法。
- `f12-three-variable-rewards` 与 `f15-five-stored-values`：分别与 f13 构成"酬赏链"（选类型→查存续）与"留存双支柱"（体验侧 vs 资产侧）关系，见 A2。
