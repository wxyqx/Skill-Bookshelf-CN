# 保护重度用户：识别能力产生告知与保护义务

## R — 原文 (Reading)

> "开发习惯养成类产品的公司肩负一种道德义务，也许有一天会变成一种法律责任，即必须告知并保护那些对产品慢慢上瘾的用户。正在开发有可能会令用户上瘾的产品的企业家们理应制定指导性准则，以识别并帮助上瘾用户。"
>
> — 第6章 上瘾模型与道德操控（L1930）

> "据业内人士估计，对诸如老虎机这样最容易令人上瘾的习惯养成类产品达到病理性上瘾程度的用户只有 1%。……不过，如果简单地认为这一问题太微不足道，因而无关紧要的话，就会忽略技术上瘾导致的真正问题。"
>
> — 第6章 上瘾模型与道德操控（L1928）

> "除了 1% 的上瘾用户之外，其余用户应对自己的行为承担最终责任。"
>
> — 第6章 上瘾模型与道德操控（L1966）

---

## I — 方法论骨架 (Interpretation)

这条原则的独特之处在推理结构而不在结论：义务不来自"伤害已经发生"，而来自"识别能力已经出现"。习惯产品的公司第一次可以用自己采集的数据标记过度使用的用户——从这一刻起，"不知道"不再构成辩护，告知与保护的道德义务随之产生；作者甚至预言它将变成法律责任，这在部分法域已经应验。配套两条：其一，"只有约 1% 病理性上瘾"不能当作无关紧要的豁免理由——极端个案的公共曝光（诉讼、报道）足以定义产品形象，而"制定识别并帮助上瘾用户的准则"是能力范围内的应尽之责；其二，义务有明确边界——作者同时把其余用户的行为责任归还给用户本人（L1966）：保护义务的对象是被识别的过度使用模式，不是替所有用户管理人生。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: "1% 上瘾"的义务论证
- **问题**: 习惯养成产品导致部分用户过度使用、沉溺其间，公司该怎么办？
- **方法论的使用**: 作者先承认比例事实（最易上瘾的老虎机类产品病理性上瘾约 1%，且多为心理状况特殊者），再拒绝"太微不足道"的推论，指出公司现已首次被允许用自身数据给过度使用的用户做标记。
- **结论**: 义务随识别能力产生：必须告知并保护慢慢上瘾的用户，并制定识别与帮助的指导性准则。
- **结果**: 成为第 6 章道德操控的核心主张之一；作者在书中即预言其法律化（L1928–1930）。

### 案例 2: 第 1 章的跨章呼应
- **问题**: 成瘾风险应该在设计的哪个环节被处理？
- **方法论的使用**: 作者在第 1 章章末就把红线前置——"生产企业在做设计之前，最好先审慎思考，以确保自己的设计会引导用户形成健康的习惯，而不会发展为病态的成瘾"。
- **结论**: 成瘾风险不是上线后的公关议题，而是设计起点的审慎义务。
- **结果**: 与第 6 章的义务论形成跨章闭环，构成全书"机制在前、道德闸门随后"结构的一部分（第 1 章，L504）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 决策"要不要做"：每周/每日使用报告、时长提醒、青少年模式、自主限速功能。
2. 产品被媒体或用户质疑"让人停不下来"，需要评估暴露面与应对责任。
3. 客服/社区出现"我停不下来""我控制不住刷"类求助，尚无处理流程。
4. 面向未成年人或心理易感人群（焦虑、抑郁倾向用户）的功能上线前评估。

### 语言信号 (用户的话里出现这些就应激活)

- "重度使用 / 停不下来 / 刷到停不下来"（heavy users, compulsive use, can't stop scrolling）
- "防沉迷 / 使用报告 / 时长提醒 / 屏幕时间"（digital wellbeing, usage report, screen time, anti-addiction system）
- "上瘾风险 / 成瘾用户 / 保护义务 / 未成年人和 1%"（addiction risk, duty of care, vulnerable users, minors）

### 与相邻 skill 的区分

- 与 `f18-manipulation-matrix` 的区别：f18 在做之前问"该不该做"（象限自检），p16 在做了之后问"对已被识别的过度使用者怎么办"（义务执行）——同一伦理链条的上下游两站。产品还没做的判断不归 p16。
- 与 `f20-habit-test-three-steps` 的区别：f20 也筛高频用户，但目的相反——f20 找的是粘性习惯用户（经营对象），p16 找的是过度使用/依赖模式（保护对象）。判据是使用是否已挤占生活功能、用户是否主观失控，而非频率本身。
- 与 `p09-preserve-user-autonomy` 的区别：p09 是单次"要求"的交互规则，p16 是组织级的识别-告知-帮助准则与流程；弹窗措辞归 p09，义务体系归 p16。
- 与 g20（成瘾/习惯之辨）的区别：g20 是词典判据（习惯与成瘾的分界），p16 是该判据落到企业责任上的具体化——判分界线用 g20，问"所以公司该做什么"用 p16。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **评估识别能力**
   - 完成标准: 盘点现有数据能否识别过度使用模式（总时长、时段分布、深夜使用、卸载重装、反复尝试自限又失败等），逐项标注"已有/可建/不可得"；多数产品已有足够数据，"不可得"结论须给出理由。

2. **制定识别准则**
   - 完成标准: 写出可操作的预警定义——哪些使用模式算过度使用、阈值如何定、未成年人与成年人是否区分，以及由谁（角色/流程）承接预警信号。

3. **落地告知与帮助动作**
   - 完成标准: 至少落地一类低成本动作——使用报告、用户可自设的限速/休息提醒、成瘾求助资源入口；动作默认对被识别用户可见，且措辞不羞辱、不评判。

4. **划定义务边界**
   - 完成标准: 明确保护对象是"被识别的过度使用模式"，同时为所有用户保留自主工具（报告、提醒、关闭），不替全体用户管理使用——对应作者 L1966 的责任分配。

5. **分布复查与上报（判停条件）**
   - 完成标准: 检查过度使用是个别极端现象还是分布整体左移。
   - 判停条件: 若数据显示广泛依赖（整体分布左移），本原则覆盖不足——须升级至 f18 重审产品前提，并向决策层上报，不得以"义务已履行"结案。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用"保护"包装时长 KPI 的反向操作（假提醒、真留存）——识别数据一旦反用于优化粘性，义务即变成操纵工具。
- 把所有高频使用病理化——高频可以是健康的习惯用户（f20 的经营对象），义务对象是被识别的过度使用模式。
- 替代监管合规：未成年人保护立法、防沉迷规定是硬约束，本原则是合规之内的自查延伸，不是替代品。

### 作者在书中警告的失败模式

- 轻慢 1%（ce19）："太微不足道，因而无关紧要"——作者明文拒绝该推论；极端个案的诉讼与报道足以定义产品形象，且数据能力已使"不知道"的辩护不成立。
- 只优化总时长这一个指标：与保护义务直接冲突的 KPI 会在每次取舍中胜出——识别与帮助准则必须先于 KPI 体系存在。
- ce19 的警告信号清单：无重度使用预警指标；客服无成瘾求助流程；只优化总时长。

### 作者的盲点 / 时代局限

- "1% 框定"的争议：注意力经济批评者（Tristan Harris 等）指出问题不是 1% 极端者，而是全体用户的分布整体左移；作者把其余责任推给用户（L1966），回避了默认设置与产品形态管制层面的解法——E 段第 5 步的分布复查即是对此盲点的补丁。
- 2014 年的"道德倡议"在今天部分已是法律义务（未成年人保护、防沉迷、部分法域的平台责任立法）——先查当地法规，再谈自觉。
- 书中只给出义务呼吁，没有任何识别准则的具体样例；阈值与流程须由使用者自行设计并验证。

### 容易混淆的邻近方法论

- 通用"科技向善/企业社会责任"口号：本原则的可区分处是"能力产生义务"的责任推理结构——义务起点是数据能力事实，不是价值观宣言。
- 数字健康（digital wellbeing）产品设计：那是用户侧工具的实现学；p16 是设计者侧的义务判断——两者互补：先尽义务（p16），再做好工具。
- `f20-habit-test-three-steps`：同样是筛"高频人群"，方向相反（经营 vs 保护），判据不同（频率 vs 失控），勿互相抢调用。
