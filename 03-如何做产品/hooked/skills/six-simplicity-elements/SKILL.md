# 能力六要素与"补最短板"

## R — 原文 (Reading)

> "福格总结了简洁性所包含的6个元素，即影响任务难易程度的6个要素：时间——完成这项活动所需的时间；金钱——从事这项活动所需的经济投入；体力；脑力；社会偏差——他人对该项活动的接受度；非常规性——该项活动与常规活动之间的匹配程度或矛盾程度。"
>
> — 第3章 能力的六个要素（L905–L921）

> "为了增加用户实施某个行为的可能性，设计人员在设计产品时，应该关注用户最缺乏什么。也就是说，要弄清楚是什么原因阻碍了用户完成这一活动。"
>
> — 第3章 能力的六个要素（L923–L925）

> "用户遇到的问题不尽相同，而我们也没有一个包治百病的良方。因此，设计者们应该尽可能广开思路，设想一下用户可能遇到的阻碍。"
>
> — 第3章 Facebook 注册器的案例（L945）

---

## I — 方法论骨架 (Interpretation)

"让产品更易用"是一句口号，这六项要素把它变成一张可排查的清单：完成一个行为，用户可能没时间（时间）、掏不起（金钱）、动不了（体力）、学不会（脑力）、怕被人指指点点（社会偏差），或者这件事跟他一贯的做事方式拧着（非常规性）。后两项是这份清单相对常见易用性维度最有辨识度的补充——摩擦不只存在于界面里，也存在于用户所处的社会眼光与既有习惯中。

核心操作规则不是六项平均用力，而是**诊断最短板**：同一流程对不同人群的卡点完全不同，设计者应先弄清目标用户"最缺乏哪一项"，集中火力补那一项，而不是到处抹平。补法也对应各要素——时间靠自动化与预填、脑力靠删步骤、社会偏差靠隐私保护与"正常化示范"、非常规性靠贴近用户既有的做事顺序。它和 B=MAT 的关系：它是"能力"这一要素内部的展开检查表。

## A1 — 书中的应用 (Past Application)

### 案例 1: 简化设计四例——各补不同短板
- **问题**: 成功公司如何推动用户快速跨过"行动线"？是否存在通用的简化手法？
- **方法论的使用**: 作者拆解四个案例并指出各自补的短板不同：Facebook 注册器删去注册中间步骤（补脑力/时间）；Twitter 嵌入式分享按钮把"复制链接再粘贴"缩为一步（补脑力）；iPhone 把相机设为锁屏可直接打开（补时间，抢拍关键瞬间）；Pinterest 无限滚动取消翻页等待（补时间）。Google 干净主页同样省时间与脑力。
- **结论**: 没有统一答案——每个成功设计都瞄准了各自流程中的特定摩擦源。
- **结果**: 四例构成第 3 章能力节的主体证据（L934–998），作者同时借 Facebook 注册器的异议（隐私敏感者反而焦虑）警告"包治百病"方案不存在。

### 案例 2: 内容发布简化史
- **问题**: 为什么网络内容供给会在特定节点爆发式增长？
- **方法论的使用**: 作者回溯发布门槛的逐级骤降：注册域名装 CMS → 博客平台一键注册 → 140 字符的 Twitter → 随手拍摄即发的 Pinterest/Instagram，每一代都在压缩完成行为的必经环节。
- **结论**: 供给爆发的共同原因是"使更多的人具备了在网络上书写的能力"——行为难度的系统性下降直接放大行为频率。
- **结果**: 成为"简化驱动行为频率"的宏观证据（L892–902），支撑六要素清单的历史有效性。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 流程转化诊断：注册、下单、报销、办事等流程"进得多、出得少"，要定位具体卡在哪一类摩擦。
2. 特定人群不使用：老年人不用政务 App、一线员工不用内部系统——需要判断是不是"界面不够简单"之外的摩擦（如怕办错丢人）。
3. 新功能上线遇冷：功能本身被认可，但没人完成第一次使用。
4. 竞品更简单导致流失：要系统对比双方流程的摩擦结构，而不是逐像素改 UI。

### 语言信号 (用户的话里出现这些就应激活)

- "流程太复杂 / 用户嫌麻烦 / 门槛太高 / 哪一步卡住了"（too much friction, where do users drop off, cumbersome flow）
- "简化 / 易用性 / 老人不会用 / 上手难"（simplify, usability, steep learning curve）
- "怕被人笑 / 不敢在同事面前用 / 跟他们平时习惯不一样"（social embarrassment, breaks their routine）

### 与相邻 skill 的区分

- 与 `f07-bmat-action-diagnosis` 的区别：f07 先判定"问题出在能力还是动机还是触发"；f09 只在归因到能力之后启动，是能力项内部的六格检查表，不要跳级使用。
- 与 `f08-three-core-motivations` 的区别：f08 补"不想做"，f09 补"做不动"；完成率问题多数是 f09，意愿问题才是 f08。
- 与 `f17-investment-timing-granularity` 的区别：方向相反——f09 服务行动阶段（减摩擦），f17 管投入阶段（允许加摩擦、拆小步）。用 f09 的思维去简化投入环节，会做出"什么都替用户做好"从而失去投入效应的产品。
- 与 `f02-habit-zone-frequency-first` 的区别：使用频率不足是习惯区间问题（使用频次轴），不是单次行动的摩擦问题；高频但完不成的行为才轮到 f09。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **列全目标行为的必经步骤**
   - 完成标准: 从触发出现到动作完成，每一步可罗列（可借助流程图或真实走查）。步骤不全则后续排查失真。

2. **逐项排查六要素**
   - 完成标准: 对每一步问"目标用户在这里缺什么"，给六要素各标高/中/低摩擦并附证据——证据必须来自用户观察或数据，不得全凭团队想象（"设计者以为的卡点"是本书反复警告的偏差）。
   - 判停条件: 若发现用户根本不认为该行为有价值（无需求），停止排查——简化救不了没有价值的行为，转回需求验证。

3. **锁定最短板**
   - 完成标准: 选出摩擦最高的一项作为主攻点并说明理由。
   - 判停条件: 若两项并列最高，先处理行为发生顺序更早的一项（上游摩擦会让下游根本没机会暴露）。

4. **针对最短板做对应减法或补偿**
   - 完成标准: 按要素选对策——时间：自动化/预填/异步；金钱：降费/分期/免费层；体力：代操作/语音；脑力：删步骤/默认值；社会偏差：隐私选项/正常化示范/可匿名；非常规性：模仿用户既有流程的顺序与语言。方案落地可测。

5. **验证并循环**
   - 完成标准: 同一人群改前改后对比完成率；未改善则回到步骤 2 重查是否误判短板（警惕"解决了 A 项却在 B 项竖起新墙"，如注册器之于隐私敏感者）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 投入阶段的设计：储存价值类投入（填资料、建内容）需要的是 f17 的"拆小步+预填进度"，不是持续减摩擦；把一切环节都简化到零会同时消灭投入。
- 需求不存在的产品：六要素只解释"想做而做不动"，产品价值缺失时最优流程也是零转化。
- 用"行业最佳实践"替代诊断：把第三方登录/一键注册等某个手法当普适答案全量套用，是本书点名的失败模式。

### 作者在书中警告的失败模式

- "包治百病"方案（ce20，L945 原文警告）：Facebook 注册器对惜时如金者是宝贝，对个人信息格外谨慎的人却"催生出新的焦虑"、带来信任危机——短板因人而异，不诊断就套方案，会在补短板的同时竖起新墙。
- 桌面网站之败的镜像（ce13）：载体与场景错位使时间/体力要素瞬间不可及——诊断时要把"设备/介质是否在场"计入能力。

### 作者的盲点 / 时代局限

- 出处披露：简化思想部分出自豪普特利等二手来源（"简化三步法"独立单元未通过三重验证，其证据链已并入本单元）；"六要素"亦为福格的总结，埃亚尔的增量是把"社会偏差""非常规性"纳入产品语境并给出"补最短板"的优先级规则。
- "最短板"假定卡点可识别且相对稳定；面对多人群并存的动态场景，需分群诊断而非找一个全局短板。
- 2014 年移动 App 语境：未覆盖多端协同、无障碍与适老化监管等后继议题；社会偏差要素的文化敏感性（丢人/体面的标准）因文化而异，书中证据全部来自美国市场。

### 容易混淆的邻近方法论

- 尼尔森可用性启发式等通用易用性清单：常见清单聚焦界面与认知负荷；本清单的可区分维度是"社会偏差"（他人接受度）与"非常规性"（与既有习惯的冲突度）两个社会性摩擦源。
- 服务蓝图/旅程图：描述流程的工具，f09 提供对流程逐段做摩擦归因的镜头，二者可叠加但分工不同。
