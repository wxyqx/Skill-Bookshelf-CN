# 初始效应双律：学习前置、永远优先第一次的用户

## R — 原文 (Reading)

> "在学习心理学中有'初始效应'。在花时间学习的时候，在体验开始的时候，人们的注意力和学习效率就会提高。" / "优先考虑第一次使用的用户，一定要让其觉得产品简单、易用。……'第一次'是人生只有一次的最有效的学习机会，体验设计师绝对不能错过。"
>
> — 玉树真一郎，第1章 / 第5章《应用4 设计/产品设计》

---

## I — 方法论骨架 (Interpretation)

初始效应说：系列体验开始时，人的注意力和学习效率最高。本书从这一个心理学事实推出两条与直觉相反的硬规则。

**规则一（学习前置）**：必须学习的内容要全部集中在开头，而不是按"均匀合理"的节奏分散到全程。马里奥把仅有的 4 种道具全部放在最初阶段；《勇者斗恶龙》用一个"国王房间被反锁"的不合理障碍，逼玩家在出门前一口气学齐 5 个指令。均匀分布的合理直觉恰恰是错的——先集中教完，后面才能安心变复杂。

**规则二（优先第一次的用户）**：任何时候优先为"第一次使用的用户"设计。第一次是学习效率最高、且**只有一次**的窗口；第一次用不顺，就没有第二次了。反面是开发者偏差：因为爱自己的产品，不自觉地为最热爱的深度用户堆功能、加深度，把"不熟悉也没热情的普通用户"抛在一边——这是产品失去大众的常见路径。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 4 种道具集中在最初阶段
- **问题**: 蘑菇、花、星星、1up 四种道具放在 32 个关卡的哪里？
- **方法论的使用**: 选了看起来不合理的答案②——全部集中在最初的阶段，依据初始效应在注意力最高处完成教学。
- **结果**: 玩家在注意力峰值学会全部道具，中后期无需再教。

### 案例 2: 国王房间反锁
- **问题**: DQ 的 8 个指令系统怎么教？
- **方法论的使用**: 故意造一个不讲道理的障碍（国王的房间从外面上了锁），玩家为出门必须对勇者用"对话"指令——5 个指令在假设→尝试→高兴中一次学齐。
- **结果**: "游戏教科书"级别的指令教学。

### 案例 3: 开发者偏差警告
- **问题**: 为什么很多功能丰富的产品没人用？
- **方法论的使用**: 作者点名开发者心态——对产品有感情、希望"它被一直使用"，结果为深度用户设计、剧情复杂、难度很高。
- **结论**: 时刻假设有一个"不熟悉也没热情的普通用户"在场。
- **结果**: 书中被列为产品失去大众的典型路径（反例 ce34）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 排培训课表/入职计划，在"分散学习"与"集中前置"之间纠结。
2. 决定产品功能的引导顺序、教学内容的先后。
3. 争论"要不要砍新手教程"——老用户嫌烦，新用户离不开。
4. 评审 roadmap：资源该投给重度用户的新功能，还是降低上手门槛。
5. 写课程大纲/操作手册时决定章节顺序。

### 语言信号 (用户的话里出现这些就应激活)

- "新手培训/入职/开课怎么排"
- "要不要保留新手教程 / 老用户抱怨教程"
- "先教什么后教什么 / 学习顺序"
- "第一次使用 / first-time user / onboarding 顺序 / primacy"
- "要不要给核心用户加功能，还是先照顾小白"

### 与相邻 skill 的区分

- 与 `comprehension-first-affordance` 的区别：那个决定"第一秒传达什么"（空间维度的取舍）；本 skill 决定"必须学的东西放在时间轴哪里"（时间维度的排序）。首屏用它，课表用本 skill。
- 与 `intuition-design-loop` 的区别：本 skill 只管"何时教"（前置），教学本身怎么让人学会要靠三步微循环来编排。

## E — 可执行步骤 (Execution)

1. **清点"必须学习清单"**
   - 完成标准：列出用户要顺畅使用/工作必须掌握的全部概念、功能、规则（马里奥=4 种道具；DQ=5 个指令）。
2. **全部前移到开头**
   - 完成标准：清单上的每一项都能回答"它在开头哪个环节被学会"；删除所有"以后用到再教"的安排。判停条件：若某项在开头教不成立（前置依赖缺失），标注依赖关系后仍尽量前移到依赖链的最早点。
3. **为前移设计承载**
   - 完成标准：开头被塞满后，用"故意的不合理障碍/强制场景"承载学习（像反锁的国王房间），而不是加长说明文——教学发生方式交给 `intuition-design-loop`。
4. **用"第一次的用户"画像复查**
   - 完成标准：对每处设计问"不熟悉也没热情的普通用户能过吗？"；发现任何"为热爱产品的老用户才需要"的开头内容，移出开头。
5. **给老用户留跳过口**
   - 完成标准：已掌握者可跳过前置教学（跳过方式的设计可参考 `stop-design-graceful-endings` 的自由原则）；跳过路径本身也不得抢夺新用户的开头注意力。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **间隔复习/记忆巩固场景**——前置律针对**初次学习**；技能巩固（背单词、肌肉记忆）遵循间隔重复，别混用。
- **进阶产品**——用户群全部是熟练者时，"优先第一次的用户"没有对象，规则自然失效。
- **认知负荷确实超限的开头**——前移不是把 50 个概念砸进第一天；超出"简单容易"上限时要先砍内容而不是硬塞。

### 作者在书中警告的失败模式

- 按"均匀合理"分散必学内容——直觉恰恰是反例（ce09）。
- 为深度用户设计、堆功能，普通用户望而却步（ce34）。
- 直觉引导只对第一次有效，对老用户重复引导是噪音（ce33）——所以跳过口必须存在。

### 作者的盲点 / 时代局限

- 案例是买断制游戏：玩家带着"必须学会才能玩"的动机。低动机场景（可选工具）里，完全前置可能造成初始压力，需要把前置内容切得更小、配更高成功率的微循环。
- "第一次只有一次"在小流量高客单场景可能被过度放大——为一次会话过度投入，要看业务复购结构。

### 容易混淆的邻近方法论

- 渐进披露（progressive disclosure）：主流 UX 主张按需逐步展开；本书反着来——**必学的**全部前置，渐进的只是"非必学"内容。两者适用对象不同，先分类再选方法。
- 间隔效应（spacing effect）：同样来自学习心理学但作用于复习巩固；判断"这是初学还是巩固"是选用前提。
