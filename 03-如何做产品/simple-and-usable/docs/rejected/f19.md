# rejected/f19 — 方案不是流程（聚焦目的而非步骤）

## 候选原文

- **id**: f19（对应 p24）
- **title**: 方案不是流程（聚焦目的而非步骤）
- **type**: reasoning-method
- **source_chapter**: 第4章
- **内容摘要**: 盯住流程设计会为每个异常情况加功能（银行"存钱罐"案例：一步变两步、拒付规则、不知情的默认罐）；退回到客户目的（想要有名字的账户），往往有更简单的等价方案（允许给账户命名）。

## 不独立成 skill 的原因

**V1 与 V3 均可过（目的优先的重框思路在第4章与"排定功能优先级"专节呼应；"问客户的目的到底是什么"有可执行句式），但败在与 s11（删除策略）的调用场景完全重叠**：

1. 它在第4章的语境是删除策略的一环——"要删什么"的判断方法之一（退回目的再看还有什么可删/可简化）。
2. 用户遇到"功能在处理异常情况时越堆越多"的场景时，自然的调用单元是"删除策略"整体（先重框目的、再翻转举证责任、再排优先级）；若独立成 skill，其 trigger（"异常处理越加越多/要不要为边界情况加功能"）与删除策略的 trigger 必然互相抢调用。

## 处置

- 并入 **s11 remove-strategy 的执行步骤**：作为步骤之一（"怀疑自己在为流程而非目的设计时，退一步问客户的目的与替代方案"）。
- 原候选保留在 candidates/frameworks.md 中备查。
