# 简约四策略

## R — 原文 (Reading)

> "删除——去掉所有不必要的按钮，直至减到不能再减。组织——按照有意义的标准将按钮划分成组。"（第3章）
>
> — Giles Colborne，《简约至上：交互式设计四策略》第3章

---

## I — 方法论骨架 (Interpretation)

作者用一道面试题发现了这个框架：让设计师简化一个 40 多个按钮的 DVD 遥控器，收集来的五花八门的方案，归纳后全部落进四类——**删除**（做减法）、**组织**（不加功能但降低复杂感）、**隐藏**（降低视觉噪音）、**转移**（把复杂性挪到别的设备、平台或人身上）。

它的价值在三点。第一，**完备性**：有人会想到触摸屏、手势识别这类"新技术"方案，但拆开看本质仍是四类之一——所以面对简化任务时不必发散，按这四条排查即可。第二，**有优先序**：先问"该删什么"（最彻底），删不掉的问"怎么分组"，不能分的问"能否藏起来"，都不行再问"能否转移"（涉及重新布局，代价最大）。第三，**可叠加**：一个页面的收拾常常是"删一批、组一批、藏一批"的组合拳，但通常有主导策略——选对主导策略是成败关键。

配套两条使用前提：加功能不可持续（盲目添加的新功能早晚会成为垃圾功能），以及不要拿到问题就抓住第一个方案不放——多出三四个方案再选。

## A1 — 书中的应用 (Past Application)

### 案例 1: DVD 遥控器思想实验
- **问题**: DVD 遥控器 40-50 个按钮，而多数人只用播放和暂停。
- **方法论的使用**: 作者收集大量面试者的简化方案，发现所有方案（包括加触摸屏、手势识别的）都能归入四类，由此确立四策略的完备性。
- **结论**: 四策略覆盖一切简化路径，且各有限制条件。
- **结果**: 成为全书骨架，作者继续用它审视网站、页面乃至整个产品。

### 案例 2: Flip 便携摄像机
- **问题**: 索尼、松下在比拼功能（好莱坞式字幕特效），摄像机越来越复杂难用。
- **方法论的使用**: Flip 甩开一切不必要的：无连接线、9 个键（1 个大红录像键）、驱动内置自动安装——删除与组织的极致。
- **结论**: 做的少但比竞争产品做得更好。
- **结果**: 一年卖出上百万台（当时全美摄像机年销量约 600 万台）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 产品/页面/表单/流程"太复杂"，需要一个系统的简化思路而不是零散改改。
2. 需求评审中争论"要不要加这个功能"，需要一个比"感觉"更硬的决策路径。
3. 接手遗留产品做减法（信息架构梳理、功能瘦身）。

### 语言信号 (用户的话里出现这些就应激活)

- "太复杂了 / 功能太多 / 怎么做减法 / Simplify / declutter"
- "这个页面/流程怎么收拾 / 信息架构太乱"
- "要不要砍掉这个功能 / feature bloat"

### 与相邻 skill 的区分

- 与 `remove-strategy` / `organize-strategy` / `hide-strategy` / `transfer-strategy` 的区别：本 skill 是总纲与选择逻辑（"该走哪条路"），四个单点 skill 各自承接具体策略的执行细节与陷阱。
- 与 `complexity-placement` 的区别：四策略处理"怎么简化"；复杂性放置是四策略用尽后的终局问题（"消不掉的复杂性放到哪里"）。
- 与 `declutter` 的区别：本 skill 是策略层；减速带清理是感知细节层（视觉、文字、干扰物）的清扫工序。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **盘点对象，写下简化目标**
   - 完成标准: 一句话说清"简化的对象是什么、为谁简化、简化后什么样"（可借助 simplicity-baseline）
2. **按序过四策略，每条给出去留判断**
   - 删除: 哪些元素目标用户根本不需要？→ 产出可删清单
   - 组织: 剩下的按什么用户认可的标准分组？
   - 隐藏: 哪些非核心项可以收起而不伤可发现性？
   - 转移: 哪些控制可以挪到其他平台/自动化/用户擅长的环节？
   - 完成标准: 每个元素都有明确去向（删/组/藏/转/保留），并注明主导策略
3. **检查组合与代价**
   - 完成标准: 确认各策略叠加后没有互相破坏（如隐藏的可发现性被组织的层级淹没）；每个"转出去"的复杂性知道落在了谁头上
4. **收尾交给复杂性放置**
   - 完成标准: 若仍有消不掉的复杂性，转入 `complexity-placement` 做"放到哪里"的决策

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 问题只是视觉风格（美化 ≠ 简化，先确认是复杂性问题）
- 目标用户是专家本人（专业工具软件的"专家"就是主流用户，删除策略要慎用）
- 拿不到用户信息且不允许假设——此时先做用户研究，四策略会建立在错误想象上

### 作者在书中警告的失败模式

- 盲目加功能不可持续：功能越多越难发现真正有价值的，早晚会成为垃圾功能，维护成本滚雪球（2008 汽车业）
- 貌似简单的假捷径：说明书、向导、卡通助手看似省事，实为把失败责任推给用户
- 只抓第一个方案：多画三四个草图强过一条道跑到黑

### 作者的盲点 / 时代局限

- 成书于 2011 年，案例以功能手机与 Web 时代硬件为主；移动互联网、AI 界面的复杂性形态未被覆盖
- "忽略专家型用户"的结论不适用于开发者工具等专业产品——那里的专家就是主流用户
- 组织内推行简化的阻力（"重要客户"论）只给了商业论证一条路

### 容易混淆的邻近方法论

- 极简主义（minimalism）：简单≠最少化，朴素设计仍应有特征与个性 → `simplicity-boundaries`
- 纯视觉减法（declutter 风格）：那是感知细节层的清扫，不解决功能与结构的复杂
