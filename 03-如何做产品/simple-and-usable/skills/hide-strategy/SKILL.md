# 隐藏策略

## R — 原文 (Reading)

> "把那些不是最重要的按钮安排在活动仓盖之下，避免分散用户注意力。"（第3章）
>
> "无论隐藏什么功能，都意味着你在用户和功能之间设置了一道障碍。"（第6章）
>
> "首先是彻底隐藏，其次是适时出现。"（第6章）
>
> — Giles Colborne，《简约至上：交互式设计四策略》第3、6章

---

## I — 方法论骨架 (Interpretation)

隐藏的直觉是"收进更多菜单就看不见了"，但作者的定义更冷：无论隐藏什么，都是在用户和功能之间设一道障碍。障碍的成本是"找不到"——所以隐藏是有代价的设计动作，先想清楚值不值，再谈怎么做。

**什么该藏**：主流用户不常用的三类东西——① 细节与个性化设置；② 选项与偏好；③ 地区等场景特有的信息。铁律：核心功能绝不可藏。

**怎么藏**：成功的隐藏 = 彻底隐藏 + 适时出现。三种手法：渐进展示（默认只露核心，精确控制放进扩展区，如保存对话框）；阶段展示（设定场景、讲用户的语言、信息分成完整自洽的小块）；适时出现（平时不见，只在需要的时刻出现在需要的位置，如选中生词弹出问号词典）。

**怎么提示**：用户专注任务时，关注点会收窄到屏幕一两个区域，遇到问题时更只盯着问题区域——所以入口的位置比大小重要得多：放在任务发生的地方，小标签胜过大弹窗；用"应邀探索"（按住小三角出现高级项）代替文字说明；永远别贴"高级/更多"标签——那等于喝斥用户"你不配"。

**为什么不做自定义/自动定制**：算法猜不准"你的常用项"，命令位置一变就摧毁空间记忆——好比每晚有人把你的衣柜搬到不同地方；重型自定义则要求用户先成为专家。主流用户要的自定义是表达个性（换张狗狗桌面），不是重建界面。正解是聪明默认值：记住用户上次的状态。

## A1 — 书中的应用 (Past Application)

### 案例 1: 保存对话框与"应邀探索"四示范
- **问题**: 高级功能不能删，但摆在明面上会淹没主流用户。
- **方法论的使用**: 保存对话框只露"文件名+位置"两个核心问题，专家点扩展图标展开高级项，系统还记住用户上次用的是哪个版本；谷歌主界面只有关键字框，布尔与文件类型全部藏起；Illustrator 工具箱用小三角——单击选基本工具，按住不放出现高级项，用"应邀探索"代替标签。
- **结论**: 核心+扩展的渐进展示既简化主流体验又满足专家；提示要在正确环境下明确给出。
- **结果**: 保存对话框成为业界通用模式；Illustrator 的做法让专家和主流用户各得其所。

### 案例 2: 《纽约时报》选词问号词典
- **问题**: 用户读报遇到生词要查，但正文加链接会分散注意力、每个词都加链则页面一团糟、只挑个别词加注释则要人力逐篇编辑——大多数设计在"炫耀功能"上把自己拖入泥沼。
- **方法论的使用**: 功能平时彻底隐藏：选中复制生词时，选区后出现问号图标，点击才弹出定义——零干扰地出现在用户关注点上。
- **结论**: 成功的隐藏 = 尽可能彻底隐藏 + 只在合适时机、合适位置出现。
- **结果**: 作者主动发现并使用了该功能，查询全程零干扰。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 设置页/偏好面板几十个选项，新用户一进来就被吓退。
2. 一批高级功能不能删，但天天摆在主界面上干扰大多数人。
3. 隐藏的功能用户找不到（可发现性危机），提示怎么设计成了难题。
4. 有人提议"让界面按用户使用习惯自动调整"或"给用户自定义布局的自由"。
5. 需求评审里争论某个选项该删、该藏还是该摆出来。

### 语言信号 (用户的话里出现这些就应激活)

- "藏起来 / 收起来 / 设置太多 / 高级功能放哪 / 别吓到新用户"
- "渐进展示 / 适时出现 / 需要时才显示 / progressive disclosure / hide / advanced options"
- "用户找不到这个功能 / discoverability / 自适应菜单 / 要不要做自定义"

### 与相邻 skill 的区分

- 与 `four-strategies` 的区别：总纲管"该不该走隐藏这条路"的选择；本 skill 管隐藏的执行工序（什么该藏、怎么藏、怎么提示）。
- 与 `remove-strategy` 的区别：删除是彻底去掉，隐藏是收起非核心项；"先藏着以后再决定删不删"是书中点名的拖延。
- 与 `organize-strategy` 的区别：组织把所有项摆成用户可理解的组；隐藏是把非核心项收起防分散注意力。
- 与 `declutter` 的区别：减速带清理是删感知负担（视觉、文字、干扰）；本 skill 是功能收纳。
- 与 `pseudo-simplicity-detection` 的区别：向导是分步牵着用户走的假捷径；适时出现是藏好功能、在关注点上给入口——形态相似，方向相反。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **三类判断什么该藏**
   - 逐项问：目标主流用户会经常用到吗？它是核心任务的一环吗？
   - 完成标准: 产出可藏清单，每项标注类型（细节设置/偏好选项/地区信息）；核心功能与高频项零隐藏
2. **为每个被藏项选藏法**
   - 渐进展示（核心+扩展区）/ 阶段展示（设定场景、讲用户语言、完整小块）/ 适时出现（需要的时刻+需要的位置）
   - 完成标准: 每项写明"平时在哪、何时出现、出现在哪"；默认路径上没有任何被藏的东西
3. **设计入口与提示**
   - 入口落在用户关注点上（任务发生处）；用应邀探索类线索；检查全文无"高级/更多"标签
   - 完成标准: 每个入口都能对应到所在任务的关注区域；提示文案不制造心理门槛
4. **排除自定义/自动定制并判停**（判停条件：若发现要藏的其实是核心功能或多数项，说明该删该组，转 remove-strategy / organize-strategy）
   - 用聪明默认值（记住上次状态）替代自适应 UI；不逼用户重建界面
   - 完成标准: 方案中无"按使用频率自动调整"类设计；隐藏项的可发现性有验证计划

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 隐藏对象是核心功能或任务必经步骤——藏了用户就完不成任务
- 界面还没做过删除与组织——用隐藏收拾本该删掉的功能，只是把问题推迟（隐藏不减少维护成本）
- 纯粹为了"首页好看"，把用户每周都要用的东西藏进三级入口

### 作者在书中警告的失败模式

- **自动定制的翻车（Office 2000 自适应菜单）**：菜单按使用频率自动增减，有人装完几天就挨桌打听怎么禁掉；默认菜单猜不准个体、命令位置会变、用户要把长短菜单各看一遍——"每晚有人把你的衣柜搬到不同地方，你会作何感想？"
- **重型自定义（电视频道排序）**：重排 60 几个频道要按几百次遥控器；想自定义界面得先对功能了如指掌——简化之前先得成为专家
- **提示落在关注点之外（Skitch）**：按住某键触发的高级功能配了大号帮助弹窗，大多数用户说"看不见"；同一位设计师在 Comic Life 改用工具面板小标签（关注点上）就效果好——标签放哪比做多大重要
- **半藏半露两头不讨好（玻璃仓盖）**：藏在屏障后用户永远不知道掀开；忍不住炫耀则陷入"混乱、难看、成本高昂的泥沼"；把隐藏当拖延的删除，功能"在黑暗中默默死去"

### 作者的盲点 / 时代局限

- 成书于 2011 年：移动端手势导航、汉堡菜单后来爆发的可发现性争议（隐藏的新风险形态）书中未预见
- 隐藏功能带来的支持成本由谁承担（客服、文档），书中从用户感觉角度论证多、成本核算少

### 容易混淆的邻近方法论

- 汉堡菜单/抽屉式导航 ≠ 正确的隐藏——没有关注点上的入口，只剩障碍
- `remove-strategy`：先藏起来"以后再决定删不删"是书中点名的拖延——欲删，从速
- 极简主义：藏非核心项 ≠ 删光特征与个性 → `simplicity-boundaries`
