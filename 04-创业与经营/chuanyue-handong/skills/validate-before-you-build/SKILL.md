# 先验证再投入：用证伪实验代替自我幻想

## I — 方法论骨架 (Interpretation)

点子不缺赞美，缺证据。本 skill 提供一条从"我觉得"走到"市场说"的最短路径，核心纪律只有一条：**先验证，再投入**——验证不是创业后的动作，而是立项前就要跑完的闸门。

1. **先界定，再验证（5 问压缩）**：把模糊构想压缩成可检验的陈述——要解决什么问题、方案是什么、客户是谁、带来什么好处、市场多大，每问不超过三句话，写下来读给完全不懂行的人听，听不懂就重写。说不清楚的问题，永远验证不了。
2. **创意从自己的痛点出发**：最好的选题是你自己生活中反复苦恼、市场上又找不到解法的问题——你自己就是第一个客户，不需要猜测需求。从自己的真问题出发，验证起点就比别人高一层。
3. **创新循环 8 步（验证的主循环）**：构思创意 → 把创意分解成若干**可测试的假设** → 从最关键的假设入手 → 设计**否定性实验**（目的是证伪，不是找认同）→ 收集数据 → 分析数据并提炼结论 → 数据支持则迭代并测下一个假设 → 数据不支持则回到第一步重构创意。要点：实验要"聪明、快捷、低成本"，用最快速度循环。创意只是指南针，答案只能由实验给出。
4. **最小成本验证纪律**：每个实验的花费只够回答"这个假设成立与否"即可——软件做 MVP 加贝塔测试，硬件先做登录页测预订，B2B 问客户前五优先事项。能花一周和十次对话解决的，绝不花十万块。验证阶段花的每一分大钱，都是在给未经验证的假设加杠杆。
5. **公开换数据，不保密创意**：尽早把创意讲给客户、顾问、潜在投资人听。被剽窃的概率远低于因保密而错过调整机会的失败概率——没有反馈数据的想法只是空想。边界是不向一屋子竞争对手和盘托出。
6. **需求为王：两种死亡判据**：需求独立于产品存在，没人能凭空创造需求——需要你"教育市场/培育客户"才能成立的产品，是死亡之吻；同样，产品必须是**必需品**（解决关键问题或提供无处可获得的价值），而不仅是"好东西"（不错但可有可无）。价值必须大到压过生活惯性，否则没人会改变习惯。发现产品是"好东西"，唯一出路是重来。
7. **用行动验证，不听嘴说**：口头赞美等于没有反馈。有效的验证信号只有行动承诺——预订、付费、意向书、主动催你上线；用户愿不愿意回头、使用频率高不高、是否主动推荐，才是必需品的证据。
8. **六个月止损规则**：给验证设死线——产品推出六个月后仍得不到目标客户非常正面的反馈，就果断放弃、重新起步。预设截止日是对抗沉没成本和自我欺骗的唯一可靠工具。注意区分：放弃的是一个项目，不是创业本身——杰出创业者不断放弃想法，但不放弃创业。

## A1 — 书中的应用 (Past Application)

### 案例 1: Slack 巴特菲尔德——逐层扩大贝塔测试
- **问题**: 企业即时通信应用在没有完成开发、没有真实用户数据前，如何确认自己造的是必需品？
- **方法论的使用**: 严格执行创新循环——产品完成前就送到客户手中，7 个月做出阿尔法版；先给 6-10 家公司小范围试用，"祈求并哄骗"朋友所在的公司试用并给反馈，之后逐层扩大贝塔测试规模，每加一家就多收获一批反馈，并据此做关键调整，常发现"这个主意并不如想象中的那么好"。
- **结论**: 尽早让真实客户互动是发现必需品属性的唯一途径；反馈要逐层放大，而不是憋大招一次发布。
- **结果**: Slack 靠持续反馈循环打磨出客户真正离不开的产品，成为企业协作赛道的主导者。

### 案例 2: Oculus VR——公开创意反而赢得一切
- **问题**: 创意尚未做成产品，怕被抄袭，要不要保密？
- **方法论的使用**: 帕尔默·拉齐反其道而行——基于开源项目制作展示愿景的视频，放到 Kickstarter 上让全世界看到，用公开换取预订、媒体传播与投资人关注。
- **结论**: 分享创意的能量远大于保密：产品还没正式发布（距发布尚有数年），公开已带来预订潮、品牌与融资。
- **结果**: 筹到数千万美元，并被 Facebook 以 20 亿美元收购。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 有了一个点子/产品构想，想知道"这是不是真需求"，准备投入时间金钱前想先低成本试一把。
2. 已经做了产品或原型，收到的都是朋友和潜在客户的客气话，想分辨反馈的真伪、设计有效的验证实验。
3. 项目做了几个月没起色，在"再坚持一下还是及时止损"之间摇摆，需要一个客观的止损判据。

### 语言信号 (用户的话里出现这些就应激活)

- "这个点子靠不靠谱""怎么验证需求""真需求还是伪需求""做个 MVP 试试"
- "朋友都说不错，但没人付钱""用户用过一次就不来了""礼貌性反馈"
- "要不要继续做""该不该放弃""止损""已经投了这么久"
- "怕创意被抄""要不要保密""先秘密开发还是先找人聊"

### 与相邻 skill 的区分

- 与 `founder-fit-self-assessment` 的区别：那个 skill 问"**我这个人**适不适合创业"（动机、代价、承受力），本 skill 问"**这个点子**值不值得做"（需求真伪与验证）。同一用户可能两个都要——先用人格闸门自审，再用本 skill 验证点子；但一句话若在谈创意本身的真伪，用本 skill。
- 与 `design-business-model-and-moat` 的区别：需求尚未验证时归本 skill；需求已被验证、要设计变现方式、定价与护城河时，转那个 skill。顺序不可倒置——模式设计建立在"需求成立"之上。
- 与 `choose-your-funding-path` 的区别：融资决策的前提是验证完成（先验证后融资）；用户还在"点子阶段想找钱"，先回本 skill。
- 与 `sell-like-a-founder` 的区别：B2B 场景下"客户前五优先事项"等访谈技术两边共用，但本 skill 用它做**需求验证**，后者用它做**成交销售**；看用户的目的是验证还是拿订单。

## E — 可执行步骤 (Execution)

按创新循环组织，五步走完即完成一轮验证：

1. **界定问题（循环的入口）**：用 5 问各写不超过三句话：解决什么问题、方案是什么、客户是谁、好处是什么、市场多大；读给一个完全不懂行的人听。
   - 完成标准：外行听完能用自己的话复述"你为谁解决什么问题"；否则重写。
2. **分解假设并排序**：把构想拆成若干可测试的假设，标出**最关键的一个**（通常是最致命的："客户真的有这个痛点并愿意为它改变习惯吗"）。
   - 完成标准：一份假设清单，每条可被事实证明为真或假，且最关键假设已标出。
3. **设计最小成本证伪实验**：为关键假设设计一个以"否定它"为目的的实验——MVP、登录页预订、客户前五优先事项访谈皆可；同时明确实验的花费上限与时长。
   - 完成标准：写清"什么结果算假设被证伪"的判据；总成本控制在最小可回答问题的范围内。
4. **跑实验，只认行动数据**：执行并收集数据；过滤礼貌性反馈——只有预订、付费、复用、主动推荐算数，"不错啊做完再来找我"视为零反馈。数据支持则迭代测下一个假设，不支持则重构创意回到第 1 步。
   - 完成标准：每个假设都有明确的数据结论（支持/不支持），口头赞美不计入任何结论。
5. **执行六个月止损**：立项时即写下截止日期与达标线（目标客户非常正面的反馈）；到期不达标，果断放弃、重新起步。
   - 完成标准：截止日与达标线在验证开始前已书面化；到期日当天有明确的"继续/放弃"决定，不做无限期拖延。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户已完成需求验证，在设计变现模式、定价或护城河——转 `design-business-model-and-moat`。
- 用户在评估"我这个人要不要创业"——转 `founder-fit-self-assessment`（先过人格闸门再谈点子）。
- 公司已验证、已融资，问题是经营中的持续迭代与实验心态——转 `founder-resilience-and-learning`（从零验证与经营态迭代分属两个阶段）。

### 作者在书中警告的失败模式（客户验证家族反例）

- **礼貌性反馈假阳性**：一位创业者走访潜在客户，90% 以上表示喜欢产品并让他"做完再来"，作者却断定这恰恰证明产品不是客户想要的——人们不愿当面说难听话，没有主动询价、要求预订等行动式反馈就等于没有反馈。
- **"蜘蛛舞"：培育市场的死亡之吻**：作者自己的第一家公司做互动电视，不得不逐字逐句向好莱坞"教育"市场，市场崩溃后客户砍掉全部预算——需求必须先于产品存在，走在市场前面指望市场追赶是死路。
- **不研究过往失败者**：想做位置社交网络的团队被告知此前无数人尝试均告失败、连 Facebook 做该功能都不成功——不搜索已死亡的产品就立项，是最常犯的错误；作者自己也曾花数月做出早已有人做过且破产的东西。

### 作者的盲点 / 时代局限

- 风投中心视角：验证流程默认通向"可融资的高增长赛道"，对生活方式企业、利润优先路线的验证标准（何时该"小而美"）着墨少。
- 六个月是经验法则而非定律：对慢热型、季节性或长销售周期的业务，硬性六个月死线可能误杀本可成立的项目；判据的精神（预设死线、对抗沉没成本）比具体月数更可迁移。
- 案例集中于 2012-2019 的美国与中国互联网语境，渠道与工具（众筹、某些平台）时效性有限。

### 容易混淆的邻近方法论

- **"好东西" ≠ 坏产品**：它可能是优秀的产品，只是不足以让用户改变习惯；判据是"必需品 vs 可有可无"，不是"好坏"。
- **证伪 ≠ 自我否定**：使命是证伪创意，不是否定创业者本人；放弃项目与放弃创业身份是两回事。
- **公开创意 ≠ 毫无边界**：不保密针对客户、顾问、投资人的反馈场景，不包括向一屋子竞争对手宣布核心细节。
- **验证销售 ≠ 成交销售**：同样问客户前五优先事项，目的是证伪假设（本 skill）还是拿到订单（`sell-like-a-founder`），话术与心态不同。
