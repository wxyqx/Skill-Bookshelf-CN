# A/B 测试操作规范（铁律、失败率与陷阱）

## R — 原文 (Reading)

> "A/B测试的基本思想包括：提供两个方案并行测试。不同方案之间只存在一个变量，排除其他干扰因素。以某种标准判定结果优劣，筛出最优方案。"
>
> — 范冰，《增长黑客》第4章（A/B测试，网站活跃率提升的法宝）

---

## I — 方法论骨架 (Interpretation)

A/B 测试是一种决策替代机制：凡是"模棱两可、人人有理"的设计分歧（颜色、文案、布局、流程），不靠审美、职级或表决，靠两方案并行、只变一个变量、预先定好判优标准的对照实验来裁决。骨架有四块：

1. **三条铁律**：双方案同时跑（排除时间与环境干扰）；单变量（这是底线，一次只比较一个差异）；事先设定判优标准（看什么指标、差异多大算赢），不许跑完再挑指标。
2. **失败率预期**：微软仅 1/3 的测试验证有效，谷歌一年 12000 多次测试只有 10% 带来业务变化。多数测试注定失败——失败同样有价值（终结无意义争吵、省下无效消耗），且"产品不息，测试不止"，测试是常态机制而非一次性项目。
3. **微优化边界**：谷歌为挑一种蓝色测了 41 种色值，那是"0.x% 波动=百万美元损失"的巨头专属玩法；体量不够的团队精力应投向跃进式改变（换方向、换模式、换渠道），别用微优化的勤奋掩盖大方向的懒惰。
4. **测量失真警惕**：实验架构本身可能扭曲用户选择空间（强制单按钮"胁迫"点击），结论与用户反馈冲突时先怀疑测量方法。

一句话：A/B 测试擅长终结争吵、排除明显更差的方案，不擅长产出突破性创新——用它之前先确认问题属于前者。

## A1 — 书中的应用 (Past Application)

### 案例 1: 安迪·琼斯的 Twitter 着陆页改版（c02）
- **问题**: Twitter 早期着陆页堆满热门话题、搜索框、头像墙，注册按钮挤在角落，注册率低。
- **方法论的使用**: 按"别让用户思考"原则聚焦单变量改版——砍掉干扰元素，把注册登录区扩大到整页三分之一，突出唯一行动召唤；改版与旧版对比注册率。
- **结论**: 删除一切不服务核心目标的元素本身就是可测量的高收益变量。
- **结果**: 上线 24 小时内注册率提升约 250%。

### 案例 2: LinkedIn 邀请页魔法数字（c10）
- **问题**: LinkedIn 高达 50% 的注册用户是沉默用户，邀请页默认推荐几个好友最有效没有依据。
- **方法论的使用**: 对"默认推荐邀请人数"做反复 A/B，比较邀请转化率。
- **结论**: 魔法数字是"4"——少于 4 人易被忽略，多于 4 人让用户焦虑；此后 PV 提升 41%、站内搜索量提升 33%。
- **结果**: 该参数成为注册引导的默认配置，支撑了后续的双重病毒循环。

（另见 Bidsketch 静默删除免费选项的一周 A/B，c12：先悄悄删、验证付费用户数不变再公开切换——A/B 用于降低商业模式切换风险的范例。）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 设计/产品/老板为按钮颜色、文案、页面布局吵了很久，需要裁决机制。
2. 想系统地做转化率优化，问"实验该怎么做才靠谱、要看什么指标"。
3. 测试结果与用户反馈/直觉矛盾（数据说好、用户骂街），不知信谁。
4. 团队开始迷信 A/B，把所有问题都想用测试解决，需要边界校准。

### 语言信号 (用户的话里出现这些就应激活)

- "A/B 测试怎么设计 / A/B test / split test / 灰度实验"
- "两个方案谁好，用数据说话 / 按钮颜色吵起来了"
- "单变量 / 对照组 / 判优标准 / 显著性"
- "测试结果和用户反馈不一样，信哪个"

### 与相邻 skill 的区分

- 与 `activation-aha-magic-number` 的区别：A/B 测试是**测量方法**，回答"怎么测才有效"；魔法数字 skill 是**激活策略**，回答"找到 Aha 时刻与关键行为后怎么降门槛、定参数"。校准魔法数字参数时会调用本 skill，但策略层不在本 skill。
- 与 `growth-metrics-system` 的区别：指标体系管"看什么指标、口径是什么"；本 skill 管"用指标做对照实验的规范"。
- 与 `freemium-decision` 的区别：砍免费版的静默 A/B 是本规范的一个具体应用场景，但免费/收费模式决策的完整判据在 freemium-decision。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **先过体量与问题类型判据**
   - 问两个问题：当前体量下这个改动的绝对收益值得测吗（未到"0.x%=百万美元"规模，优先做跃进式改变）？这是"两方案选优"还是"寻找突破方向"（后者 A/B 测不出来）？
   - 完成标准: 明确写出预期收益量级与问题类型，判定"A/B 适用/不适用"。
   - 判停条件: 若属于方向、模式、渠道级别的跃进式问题，停止实验设计，改用原型验证或小范围试点回答。

2. **按三铁律设计实验**
   - 双方案并行分流；确认只改动一个变量（页面元素和测试架构都不得改变用户的选择空间）；预先写下判优指标与达标阈值。
   - 完成标准: 实验方案文档包含变量清单、分流方式、判优指标、预期运行时长/样本量。
   - 判停条件: 若发现单变量无法满足（改动必然牵连多处），改拆成多轮单变量实验或放弃对照改用前后对比+明显阈值。

3. **运行并按规范解读**
   - 补齐原书缺失的统计严谨性：确认样本量足够、避免过早peek下结论（2015 年原书无显著性检验讨论，此步按当代统计规范执行）。
   - 完成标准: 结论包含效应方向、幅度与不确定性；若结论与用户反馈冲突，先复核测量架构是否扭曲了行为（如 x10 的单按钮胁迫点击），再下产品结论。

4. **沉淀与常态化**
   - 无论成败都记录归档：成功的部署，失败的终结争论；把测试变成常态机制。
   - 完成标准: 实验结论进入团队知识库，并明确下一步（部署/回滚/继续迭代）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **寻找突破性创新或新方向**：A/B 只能在既有空间里选优，测不出跃进式改变；谷歌测 41 种蓝色是大巨头的理性、小团队的致命时间黑洞（x09）。
- **流量不足以支撑对照的问题**：样本量太小跑不出可靠结论，硬跑只会得到噪声。
- **需要统计口径定义的问题**：先去 `growth-metrics-system` 把指标定义清楚，否则测了也白测。

### 作者在书中警告的失败模式

- 微软 2/3、谷歌 90% 的测试无效——把 A/B 当万能药会陷入"一点一滴的变更而忽略更大的突破性变化"（x09）。
- 百姓网"投递简历"按钮：架构只允许放一个按钮，用户是被胁迫点击的，点击量相当纯属假象——测试架构扭曲选择空间时结论失真（x10），客服随即收到大量"为什么不能直接打电话"的抱怨。

### 作者的盲点 / 时代局限

- **方法内伤**：全书 A/B 章节完全不谈统计显著性、样本量、多重检验问题，照搬原书操作会产出大量假阳性结论——执行时必须按当代实验统计规范补齐。
- **2015 年快照时效警示**：书中移动端 A/B 依赖"服务端下发配置/HTML5 容器"等 2015 年技术方案，实验平台与灰度工具按当期技术栈重查；本 skill 保留的是铁律与陷阱的判断逻辑层。

### 容易混淆的邻近方法论

- 与魔法数字/激活引导（`activation-aha-magic-number`）：一个是尺子，一个是用尺子量出来的策略；与"砍免费版静默试验"（`freemium-decision`）：那是本规范在商业模式上的特例；与数据看板/虚荣指标甄别（`growth-metrics-system`）：体系先于实验。
