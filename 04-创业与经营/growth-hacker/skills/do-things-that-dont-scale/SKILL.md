# "从最笨的事情做起"人工补课式增长

## R — 原文 (Reading)

> 2009 年时，他们每周的营收仅为 200 美元，公司的发展遭遇瓶颈。……他们索性租了一台昂贵的相机，挨家挨户上门去帮房东拍照，替他们把挂在网站上的旧照片更换成漂亮的新照片。一周之后，效果立竿见影，网站的营收立刻从 200 美元上涨到了 400 美元。
>
> — 范冰，《增长黑客》第3章 3.2 从最笨的事情做起（Airbnb 上门拍照）

---

## I — 方法论骨架 (Interpretation)

在渠道红利不可得、没有投放预算的冷启动阶段，"人工补课"是唯一可控的增长杠杆：用创始人的人力直接补上产品缺失的那一环，同时顺带建立对用户的真实理解——磨刀不误砍柴工。选动作的判据是**先诊断卡在哪一环**：

1. **内容/展示缺失** → 人肉生产：替用户拍照、创始人注册马甲写专业内容、一件件实拍商品（Airbnb 挨家拍照、聚美马甲软文）。
2. **信任缺失** → 一对一陪聊：创始人直接加用户逐个深聊，把投诉与流失原因问出来（Strikingly 创始人加 2000 个用户）。
3. **供给/服务缺失** → 手工服务：先用人工顶上自动化流程，验证价值再谈效率（Groupon 式手工券、内部 50 人高强度试用再分层扩大内测）。

铁律有二：人工补课是**阶段手段**——规模化后应制度化（Airbnb 后来把上门拍照沉淀为专业摄影师项目），不能一直人扛；人工环节同时是用户研究，边做边记录洞察，不能只当苦力。

## A1 — 书中的应用 (Past Application)

### 案例 1: Airbnb 挨家挨户上门拍照（c18/c19）
- **问题**: 2009 年每周营收仅 200 美元濒临倒闭；房源照片是手机随手拍，毫无吸引力，拍照教学手册也不奏效。
- **方法论的使用**: 判断卡点在"内容/展示缺失"，租高档相机挨家挨户免费为纽约房东实拍换图——最笨、最不 scalable，但直击"好卖相带来好收益"。
- **结论**: 补课见效后制度化，而非一直人扛。
- **结果**: 一周内周营收 200→400 美元；后沉淀为专业摄影师项目，受益房源获 2-3 倍订单，2012 年 2000 余名摄影师拍摄 13000 余间房。

### 案例 2: 聚美优品的马甲软文与自拍摄影棚（c08）
- **问题**: 转做女性化妆品电商时天使投资见底，没钱请达人、砸广告。
- **方法论的使用**: 判断卡点在"信任/内容缺失"——创始人戴雨森注册女性马甲扮美妆达人写 BB 霜科普软文；自建简易摄影棚把所有化妆品实拍精修，配合口语化描述。
- **结论**: 零预算下人工生产的专业内容能同时解决信任与流量。
- **结果**: 软文几十万阅读，导流贡献几十万销售额，为团队赢得最早的生存现金流。

### 案例 3: Strikingly 的一对一陪聊（U06 素材）
- **问题**: 早期用户流失、需求拿捏不准。
- **方法论的使用**: 判断卡点在"信任/理解缺失"——创始人直接加 2000 个用户逐个聊天。
- **结论**: 人工触达换来的用户洞察是后续产品决策的底料。
- **结果**: 沉淀为对超级用户的判据（"没有它你愿付费维系吗"），支撑后续筛选与迭代。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 零预算冷启动：拿不到应用商店/平台推荐位、没有投放预算，问第一批客户还能从哪里来。
2. 核心内容/数据质量拖垮体验：房源照片丑、商品描述烂、UGC 空洞，纠结要不要人工先顶上。
3. 流失原因不明：数据看不出用户为什么走，需要创始人直接接触用户。
4. 争论"这活儿太低级/太慢了要不要做"：需要判断人工补课的时机与退出方式。

### 语言信号 (用户的话里出现这些就应激活)

- "没预算怎么获客？""第一批用户/客户从哪来？"
- "要不要人工帮用户做/手动录入/上门服务？""马甲内容行不行？"
- "do things that don't scale / 最笨的事情 / 手动冷启动 / founder-led"

### 与相邻 skill 的区分

- 与 `seed-user-selection` 的区别: 本 skill 是**进来之后的补课动作**（做什么服务把早期体验撑起来），seed-user-selection 是**准入机制**（谁被放进来）。美丽说 500 元买群主带对的人属于准入；进来之后人肉维护氛围与内容属于本 skill。诊断"人不对"用前者，诊断"体验缺一块"用本 skill。
- 与 `content-marketing-engine` 的区别: 聚美马甲软文是双属案例——一次性的人肉内容是补课（本 skill）；建立在选题机制、持续输出、渠道矩阵上的内容体系是引擎（content-marketing-engine）。判据：能否脱离创始人人力持续运转。
- 与 `aarrr-funnel-diagnosis` 的区别: 漏斗诊断面向已有流量池的转化率定位；本 skill 面向流量近零的 0 到 1 阶段。有数据可诊断时先诊断，无数据可用时才人工补课。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **诊断获客卡点属于哪一环**
   - 检视当前最大瓶颈：内容/展示质量差（内容环）、用户不信任不转化（信任环）、供给/服务跟不上（供给环），还是根本没有对的人进来（准入环——则转 `seed-user-selection`）。
   - 完成标准: 卡点明确归到一类并写明依据。
   - 判停条件: 若问题是"进来的不是目标用户"而非"体验缺一块"，移交 `seed-user-selection`，本 skill 不接手。

2. **选对应的最笨动作并设止损线**
   - 内容环→人肉生产（拍照/马甲专业内容/实拍）；信任环→一对一陪聊；供给环→手工服务。每个动作配时间盒、负责人与观察指标（周营收、回复率、首批留存）。
   - 完成标准: 动作有明确期限与指标，写进日程而非停留在倡议。

3. **见效后制度化或退出**
   - 动作见效后立即回答：这个人工环节能否工具化/团队化/体系化（Airbnb 摄影师项目）；能则转化为长效机制，不能则设定退出点，把人力还给产品迭代。
   - 完成标准: 每个补课动作都有"制度化方案"或"退出日期"二者之一，禁止无限期人扛。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已有被验证的规模化有效渠道（投放 ROI 为正、内容引擎在转）——此时人工补课挤占的是本可放量的预算，是倒退。
- 产品未过基本可用线（核心流程跑不通）——人工补课会加速把用户送进坏体验，先回 `pmf-gate`/`mvp-validator`。
- 创始人时间的机会成本高于动作产出时（如已融资、时薪隐含价值极高），应买服务而非亲自上。

### 作者在书中警告的失败模式

- 本书对本打法未列直接反例（书中正面案例密集）；但 Airbnb 案例本身内嵌警示：上门拍照只有沉淀为摄影师制度后才成为长效引擎——**不制度化的补课会变成创始人的无底洞**。
- 关联警示（x16/x17 之鉴）: 马甲、假数据等补课手法游走在平台规则与道德边缘，须先过 `growth-ethics-redlines` 的三闸，且平台政策随时收紧。

### 作者的盲点 / 时代局限

- 与 Paul Graham 同源的格言式方法，本书贡献是中国语境判据，但案例全是幸存者：聚美、Airbnb 成了，同样写马甲软文的无数店铺无人知晓——手法是放大器不是护城河（外卖库之鉴：手法全可复制、成本近零，仍被碾压出局）。
- 创始人时间的机会成本在书中未被定价；补课与产品开发争夺同一份注意力的权衡缺席。
- **时效警示（2015 年快照，全集群通用）**: 本 skill 只保留"按卡点选人工动作 + 制度化退出"的判断逻辑层；案例中的平台环境（微博/人人马甲生态、早期淘宝摄影棚外包价格）已变，马甲账号等手法还叠加当期平台合规风险，按当期政策重查并先过道德三闸；引用案例数据带幸存者偏差前提。

### 容易混淆的邻近方法论

- Paul Graham "Do things that don't scale": 同源格言，本书补充了"补哪一环、何时退出"的操作判据与本土实证。
- Concierge MVP: 手工服务形态与"供给环补课"几乎重合——区别在目的：Concierge MVP 以验证假设为目的（见 `mvp-validator`），本 skill 以撑起冷启动体验为目的；同一动作可以双任。
