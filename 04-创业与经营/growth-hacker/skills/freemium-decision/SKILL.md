# 免费-收费决策器：四支柱前提与砍免费版静默试验

## R — 原文 (Reading)

> "免费模式的前提是你的用户基数足够大，并且能够提供边际成本更低的标准化服务。……这个试验低调地进行了一周，结果——用户付费转化率提升了8倍，一个月后，转化率更是上涨到了10倍。"
>
> — 范冰，《增长黑客》第6章（免费午餐的终结）

---

## I — 方法论骨架 (Interpretation)

免费是手段不是目的。骨架是一道前提判断加一个反直觉操作序列：

1. **先过前提判据**：免费能成立，靠的是"边际成本趋零 + 海量市场 + 二八法则"——一小部分对价格不敏感的用户付的钱，补贴大多数免费用户的服务成本。三者缺一，免费就从商业模式变成慢性失血。常见模式：Freemium（基础免费+高级收费）、交叉补贴、三方市场流量变现、开源变现等，选哪种同样由成本结构与用户基数决定。
2. **再诊断免费健康度**：免费用户占比、试用转付费率、免费用户消耗的服务成本三条线一起看。免费用户往往还更挑剔——占资源而不付费，且挤占本可服务付费用户的精力。
3. **反直觉操作——静默砍免费版试验**：当免费撑不起付费率时，不要公告、不要打折挽留，而是**悄悄从页面删掉免费选项**做一周 A/B：若付费用户数不变、转化率显著跳升，说明免费选项在替犹豫者拖延决策，公开切换；若付费数应声下跌，说明免费仍是获客刚需，退回优化转化。
4. **配套心理细节**：让用户付出第一分钱最难（一分钱效应）——切换后的首个付费门槛要设计得极低。

一句话：免费要不要留，不由情怀和对手决定，由"补贴得起 + 砍掉后数据不塌"两个判据决定。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: Bidsketch 静默砍掉免费版（c12）
- **问题**: 面向设计师的在线提案工具上线六周后免费用户占 99%，试用转付费率仅 0.8%；优惠券、限制功能、升级邮件全部无效，运营与支持成本持续恶化。
- **方法论的使用**: 创始人不公告不挽留，只悄悄从页面删除免费账户选项，把"付费用户数不变、部分免费用户转付费"当作假设验证一周。
- **结论**: 免费选项在替犹豫者拖延决策；数据确认后正式全面转付费。
- **结果**: 付费转化率一周提升 8 倍、一个月达 10 倍，收入足以覆盖全部用户成本，创始人辞职全身心投入。

### 案例 2: GitHub 免费公开仓库+收费私有仓库（c21）
- **问题**: 协作开发工具如何既扩散网络效应又建立商业模式。
- **方法论的使用**: 符合四支柱前提（代码托管边际成本趋零、开发者市场海量、企业与重度用户愿为私有与协作付费）——免费公开仓库换取生态与口碑，收费私有仓库收割企业与专业用户；企业主动询问定制的那一刻确立收费点。
- **结论**: 免费与收费的切分线应落在"个人使用 vs 商业价值"上，而非随机砍功能。
- **结果**: 微软、沃尔玛、VMware 成为付费客户，5 年 300 万用户、估值 7.5 亿美元。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 免费用户占了绝大多数，服务器/支持成本快撑不住，争论"要不要收费、怎么收费"。
2. 试用转付费率长期低迷，优惠券、功能限制、升级邮件都试过无效。
3. 设计新版定价结构，要决定哪些功能进免费版、哪些进付费版。
4. 投资人/老板质疑"免费模式根本赚不到钱"，需要一个判据框架回应。
5. 考虑砍掉免费版，担心激怒用户与舆论，想找更稳妥的切换方式。

### 语言信号 (用户的话里出现这些就应激活)

- "Freemium / 免费增值 / 免费模式还撑得住吗 / freemium model"
- "免费用户太多 / 成本撑不住 / 要不要开始收费"
- "付费转化率低 / conversion to paid / 试用不转化"
- "免费版和付费版怎么切 / 定价分层 / 砍免费版"

### 与相邻 skill 的区分

- 与 `subsidy-ladder` 的区别：补贴是**推广预算**怎么花（限时刺激行为）；免费/收费是**商业模式定价结构**（免费版要不要存在）。"发券促转化"归补贴阶梯，"免费选项是否保留"归本 skill。
- 与 `turn-penalty-into-reward` 的区别：本 skill 处理**正常用户**的定价分层决策；对盗版序列号、钻价格漏洞等**越轨用户**的转化处理（不责备/给补偿/给便利）归对方。一个是设计定价，一个是处理越轨。
- 与 `growth-metrics-system` 的区别：付费率/ARPU 的口径定义与水分识别归指标体系；拿这些数字做免费/收费的模式决策归本 skill。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **过四支柱前提判据**
   - 逐项核对：边际成本是否趋零？目标市场是否海量？"少数付费者补贴多数免费者"在自家成本结构下是否算得过来（付费率 × 客单价 ≥ 单用户服务成本）？当前模式属于哪种免费模式？
   - 完成标准: 每项判据有"是/否/待验证"结论 + 一行成本测算依据。

2. **诊断免费健康度**
   - 拉三条线：免费用户占比、试用转付费率、免费用户的人均服务成本（含客服与支持）；并与"砍免费版后的预期收入"对照。
   - 完成标准: 一张三行数据表 + "免费是否可持续"的明确判断。
   - 判停条件: 前提成立且付费率健康 → 不砍免费版，转入转化率优化，流程结束。

3. **静默砍免费版试验（前提不成立时）**
   - 按顺序执行：悄悄从页面删除免费选项 → 跑一周观察付费用户数与转化率 → 付费数不变且转化率跳升则公开切换；付费数应声下跌则回滚并转优化。
   - 完成标准: 试验有预设判据（提前写下"什么结果算通过"）+ 一周数据 + 公开/回滚的决定。

4. **设计切换后的首个付费门槛**
   - 应用一分钱效应：首单价格、试用期与首充优惠设到最低阻力；公告文案不指责老免费用户，强调服务升级逻辑。
   - 完成标准: 切换方案含定价、首充设计、公告文案与老用户迁移说明。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **B 端重决策链产品照搬 C 端 freemium**：免费试用在企业采购里常是获客必需，砍前先分清免费在漏斗中的角色。
- **用"砍免费"掩盖付费价值不足**：若付费版本身没有不可替代的增值，砍免费只是把没人愿意买的东西标上价签。

### 作者在书中警告的失败模式

- Bidsketch 困局之鉴（x15）：免费用户涌入把付费占比从 54% 摊薄到 1%，优惠券/限制功能/延长试用全部无效——当免费用户撑不起付费率时，小团队照搬巨头的免费模式必死（Evernote 靠约 0.5% 付费率活，靠的是海量基数）。
- 免费用户更挑剔之鉴：占资源、不付费、支持成本还更高——免费用户质量评估别只看数量。

### 作者的盲点 / 时代局限

- 书中"二八法则"与作者自引的 Evernote 约 0.5% 付费率存在内部张力，二八并非普适常数；案例全是幸存者（Bidsketch/GitHub），砍免费失败的样本缺席。
- **2015 年快照时效警示**：当代 SaaS 定价已大量转向按用量计费（usage-based）、席位+用量混合等形态，免费额度设计随之变化；应用商店平台抽成与订阅政策也重塑了免费/付费切分点。**skill 只保留"前提判据→健康度诊断→静默试验→低门槛切换"的决策逻辑层，定价形态与平台政策按当期重查。**

### 容易混淆的邻近方法论

- 免费/收费决策（本 skill）≠ 补贴设计（`subsidy-ladder`）≠ 越轨用户转化（`turn-penalty-into-reward`）。"要不要免费"归本 skill，"要不要发券"归补贴，"怎么对待用盗版的人"归变惩为奖。
