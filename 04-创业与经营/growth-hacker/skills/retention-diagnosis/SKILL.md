# 留存诊断：三口径、五分类与有损服务取舍

## R — 原文 (Reading)

> "实际上归根到底，真正的用户增长就是增长与流失的差值。……流传出所谓的'40-20-10'规则，即如果你想让游戏的DAU超过100万，那么新用户次日留存率应该大于40％，7日留存率和30日留存率得分别大于20％和10％。"
>
> — 范冰，《增长黑客》第5章（留存与流失）

---

## I — 方法论骨架 (Interpretation)

这本书把留存当作增长的地基，骨架是一套四层诊断流程：

1. **先校准定义**：真增长 = 新增 − 流失。累计注册用户数是"游泳池进水量"，不看排水量就是自欺；留存曲线持续走低不趋平，说明产品本身不过关。
2. **三口径衡量**：次日留存看版本品质与渠道优劣，7 日留存看一个完整体验周期，30 日留存看迭代后的稳定性；另做渠道剥离，识别哪个渠道买来的是"泡沫用户"。
3. **对照品类基准**：不同品类达标线不同（游戏 40-20-10、电商 20-30% 即可、社媒月留存低于 80% 别指望做大），拿错基准会误判健康度。
4. **五分类归因后对症下药**：①程序漏洞与性能瓶颈——用有损服务两原则止血（保核心功能、牺牲的特性越少越好）；②被频繁骚扰——降噪声而非加大推送剂量；③话题热度减退——缺长效引擎，需回答"新鲜感过后用户凭什么留下"；④更好的替代品——差异化重定位；⑤其他。归因错了，药方必然错。

核心心法：留存有硬伤时，任何拉新都是在给漏水的桶灌水——先查漏，再灌水。

## A1 — 书中的应用 (Past Application)

> 注：聚类总表中本单元未挂接独立正面案例 id，以下取 verified.md 单元内的书中诊断场景作 A1 证据。

### 案例 1: Color——归因于"漏洞性能"的留存崩塌（反例 x12）
- **问题**: 弹性社交应用 Color 未上线就拿了 4100 万美元融资，团队来自苹果等顶尖公司，但几乎从第一天起图片无法分享、频繁闪退。
- **方法论的使用**: 作者把它列为流失五分类的第一类（程序漏洞与性能瓶颈）的典型：正常操作中的意外麻烦最耗尽用户宽容，多数人用脚投票。
- **结论**: 明星团队+巨额融资救不了跑不通核心流程的产品；留存曲线持续走低=产品不过关。
- **结果**: 一年后残存用户不足 3 万，被苹果以未公开价格低调收购。

### 案例 2: 新浪微博——归因于"频繁骚扰"的活跃崩塌（反例 x13）
- **问题**: 活跃用户量下滑超过 60%，产品为召回用户采用更暴力的打扰：不必要的通知、信息流广告、不合口味的推送。
- **方法论的使用**: 对应五分类第二类——"越流失越骚扰、越骚扰越流失"的死循环；诊断结论是手段生硬、不顾用户承受度的商业化催促，根本出路在降噪与重建内容价值。
- **结论**: 唤醒和召回只能是补救而非替代，加大打扰剂量只会加速流失。
- **结果**: 被媒体公开点名"请停止骚扰用户"。

### 案例 3: 有损服务的止血取舍（QQ 农场/微信，术语 t16）
- **问题**: 高峰期或故障时服务撑不住，"Everything or Nothing"的完美主义会让用户什么都干不了。
- **方法论的使用**: 按两原则降级——QQ 农场高峰期宁可返回静态默认应用列表也要保住登录；微信放弃群聊消息顺序的强一致换取可达性；刀塔传奇大版本用低清资源包保当日活跃。
- **结论**: 刻意输出有品质损失的服务，换取速度与稳定性；优先保核心，牺牲越少越好。
- **结果**: 留住"至少有事可干"的用户，避免整站瘫痪式的流失。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. DAU/新增还在涨，但收入或活跃不涨，怀疑"增长是虚的"，要判断该看什么。
2. 留存曲线持续下滑、迟迟不见走平，团队说不清用户为什么走。
3. 争论"该继续投拉新还是先停下来修产品"——需要判据而非感觉。
4. 线上事故/高峰压力下要决定牺牲哪些功能、保哪些核心能力。
5. 新版本发布后次日留存突变，要排查是版本品质还是渠道质量问题。

### 语言信号 (用户的话里出现这些就应激活)

- "留存低 / 用户流失严重 / churn / retention curve 一直在掉"
- "次日留存 / 7 日留存 / 30 日留存怎么算、多少算合格 / 40-20-10"
- "DAU 涨但不赚钱 / 增长是不是虚的 / 累计用户没意义"
- "用户为什么走 / 流失原因怎么查 / 被我们推送烦走了"
- "服务器扛不住了，砍哪些功能 / 有损服务"

### 与相邻 skill 的区分

- 与 `winback-mechanisms` 的区别：本 skill 管**判断**——为什么流失、问题多严重、先修什么；唤醒机制管**执行**——用什么通道和内容把已流失的人拉回来。诊断不清就做唤醒，等于往漏水桶里灌水后再续水。
- 与 `growth-metrics-system` 的区别：指标体系管**看什么数字、口径怎么定**（North Star、26 项字典）；本 skill 拿这些数字做**归因诊断**。选指标归对方，解读与归因归本 skill。
- 与 `activation-aha-magic-number` 的区别：激活优化针对**新用户首日/首次关键行为**的引导；留存诊断面向**已经用过产品的人为什么不再来**。次日留存差且问题集中在注册流程时归激活优化。
- 与 `pmf-gate` 的区别：PMF 门回答"产品是否值得规模化增长"这个一票否决判断；本 skill 是达成 PMF 后的精细化诊断流程。留存曲线完全不趋平时，判停后应移交 pmf-gate 重审。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **校准增长定义，冻结虚荣数字**
   - 用"新增 − 流失"重算真增长；停用累计注册用户数作为健康度依据。
   - 完成标准: 给出一个带符号的真增长数字（正/负），并指出当前汇报口径中哪些属于"进水量自欺"。

2. **三口径测量 + 品类基准对照**
   - 分别计算次日/7 日/30 日留存，找到本产品所属品类（游戏/电商/社媒/工具）的参考基准，标注差距最大的一段。
   - 完成标准: 三个留存数字 + 基准对照结论（达标/差距在哪一档）+ 渠道剥离结论（哪个渠道泡沫最大）。
   - 判停条件: 若曲线完全不平、新增持续小于流失且品类基准大幅不达标——停止优化动作，移交 `pmf-gate` 重审产品价值。

3. **五分类归因**
   - 按五分类逐项找证据：性能（崩溃率/加载时长）、骚扰（推送频次/退订与卸载原因）、热度（需求是否一次性）、替代品（竞品迁移证据）、其他。每类必须给出数据或用户行为证据，不许拍脑袋。
   - 完成标准: 确定主因（至多两个），且有至少一条可验证证据支撑。

4. **对症下药并设止血优先级**
   - 性能硬伤→先按有损服务两原则止血（列核心功能清单，明确牺牲什么），再做优化；骚扰→先降噪声（推送频控、内容降噪）再做唤醒；热度减退→设计长效引擎问题移交产品规划；替代品→差异化重定位讨论。
   - 完成标准: 产出一页诊断结论：主因、止血动作、修复动作、复查指标与复查时间点。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **拉新渠道效果评估**：渠道选型与获客成本问题属 `aarrr-funnel-diagnosis` / 获客域 skill，别把"新增质量差"误当留存问题处理。
- **召回内容与推送文案设计**：诊断结束后要执行召回时，移交 `winback-mechanisms`；本 skill 只回答"该不该救、先救什么"。

### 作者在书中警告的失败模式

- Color 之鉴（x12）：性能硬伤是流失第一大原因，明星团队与巨额融资都不能豁免——先跑通核心流程再谈增长。
- 新浪微博之鉴（x13）：为召回而加大打扰剂量，形成"越流失越骚扰、越骚扰越流失"的死循环。
- 你画我猜之鉴（x14）：爆红不等于 PMF，缺长效引擎的话题产品"风靡得快，退烧得也快"，收购价基于热度而非留存结构。

### 作者的盲点 / 时代局限

- 40-20-10 与"社媒月留存 80%"等基准系圈内口传（源自经验分享），书中无样本量与显著性讨论，只能作参考锚点而非硬标准。
- 案例全是输家/赢家的叙事样本，未统计各类归因的基率；幸存者偏差提示归因框架本身也需用自家数据校验。
- **2015 年快照时效警示**：三口径与品类基准按当期行业标准重查（如移动应用留存中位数随品类与市场大幅演变）；DAU/MAU 口径在当代需结合订阅、WAU/DAU 粘性等现代口径；书中"渠道"概念按当代投放环境重估。**skill 只保留"定义校准→三口径→基准对照→五分类归因→对症下药"的判断逻辑层，一切参数层按当期重查。**

### 容易混淆的邻近方法论

- 留存诊断（本 skill）≠ 唤醒机制（`winback-mechanisms`，召回执行）≠ 指标体系（`growth-metrics-system`，度量底座）。三者常在同一讨论中出现，按"判断/执行/度量"分工，勿互相抢调用。
