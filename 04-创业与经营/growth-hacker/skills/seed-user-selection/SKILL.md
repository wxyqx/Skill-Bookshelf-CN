# 种子用户筛选与冷启动准入

## R — 原文 (Reading)

> 混杂在真实用户之中的产品蝗虫，会干扰产品行为数据统计的准确性，聆听他们的错误反馈会令产品日后的发展方向陷入尴尬的境地。……需要邀请码才能注册的网站，后台日志里一半的 IP 来自竞争对手公司内网。
>
> — 范冰，《增长黑客》第3章 3.1 筛选你的种子用户

---

## I — 方法论骨架 (Interpretation)

冷启动用户**贵精不贵多**：种子用户数量少、进入早，其质量将决定产品初期的氛围与运营走向——知乎的邀请制、B 站的 100 道题、小米"100 个梦想的赞助商"、Facebook 的校园限定，都在用准入机制给产品定调。方法骨架三层：

1. **定义理想种子画像**：谁是能让生态长起来的第一批人；社交产品的经验是"先女后男"——高质量女性用户带动整体社区氛围；"超级粉丝"判据是"如果明天没有这个产品，你的生活是否会受很大影响、是否愿意付费维系"。
2. **选准入机制**：邀请制、答题门槛、付费门槛、先渗透高势能人群（派对圈、名校、垂直社群），必要时用排队分批放行制造稀缺。
3. **排除产品蝗虫**：观光客、找项目的投资人、做竞品调研的产品经理不是目标用户——他们占用名额、破坏氛围、乱提"用户体验"意见、污染行为数据。解读早期数据前，先用数据日志（IP 来源、注册资料、行为特征）甄别排除，只听目标用户的声音。

## A1 — 书中的应用 (Past Application)

### 案例 1: 美丽说——500 元群主与"把男人赶出去"（c22）
- **问题**: 女性时尚社区冷启动，测试二十几个人无一留存，潜入导购 QQ 群发广告即被踢；同时社区氛围被男性注册者破坏。
- **方法论的使用**: 每月 500 元付费请 QQ 群主带精准女性用户进来玩，先养出两个百人低流失小组；蔷薇粉主色调 + 禁止男性注册，硬性守住社区生态；后续再分层运营达人/超级用户/活跃用户/需求群众。
- **结论**: 准入控制先于规模扩张，氛围一旦失守很难重建。
- **结果**: 2011 年 2 月到年底指标增长至少 30 倍，2014 年 Q3 注册用户超 1 亿、日活超 1000 万。

### 案例 2: Tinder——先女后男、先攻高势能节点（c20）
- **问题**: 约会应用的"鸡与蛋"悖论：男性活跃但需要女性在场，女性怕被骚扰。
- **方法论的使用**: CMO 先把测试版发给洛杉矶派对圈最受欢迎的 600 位熟人；地推团队飞遍全美校园，先邀女生联谊会、再拉兄弟会——男生打开即见周围女生已加入，配对体验成立。
- **结论**: 高势能人群的次序就是冷启动的生命线。
- **结果**: 校园地推使用户量 5000→15000，上线两个月配对超 100 万对，2014 年底达 5000 万用户。

### 案例 3: Trak.io——排队机制的反面与补救（x07）
- **问题**: 上线两周遭遇性能瓶颈，照搬 Mailbox 强制排队数周，既无品牌势能也无额外价值托底。
- **方法论的使用**: 验证了本书判据——稀缺/排队玩法只对本身有吸引力的产品成立；其补救是付费 29 美元免排队，反而筛选出迫切用户。
- **结论**: 机制不能硬撑产品价值，但门槛可以拿来验证付费意愿。
- **结果**: 放弃强制排队；付费跳队试验中 983 人里 105 人付费（转化率 11%）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 冷启动决策：第一批用户是先冲 1 万注册量，还是只放 100 个精准用户进来。
2. 社区调性危机：早期涌入的用户与目标画像不符，氛围、内容质量正在被带偏。
3. 早期数据解读：注册量尚可但行为数据诡异（不活跃、意见离谱），怀疑用户构成不真实。
4. 稀缺机制设计：纠结要不要上邀请码、排队、内测名额，担心把用户挡在门外。

### 语言信号 (用户的话里出现这些就应激活)

- "种子用户怎么找？""第一批用户要控量吗？"
- "社区氛围被带偏了""进来的都不是目标用户"
- "要不要邀请码/排队？""seed users / invite-only / cold start / product locusts"

### 与相邻 skill 的区分

- 与 `do-things-that-dont-scale` 的区别: 本 skill 管**准入**（谁进来、怎么筛），do-things-that-dont-scale 管**进来之后的补课动作**（上门拍照、马甲内容、一对一陪聊）。聚美马甲软文写的是吸引来什么人时属于内容补课；美丽说 500 元买群主带"对的人"属于本 skill。先定准入，再谈补课。
- 与 `content-marketing-engine` 的区别: content-marketing-engine 是公开期的**规模化内容渠道**（持续输出、7 次触达）；本 skill 是 0 到 1 阶段的**窄门机制**，两者甚至常相反——一个要放量触达，一个要控量筛选。
- 与 `pmf-gate` 的区别: 若产品本身对任何人都没有吸引力，准入机制救不了——排队/邀请码只对已有基本吸引力的产品成立，此时应回 `pmf-gate`/`mvp-validator` 补课，而非设计窄门。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定义理想种子画像与超级粉丝判据**
   - 写清目标种子的人口/场景特征；用"没有它你愿付费维系吗"测试潜在种子是否真有痛点；社交/社区类产品明确是否采用"先女后男"或高势能人群次序。
   - 完成标准: 画像与判据成文，且能指出至少一个可达的高势能聚集地。

2. **选准入机制并设计蝗虫甄别**
   - 从邀请制/答题/付费/高势能渗透/排队分批中选一两种，并配套数据日志规则（IP 来源、注册资料、行为特征）用于排除观光客、投资人与竞品调研者。
   - 完成标准: 机制上线且有蝗虫排除记录（被拒/被标记的样本）。
   - 判停条件: 若产品对目标人群尚无基本吸引力（口碑/价值未立），放弃稀缺机制设计，回 `pmf-gate` 与 `mvp-validator` 补课——强行排队只会重演 Trak.io。

3. **小批量放行、观察、再放量**
   - 首批控制在能逐个运营的规模；观察留存、内容生产率、氛围指标；数据达标再逐层扩大，每层重复蝗虫过滤。
   - 完成标准: 首批用户留存与内容质量达标记录在案，扩量节奏有明确门槛值。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 大众工具型产品追求普及速度时（先冲量是合理策略），硬套精英筛选会错失窗口——本 skill 适用于氛围/生态敏感的产品。
- 已过冷启动期、进入公开增长阶段——控量逻辑让位于规模化渠道（`content-marketing-engine` 等）。
- 想用邀请码"制造饥饿感"却拿不出产品吸引力——机制不能替代价值。

### 作者在书中警告的失败模式

- x06: 产品蝗虫四重伤害（占名额、毁氛围、乱提意见、污染数据）；邀请制网站后台一半 IP 来自竞品内网的真实案例。
- x07: Trak.io 无底气的强制排队赶走用户，部分人数周后收到邀请码已忘记注册过。
- x05（关联）: 多啦口袋——最先尝鲜的种子用户最宝贵，一旦在转化环节伤害他们，前期投入全部付诸东流。

### 作者的盲点 / 时代局限

- 精英筛选策略可能错失大众化产品的窗口期；书中案例全是赢家（知乎/B站/小米/Facebook），筛选失败导致启动失败的产品未见统计——幸存者偏差。
- "先女后男"等经验来自约会/社区品类，不可直接迁移到工具、B2B 等品类。
- **时效警示（2015 年快照，全集群通用）**: 本 skill 只保留"准入筛选 + 蝗虫甄别"的判断逻辑层；案例中的渠道参数（QQ 群主、人人网、常青藤校园、微博开放平台）已随平台生态变迁失效或收紧，高势能聚集地按当期重查；案例数据引用须带幸存者偏差前提。

### 容易混淆的邻近方法论

- Paul Graham "Do things that don't scale": 同属冷启动思想，但 PG 句式强调创始人亲手做不可规模化的服务（见 `do-things-that-dont-scale`），本 skill 强调准入与筛选，二者互补。
- "早期采用者"（Everett Rogers 扩散理论）: 学术概念描述采纳曲线；本书贡献是把"筛早期用户"变成可操作的准入机制与蝗虫排除清单。
