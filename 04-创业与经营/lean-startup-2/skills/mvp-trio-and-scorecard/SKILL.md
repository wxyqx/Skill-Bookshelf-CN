# MVP 三件套头脑风暴与记分卡

## R — 原文 (Reading)

> "我经常要求团队从现有计划中选择一个假设，然后集思广益，想出三种不同的最小化可行产品。我们从简单的那个开始，就是他们已经想到要做的那个产品。然后想一个好玩的——要花很多钱的那种（终极镀金版）。"
>
> — 埃里克·莱斯，第 4 章（行 1402-1404）

> "第二种产品在复杂程度和成本方面与第一种的距离有多远，第三种产品在简单程度方面就应该与第一种产品有多远。"
>
> — 埃里克·莱斯，第 4 章（行 1404）

> "初创公司考虑的最小化可行产品虽然不同，但测试的假设完全一样，而使用的经费相差悬殊。在这种情况下，我们就需要淘汰花费高的产品，即便这么做令人感到不快。"
>
> — 埃里克·莱斯，第 4 章"用最小化可行产品来测试假设"（行 1416-1418）

---

## I — 方法论骨架 (Interpretation)

验证一个假设最常犯的错不是做错 MVP，而是只想到一个 MVP——而且往往是那个贵的。本书给出一套强制发散的工具：

1. **三件套头脑风暴**：对选定的假设，必须产出三个候选——现有版（团队原打算做的）、镀金版（预算无限的终极形态）、极简版（最省钱的验证方式）。关键约束是镜像规则：极简版离"现有版"的距离 = 镀金版离"现有版"的距离。逼着团队把"如果工程师全放假，用人力怎么测"想到底（纸板样机、人工代办、预售页都属此类）。
2. **MVP 记分卡**：把候选铺进表格（学习价值/成本/出数时间，表 4-3），认清"假设与 MVP 不是一一对应"，按单位成本换学习量比较。
3. **淘汰贵的**：不同 MVP 测同一假设而经费相差数量级时，必须淘汰贵的那个——哪怕它顺眼、哪怕"反正要做"。
4. **15 分钟练习**（司各特·库克的会议用法）：5 分钟写假设→5 分钟选指标→5 分钟为指标想 MVP，让发散在例会里随时发生。

本工具回答"用什么测"，不回答"测得合不合格"（那是四特征的职责）。

## A1 — 书中的应用 (Past Application)

### 案例 1：大学记分卡的纸板手机
- **问题**：教育部团队要验证"学生会用工具比较大学"，常规路径是开发一个带对比功能的正式应用。
- **方法论的使用**：放弃写代码，做带滑块的纸板假手机复制应用体验（极简版），在国家广场每周访谈学生；记录"添加对比名单"功能的真实使用行为。
- **结论**：核心假设被证伪——"谁都不愿意比较"；这一学习只花了纸板的钱。
- **结果**：转向迭代出用户喜爱的产品形态后，才开发正式工具与 API 上线（第 4 章，案例 c03）。

### 案例 2：GE X 系列——"造新发动机"收缩为"改造 616 型"
- **问题**：5 年数十亿美元的新柴油发动机计划，团队默认的唯一方案是全新研发。
- **方法论的使用**：研讨会上把 MVP 从"造一款新发动机"（镀金版）强制收缩为"半年内改造现有 616 型发动机测需求"（极简版）——同一假设，经费相差数个数量级。
- **结论**：按淘汰规则选了改造方案；最资深技术领导承认"问题在我"。
- **结果**：样机获得 5 份订单，研讨会成为 GE FastWorks 转型起点（第 6 章，案例 c01）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 要验证某个假设（学生愿不愿付费、用户要不要这个功能、家长买不买账），问"MVP 该怎么做"——需要不止一个候选。
2. 团队被唯一方案绑架（"先把产品做完整再说"），需要用三件套和镜像规则强制发散出极简版。
3. 预算有限而有人提出昂贵方案，需要"同假设不同经费，淘汰贵者"的裁决依据。
4. 会议/工作坊要快速激发方案（司各特·库克 15 分钟练习），或评审别人的 MVP 提案是否够省。

### 语言信号 (用户的话里出现这些就应激活)

- "这个假设用什么 MVP 测？" / "how to test with an MVP"
- "有没有更便宜的验证办法？人工能不能先顶上？"（concierge / Wizard of Oz / 预售页）
- "做纸质原型、纸板样机行不行？"（paper prototype / cardboard MVP）
- "这几个方案测的是一件事，怎么选？要不要把贵的那个砍了？"

### 与相邻 skill 的区分

- 与 `good-experiment-four-traits`（好实验四特征）的区别：mvp-trio-and-scorecard 生成并挑选候选载体；good-experiment-four-traits 对选定载体做四道质量检查与风险封顶。顺序是 mvp-trio-and-scorecard→good-experiment-four-traits，用户问"怎么选方案"给 mvp-trio-and-scorecard，问"这方案过不过关"给 good-experiment-four-traits。
- 与 `leap-of-faith-assumption-audit`（信仰飞跃假设审计）的区别：leap-of-faith-assumption-audit 先选定要测的假设；mvp-trio-and-scorecard 为选定的假设设计载体。判停条件：没有假设清单先回 leap-of-faith-assumption-audit。
- 与 `mvp-for-learning-not-scale`（优化 MVP 是为了学习，不是为了扩大规模）的区别：mvp-for-learning-not-scale 是原则（挡"给 MVP 加高可用/上规模"的要求），mvp-trio-and-scorecard 是生成工具；有人想给 MVP 加码时用 mvp-for-learning-not-scale 裁决，要产出候选时用 mvp-trio-and-scorecard。
- 与 `prfaq-working-backwards`（PRFAQ）的区别：`prfaq-working-backwards` 是一种具体的极简版载体（虚构新闻稿+FAQ 测反应），可作为 mvp-trio-and-scorecard 极简版的候选之一，两者是类与实例的关系。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **锁定假设**：确认要测哪一条信仰飞跃假设。
   - 完成标准：一句话假设且可被行为证伪。
   - 判停条件：用户没有假设清单或拿不定测哪条，先转 `leap-of-faith-assumption-audit`。

2. **三件套强制发散**：依次产出现有版、镀金版、极简版。
   - 完成标准：三个候选都落在纸上；极简版满足镜像规则（离现有版的简单程度=镀金版离现有版的豪华程度）。卡壳时追问："如果所有工程师放假一个月，你怎么用人工和现成工具测出同样的数据？"

3. **记分卡比较**：为每个候选评估学习价值、成本、出数时间，算"单位成本换学习量"。
   - 完成标准：三个候选在表上可比；明确哪些候选其实测的是同一假设。

4. **淘汰贵者**：对测同一假设的候选，按记分卡裁决。
   - 判停条件：出现"同假设、不同经费"组合时直接淘汰贵的候选，不接受"顺手多做一点"的合并理由（ce04 的入口）。

5. **移交四特征检查**：把选中的 MVP 交给 `good-experiment-four-traits` 过可证伪/下一步/风险控制/绑定假设四道检查。
   - 完成标准：通过四特征后才投入执行；若用户只需发散方案、尚不执行，本步可输出为建议。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 假设已被证明、只是没资源实现的执行任务——再"极简"也不产生新学习。
- 以品牌亮相、投标资质为目的的交付物——那不是实验，镀金是目的本身。
- 强监管场景下触碰安全底线的"极简"——合规不打折（good-experiment-four-traits），极简只能在合规空间内设计。

### 作者在书中警告的失败模式

- ce04 范围蔓延：MVP 变成正式开发的第一期，"等造出来再建分销"，验证被无限后置。
- ce21 提前投资可扩展基础设施：产品没有早期用户就为将来规模配置架构与客服——用执行完美替代学习。
- 只想一个方案的惯性：书中团队"总是"只想到贵的那个 MVP，这正是三件套与镜像规则要打破的默认状态。

### 作者的盲点 / 时代局限

- 记分卡（表 4-3）只给了维度框架，未给权重与打分标准，实际使用依赖引导者经验。
- 三件套的"极简版"在硬件/医疗等重资产行业常受监管下限约束（不能无证试用），书中未给受监管场景的替代设计。
- 案例集中于 2010 年代工具箱（纸板、Craigslist、人工服务）；线上低代码工具已普及后，"极简"形态变了，但书中未更新。

### 容易混淆的邻近方法论

- 《精益创业》正传的 MVP：正传给出定义与"最小化"原则，无三件套发散、镜像规则与"淘汰贵者"裁决——这些是本书第 4 章的增量。
- Design Sprint（五天冲刺）：产出的原型通常是单一（偏镀金）候选，不做镜像对照，也不裁决经费悬殊问题。
- 精益画布（Lean Canvas）：是计划梳理工具，不产出实验载体；画布填完仍需 mvp-trio-and-scorecard 设计验证方式。
- "MVP 类型学"（着陆页/冗余按钮/假门等流行清单）：本 skill 的独特处不在类型清单，而在"三件套镜像设计+同假设淘汰贵者"的结构规则。
