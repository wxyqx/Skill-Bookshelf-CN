# 转型还是坚持：方向性裁决与剩余机会管理

## R — 原文 (Reading)

> "这种改变称为转型：即有条理的方向性改变，用来测试新的产品、战略和增长引擎的基础假设。……错的坚持决定是对潜在创新的最大威胁。"
>
> —【作】埃里克·莱斯，第8章

> "我建议每个新创企业都应该有一个讨论'转型还是坚持'的常规会议。"
>
> —【作】埃里克·莱斯，第8章

> "失败是认知的先决条件。要是打算先推出产品再来看发生什么，那么准保你心想事成，因为你肯定会看到发生了什么。问题是然后怎么办？"
>
> —【作】埃里克·莱斯，第8章

> "第一，虚荣指数会让创业者形成错误结论，活在自己的个人世界中。……第二，如果创业者没有一个清晰的前提假设，他几乎不可能经历完整的失败……第三，很多创业者心存恐惧。"
>
> —【作】埃里克·莱斯，第8章

> "真正衡量跑道长短的标准是公司剩余的转型次数，即根本改变商业战略的机会还有几次。"
>
> —【作】埃里克·莱斯，第8章

## I — 方法论骨架 (Interpretation)

数据回来了，最难的裁决摆在面前：改弦更张还是坚守不移？本书把这一步做成一套可操作的机器：

1. **转型是"有条理的方向性改变"，不是泛泛的"改变"**：它用来测试新的产品、战略和增长引擎的基础假设；转型也不必推倒重来——常见形态是重新利用已开发和已学到的东西。
2. **错的坚持比失败更危险**："进退维谷"式的错误坚持——既无法如期增长又不垮台——是对潜在创新的最大威胁，虚耗员工与利益相关方的资源信任。
3. **用常规会议把决策制度化**：转型决定必然引起紧张情绪，须以有计划有条理的方式处理。每个新创企业都应设"转型还是坚持"常规会议——间隔数周太频、数月太少，各找节奏；产品开发与业务领导两团队共同参加，必要时引入外部顾问克服先入之见。
4. **会议要带两类输入**：开发团队带来一段时期内（而非刚刚过去的时间）的产品优化效果与预期对比；业务团队带来与现有及潜在顾客交谈的详细记录。
5. **转型的类型学——十种模式**：放大转型（单项功能变成整体）、缩小转型（整体产品变成大产品的一项功能）、客户细分市场转型（产品对、顾客错）、客户需求转型（问题不重要、相关重要问题出现）、平台转型（应用↔平台）、商业架构转型（高利润低产量↔低利润高产量）、价值获取转型（改变赚钱方式牵动全局）、增长引擎转型（病毒式/黏着式/付费式之间切换）、渠道转型（同一方案经不同渠道更高效）、技术转型（不同技术实现同一方案）。每种转型都是一个新的战略假设，需用新的 MVP 来验证——"有转型的能力却无法代替成熟的战略思考"。
6. **转型需要勇气，拖延转型的三大原因**：①虚荣指数让人形成错误结论，意识不到转变的必要；②没有清晰的前提假设就不可能经历"完整的失败"，而完整的失败才产生根本转型的冲劲——失败是认知的先决条件；③恐惧——创业者更怕愿景未经自我证实就被判错，这种恐惧反而抬高风险，等到资金将尽再转型为时已晚。决定过转型的创业者几乎都希望当初更早转型。
7. **跑道 = 剩余的转型次数，而非剩余的时间**：传统算法（银行现金÷月烧钱速度）会诱导不加选择地压缩开支，可能连反馈循环的成本一起砍掉，结果只是"让企业慢点儿关门"。加长跑道的正道是加速每次转型——以更小的成本或更短时间完成同等数量的经证实的认知。

## A1 — 书中的应用 (Past Application)

### 案例 1: Votizen 的四次转型（ch08，主线案例）
- **问题**: 比内蒂创办 Votizen 验证"有投票权的公民能影响政治"的假设：先花 1200 美元 3 个月做出第一版，8 个月只花了 2 万美元却拿不到交易——意向书上的企业"并不是早期使用者"；注册者中只有 5% 确认曾投票。
- **方法论的使用**: 通过四次转型逐层换假设：转向"放大式"聚焦投票公民、再做客户细分转型（5%→17%）、平台转型（激活 90%+）、最终落到"公民游说"产品——注册率、保留率、推荐率逐轮验证，MVP 周期从 8 个月压缩到 4→3→1 个月。
- **结论**: 转型不是推倒重来，而是带着已学到的东西换下一个基础假设；每次转型都是一个待验证的新战略假设。
- **结果**: 产品最终获得 51%/92%/28%/64% 的关键转化验证，赢得泰尔 150 万美元投资，推动 47 个州 94% 人口覆盖并促成 S.565 创新签证法案。

### 案例 2: 财富前沿的转型会议实操（ch08）
- **问题**: 金融社交平台财富前沿（kaChing）45 万玩家中仅 7 位够格成为真实资金管理者——数据很难看，团队容易陷入"要不要继续"的反复拉扯。
- **方法论的使用**: 常规转型会议机制落地：在 CEO 约翰·鲍尔斯的访谈中可见，两团队带着一段时期的优化效果对比与顾客交谈记录到会上裁决方向；公司此后在 SEC 监管下仍保持每天十几个版本的迭代节奏。
- **结论**: 把"转型还是坚持"排进日历、规定输入材料，让紧张的方向之争变成有节奏的例行裁决，而不是情绪化的临场拍板。
- **结果**: 公司以 1.8 亿美元估值融资，40 多位管理者上线真实资金管理。

### 案例 3: IMVU 的首次战略转型（ch03/引言）
- **问题**: 作者的 IMVU 按"三维即时通信"战略开发，产品"糟糕透顶、漏洞百出"，顾客拒绝邀请好友（17 岁女孩直言没听说过），而团队曾以"零的愚勇"推迟数据收集。
- **方法论的使用**: 直面完整失败，放弃原战略核心假设，转向"虚拟人像聊天"——重新利用已开发的技术与已学到的行为数据，而非从零开始；转型后用量化目标激发定性调查逐项验证新假设。
- **结论**: 转型不必羞耻，也不必归零：错的方向上积累的认知是下次转型的资产；越早承认失败，跑道上剩下的机会越多。
- **结果**: 转型后 IMVU 取得巨大成功——6000 多万虚拟人像、2011 年年收入逾 5000 万美元（引言语境：引言）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 数据都拿到了，但结果不好不坏——既没增长到可以庆祝，也没糟到必须关门，不知道该换方向还是咬牙坚持。
2. 投资人/老板问"跑道还剩多久"，团队按现金除以烧钱速度回答，想知道这种算法错在哪、还能搏几次。
3. 该开转型会议了：节奏怎么定、会上要看什么材料、看完之后从哪十种方向里选转型路线。

### 语言信号 (用户的话里出现这些就应激活)

- "转型还是坚持""该不该换方向""要不要 all in""进退维谷""再撑撑还是砍掉"
- "跑道""还能烧几个月""还剩几次机会""转型会议""该多久开一次"
- "放大式/缩小式/客户细分/客户需求/平台/商业架构/价值获取/增长引擎/渠道/技术转型""换个客群还是换个需求""十种转型"
- "舍不得推倒重来""怕被判错""不知道现在放弃算不算失败"

### 与相邻 skill 的区分

- 与 `innovation-accounting` 的区别：后者管决策**之前**的核算体系（基准线→调整引擎→转型或坚持三步框架）；本 skill 管三步走完后的**裁决本身**。问"怎么建体系/怎么证明进展"归前者，问"该不该转、往哪转"归本 skill。
- 与 `actionable-vs-vanity-metrics` 的区别：后者管指标真假与图表技法（同期群、对比测试）；本 skill 拿着已判定的真数据做方向决定。若用户还在纠结"数据可不可信"→转后者。
- 与 `bml-validated-learning` 的区别：一次假设被推翻、回到循环继续学下一圈，是循环的**常规运转**；只有当核心战略假设整体动摇、面临"换产品/换客群/换引擎"的方向抉择时才是本 skill。菜单原文："一次假设失败后回到循环继续学→bml-validated-learning。本 skill 只负责'方向抉择'本身。"
- 与 `growth-engine-selection` 的区别：三引擎怎么选、LTV/CPA 怎么算、引擎停滞怎么诊断归后者；但"引擎熄火之后要不要整个换方向"归本 skill。增长引擎转型（十种之一）的裁决在本 skill，引擎的日常运营在后者的地盘。

## E — 可执行步骤 (Execution)

1. **把转型裁决制度化：设常规会议**
   - 定下会议节奏（数月太少、几周太频，按业务节奏自定），产品开发与业务领导两团队必须共同参加；先入之见重时引入外部顾问。
   - 完成标准：会议已排进日历并有固定节奏；参会名单包含两团队负责人；下次会议日期已确定。
2. **备齐两类会议输入**
   - 开发团队：一段时期内（而非刚刚过去的窗口）的产品优化效果与预期对比；业务团队：与现有及潜在顾客交谈的详细记录。
   - 完成标准：两份材料到会齐备；缺任一份则会议延期补料，不得凭印象拍板。
3. **对照前提假设判定现状，直面完整失败**
   - 逐条核对本阶段每个基础假设的量化预测是否落空；警惕虚荣指数给出的错误结论，确认自己"经历了完整的失败"而非回避它。
   - 完成标准：能说出"假设 X 的预测是 A，实际数据是 B"；若仍有假设未经真实顾客数据检验，先转验证流程而非开会裁决。
4. **若决定转型：从十种类型中选定转型类型并表述为新战略假设**
   - 优先重新利用已开发和已学到的东西；把所选转型（放大/缩小/客户细分/客户需求/平台/商业架构/价值获取/增长引擎/渠道/技术）写成一句可证伪的新战略假设，并规划验证它的新 MVP。
   - 完成标准：一句话新假设陈述（指明若真/若假各意味着什么）+ 下一个 MVP 的验证计划已立项。
5. **用跑道校验决策节奏，加速下一次转型**
   - 以"剩余转型次数"而非"剩余现金月数"评估处境；砍开支时不得砍掉反馈循环本身的成本；为下一次转型预留并压缩其成本与时间。
   - 完成标准：写出当前估计的剩余转型次数；列出下一轮转型中拟压缩的一处成本/时间，并落实为具体行动。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户还在生产决策所需的数据（建基准线、搭指标、设计实验）——转 `innovation-accounting` / `actionable-vs-vanity-metrics` / `mvp-design-patterns`。
- 单次实验失败、核心战略未动摇——回到循环继续学，转 `bml-validated-learning`；增长引擎的日常运营与判据归 `growth-engine-selection`。
- 风险与不确定程度已知、仅靠执行即可推断成败的常规生意——"转型还是坚持"裁决的前提（极端不确定）不存在。

### 作者在书中警告的失败模式（按家族速查）

- **e09 IMVU 引擎熄火、错失客户细分转型（F4）**：早期 IMVU "开始被虚荣指标蒙蔽了……业务引擎随之熄火"——月收入 100 多万美元的总量假象让人"别和成功过不去"，推迟了本应更早的客户细分转型。
- **e08 Grockit 被虚荣指标操控（F4）**：虚荣指数让人形成错误结论（拖延转型第一因）——数字好看时没人相信需要转型，这正是" 注册率、激活率及后续的保留率均相同……纯属浪费"揭露的自欺。
- **e10 Votizen 意向书不等于交易（F4）**：把过早乐观信号（意向书）当已验证需求继续扩投——在错误坚持的路上多走了 8 个月，本是转型会议该拦截的决策。
- **e06 把"学习"当借口（F3）**："你无法把学习拿去银行"——没有清晰前提假设，"我们还在学习"就成了无限期回避转型裁决的说辞，永远无法经历完整失败。
- **e05 分析瘫痪症（F2）**：无休止分析而不裁决——转型会议若无固定节奏与规定输入，会退化成又一轮分析瘫痪，同样消耗跑道。

### 作者的盲点 / 时代局限

- 十种转型类型学是 2011 年对彼时互联网软件业的归纳；对硬件、强监管、长交付周期行业，转型单次的成本与周期远高于书中案例，"几周太频、数月太少"的会议节奏需按行业重定。
- 案例多为获得风险投资的软件新创企业，"跑道=剩余转型次数"隐含"还有外部资本补给"的场景；资源枯竭型创业（自我雇佣、民生小生意）的转型余地更窄，需结合现实约束打折使用。
- 书中承认"转型的能力无法代替成熟的战略思考"——本 skill 是裁决流程，不产出原创战略洞见。

### 容易混淆的邻近方法论

- **"产品/市场契合"（马克·安德森概念）**：莱斯在第10章用增长引擎指标将其量化重述（病毒系数 0.9 等）；"没到 PMF 就转"是粗糙口号，本书要求先经创新核算判定哪些假设落空，再选转型类型——诊断归 `actionable-vs-vanity-metrics`/`growth-engine-selection`，裁决才归本 skill。
- **蓝海战略/常规战略规划**：战略规划产出方向假设，但不处理"假设已被数据推翻后怎么办"的裁决；本 skill 恰是计划失败后的那台机器，且转型本身必须回到 MVP 验证，不靠重新规划一轮纸面战略。
- **"快速失败"口号（fail fast）**：流行语只鼓励放弃；本书要求转型是"有条理的方向性改变"——带着已验证认知换假设，且以剩余转型次数（而非情绪或勇气口号）管理放弃的成本。
