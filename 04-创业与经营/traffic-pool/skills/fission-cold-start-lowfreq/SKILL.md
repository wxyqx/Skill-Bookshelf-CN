# 存量找增量与低频高频化（裂变冷启动）

## R — 原文 (Reading)

> "在本章的结束，我想最后总结一下裂变的核心要义，就是经常讲到的'存量找增量，高频带高频'。"
>
> 同章结论口号："没有绝对低频的产品，没有不可裂变的营销。"
>
> — 杨飞，《流量池》第5章"存量找增量，高频带高频"

---

## I — 方法论骨架 (Interpretation)

1. 裂变不是无中生有：它靠老用户的关系链带新用户，因此有一个先有鸡还是先有蛋的问题——第一批老用户从哪来？作者的答案很直接：第一批种子用户不可能靠裂变本身解决，只能靠广告投放、产品试用和前期推广获得。
2. 存量基数决定裂变量上限：老用户的盘子越大，可被撬动的分享次数才越多。所以增长预算的正确结构是"两手抓"——一手投放拉新扩存量，一手老客裂变拉低整体获客成本；只做裂变是空转，只做投放是纯买量。
3. 频次决定裂变难度：高频产品（出行、外卖、咖啡、社交）给小额福利即可大量裂变；低频产品（房产、汽车、保险）不能直接套用。
4. 低频产品有两条确定性改造路径：①把低频业务转成中高频的福利载体（物业 App 缴费抽奖、绑微信刷卡提醒+抽奖、场景化微量赠险）；②做强福利转介绍（房产成交按点数付转介绍费，用大额利益对冲低频）。
5. 判断顺序是硬约束：先问"有没有存量"，再问"频次能不能转换"，最后才轮到谈奖励额度与具体玩法——顺序颠倒，任何方案都是空转。

## A1 — 书中的应用 (Past Application)

### 案例 1: luckin coffee 拉新赠杯（营销第一仗）
- **问题**: 2018 年初瑞幸冷启动，CEO 问最重要的获客方式是什么，App 下载是第一步。
- **方法论的使用**: 作者答"裂变拉新"——咖啡是典型社交饮品；但顺序上先靠分众投放、门店与微信朋友圈 LBS 定投获得第一批存量与种子，再把大部分广告费变成用户补贴，上线"拉新赠杯"老带新，而非裸做裂变。
- **结论**: 冷启动=先有存量底盘，再上裂变放大；"将广告费奖励给用户"在新品牌身上成立。
- **结果**: 2018 年 1 月 5 日上线当天新增注册环比翻番、订单环比增长 40%，获客成本大幅低于此前精准的微信 LBS 商圈定投。

### 案例 2: 神州专车"邀请有礼"App 拉新
- **问题**: App 长期拉新依赖买量，成本居高不下。
- **方法论的使用**: 在存量用户规模化之后，设双边后付奖励的邀请机制（老用户邀新注册并首乘，双方各得专车券，多邀多得），用存量基数持续放大裂变量。
- **结论**: 机制毫无创意成分、属纯技术驱动的基础裂变，但存量足够大时它最持久有效——印证"存量找增量"。
- **结果**: 神州专车至少 70% 的新增用户来自该玩法，同时为品牌带来朋友圈长期露出。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？

1. 增长规划会上的冷启动之问："我们新品牌第一批种子用户从哪里来？能不能靠裂变直接解决从 0 到 1？"
2. 低频行业自我设限："我们是卖房/卖车/卖保险的，用户几个月甚至几年才成交一次，老带新根本没人参与，怎么办？"
3. 佣金与奖励额度决策前："老带新佣金给多少才合理？"——需要先过顺序与可行性，再谈数字。
4. 预算分配争论："钱是全投信息流拉新，还是拿一半出来做老带新奖励？"

### 与相邻 skill 的区分

- 与 `fission-playbook-design` 的区别: CL10 管具体活动怎么设计——选哪种玩法、三要素齐不齐、合规过不过；本 skill 管启动顺序与产品频次适配——"能不能裂、先得有什么才能裂"。问"哪种玩法/帮我检查方案"→ CL10；问"做不了裂变/第一批用户哪来"→ 本 skill。
- 与 `social-fission-principle` 的区别: CL09 管为什么裂变有效、奖励与成本结构怎么设计（后付奖励成本公式的原理层）；本 skill 管冷启动悖论与低频改造路径（可行性层）。
- 与 `wechat-service-superapp` 的区别: 裂变拉来用户之后的留存与提频归 CL12；本 skill 只管拉新端的启动判断。

## E — 可执行步骤 (Execution)

1. **盘存量**
   - 完成标准: 数清当前活跃老用户基数与可触达渠道（App/微信/门店/CRM），写出"存量规模 vs 预期裂变量级"的判断结论。
   - 判停条件: 若存量≈0（新品牌/新产品），明确判停——裂变 KPI 暂缓，先回到投放/试用/地推获得第一批种子；此时任何"裂变拉新"指标都是无效承诺。

2. **测频次**
   - 完成标准: 给出产品频次定性。高频→小福利即可裂变，转 `fission-playbook-design` 进入玩法设计；低频→在两条路径中选定其一：福利载体高频化（缴费/提醒/签到/赠险/订阅类权益）或强福利转介绍（成交阶梯佣金、大额转介费）。

3. **定预算结构（两手抓）**
   - 完成标准: 预算表里同时存在两条线——投放拉新扩存量、老客裂变降均价；裂变奖励全部后置到注册/成交等关键行为之后发放，并核算"投放获客成本+裂变奖励成本"的总账而非只看裂变账。

4. **设检验与退坡观察**
   - 完成标准: 建立"存量→分享率→新增"链路基线，约定复盘时间点；观察补贴退坡后裂变量是否萎缩，把衰减速度写进结论——它决定这套机制的可持续性。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 没有任何存量却想靠裂变完成从 0 到 1——裂变解决不了冷启动，这是本方法论自己承认的边界。
- 把裂变当"免费增长"、预算里不留投放线——违背两手抓结构，必然空转。
- 用超高频大额福利砸分享但产品本身无留存——那是买一次性羊毛，不是裂变资产。

### 作者在书中警告的失败模式

- 同质化审美疲劳（反例 x21）: 裂变红包成标配后各家互相模仿、福利逐期缩水（团购券从几元降到几分），用户审美疲劳、越来越不愿分享，机制失灵。低频转福利载体时若福利持续缩水，死法相同——规则须按投入产出比持续升级。
- 裂变变味破坏关系链（第5章开篇警告）: 大量裂变不讲原则和方法，"已经严重变味，甚至破坏了社交朋友圈"——无差别狂发利诱海报杀的是自己的关系链渠道。

### 作者的盲点 / 时代局限

- 冷启动外部化: 作者承认第一批用户只能靠广告投放获得——"最低成本获客"的宣称把最大一块成本移出了账本，存在循环论证；评估可行性时必须把投放成本计入总账。
- 可持续性未展开: 补贴驱动分享对社交信任的透支、羊毛党、留存质量与补贴退坡书中均未讨论；"1 个老用户找来 5 个新用户"的 K 因子没有数值测算路径。
- 案例口径单方自报: "70% 新增来自邀请有礼"无第三方验证；作者深度参与的瑞幸 2019-2020 年财务造假事件提示——补贴式裂变的打法有效性与资本可持续是两回事，需批判看待。

### 容易混淆的邻近方法论

- 增长黑客 AARRR 的 refer 环: 同源（作者转引），本书增量是"冷启动悖论+频次转换路径"这一层诚实设限；AARRR 其余环节不在本 skill。
- 分销裂变合规（层级/话术/防刷）: 相邻但归 `fission-playbook-design`。
- 私域流量运营: 本书是"存量找增量"话语的源头表述之一，但私域的日常承载与运营归 `wechat-service-superapp`。
- **时效警示（内嵌）**: 本书为 2018 年快照——书中裂变玩法大半已被微信后续规则封杀（砍价 H5、打卡返现、集卡等），物业 App/绑卡抽奖/赠险等路径的参数与合规口径均已变动；本 skill 只保留"存量→频次→路径"的判断逻辑层，一切玩法与奖励参数须按当期平台规则重查。
