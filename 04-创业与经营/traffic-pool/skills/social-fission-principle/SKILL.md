# 社交关系链与裂变双原则

## R — 原文 (Reading)

> "移动互联网时代最贵的是什么？是流量吗？是，也不是。流量只是结果，移动互联网时代最贵的是用户关系和关系链。"
>
> — 杨飞，《流量池》第4章"社交流量：移动互联网上最重要的免费流量"

---

## I — 方法论骨架 (Interpretation)

1. 底层判断: 流量只是结果，真正稀缺的是用户关系和关系链。腾讯稳坐巨头靠的不是工具而是微信 QQ 绑定的关系链——"你可以轻易离开一个书店，却很难离开一个朋友圈"。谁绑定关系链，谁就拥有最低成本、自带信任背书的流量来源。
2. 由此推出立场: 裂变（老用户带新用户）不是可选的营销活动，而是移动产品的标配——"如果 App 或微信中没有裂变营销，那是不可接受的"。
3. 裂变双原则: 一是强调分享（新用户必须经由老用户的分享行为带来，而不是广告砸出来的）；二是后付奖励（用户完成注册或关键行为之后才兑现奖励，而不是先发钱）。
4. 成本公式: 广告成本 = 老用户拉新奖励 + 新用户注册奖励。把原本事前一次性预付给媒体的广告费，拆成双边奖励、事后付给用户——获客支出从"100% 预付、结果不确定"变成"按效果事后支付"，且新流量自带社交信任背书，转化率与留存率高于陌生渠道。
5. 这个 skill 回答的是原理层三问: 要不要做裂变？预算在买量与裂变之间怎么倾斜？奖励结构（给谁、何时给、给多少）怎么定？具体选哪种玩法、活动怎么上线，是另一个 skill 的事。

## A1 — 书中的应用 (Past Application)

### 案例 1: 神州专车"邀请有礼"
- **问题**: App 拉新要持续降低获客成本，不能永远靠外部投放。
- **方法论的使用**: 长期设置"邀请有礼"——老用户邀好友注册并首乘后，双方得券、多邀多得。机制毫无创意成分，纯技术驱动，但严格遵守双原则: 分享驱动 + 行为后付。
- **结论**: 见效最快的仍是拉新奖励这种基础玩法；双边后付奖励把广告的不确定性降到最低。
- **结果**: 神州专车至少 70% 的新增用户来自该玩法，同时为品牌带来朋友圈的长期免费露出。

### 案例 2: luckin coffee 拉新赠杯（营销第一仗）
- **问题**: 新品牌冷启动，CEO 问最重要的获客方式是什么。
- **方法论的使用**: 作者的回答是"裂变拉新"——咖啡是典型社交饮品，把大部分广告费变成用户补贴、激发老用户分享拉新。2018 年 1 月上线"拉新赠杯": 老用户分享得咖啡、新用户注册首杯免费，奖励在注册/购买行为后兑现。
- **结果**: 上线当天新增注册环比翻番、订单环比增长 40%；获客成本大幅低于此前精准的微信 LBS 商圈定投（一周后 CPS 仅低于用户裂变本身）。

### 案例 3: 拼多多"社交+电商"拼团
- **问题**: 电商新玩家没有流量优势，如何低成本获客并自带转化。
- **方法论的使用**: C2B 拼团把"低价福利"与"关系链"焊死——主动用户被福利刺激后付款开团并分享，被动用户被"便宜、有用"驱动参团并再次分享，每个用户都是流量中心，参团用户自带强购买意向。
- **结果**: 上线未满一年单日成交额突破 1000 万元、付费用户突破 2000 万，成为"一切产品皆可裂变"的电商样板。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？

1. 公司讨论要不要上"老带新"，反对理由是"羊毛党、打扰用户"，需要判断依据与风险边界。
2. CAC（获客成本）太高，想找结构性降本办法，不确定裂变是不是答案。
3. 设计推荐奖励时纠结"先给还是后给、给推荐人还是被推荐人、给多少"——成本结构问题。
4. 预算分配之争: 同样一笔钱，投信息流买量还是变成用户补贴激励分享。
5. 管理层问"为什么别人裂变能做起来、我们做不起来"，需要原理层认知校准。

### 语言信号 (用户的话里出现这些就应激活)

- "要不要做裂变/老带新/推荐奖励""值不值得做"
- "裂变为什么便宜""便宜在哪""获客成本怎么降"
- "奖励先发还是后发""给谁、给多少""后付"
- "买量还是做裂变""referral program""post-paid reward""fission principle"

### 与相邻 skill 的区分

- 与 `fission-playbook-design` 的区别: CL10 是"选哪种玩法 + 三要素检查 + 合规上线"的手册（执行层）；本 skill 是"该不该做、奖励与成本结构怎么定"的原理（决策层）。用户在讨论方案细节（海报、砍价、拼团、分销层级）时走 CL10。
- 与 `fission-cold-start-lowfreq` 的区别: "第一批种子用户从哪来""我们产品低频能不能裂变"是可行性与启动顺序问题，归 CL11；本 skill 假设有存量用户，只回答原理与结构。
- 与 `wechat-service-superapp` 的区别: 裂变挂在微信上时，服务号/小程序载体怎么建、怎么运营归 CL12。
- 与 `pinxiao-heyi-marketing` 的区别: CL02 是营销总纲（一切传播要导向转化）；本 skill 是其中获客方法之一的原理深化。

## E — 可执行步骤 (Execution)

1. **关系链资产盘点**
   - 完成标准: 写出产品当前的用户关系触点（App 内分享、微信关系、社群、会员体系）与"用户离开成本"评估；列出现有活跃用户基数——存量决定裂变量上限。
   - 判停条件: 若第一批种子用户尚无（活跃用户仅数百以下），判停——先解决冷启动（逻辑归 `fission-cold-start-lowfreq`），本 skill 的奖励设计暂缓。

2. **成本公式套算**
   - 完成标准: 用"广告成本 = 老用户拉新奖励 + 新用户注册奖励"，把当前买量 CAC（或目标 CAC）拆成双边奖励的预算上限；核对方案满足: 双边奖励总额 ≤ 单个获客成本，否则调低奖励或改奖励形态。

3. **双原则合规设计**
   - 完成标准: 方案明确两条——分享行为驱动（奖励与分享/拉新动作绑定，不是无门槛发钱）、后付兑现（新用户完成注册/首单等关键行为后才发奖）；写明奖励形式（券/现金/权益）与兑现时点。

4. **决策输出**
   - 完成标准: 给出"做 / 不做 / 先补存量"三选一结论及理由；若做，输出奖励结构表，与买量方案并列对比测算 CAC，供决策会直接选用。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户只是想"做个分享有奖的活动"——具体玩法选型与上线检查归 `fission-playbook-design`。
- 产品低频（房产/汽车/保险/婚庆）纠结"能不能裂变"——可行性判断归 `fission-cold-start-lowfreq`。
- 目标是留存提频而非拉新——留存程序不在本 skill 范围。
- B2B 无 C 端关系链的场景直接套双边现金奖励——原理可参考（信任背书、后付逻辑），奖励形态须改造为权益型。

### 作者在书中警告的失败模式

- 裂变变味（反例 x22）: "有大量裂变形式并不讲原则和方法，已经严重变味，甚至破坏了社交朋友圈"——无差别狂发利诱海报透支社交信任，杀的是自己的关系链渠道；奖励必须服务于分享心理（谈资、个人形象），而非单纯利益砸脸。

### 作者的盲点 / 时代局限

- 补贴可持续性零讨论: 书中对补贴退坡、羊毛党、社交信任透支的长期风险未展开；"1 个老用户找来 5 个新用户"的 K 因子无数值测算路径，奖励额度需自行建模验证。
- 冷启动外部化: "最低成本获客"的宣称把最大一块成本（第一批用户靠投放获得）移出了账本，存在循环论证。
- 追溯性风险: 作者以"流量池+补贴裂变"打法深度参与瑞幸前期创建，2019-2020 瑞幸财务造假事件提示——打法有效性与资本操作是两回事，补贴式裂变的财务可持续性需批判看待。
- **时效警示**: 本书为 2018 年快照。具体奖励形态（专车券、赠杯）与微信生态参数已变；"双边后付"的成本判断逻辑层保留，奖励的合规口径（诱导分享红线、分销层级、资金监管）须按当期平台规则重查。

### 容易混淆的邻近方法论

- 西方增长圈常规的 referral cashback: 本方法论的特殊处是"把广告预算结构性转移给用户"的会计逻辑与关系链护城河论证，不只是发返利。
- 传销式分销: 双边后付奖励 ≠ 多层级人头返利；分销层级红线属玩法合规，归 `fission-playbook-design` 检查。
- 积分/忠诚度体系: 那是留存运营工具，目标是复购；裂变的目标是拉新，两者指标与结构不同。
