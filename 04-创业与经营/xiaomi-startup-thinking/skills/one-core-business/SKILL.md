# 一元核心律（"+"改"×"的业务过筛）

## R — 原文 (Reading)

> 把加号改成乘号，是首先突出核心业务，同时强调不再是“简单相加”，而是乘数效应。所以，公司的核心业务和核心方向、核心目标一定是一元的，不存在二元甚至多元的可能。
>
> — 雷军，《小米创业思考》第六章 互联网七字诀·专注

---

## I — 方法论骨架 (Interpretation)

这门方法论断言：**核心业务只能有一个，不存在"二元核心"**。检验工具出奇地简单——看战略表述里的连接词。"A+B"式的并列结构意味着两件事都重要、各自有独立增长指标，业务间失去主从检验，是失焦的第一个信号；正确写法是"A×B"：明确唯一核心，其他业务的职责是放大核心（乘数），其价值以"对核心的放大倍数"计量，而不是自身 GMV。

判断连接词改法之后，用**业务三问**对存量业务定期过筛：①对核心战略贡献了什么价值？②是否带动其他业务持续连带增长（不是"不拖后腿"，是要有乘数贡献）？③消耗了哪些资源？三问答不好的业务就是"容易实现的低质量增长"——成交金额在涨但公司体质没变强，只是虚胖，应列入收缩或重构候选。

背后的机制：战略表述即指挥棒。加号结构下每个业务群自然追求自己的用户数、连接数、GMV，资源被摊薄到无协同的品类上；乘号结构强制每项业务回答"你如何放大核心"，回答不了就不该获得资源。配套动作是把三问写进经营复盘周期（与 OKR 对表），而不是一次性战略讨论。

## A1 — 书中的应用 (Past Application)

### 案例 1: "手机+AIoT"改"手机×AIoT"
- **问题**: 小米战略曾是"手机+AIoT"二元并列，执行中 AIoT 业务群倾向独立的用户数、连接数与 GMV 提升，迷失了两者共同构成的"智能生活"体验核心。
- **方法论的使用**: 十周年反思中把加号改成乘号（2020 年 8 月），明确智能手机是唯一核心，其他业务围绕手机展开；用连接词重构强制每条业务回答对核心的放大关系。
- **结论**: 核心必须一元，扩张是围绕一元核心展开增长飞轮的不同阶段，而非并列堆业务。
- **结果**: 乘法战略成为后续品类治理（砍 799 元非智能洗衣机式凑数产品）的裁判基准。

### 案例 2: 业务三问筛"虚胖增长"
- **问题**: 规模增长期，容易实现的增长未必是高质量的增长——"成交金额增加未必是公司体质增强了，也可能是虚胖"（第六章原文）。
- **方法论的使用**: 对每条业务线周期性作答三问：对核心贡献什么、是否带动连带增长、消耗什么资源；生态链 1.0 后期 SKU 过冗、资源分散、效率下降，正是三问答不好的形态。
- **结论**: 把增长庆典转为增长审计，低质量增长列入收缩候选。
- **结果**: 生态链 2.0 以"手机×AIoT"为边界重新设立进入/退出标准、砍 SKU，效率回稳。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 起草或评审战略文档/使命表述，里面有"A+B+C 三驾马车/双引擎/多元布局"式并列结构。
2. 公司 GMV/营收高速增长，但有人质疑增长质量（靠补贴买量、SKU 铺货、与核心用户无交集）。
3. 业务线年度复盘：某条业务线连续亏或原地踏步，决定收缩、重构还是加码。
4. 资源分配争执：新业务和核心业务抢人抢钱，需要一个裁决框架。
5. 集团/生态多品牌治理：各子公司、各产品线 KPI 各自为战，需要统一到核心增长上。

### 语言信号 (用户的话里出现这些就应激活)

- "双引擎、三驾马车、多元化、第二曲线"（dual engine, core business, diversification, focus）
- "聚焦还是扩张、该不该砍业务、业务取舍"
- "战略表述、使命愿景怎么写、业务结构"
- "增长质量、虚胖、低质量增长、GMV 陷阱"
- "协同、连带增长、资源摊薄、各自为战"

### 与相邻 skill 的区分

- 与 `endgame-reasoning` 的区别：问题是"要不要做某个大额新业务"（向前看的决策三层推论）用后者；本题是对**现有业务组合**的聚焦结构审计（一元核心+三问过筛）。新业务立项通过后回到本题管它怎么挂到核心上。
- 与 `new-business-three-pits` 的区别：新业务已经决定做、问团队心态与执行风险用后者；本题是结构问题不是心态问题。
- 与 `downturn-remediation` 的区别：公司已经失速、要止血补课（四征兆诊断、质量一票否决）用后者；本题适用于还没失速时的日常聚焦纪律——失焦四征兆里"KPI 偏离集团目标"正是本题要防的早期状态。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **连接词诊断**
   - 把用户的战略表述原样抄出，找出所有并列连接（A+B+C）；对每个加号问"这两件事谁是核心、谁放大谁"。
   - 完成标准：列出全部加号位置及其对应的业务对；无加号则确认现有表述已是一元结构。
   - 判停条件：用户只有一条业务线、无多元取舍问题 → 直接确认聚焦健康，结束。

2. **确定唯一核心**
   - 与用户一起验证哪个业务是核心（判据：对使命的贡献、资源与营收主体、用户关系主载体）；核心只能选一个。
   - 完成标准：写出一句话"X 是唯一核心，其余业务均为 X 的乘数"；出现两个核心候选争执时，明确提示"不存在二元核心"要求做出选择。

3. **改写为乘数结构并重排 KPI**
   - 把表述改成 A×B(×C)，为每个乘数业务定义"放大核心"的指标（如生态业务的 KPI 挂手机核心的活跃/复购而非自身 GMV）。
   - 完成标准：新表述+每条业务的乘数指标清单；原各自独立的 GMV 类指标被降级或删除。

4. **业务三问过筛存量**
   - 对每条存量业务逐条作答：对核心贡献了什么？是否带动连带增长？消耗了什么资源？
   - 完成标准：每条业务有三问答案与"健康/虚胖"判定；答不好的列入收缩/重构候选清单并说明处置建议。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户在论证"要不要进入一个全新的大额业务"（造车式决策）——那是向前看的三层推论，用 `endgame-reasoning`；用"不聚焦"直接否决新业务会误用本方法论（小米恰恰以一元核心为前提做了造车决策）。
- 纯组织架构调整（汇报线、编制）——乘号结构是战略与 KPI 层的设计，直接推导组织图会越权。
- 单产品的功能取舍——那是 `hit-product-system` 的 80/80 范畴，业务一元化不等于产品功能极简。

### 作者在书中警告的失败模式

- **加号结构的执行失焦**（第六章反例）：并列"二元核心"使 AIoT 业务群追逐独立用户数/连接数/GMV，产出 799 元非智能洗衣机这类对核心体验无增益的凑数产品，拖累品牌。
- **容易实现的低质量增长**（第六章）：增长靠资源不合理消耗，"成交金额增加未必是体质增强，也可能是虚胖"；流量渴求压倒真实用户增长即是规模不经济陷阱（第十四章）。
- **无边界即无专注**（第十二章）：生态扩张不设进入/退出边界，SKU 过冗摊薄定义、渠道与营销资源，"杂货铺"认知反噬品牌。

### 作者的盲点 / 时代局限

- **幸存者叙事**：加号改乘号的正确性由小米后来的回稳反推；二元结构阶段的具体损失量化、以及若不改乘号是否真会更差的反事实，书中未论证。
- **进行时假设**："手机×AIoT"于 2020 年 8 月提出，书写于 2022，乘法战略能否持续兑现属未完成验证的进行时判断；且该框架由一家有绝对主导硬件核心的公司提出，对核心本身仍在漂移的公司适配性未讨论。
- **一元化的代价未被充分讨论**：书中把"多元化失焦"作为主要风险，但对"过度聚焦错过结构性机会"（专注纪律下放掉的窗口）缺少对称分析。
- **价值宣示色彩**："不存在二元核心"是立场性断言而非实证结论；现实中双主业公司（如同时成功经营两条互不放大业务线）的反例未被处理。

### 容易混淆的邻近方法论

- 波士顿矩阵/业务组合管理：BCG 按增长率-份额给业务分类，业务三问按"对核心的乘数贡献"过筛——裁判标准不同，前者无"唯一核心"前提。
- 飞轮效应（亚马逊式）：都谈业务间互相放大，但本书强调先裁定唯一核心再谈飞轮，防止"人人都是飞轮的一环、没人对核心负责"。
