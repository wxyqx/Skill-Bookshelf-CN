# 外部触发四分类（付费/回馈/人际/自主）

## R — 原文 (Reading)

> "付费型触发、回馈型触发以及人际型触发都是以争取新用户为主要目标，而自主型触发以驱动用户重复某种行为作为重点，目的是让用户逐渐形成习惯。如若没有自主型触发，不能在用户默许的前提下获得他们的关注，产品就很难以足够高的出现频率渗透进用户的使用习惯里。"
>
> — 第2章 外部触发的类别（L628）

> "付费型触发能够有效地拉拢用户，但是代价不菲。……靠花钱来拉拢回头客不是长久之计，企业往往只在争取新客户时才使出这一招。"
>
> — 第2章 外部触发的类别（L598–600）

> "由此出现的销量和点击量的飙升很容易使企业盲目乐观，认为这就算大功告成，实则不然。回馈型触发所引发的用户关注往往是昙花一现。"
>
> — 第2章 外部触发的类别（L604）

## I — 方法论骨架 (Interpretation)

所有藏在信息里、明确告知下一步行动的外部触发，按成本结构与生命周期分四类：付费型（广告，拉新快但代价高）、回馈型（媒体报道、应用商店推介，免费但要持续经营且来去如潮水）、人际型（熟人推荐，可病毒式扩散，根基是信任）、自主型（用户同意后持续出现的图标、推送、简报，唯一每天出现在用户生活中的类型）。

真正做设计的分界线不是四类本身，而是它们的**分工**：前三类管拉新，第四类管留存。广告买来的、媒体带来的、朋友推荐的注意力都是一次性的；只有用户许可的自主型触发能以足够高的频率反复出现，把行为喂成习惯。所以资源分配问题从"哪种渠道便宜"变成"哪类触发服务哪段旅程"——拉新预算花在前三类，但要尽早拿到自主型许可（安装、订阅、授权通知），否则拉来的新用户没有回访通道，一切归零。

四类还是一组体检指标：停投即流失（付费依赖）、无媒体即归零（回馈幻觉）、邀请被朋友嫌弃（人际透支）、首屏无入口（自主缺失）——各对应一种结构性缺陷。

## A1 — 书中的应用 (Past Application)

### 案例 1: 英与 Instagram——四类触发的接力链
- **问题**: Instagram 如何从无人知晓走到每天吸引上万新用户，并让用户最终摆脱外部触发？
- **方法论的使用**: 作者拆解英的完整触发链：朋友的图片分享（人际型，L730–735）→ 媒体、博客与应用商店特色推荐（回馈型，L735）→ 下载后手机屏幕上的应用图标与朋友圈更新（自主型，L736–737）→ 数周后内部触发接管。
- **结论**: 四类不是并列选项而是接力棒——前三类完成"第一次拉进去"，自主型完成"喂成固定用户"。
- **结果**: Instagram 用户达 1.5 亿、以 10 亿美元被 Facebook 收购（c03 记录）；作者用它示范"外部触发的终极目标是驱使用户进入上瘾模型完成余下循环"（L632）。

### 案例 2: 《圣经》应用的多层触发冗余
- **问题**: 读经计划如何保证用户每天不中断？
- **方法论的使用**: 格吕内瓦尔德团队叠加多种自主型触发：每日通知（L2069）→ 未打开则图标红徽章提醒（L2071）→ 忘读则建议换低难度计划并可改用电子邮件接收经文（L2071）→ 社区成员互相发信息鼓励，"社区邮件也能作为一个小触发"（L2073）。
- **结论**: 自主型触发不必是单点推送，可以做成多层冗余体系（通知/徽章/邮件/社区），层层兜住漏网的用户。
- **结果**: 触发"在所有读经计划中都发挥着十分重要的作用"（L2069），成为用户坚持读经的关键原因之一。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 冷启动资源分配：预算只够投放或只够做内容，或投放/裂变/公关怎么配比——按"哪类触发服务哪段旅程"而非"哪种便宜"来定。
2. 增长复盘诊断：停投次日留存就腰斩、媒体曝光一停流量归零、老带新招来越来越多人反感——对照四类的典型失败模式定位结构性缺陷。
3. 触达体系设计：规划推送、邮件、图标、社区通知等自主型触发的分工与冗余（哪些场景用哪层兜底）。
4. 渠道结构审查：增长模型里只有付费触发没有自主型许可通道（未引导授权通知/订阅），拉新越多漏得越多。
5. 跨域（组织/个人）：推广内部工具时区分"行政通知（类自主型但缺许可）"与"同事安利（人际型）"的触达结构；个人建立新习惯时自建提醒（日历、置顶、便签）本质是在给自己搭自主型触发。

### 语言信号 (用户的话里出现这些就应激活)

- "外部触发 / external trigger / 付费型/回馈型/人际型/自主型触发"（paid / earned / owned trigger，referential trigger）
- "投放还是内容 / 获客渠道 / 冷启动预算 / 拉新"（paid ads vs content, acquisition channel, cold start budget）
- "老带新 / 裂变 / 邀请机制 / 病毒式增长 / 转介绍"（referral, viral loop, invitation mechanism）
- "推送通知 / 召回 / 唤醒 / 打开率 / 停投就掉量"（push notification, re-engagement, win-back, churn after stopping ads）

### 与相邻 skill 的区分

- 与 `internal-trigger-anchoring` 的区别：f04 管外部（信息中的行动召唤，拉新 + 喂养期），f05 管内部（情绪→产品的绑定，习惯的终局）。规则是"外部触发的终局是被内部触发取代"——f04 铺入口，f05 装终点。
- 与 `load-next-trigger` 的区别：f16 的触发由用户自己的投入内生生成（个性化、时机对准情绪，如 Any.do 会后通知），f04 是产品方统一铺设的通用触发；前者是第 5 章投入阶段的闭环合页，后者是第 2 章的入口变量。
- 与 `hook-model-four-stages` 的区别：f01 是四阶段全景与出厂五问，f04 只细化第一阶段"触发"的入口结构；做全循环设计走 f01，单做触达体系走 f04。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **盘点并归类现有触达手段**
   - 完成标准: 列出产品全部触达手段，逐个贴上四类标签（付费/回馈/人际/自主），并标注各自服务的旅程段（拉新/留存）；无遗漏、无重复归类。

2. **查自主型缺口**
   - 完成标准: 明确回答——用户是否被引导授予持续触达许可（安装图标、推送授权、订阅、关注）？自主型触发清单及各自出现频率是否成体系？若自主型缺失或多层冗余不足，先补许可通道与兜底层级（参照圣经应用四层结构：通知→徽章→邮件→社区）。

3. **按旅程段配比拉新资源**
   - 完成标准: 对前三类写出分配方案及依据——付费型只用于购买第一批进入循环的用户（设 CAC 上限）；回馈型当脉冲不当饭吃（不按峰值配置资源）；人际型只在产品有真实价值时启用（设计透明的分享动机）。每个渠道配一个"转为自主型许可"的转化检查点。

4. **判停条件**
   - 停投即流失、回访高度依赖投放预算 → 问题不在投放而在内部触发未建立，转 `internal-trigger-anchoring` / `bmat-action-diagnosis` 诊断，停止加码投放。
   - 增长曲线与媒体事件完全同构、无媒体期留存断崖 → 判定回馈型幻觉，禁止按峰值扩张，先补自主型。

5. **伦理自检**
   - 完成标准: 人际型触发过黑暗模式三问（ce01 警示信号）：邀请流程对被邀请方透明吗？用户分享后会尴尬或道歉吗？增长是否依赖持续加大诱导力度？任一不过，重构邀请机制。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 行为没发生时的动因诊断：用户看了推送也不行动，问题可能在动机或能力（B=MAT），不是触发类型问题——先走 `bmat-action-diagnosis` 三归因，再回触发层。
- 把四分类当渠道效果排行：它不是 AARRR 式渠道分级，而是按"拉新 vs 留存"分工的结构变量；用 ROI 单维排序会丢掉分工信息。
- 用户已是深度习惯用户时还堆付费触发：习惯用户由内部触发驱动，对外部触发的边际需求是冗余与打扰。

### 作者在书中警告的失败模式

- 黑暗模式滥用人际型触发（ce01）：恶意引诱用户邀请朋友"一开始会带来一定的收益，但代价却是失去用户的信任与期望"（L616），被套路者愤怒离场，病毒循环变负循环。
- 回馈型触发的昙花一现（ce02）：媒体带来的流量高峰被误判为习惯形成、团队按峰值扩张，聚光灯移走即归零。
- 付费型触发的长期依赖（ce03）："假如 Facebook 或者 Twitter 要靠打广告来触发用户，那可能过不了多久就会资不抵债"（L598）——买曝光买不来情绪绑定，停投即流失。
- 一次性应用陷阱（ce14）：2010 年 26% 的下载应用只用一次——无自主型回访入口的应用，首屏位置会被高频应用挤掉。

### 作者的盲点 / 时代局限

- 2014 年 App 语境：自主型触发默认是"App 图标 + 推送 + 邮件简报"（L620–628）；算法推荐信息流接管了分发（回馈型被平台工业化）、超级 App 内嵌生态与小程序改变了"图标"形态、iOS ATT 等隐私新规收紧了付费型的数据弹药。套用前先对今日产品重新映射四类，别把"推送"当自主型的唯一形态。
- 设计者本位：四分类完全站在企业视角分配用户注意力，未讨论用户侧的触达治理（通知分级、免打扰默认）——今日落地应默认尊重用户关闭权限（L626–628 的前提正是"用户默许"）。
- 对低收入用户与付费型触发的收割面无着墨（BOOK_OVERVIEW 硅谷精英视角条）：付费型触发的成本转嫁与诱导结构在不同人群上的不对称，书中未讨论。

### 容易混淆的邻近方法论

- 推送策略/召回运营：推送只是自主型触发的一种，且是四分类中最浅的一层；把本 skill 用成"推送文案技巧"是用小了。
- AARRR 增长模型： Acquisition 只覆盖拉新段；四分类额外给出留存段的触发结构（自主型）与三类拉新触发的信任/成本差异。
- `load-next-trigger`（f16）：内生触发与外铺触发的区别见 A2；混用的典型错误是把群发推送当成"加载下一个触发"。

### 伦理红线

人际型触发的红线：**不用于黑暗模式**——不设计透支社交信任的诱导邀请，不为增长伪造"朋友动态"。自主型触发的红线：以"用户默许"为合法性前提（L626），不绕过系统权限做触达，不用误导性文案骗打开（假新闻式推送标题、伪装系统通知）；尊重用户关闭推送的选择，被关闭后不以骚扰性渠道补偿。任何触发设计不得绕过用户自主权，落地前过操纵矩阵（`manipulation-matrix`）两问。

## 相关 skills

本 skill 是触发链条的入口段：管"信息中的行动召唤"如何拉新与喂养，终局交棒给内部触发。

**depends-on**（使用前提）: 无。

**contrasts-with**（同境况二选一）:

- `load-next-trigger` — 同是"触发/召回"，生成机制相反：本 skill 是产品方统一铺设的通用外部触发（外生），f16 是用户自己的投入内生生成的个性化触发（内生，第 5 章闭环合页）。问"预算投哪类触发"用本 skill，问"让用户行为自己生成下次召回"用 f16；把群发推送当"加载下一个触发"是典型混用。

**composes-with**（配合使用/先后接力）:

- `internal-trigger-anchoring` — 接力链的下游：外部触发（尤其自主型）喂养数周，直到内部触发接管（"外部触发的终局是被内部触发取代"）；停投即流失说明接力失败，转 f05 诊断（E 段判停条件）。
- `bmat-action-diagnosis` — 行为没发生时先走 B=MAT 三归因（触发/能力/动机），确认问题确实在触发端再回本 skill 做四分类选型（B 段反场景的路由）。
