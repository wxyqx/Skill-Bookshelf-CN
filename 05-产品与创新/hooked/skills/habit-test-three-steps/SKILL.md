# 习惯测试三步：定义频率→5% 门槛→习惯路径→改产品

## R — 原文 (Reading)

> "通过我的研究以及与当今最成功的习惯养成类产品生产公司的企业家们的讨论，我对这一过程进行了提炼，并将其命名为'习惯测试'。该过程是受精益创业运动所提倡的'建造——评估——学习'方法启发而来。"
>
> — 第8章 习惯测试和寻找机会·习惯测试（L2161）

> "可是多少用户才算够呢？我的经验是 5%。……如果至少有 5% 的用户认为你产品的价值还不够大，他们对产品的使用频率没有达到你的预期，那你就麻烦了。要么是你对用户判断有误，要么是你的产品需要重新设计。"
>
> — 第8章 习惯测试（L2183–2185）

> "你要找到一条'习惯路径'，即你最忠实的用户共同具有的一系列相似行为。……Twitter 发现，只要新用户关注的其他用户人数达到 30，即可达到一个临界点，极大地增加他们今后继续使用网站的可能性。"
>
> — 第8章 习惯测试（L2187–2189）

---

## I — 方法论骨架 (Interpretation)

习惯测试把"用户为什么留下来"从玄学变成可证伪的数据程序，三个动作的顺序固定：先定义，再数人头，最后找路径。第一步定义忠实用户的使用频率"应该"是多少——这一步必须先于看数据，且不许拿专业用户当标准（社交产品设想每天多次，电影推荐每周不超过两次，因产品而异）。第二步数达标人头：活跃用户中至少 5% 达到你定义的频率，这是一个二元归因的硬门槛——不达标只有两种解释，用户判断错了，或产品要重做。第三步只从已达标的忠实用户行为流里反推共同序列（习惯路径），绝不接受设计者想象的"正途"，然后通过注册渠道更新、内容变更、功能增删，把新用户往该路径上导。程序随每次迭代重复——没有这套验证，上瘾模型四阶段只能是事后叙事。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: Twitter 的"关注 30 人"临界点
- **问题**: Twitter 早期如何知道该把新用户往哪导？
- **方法论的使用**: 按三步走——先确定习惯用户标准，再分析发现"新用户关注满 30 人"是留存可能性的临界点（即习惯路径），最后针对性改进注册流程、鼓励新用户即刻关注其他用户。
- **结论**: 习惯路径指出了"哪些行为对培养忠实用户至关重要"。
- **结果**: Twitter 从注册渠道更新入手改版加关注流程，成为书中习惯测试的标杆案例（L2189–2198）。

### 案例 2: 频率定义的两个示范（社交网络 vs 烂番茄）
- **问题**: 第一步"忠实用户频率"如何定义才不拍脑袋？
- **方法论的使用**: 作者给出对照示例：类 Twitter/Instagram 的社交产品应设想习惯用户每天多次访问；烂番茄式的电影推荐网站则不能指望用户每周访问超过两次——因为使用由观影事件触发。
- **结论**: 定义因产品而异，参照同类产品公开资料或符合实际的诚实假设，"不要只针对专业级用户做出过于激进的预测"。
- **结果**: 成为习惯测试第一步的操作规范（L2174）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 产品 DAU 不低，但被问"你的铁杆用户是谁、他们共同做了什么"时答不上来。
2. 留存分析做完只有曲线没有动作：不知道该改注册流程、改内容还是改功能。
3. 新产品上线前后判断"有没有习惯潜能"：5% 是可证伪的门槛，不是感觉。
4. 大改版/新功能上线后的复测：习惯用户的行为路径是否发生变化。

### 语言信号 (用户的话里出现这些就应激活)

- "习惯测试 / 习惯用户 / 忠实用户怎么定义"（habit test, habit users, define loyal/power users）
- "留存为什么上不去 / 习惯路径 / 关键行为 / aha 时刻"（retention benchmark, habit path, key behavior, aha moment）
- "百分之几才算健康 / 多少用户达标 / 频率基准"（what % counts as success, usage frequency benchmark）

### 与相邻 skill 的区分

- 与 `f01-hook-model-four-stages` 的区别：f01 是设计框架（四阶段怎么搭，含出厂五问），f20 是上线后的验证装置（搭完怎么测、怎么迭代）。问"产品该怎么设计"用 f01，问"做出来到底行不行"用 f20。
- 与 `f02-habit-zone-frequency-first` 的区别：f02 的频率是产品立项前的创意过滤器（该不该做这个产品），f20 的频率定义是上线后的测量基准（做成没做成）。同是"频率"，一个在设计之前，一个在数据之后。
- 与 `f22-four-opportunity-sources` 的区别：同在第 8 章，f20 面向现有产品验证，f22 面向新产品机会扫描。问"下一个做什么"用 f22，问"现在这个行不行"用 f20。
- 与通用留存/增长分析（留存曲线、漏斗）的区别：留存曲线回答"多少人留下了"，习惯测试回答"留下的人走的哪条路、没走的人差在哪一步"，产出物是可执行的习惯路径而非留存率本身。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定义忠实用户的频率**
   - 完成标准: 一句话写出"忠实用户每 X 天/周使用 Y 次"，附参照依据（同类产品公开资料或诚实假设）；显式排除专业用户标准，并说明该定义适配产品的使用触发方式。

2. **数达标人头（判停点）**
   - 完成标准: 从数据算出活跃用户中达标占比。
   - 判停条件: 若 <5%，停止一切增长动作，按二元归因先审"用户判断是否错了"（画像、场景、频率假设），再审"产品是否需要重新设计"——不先修增长（漏水桶里倒水）。

3. **提取习惯路径**
   - 完成标准: 对比达标用户与普通用户的行为流，列出至少一条由数据反推的共同行为序列（如"注册当周关注满 30 人"）；仅接受数据证据，不接受设计者想象的路径。

4. **改进产品导流**
   - 完成标准: 针对习惯路径设计具体改动（注册渠道更新、内容变更、功能增删或增强），让新用户更早到达路径上的关键节点；写明预期指标与观察窗口。

5. **迭代复测**
   - 完成标准: 每次功能迭代后重复步骤 1–4，重新校准频率定义与习惯路径；没有复测计划即视为未完成——习惯测试是持续过程，不是一次性报告。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 低频高价产品（汽车、房产、婚庆、保险类）：按周/日定义的 5% 门槛明显失灵——应转 f02 的"可感知用途"路线，或为该产品重设频率语义，而非硬套本程序。
- 一次性营销活动优化：没有"习惯"语义，属漏斗转化分析，不涉及使用频率定义。
- 冷启动无行为数据阶段：先做 f01 五问自检与定性验证，不要假装在做习惯测试。

### 作者在书中警告的失败模式

- 把 5% 当万能常数：作者自述"我的经验是 5%"，是经验值而非推导结论（L2183）；跨行业、跨频谱照搬会产生伪达标或伪不达标。
- 拿专业用户当忠实标准：作者明示"不要只针对专业级用户做出过于激进的预测"——按重度玩家定义频率，会让所有正常用户都显得"不忠诚"。
- 框架包摄力陷阱：产品成功→"它符合上瘾模型"，失败→"你的某环节没做好"——四阶段事后解释无所不包，必须靠步骤 2 的二元归因与判停条件保持可证伪性（阶段 0 批判节）。

### 作者的盲点 / 时代局限

- 5% 基准无推导、无跨行业验证（作者自认经验值）；对 B2B 低频高价产品该基准失灵。
- 书中默认埋点自由、行为数据可得（2014 年移动 App 语境）；移动平台隐私新规（ATT 等）之后，跨平台、跨设备的行为路径提取难度大增——程序可保留，数据前提需重估。
- 只测"频率达标"不测"质量"：频率达标也可能来自依赖与焦虑（打卡清零式使用）——达标后应并 f18 检查这个习惯是否值得经营，并按 p16 检查对过度使用者的保护义务。

### 容易混淆的邻近方法论

- 精益创业"建造—评估—学习"：作者明示启发来源（L2161）；习惯测试是其对习惯产品的特化——差异在"频率定义先行"与"5% 门槛"两个新增判据。
- 通用留存/参与度分析：见 A2 第 4 条——产出物不同（习惯路径 vs 留存率），归因顺序不同（先频率门槛后路径）。
- `f02-habit-zone-frequency-first`：立项过滤器与上线测量仪，勿互相抢调用。
