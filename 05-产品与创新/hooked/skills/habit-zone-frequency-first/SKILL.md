# 习惯区间与频率优先

## R — 原文 (Reading)

> "若某种行为发生的频率足够高，被感知到的用途足够多，就会进入我们的'习惯区间'，进而演变为一种默认的行为方式。这两个因素缺一不可，如果有任何一方面欠缺，某种行为发展为习惯的可能性就会降低。"
>
> — 第1章 习惯的区间（L433）

> "图中的曲线向下延伸，但是永远都不会和代表'可感知用途'的横轴重合。……无论这种行为能为你带来多么丰富的用途，发生频率的不足都只会让它作为你有意识的举动而存在，却永远都不会成为你下意识的反应。"
>
> — 第1章 习惯的区间（L435）

> "结果显示，新习惯出现的频率越高，稳定性就越强。与使用牙线一样，如果用户频繁地接触某个产品，尤其是在较短的时间内，那么他形成新的行为习惯的可能性就会加大。"
>
> — 第1章（L401，伦敦大学学院牙线研究）

---

## I — 方法论骨架 (Interpretation)

这是一个给新点子做可行性过滤的二维坐标系：横轴是可感知用途（用户觉得比别处多出什么好处），纵轴是发生频率。两项都够高，行为才可能滑入"习惯区间"，变成不再经过决策的默认动作。

真正值钱的是它的**不对称性**：用途轴是软的，频率轴是硬的。频率不足的行为，无论多有价值，永远停在"有意识的举动"，成不了下意识反应——曲线在数学上就不会与横轴相交；反过来，频率够高的行为即使用途微弱（刷社交媒体的"用处"说不清）也能成习惯。所以两轴的努力方向不对称：用途可以慢慢讲，频率必须先解决，或者承认不做习惯。

作者配套交代了两个诚实的注脚：习惯形成没有通用时间表（几周到 5 个月以上，复杂度和重要性会改变速度），"频率多高才算高"也没有定论。低频产品并非死刑——亚马逊、Progressive 走的是另一条"用极致可感知用途占据首选心智"的路线，但那是另类路线，别把它误当习惯路线。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 亚马逊与 Progressive——低频高用途的另类路线
- **问题**: 购物比价、买车投保都是低频行为，按频率轴做习惯设计似乎无解。
- **方法论的使用**: 作者用"基于习惯的发展战略"一节给出替代解：亚马逊给竞争对手做广告消除用户价格顾虑，把可感知用途做到极致；Progressive 用同样的比价策略。
- **结论**: 低频行为靠"深切感受到它的用处"也能占据用户心智——"他们已经把亚马逊网站当成了自己购买商品时的首选"。
- **结果**: Progressive 年营业额从 34 亿美元拉到 150 亿美元；用户逛实体店时打开亚马逊 App 比价，行为反而高频化（L416–422）。

### 案例 2: Google vs Bing——频率铸成的壁垒
- **问题**: 两个效能几乎相同的搜索引擎，为什么用户死守 Google？
- **方法论的使用**: 用习惯区间解释：搜索是天然高频行为，早已滑入习惯区间；转用 Bing 只会"增加他们的认知负担"，微小的像素差异都让用户"觉得 Bing 稍逊一筹，这种感觉与技术无关"。
- **结论**: 频率先行的高频行为形成习惯后，性能 comparison 失去意义；Google 再用搜索轨迹做个性化，越用越准，循环加固。
- **结果**: "正是这种习惯驱动下形成的良性循环，成就了 Google 的业界霸主地位"（L403–407）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 立项过滤：拿到一个产品点子，第一道闸是判断目标行为落不落在习惯区间——"频率低且用途弱的想法可直接放弃"。
2. 低频产品战略：房贷计算器、报税工具、婚庆服务这类产品，要决定做习惯设计还是走"首选心智"路线。
3. 需求评审：功能非常有用但使用频率上不去，团队在"要不要继续加留存功能"上争执。
4. 设计落点检查：已经在做习惯产品，要检查所有步骤是否真的围绕目标频率组织。

### 语言信号 (用户的话里出现这些就应激活)

- "习惯区间 / habit zone / 这个行为多久发生一次"（habit zone, how often does this behavior occur）
- "使用频率不够 / 低频产品 / 一年就用两次"（low frequency, infrequent use, used twice a year）
- "能不能让用户每天打开 / 值不值得做习惯 / 每日打开率"（daily habit, daily open rate, is it worth building a habit）

### 与相邻 skill 的区分

- 与 `f01-hook-model-four-stages` 的区别：f02 是入场前的过滤闸（该不该做），f01 是入场后的全流程设计（怎么做）。频率不达标时 f01 的适用性检查会直接判停。
- 与 `f03-vitamin-to-painkiller` 的区别：f02 判断"能不能成为习惯"，f03 判断"已经成了没有"（无法使用即痛苦的证据判据）。一个向前看，一个向后看。
- 与 `f20-habit-test-three-steps` 的区别：f02 是上线前的判断，f20 是上线后用数据测真实频率与习惯路径。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定位目标行为的自然频率**
   - 完成标准: 用一句话写出目标行为当前在真实用户生活中多久发生一次（每天/每周/每年），并注明该行为是否用户主动参与。

2. **过频率轴：问"能否重构出更高频入口"**
   - 完成标准: 列出把行为贴近每日的具体重构选项（如亚马逊把比价变成逛店扫码；圣经应用把读经切成每日小片段，"我们读经计划的所有步骤都以每日阅读为核心"，L2063），或明确回答"无自然高频形态"。

3. **过用途轴：低频时检查"首选心智"路线**
   - 完成标准: 若频率无法提升，写出可感知用途做到极致的具体方案（消除什么顾虑、占据什么"首选"位置），并接受这是心智战略而非习惯战略。

4. **判停与结论**
   - 判停条件: 频率重构无解、且用途路线与产品定位冲突（如高价低频决策怕被比价）→ 放弃习惯设计，诚实定位为工具型产品，不要硬造推送轰炸。
   - 完成标准: 输出三选一结论——进习惯区间（转 f01 做循环设计）/ 走低频高用途路线 / 不做习惯设计，各自附理由。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 强制消费型/低频一次性产品强行套用：人寿保险、婚礼服务没有"频率轴"可言，作者自设边界（L310–314）。
- 把"用户说喜欢"当频率证据：口头喜爱与实际发生频率是两回事，判断只看行为数据或行为学证据。
- 用本判据给打扰式推送开脱："提高频率"指用户主动行为的发生频率，不是运营发送的频率——为凑数推送给用户刷屏违反自主权，也推高低频入口的打开率。

### 作者在书中警告的失败模式

- 旧习惯回转（ce04，"后进先出"）：就算行为进了习惯区间，新习惯在旧通路未消亡时建立，戒酒者 2/3 一年内重拾旧习——频率领先不等于一劳永逸，要设防复发。
- 桌面网站之败（ce13，圣经应用）：可及性不足=触发密度不足=频率上不去；产品形态本身决定频率上限。
- 复制品之死（ce15，App.net）：功能更好的复制品无法撼动已进习惯区间的对手——与 c08 Google/Bing 互证，"略胜一筹"吞不过习惯壁垒。

### 作者的盲点 / 时代局限

- "频率多高才算高"作者自认无定论，无通用时间表（L441）——本判据给方向，不给出数值门槛。
- 2014 年 App 语境：书中"行为"默认是独立 App 的打开；小程序、超级 App 内嵌服务、桌面/穿戴入口改变了"一次使用"的计量方式，套用时要先重新定义行为单元。
- 频率轴上成习惯不等于该成习惯：刷短视频的高频习惯未必是用户福祉——本判据是描述性工具，不是价值背书。

### 容易混淆的邻近方法论

- 留存率/DAU 指标：留存是上线后的结果度量，习惯区间是上线前的设计判断；DAU 目标不能替代"该行为自然频率够不够"的追问。
- PMF（product-market fit）：PMF 问"需不需要"，本判据问"频不频率 × 够不够成为下意识反应"，正交关系。
- `f03-vitamin-to-painkiller`：常被并成"习惯可行性"一锅谈，但一个是入场判断、一个是已成证据，E 段动作完全不同。

### 伦理红线

本 skill 涉及"设计用户的行为频率"，红线：**不用于绕过用户自主权的设计**——不得以人为制造焦虑、虚假稀缺或高频打扰来人为抬高行为频率；对未成年人不做诱导性高频设计。频率设计的正当性来自行为本身对用户有益且用户自愿参与；落地前过操纵矩阵（f18）两问。
