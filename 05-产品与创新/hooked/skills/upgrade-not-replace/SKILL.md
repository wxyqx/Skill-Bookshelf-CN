# 升级而非替换：在既有行为与改良模式之间给选择

## R — 原文 (Reading)

> "那些成功打造出习惯养成类产品的公司总是会潜移默化地影响用户，使他们在既有的行为方式和更便捷的改良模式之间做选择。由于产品保障了用户自主选择的权利，因此更容易被人们接纳，也更容易成为人们固定行为习惯的一部分。"
>
> — 第4章 多变的酬赏：满足用户的需求，激发使用欲（L1461）

> "这样的公司不可能改变用户的使用习惯，因为它们没能让自己的产品趣味十足，没能简化已有的使用模式，而只是一味地要求用户掌握新的、晦涩的技巧。"
>
> — 第4章 保障用户的自主权（L1459）

> "我们通常会以为互联网的优势在于花样翻新，但其实人们只想在网络上继续做自己熟悉的事情。"
>
> — 第2章 触发：提醒人们采取下一步行动（威廉姆斯语，L682）

---

## I — 方法论骨架 (Interpretation)

让用户改变习惯，最稳的路径不是发布"新方式"，而是改良"旧方式"：把产品呈现为用户既有行为的更顺手版本——健身记录社交化、拍照分享一键化、线下花名册搬到线上——然后让用户自己决定换不换。心理机制与逆反心理同源：被迫换习惯触发对抗，自主选择的改良才会被接纳为"我自己的习惯"；威廉姆斯的观察给出方向性注脚——人们上网只是继续做熟悉的事情。操作判据是本原则的落点：检验一个习惯设计是否健康，看用户是否保有退回旧行为的自由；砍掉旧路径、强制全量切换不是执行力的证明，而是失败信号。它解释了为什么"略胜一筹"的产品撬不动用户——改良必须显著优于既有行为，而不是强迫用户放弃既有行为。

## A1 — 书中的应用 (Past Application)

### 案例 1: Facebook 复刻线下"花名册"
- **问题**: 线上社交如何从零起步、让大学生接受？
- **方法论的使用**: Facebook 早期仅限哈佛，复制的是学生早已熟悉的行为——浏览带照片和个人信息的"花名册"，而非发明全新社交方式。
- **结论**: 复制熟悉行为而非发明新行为，新习惯长在旧习惯的坐标上。
- **结果**: 从校园花名册滚雪球至十亿用户，成为"新生行为长于熟悉行为"的标杆证据（第 8 章，L2244–2246）。

### 案例 2: MyFitnessPal vs Fitocracy 的采纳对照
- **问题**: 同为健康记录应用，为何作者弃用一个、回访另一个？
- **方法论的使用**: MyFitnessPal 要求用户掌握"逐餐供认"式的新行为，摩擦与道德压力日增；Fitocracy 把既有健身记录改良为社交参与——照旧锻炼、照旧记录，只是多了评论与"奖品"。
- **结论**: 改良既有行为者胜；要求用户掌握"新的、晦涩的技巧"者败。
- **结果**: 作者的第一人称对照支撑"既有行为与改良模式间做选择"规则（第 4 章，L1437–1455）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 公司推新协作工具/新系统，老员工抵触、装了不用、用回旧的。
2. 产品大改版被老用户抗议"还我旧版"、口碑下滑。
3. 设计方案要求用户改变既有习惯：换工作流、换记录方式、换沟通渠道。
4. 迁移方案评审：旧路径要不要保留、保留多久、切换是 opt-in 还是 opt-out。

### 语言信号 (用户的话里出现这些就应激活)

- "老用户不买账 / 改版被骂 / 还是习惯旧的"（user backlash, redesign resistance, legacy habits）
- "替换 / 迁移 / 切换成本 / 旧流程"（replace, migrate, switch cost, legacy workflow）
- "让用户自己选 / 不要强制升级 / 渐进式迁移"（opt-in migration, gradual rollout, don't force upgrade）

### 与相邻 skill 的区分

- 与 `p09-preserve-user-autonomy` 的区别：p09 是单次"要求"的提法（明示可拒绝），p18 是"新旧行为迁移"的路线设计——p18 可视为 p09 在采纳/替换场景的应用特化。单点弹窗用 p09，整体迁移用 p18。
- 与 `f15-five-stored-values` 的区别：f15 解释用户为何抱住旧产品（内容/数据/关注者/信誉/技能五类储存价值与切换成本），p18 给出导入新行为的正确姿势。迁移阻力评估先用 f15，落地策略用 p18。
- 与 `ce05`（"略胜一筹"幻觉，p21 素材）的关系：ce05 警告"好一点不足以撬动迁移"，p18 回答"那怎么才能动"——不硬撬，改良+选择；引用 ce05 作 B 段素材时注意它是反例不是本 skill。
- 与 `f02-habit-zone-frequency-first` 的区别：f02 管一个行为够不够格成为习惯（频率×用途），p18 管一个新行为怎么被接纳（改良旧习惯）——立项判断与采纳策略的分工。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **找到用户的既有行为**
   - 完成标准: 具体描述目标用户现在怎么做这件事（用什么工具、多久一次、什么场合），证据来自观察而非问卷想象；写不出这一条则不进入方案设计。

2. **把新方案改写为既有行为的改良版**
   - 完成标准: 能一句话说出"照旧做 X，只是 Y 变得更容易"；若写不出，说明你在发明新行为而非改良——回到第 1 步重估需求。

3. **保留旧路径与选择权**
   - 完成标准: 迁移期内旧方式可用，切换为 opt-in（或至少可退回），并向用户明示两者并存期与差异；检查方案里没有"过 N 天自动停用旧路径"式的暗砍。

4. **监测自主选择信号**
   - 完成标准: 跟踪自愿迁移率、回退率与抗议量，区分"自愿换"与"被迫留"；被强迫感出现（如"不升级就不让用"的舆情）即触发第 5 步。

5. **判停条件**
   - 完成标准: 若业务上必须强制替换（合规、安全、成本），诚实说明强制原因、给出过渡期与储存价值补偿（数据导出、行为平移），不伪装成"为你好"的改良——伪装式改良是本 skill 的红线。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 全新行为（用户此前没有对应习惯）：没有"旧方式"可改良，属冷启动——用 f04 外部触发拉新、f05 建内部触发。
- 以"改良"为名的诱骗式迁移：先并存后砍旧路径、默认偷偷切换、用暗黑模式消耗旧选项——这是 p18 的反用，不是本 skill 的用途。
- 组织变革管理的宏大议题（部门利益、KPI 冲突、IT 管控政治）：p18 只处理"行为改良 vs 替换"的产品/采纳策略，不替代变革管理方法论。

### 作者在书中警告的失败模式

- "略胜一筹"的产品幻觉（ce05）：功能好 10%–20% 就想撬走用户——旧产品的影响"深入骨髓"，微弱优势被切换成本吞没后，新产品的体验反而"感觉更差"；改良必须让新方式在既有行为坐标内显著更顺。
- 要求用户掌握"新的、晦涩的技巧"（L1459）：把改变习惯设计成重学课程，用户只会弃用。
- Quora 强制公开（ce09 的另一面）：收回既有权利（匿名）等于强制替换用户已有行为模式——数周后撤回，迁移以失败告终。

### 作者的盲点 / 时代局限

- 证据来自消费互联网（社交、健身、拍照）；企业级迁移的政治因素（KPI、部门利益、IT 管控）不在模型内——平移到组织场景需自行补充（阶段 0 批判节：硅谷精英视角）。
- "给用户选择"在竞争剧烈时可能输给"默认全量切换"的激进产品——速度与和谐的张力书中未讨论；使用者应自知这是取舍而非普适最优。
- 威廉姆斯"人们只想继续做熟悉的事情"是 2010 年代观察；算法推荐时代，平台主动重塑"熟悉"本身——改良的锚点会漂移，"旧方式"的定义需按当下用户实际行为重新校准。

### 容易混淆的邻近方法论

- 变革管理的"渐进式推进"通识：本书可区分处是把"退回旧行为的自由"设为习惯设计健康与否的可检验标准，并给出强迫感=逆反=流失的机制链，而非一般性的"慢慢来"。
- `p09-preserve-user-autonomy`：同源不同层——单次要求的措辞与退出权（p09）vs 迁移路线与旧路径保留（p18）。
- `f15-five-stored-values`：切换成本的静态盘点（f15）与迁移策略的动态设计（p18）互补成对。
