# 把难题提出来（5 年"可能会怎样"与组织自检）

## R — 原文 (Reading)

> "我们要提出的问题不是未来'一定会怎样'，而是未来'可能会怎样'。'一定会怎样'的问题要求你对未来做出预测，这在瞬息万变的世界中无异于自欺欺人。" / "我们才需要提出这些难题，为的就是要让大家不安。"
>
> — 施密特、罗森伯格，结语《想象无止境·把难题提出来》

---

## I — 方法论骨架 (Interpretation)

每个组织心里都藏着一个没人敢碰的问题：我们赖以生存的东西，会不会被某种新东西整个绕过去？这个方法论说的是：**先把这个问题公开问出来**，而且要用正确的语法——问"5 年后可能会怎样"，不问"一定会怎样"。前者打开想象，后者逼人做注定失败的预测，然后被"预测不准"反过来当借口。

提问的价值不在得到答案。最难的题往往没有现成答案，但把它摆上台面会让组织感到不安——这种不安是有用的燃料：**相比于被竞争者置之死地，宁可这种不安来自自己人**。反面样板是太阳公司：致命的问题被当面提出来了，没有后续机制，什么也没发生，9 年里市值从 1410 亿跌到 74 亿——提出难题而无跟进，等于没提。

所以完整动作是三件套：一种提问语法（可能会怎样）、一个公开化的动作（摆上台面）、一套跟进机制（指定反方、定期复查）。自检的第一问通常是平台之辨：我们是在单向卖产品的企业，还是与买卖双方双向互惠的平台？

## A1 — 书中的应用 (Past Application)

### 案例 1: "谷歌受阻"——把官僚化摆上董事会标题
- **问题**: 作者想在董事会上讨论官僚制度对企业发展的阻碍，但报忧比报喜难，团队倾向粉饰。
- **方法论的使用**: 把会议标题直接设为"谷歌受阻：我们不得不面对的重大问题"，在不足上花最长的准备时间，并让一线产品经理而非传播或法务部门组织发言。
- **结论**: 难题摆上台面换来的是支持而非恐慌——百分之百的坦诚是决策质量的前提。
- **结果**: 董事会聚焦战略与产品；深挖细节的训练日后成就了桑达尔·皮查伊等领导者（c69）。

### 案例 2: 维克的午餐之问
- **问题**: Wave 放弃、Buzz 受挫，谷歌在社交上努力归零，而脸谱网已成领军平台——这个威胁该怎么进入议程？
- **方法论的使用**: 手机业务负责人维克·冈多特拉（社交并非其职责）自问"社交网络会不会让搜索过时"，主动约谈霍洛维茨并启动"翡翠海"项目——管理层未曾下令。
- **结论**: 个人层面的难题提问能绕开组织对创新的反对力量；只需提出最困难的问题，就可能引爆自下而上的行动。
- **结果**: 约一年后推出 Google+，谷歌史上最大的赌注（c91）。

### 案例 3: 太阳公司的 Wintel 之问——提出而无跟进
- **问题**: 20 世纪 90 年代，太阳公司的计算机性价比终将被 Wintel 超越，这会对公司造成什么影响？
- **方法论的使用**: 埃里克把这个问题当面摆给董事长与 CEO——问题被承认（两人没找到好答案），然后就没有然后了：没有人采取任何实质性措施。
- **结论**: 提出难题而没有跟进机制等于没提；难题的作用就是让大家不安，不安没有转化为动作，提问只是高级哀悼。
- **结果**: 市值从 2000 年 4 月的 1410 亿美元跌到 2009 年以 74 亿美元被甲骨文收购（c92）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 筹备战略会/年度复盘，议程上全是成绩与计划，缺"真正的问题"。
2. 团队里有人（或你自己）怀疑核心业务会被新技术/新平台绕过，但话题太敏感没人敢摆到桌面上。
3. 想要一份"5 年后我们会在哪里"的组织自检问题清单。
4. 公司讨论某个颠覆性趋势时，第一反应总是"找谁合作/买谁"，从未问过"它会不会让我们过时"。
5. 难题曾被提出过（某次复盘/某份报告），然后消失在日常议程之外，想设计跟进机制。

### 语言信号 (用户的话里出现这些就应激活)

- "5 年后会怎样 / 会不会被颠覆 / 会不会过时"
- "把问题摆上台面 / 揭伤疤 / 自曝家丑"
- "战略会缺真问题 / 复盘不敢碰核心"
- "可能会怎样 / what might happen / 平台冲击"
- "自检清单 / health check / 组织体检"

### 与相邻 skill 的区分

- 与 `default-open-candor` 的区别：那个是信息环境的基建（共享一切、报忧安全、匿名通道），回答"真话怎么说出来"；本 skill 是提问的内容与语法（哪些难题、怎么问、怎么跟进）——难题能不能被公开提出，往往依赖那个环境先存在。
- 与 `technical-insight-first` 的区别：那个管"往哪走"（用技术洞见替代计划），本 skill 管"先敢不敢承认脚下有裂缝"（自检与危机感）。
- 与 `real-consensus` 的区别：难题摆上台面之后的讨论组织与拍板是那个 skill 的事；本 skill 只负责让难题出现在议程上并保持不安。

## E — 可执行步骤 (Execution)

1. **用"可能"语法改写问题**
   - 完成标准：把担忧写成 2-3 个"5 年后可能会怎样"的问句，禁用"一定会怎样"；问题指向组织核心业务而非具体部门的成绩。
   - 判停条件：用户要的是市场预测/规模测算 → 这不是本 skill 的题（它恰恰拒绝预测），转说明后停止。
2. **公开摆上台面**
   - 完成标准：难题以显性形式进入正式议程（全员会、董事会、管理会的标题级议题），而不是私下一对一转述；参照 c69 把"最难的题"写进会议标题。
3. **声明不安的正当性**
   - 完成标准：明说提问的目的就是让大家不安——"自造的不安好过对手给的"；不承诺"我们已想好对策"，把"没有答案"合法化。
4. **配跟进机制（防太阳式空转）**
   - 完成标准：每个难题有指定反方角色、固定复查节奏（如季度）、并写进自检清单；若一轮复查后无任何动作，视为"提出等于没提"，升级到最高负责人。
5. **走一遍自检清单**
   - 完成标准：至少回答书中清单的三问——表现突出的竞争者会以什么方式危及核心业务？我们是否在为避免厮杀而扼杀创新？我们是单向卖产品的企业，还是双向互惠的平台？答案形成书面记录并进入下次复查。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **预测式请求**："预测一下明年行业规模/股价"——本 skill 的语法恰恰拒绝预测，硬套会变成占卜。
- **日常运营问题**：进度延误、人员摩擦这类有明确答案的问题不叫"难题"，摆上台面只会浪费不安的额度。
- **替代行动的装样危机感**：若用户只想要"我们讨论过了"的姿态而不打算配任何跟进机制，本 skill 会沦为太阳公司式的高级哀悼——应先拒绝，再谈条件。

### 作者在书中警告的失败模式

- 太阳公司：致命问题被当面承认后无人行动，"没有好方案"成了不动的理由，1410 亿跌到 74 亿（ce54）——提出难题必须配"让大家不安"的跟进。
- 在位者的框架锚定：把颠覆者的威胁想象成"又一个合作渠道"，真颠覆者不在任何雷达上，直到内部有人独立提问（ce53；维克的午餐之问正是解药，c91）。
- 鸵鸟战术：靠政客和律师维持现状、"挖个洞把头埋进沙土"，耗时费钱且扭转不了败局（ce56）。

### 作者的盲点 / 时代局限

- 技术乐观主义需限定："几乎所有大问题都是信息问题"（p213）在 AI 治理、隐私、地缘政治面前并非自明，把它当唯一透镜会漏掉非信息类难题。
- 案例的后见之明：c91 中"维克之问"催生的 Google+ 于 2019 年关停——难题之问能引爆行动，但不保证行动的方向正确；引用该案例时应交代结局。
- 作者立场内嵌张力：CEO 既要深耕核心业务又要放眼未来（p210），但书中未解决两者的时间从哪来——照搬"每天为难题开会"会与 80/80 时间律打架。

### 容易混淆的邻近方法论

- 预判式战略规划（scenario planning）：也谈未来情景，但目的仍是产出计划；本 skill 恰恰以"计划不可靠"为前提，产出的是不安与跟进机制。
- "红队/魔鬼代言人"：只解决"有人唱反调"；本 skill 解决"反调指向哪个问题、用什么语法问、之后谁盯着"——范围更大且以公开化为要义。
