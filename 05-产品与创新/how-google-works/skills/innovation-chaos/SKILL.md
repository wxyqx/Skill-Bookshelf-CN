# 创新不可指派（缔造原始的混沌）

## R — 原文 (Reading)

> "创意的开发应该是一个有机的过程。一个个想法冒出来，好似在一片原始混沌之中产生的基因突变一般……比较强大的构想不断吸引支持者，势能越来越大，而欠佳的构想则会被半路淘汰。" / "单独设立首席创新官的做法行不通，因为这个职位的权力无法营造出原始的混沌……首席创新官的职位需要由首席执行官兼任。"
>
> — 施密特、罗森伯格，第六章《创新：缔造原始的混沌》

---

## I — 方法论骨架 (Interpretation)

把创新想成一场构想的物竞天择：点子像原始混沌里的基因突变，强构想吸引支持者、势能滚大，弱构想半路淘汰，"无路可循"是这个过程的基本特点。理解了这一点，就能看穿大多数公司的做法为什么自相矛盾——**创新不可指派**：设专职创新官、创新委员会、创新指标，等于给进化过程装上一个审批关卡，被批准的必然是"安全"的想法，真正出格的构想死在流程里。

由此推出三条动作纪律。①**首席创新官只能 CEO 兼任**：营造混沌需要动用整个组织的权力与优先级，这是唯一兼任得起的人。②**给空间，不给任务**：有创意的人需要的是腾出来的余地，不是布置下来的题目。③**把创新散进每个部门**：创意的出现靠"孤独的疯子"，而成事靠第一个追随者——"将一个孤独的疯子变成领袖的，就是第一个追随者"；若创新只是某个团队的特权，你吸引得到疯子，却无处供应追随者。

混沌不等于无门槛：可以设"影响几十亿人/方法截然不同/技术可行"这类立项过滤器，但过滤器管准入，不管生产——生产永远来自自下而上。

## A1 — 书中的应用 (Past Application)

### 案例 1: 雅虎"创新负责人"的三周
- **问题**: 雅虎觉得自己创新力度不够，按 MBA 的标准动作该怎么办？
- **方法论的使用**: 指派专人——乌迪·曼博接任"创新负责人"，三周内即被要求设立创新委员会，让员工提交构想、由委员会审查批准；他 12 岁的女儿一针见血："你浪费了几百个工程师的时间，只为了告诉他们一定要创新。"
- **结论**: 创新不可把握、无法强制，设创新官等于建审批官僚机构，自相矛盾；首席创新官必须由 CEO 兼任。
- **结果**: 乌迪离开雅虎（随后加入谷歌并领导了多支最有创意的团队）（c70）。

### 案例 2: 演示日——给混沌一个制度容器
- **问题**: 非层级制组织里，新人有好点子却找不到合作者，构想容易胎死腹中。
- **方法论的使用**: 设"演示日"：一周建原型、周末科学展会式公开展示，会前清空会议与发布日程，强制至少两人成组、孤军奋战不允许。
- **结论**: 机制不生产创意，只降低创意找到追随者的摩擦；"想到好点子没有难度，吸引同事投入才难"。
- **结果**: 多数原型止步于演示日，但技能与协作沉淀下来，成为后来项目的种子（c89）。

### 案例 3: 热气球项目留住迈克
- **问题**: 连续创业者迈克·卡西迪加入谷歌后被推断迟早离开，甚至没人说清他在做什么。
- **方法论的使用**: 让他投身热气球这类"放大 10 倍"的登月项目——混沌环境里最诱人的空间是"值得疯"的挑战本身。
- **结论**: 巨大的挑战吸引并留住顶尖人才，挑战与人才共生；给空间比给头衔更能留住创新者。
- **结果**: 迈克成为热气球项目领导者之一，留在谷歌（c75）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 顾问或高管提议设立"创新实验室/首席创新官/创新委员会"，要评估该不该做。
2. 创新全靠老板立项指派，一线的好点子提了没人理、慢慢没人再提。
3. 有人拿出了一个好点子却响应寥寥，想知道怎样让别人敢跟着干（第一追随者）。
4. 公司想"变得更创新"，正在起草创新激励制度、创新 KPI、创意征集流程。
5. 500 人以上的公司开始出现风险规避文化，激进构想在内部活不过第一次汇报。

### 语言信号 (用户的话里出现这些就应激活)

- "创新实验室 / 创新官 / 创新委员会 / 创新 KPI"
- "让员工创新 / 推动创新 / 创新考核"
- "点子没人响应 / 孤军奋战 / first follower / 第一追随者"
- "自下而上 / bottom-up / 谷歌式创新"
- "创意从哪来 / 混沌 / chaos"

### 与相邻 skill 的区分

- 与 `twenty-percent-time` 的区别：20% 时间制是本 skill 的具体制度实现之一；用户若已接受"给自由"的方向、只问时间制度细则，转 `twenty-percent-time`。若还在争论"该不该设创新官/该不该管创新"，留在本 skill。
- 与 `focus-user-think-10x` 的区别：那个管构想的量级与方向（10 倍思维、登月过滤器的内容），本 skill 管构想从哪里冒出来、由谁生产；三圆过滤器在两处共用但用途不同。
- 与 `open-as-strategy` 的区别：创意来源的边界若延伸到组织之外（用户共创、草根制图），接的是开放战略的资源——但那是"要不要开放"的战略题，本 skill 只到"创意无处不在"为止。

## E — 可执行步骤 (Execution)

1. **拆除创新官僚机构**
   - 完成标准：盘点现有机制中所有"创意审批"环节（创新提案表、评审会、创新 KPI）；出现即按 ce46 判为自相矛盾，给出拆除或改造成"展示通道"（无审批权）的方案。
2. **落实 CEO 兼任**
   - 完成标准：创新环境的责任人明确到人且是最高负责人（其职责是腾空间、保出格构想、当第一追随者的示范），不存在分管创新的中间层官职。
3. **把"任务"换成"空间"**
   - 完成标准：给自下而上构想让渡出真实余量（时间、算力、免审预算的通道），指派型"创新任务"清单清零；余量来源可衔接 `twenty-percent-time` 与 `resource-70-20-10` 的 10% 档。
   - 判停条件：组织连核心业务的时间余量都挤不出 → 先解决余量问题，本 skill 的其余步骤暂缓，避免"要求创新却没收时间"的空头支票。
4. **铺设第一追随者通道**
   - 完成标准：创新权散在各部门而非集中一处（部门特权的检验：别的部门能否发起项目）；存在低摩擦的展示与加入机制（演示日式的原型展示、跨部门组队、孤军奋战不允许）。
5. **用"未经指派的项目出现率"验收**
   - 完成标准：验收指标不是创新部门的产出数，而是每季度"无指派、自发立项并通过原型展示"的项目数量与参与人数；若指标持续为零，回查步骤 1-3 而不是加压。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **单个创意的可行性评审**：用户拿着一个具体点子来问"值不值得做"，需要的是立项过滤与市场/技术判断，不是环境哲学——硬讲"混沌"是答非所问。
- **合规与安全流程**：药物试验、金融风控、生产安全等领域的审批不是"创新官僚机构"，是必要的边界条件；混沌的适用范围是创意来源，不是流程豁免。
- **把"不受管"等同于创新**：用户想用本 skill 论证"所以不用任何流程/质量把关"时，应拒绝——混沌指的是创意的生产方式，执行纪律照旧。

### 作者在书中警告的失败模式

- 雅虎创新委员会：审批制把创意的定义权交还层级，被批准的都是安全的想法，负责人三周即离职（ce46）。
- 大企业创新的双重结构失灵：组织层面小机遇"不值得做"，个人层面"冒险失败要受罚"——两条曲线叠乘出集体僵化，修环境必须同时修入口与激励（ce55）。
- 过度有序的代价：诺勒公司运营顺畅而新产品栏空空如也——秩序把混沌完全挤出后的组织空心化（ce40）。

### 作者的盲点 / 时代局限

- **混沌不保证成功**：自下而上创新的最大案例 Google+（维克自发启动"翡翠海"，c91）在 2019 年关停——环境只提高构想的出现率，不保证方向正确；书中对 Google+ 的成功叙事需要打折引用。
- 幸存者偏差：Gmail、AdSense、街景三轮车被反复讲述，大多数死在演示日的原型（c89 自己承认）不入叙事——推广时不可许诺"自由时间=爆品"。
- 工程师中心：混沌叙事以工程师为默认员工模型，对强流程、强合规、线下运营为主的组织，"无路可循"的自由度需要大幅重译。

### 容易混淆的邻近方法论

- "Skunkworks/特种部队"模式：设立独立的创新小团队仍属"把创新圈进特权部门"，恰恰违反第一追随者原则的分布要求——它是本书立场的反面而非同义。
- 设计思维工作坊：产出的是"被组织的创意活动"，可作混沌环境的展示通道，但活动本身不等于环境改造；判据仍是未经指派项目的出现率。
