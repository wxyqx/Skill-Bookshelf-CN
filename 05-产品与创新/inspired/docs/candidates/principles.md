- id: p11
  title: 20%余量法则
  type: principle
  source_chapter: 第5章
  source_quote: |
    "与开发团队合作应该遵循以下原则：在产品管理上为开发团队预留20％的自主时间，
    让他们自由支配。"
  summary: |
    永远为开发团队预留20%的自主资源（余量/headroom），让他们自由支配——重构代码、
    完善架构、更换数据库、提高性能，避免"需要停下来重写代码"的危机。
    道理：所有软件架构都有功能极限，满负荷赶功能会让系统越过崩溃临界点；eBay
    1999年濒临崩溃就是前车之鉴，重写代码期间用户会流向不断改进的竞争对手。
    落实方式：产品规划时主动把20%资源划给技术债；处境已现端倪时至少拿出20%
    资源调整；绝不为短期功能把余量吃光。
  tags: [product, rule, engineering]

- id: p12
  title: 进入开发阶段后冻结需求与设计
  type: principle
  source_chapter: 第5章
  source_quote: |
    "一旦产品进入开发阶段，要尽可能避免修改产品的需求和设计。……千万不要在此时

  summary: |

    出现的问题是正常的，解决它们应以"维持基本功能、尽量少改"为原则。
    落实方式：把新点子记下来放入下一个版本的探索；执行阶段只处理必须处理的问题。
  tags: [product, rule, execution]

- id: p15
  title: 重写代码三原则
  type: principle
  source_chapter: 第5章
  source_quote: |
    "只要有可能，最好把重写目标分成几大块，实现递增修改，让用户感受到产品的改进，

- id: p16

  type: principle

  source_quote: |
    "外包不是为了节约成本，而是为了实现合理的人员配置。"
  summary: |

- id: p17
  title: 产品经理素质清单
  type: principle
  source_chapter: 第6章
  source_quote: |
    "技术可以学习，素质却难以培养，有些素质是成功的产品经理必不可少的。"

- id: p18

  type: principle

  source_quote: |

  summary: |

    落实方式：面试考察学习思路而非已掌握的知识；不要以年龄、性别、行业背景
    一票否决候选人。

  title: 过滤多余功能
  type: principle
  source_chapter: 第6章
  source_quote: |
    "几乎所有产品都有些不那么重要的功能——这些功能对提高销量和用户满意度毫无作用。
