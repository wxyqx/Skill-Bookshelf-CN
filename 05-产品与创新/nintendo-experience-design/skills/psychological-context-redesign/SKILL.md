# 心理脉络重设计（产品×环境×心理状态）

## R — 原文 (Reading)

> "重要的不是石头本身，而是石头和用户交互的环境。用户在具体的环境中接触石头，这样才会产生体验的价值。" / "重要的是，在酷栗宝登场之前，玩家是怎样的心情……正是玩家的心路历程决定了体验的意义。"
>
> — 玉树真一郎，第5章《实践篇总论》/ 第1章

---

## I — 方法论骨架 (Interpretation)

体验的价值不在物本身，而在"产品×环境×心理状态"的组合里。同一块石头：放在又长又直的路中央，路过的路人忍不住想踢一脚；丢在看恐怖片的人旁边，会吓人一跳然后笑出声；藏进被监禁者的口袋，就成了逃亡工具。所以面对"无聊的东西"，"让这个东西变有趣"是伪问题——合格答案一个都不触碰物本身。

配套一个解释工具——**心路历程分析**：同一个事件在不同前置心理状态下意义相反。玩家遇到酷栗宝（敌人）反而高兴，因为登场前他正处在"不知道向右前进对不对"的不安里，敌人从右边出现恰好确认了假设。所以解释任何打动/惊吓/高兴的瞬间，先重建"事件发生前一刻用户的心理状态"，再下判断。

工作流由此变成：观察无聊的、不顺畅的、反应诡异的体验 → 找出拉低（或意外拉高）体验价值的心理脉络 → 针对脉络重新设计（改环境、改时机、改登场前的心情），而不是继续打磨物。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 石头的三个回答
- **问题**: "这里有一块毫无特色的石头，请让它变得有趣。"
- **方法论的使用**: 三个答案分别只动环境与心理脉络：放长路正中央（想踢）、丢给看恐怖片的人（吓一跳）、藏进被监禁者口袋（逃亡工具）——没有一个改石头。
- **结论**: 设计对象从"物"换成"物所处的心理脉络"。

### 案例 2: 酷栗宝之谜
- **问题**: 玩家发现敌人（酷栗宝）时心情如何？防御？攻击？
- **方法论的使用**: 光看酷栗宝无法作答；还原登场之前的心情——玩家正处于"向右前进对不对"的不安中，敌人的出现确认了假设，所以高兴。
- **结论**: 心路历程决定体验的意义；分析方法从"事件"移到"登场之前"。

### 案例 3: onboarding 邮件（V2 推演方向，书中方法的直接应用）
- **问题**: 邮件打开率 12%，文案改了三轮。
- **方法论的使用**: 停止改邮件（物）；还原打开瞬间（刚注册、焦虑、收件箱拥挤），把注册流程最后一步变成一个问题、让邮件成为它的答案——改"登场之前的心情"。
- **结论**: 这是石头纪律在增长场景的复现。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 东西反复优化（文案、界面、课程、活动）仍无起色，不知道还能改哪。
2. 用户反应"诡异"：该高兴的地方无感、该流失的地方爆火、该紧张的地方发笑。
3. 创意枯竭：对一个产品/活动想不出新点子，只会给它加功能。
4. 复盘某个爆火/翻车瞬间，想知道"为什么是这里"。
5. 竞品同样的功能反应迥异，想找解释。

### 语言信号 (用户的话里出现这些就应激活)

- "怎么改都没用 / 优化了好几轮还是不行"
- "为什么用户反应跟预期相反 / 反而很高兴"
- "换个场景/时机/环境会不会不一样"
- "用户当时是什么状态 / 前情是什么"
- "context / 场景化 / 时机不对"

### 与相邻 skill 的区分

- 与 `comprehension-first-affordance` 的区别：那个是信息取舍的执行标准（首屏放什么）；本 skill 是更前置的诊断方法（先找到"体验价值被什么拉低"，可能结论是改环境而非改信息）。
- 与 `surprise-design-two-beliefs` 的区别：那个主动制造坚信崩塌；本 skill 先解释和诊断（为什么此刻反应诡异），是它的前置分析步骤。
- 与 `stop-design-graceful-endings` 的区别：共享"用户人生是主角"的立场，但那个是收尾设计，本 skill 是全局诊断。

## E — 可执行步骤 (Execution)

1. **锁定异常体验**
   - 完成标准：具体到"谁、在哪里、做什么时、出现了什么反应"，有观察或数据支撑，不是泛泛的"用户不喜欢"。
2. **重建登场之前的心情**
   - 完成标准：写出事件发生前一刻用户的心理状态（期待/不安/疲惫/刚经历了什么）；同一事件用两种不同前置状态各推演一次，确认"意义随脉络变化"。判停条件：推演不出有意义的差异 → 异常原因不在脉络，转查物本身（质量/正确性）。
3. **做石头纪律自检**
   - 完成标准：把当前所有改进方案过一遍——凡仍在改进物本身的（换文案、加功能、调样式）标记为"伪问题候选"；至少生成 2 个完全不动物、只动环境/时机/前置状态的方案。
4. **选脉络杠杆并落地**
   - 完成标准：从三类杠杆中选定并实施——改环境（它出现在哪、跟什么并置）、改时机（什么时候出现）、改前置状态（在它登场前让用户经历什么）；落地方式可衔接 `comprehension-first-affordance`。
5. **小规模验证归因**
   - 完成标准：A/B 或灰度验证"动脉络"是否优于"动物"；若动脉络无效，回步骤 2 重查前置状态，仍无效则承认物本身有硬伤。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **物本身有硬缺陷**——质量、正确性、安全问题必须先修；脉络分析救不了坏产品。
- **需要普适一致的物料**——合同、警示标识、合规文档的意义不能依赖语境，必须无条件可读。
- **把"场景化"当万能归因**——若推演不出脉络差异还硬改环境，是本 skill 的滥用；先做第 2 步的判停检查。

### 作者在书中警告的失败模式

- 只盯着物本身想办法让它有趣（换材质/加功能）——石头问题的所有失败答案（ce28）。
- 光看事件本身下结论——酷栗宝之谜的"防御/攻击"错误答案都源于不看前情（c03）。

### 作者的盲点 / 时代局限

- "心理脉络"判据偏定性，依赖设计者对用户的想象力；跨文化、大规模场景下，前置状态需要真实用户研究数据佐证，不能全靠内省。
- 本单元是全部录取单元中 V3 最接近常识的一条（"context matters"人人会说），价值在两条纪律的强制性——跳过自检步骤就退化成口头禅。

### 容易混淆的邻近方法论

- Jobs-to-be-done（场景需求分析）：同讲情境，JTBD 找"雇用产品完成的任务"，本 skill 找"拉低体验价值的心理脉络"并允许答案完全不动产品。
- A/B 测试文化：A/B 动物（两个版本），本 skill 提醒先检查"该不该动物"；两者是先后关系不是竞争。
