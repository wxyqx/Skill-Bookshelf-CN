# 《增长黑客》原则/清单/规则/断言候选（principle-extractor 输出）

> 来源：范冰《增长黑客》全书 10 个章节文本。共 35 条候选，宁多勿漏，未做筛选。
> 注意：部分打法（SEO/ASO/开放平台/重定向广告等）高度依赖 2014-2015 年平台生态，引用时需区分"元方法"与"过时玩法"。

```yaml
id: p01
title: 未达 PMF 之前，禁止过早推广与过量优化
type: principle
source_chapter: 第2章 PMF，探寻产品与市场的完美契合
source_quote: |
  马克·安德森（Marc Andreessen）将"产品与市场相契合"的这一状态称为PMF（Product/Market Fit）。
  在达成PMF之前，过早的推广和过多的优化都是不必要的。
summary: |
  PMF 是一切增长动作的前置条件。产品未验证"市场愿意接纳"之前，增加功能保"完整性"、
  大规模买量推广，都只是推迟真实市场检验、放大沉没成本。此阶段唯一任务是从小部分
  早期用户获得反馈、以最低成本持续改进。作为决策门使用：任何扩张/推广预算审批前，
  先问"PMF 证据是什么（留存、复购、自发口碑）"。叮咚小区 1 亿元即反例。
tags: [growth, pmf, premise, decision-gate]
```

```yaml
id: p02
title: 真正的浪费是在错误方向上大踏步高歌猛进
type: maxim
source_chapter: 第2章 PMF，探寻产品与市场的完美契合
source_quote: |
  真正的浪费不是上班刷微博，不是开给员工高于市场标准的工资，也不是没有谈到最优惠的
  广告报价。真正的浪费是在错误的方向大踏步地高歌猛进，走得越远，就越与成功背道而驰。
summary: |
  对"节约"的重新定义：执行效率高不等于不浪费，方向错误时执行力越强损失越大。
  适用于判断"要不要加速"——先确认方向正确（PMF、需求验证），再谈速度与规模。
  成功地执行一项没有意义的计划是导致失败的致命原因。
tags: [growth, direction, waste, strategy]
```

```yaml
id: p03
title: 需求分析四问：真伪 / 刚需 / 量与肥 / 变现
type: checklist
source_chapter: 第2章 需求，催生产品的第一原动力
source_quote: |
  产品开发中40％～60％的问题都是在制定需求方向阶段埋下的"祸根"。在测试及运营阶段发现
  需求方向的问题，解决的代价是制定需求方向中发现问题的68～200倍。
summary: |
  立项前对需求过四道筛：1) 真实存在还是伪需求（QQ邮箱附件聚合功能上线即撤）；
  2) 刚需还是弹性需求（信息、生产生活资料、沟通是互联网三大底层刚需）；
  3) 需求量是否够大、市场是否够肥（可规模化，"要做最肥的市场"）；
  4) 变现能力如何（用户量大≠能赚钱，搜狗输入法、VeryCD 皆为例证）。
  依据：需求方向问题的修复成本是制定阶段的 68~200 倍，前期四问是最便宜的质量关。
tags: [growth, demand, checklist, validation]
```

```yaml
id: p04
title: 行胜于言：看用户做什么，不问用户要什么
type: principle
source_chapter: 第2章 "行胜于言"的用户调研
source_quote: |
  用户说了什么固然重要，但更多心思应当花在分析他们做了什么。……避免被用户口头意见带到
  沟里的另一种方法是，不要问他们喜欢什么，而是看他们是否愿意为某项功能付费。
summary: |
  口头调研会被测试环境、提问方式、面子心理污染（"一键标为已读"上线后使用率远低于访谈
  结论；100% 受访者说要填真实资料，实装后吓跑用户）。决策规则：行为数据 > 口头意见；
  愿意付费的用户意见 > 免费评论家意见。付费意愿是校准意见权重的最佳标尺。
tags: [growth, user-research, behavior, principle]
```

```yaml
id: p05
title: MVP 是"能帮用户完成任务的最小功能合集"，不是便宜难看残破
type: principle
source_chapter: 第2章 用最小化可行产品验证需求
source_quote: |
  它并不意味着"便宜"、"难看"或是"核心功能残破"，而应是能帮助用户完成任务的最小功能合集。
  除此以外对需要认知的内容没有直接帮助的一切功能或流程都应当暂时放弃。
summary: |
  MVP 只回答两个问题：价值假设（产品是否满足需求）与增长假设（用户是否愿意买单）。
  形态可以是视频（Dropbox）、手工服务（Groupon/Zappos）、假门网站（Sendwithus 仅花 28 美元）、
  微信公众号（悠泊）。判断标准不是"做得多糙"，而是"砍掉一切与验证无关的东西之后，
  用户能不能完成核心任务"。
tags: [growth, mvp, lean, definition]
```

```yaml
id: p07
title: MVP 三大必备模块：反馈渠道、公告看板、自动升级
type: checklist
source_chapter: 第2章 用最小化可行产品验证需求（MVP的三大必备模块）

summary: |

  灰度发布——微信约 70% 的想法最终未能通过市场检验。
```

```yaml
id: p14
title: A/B 测试铁律：双方案并行 + 单变量 + 预设判优标准
type: rule
source_chapter: 第4章 A/B测试，网站活跃率提升的法宝
source_quote: |
  提供两个方案并行测试。不同方案之间只存在一个变量，排除其他干扰因素。以某种标准判定结果
  优劣，筛出最优方案。其中第二点，即单变量，需要重点关注。
summary: |
  凡是"模棱两可、人人有理"的设计分歧（按钮颜色、位置、文案），一律不靠审美、表决或领导
  拍板，靠 A/B 测试。单变量是底线：比较的必须是"红烧 vs 干拌"或"茄子 vs 土豆"之一，
  不能同时变两个。数据面前，经验主义和主观揣测都不可靠。
tags: [growth, ab-test, experiment, rule]
```

```yaml
id: p15
title: 产品不息，测试不止：多数测试注定失败
type: maxim
source_chapter: 第4章 A/B测试，网站活跃率提升的法宝

  两条用法：1) 预期管理——大部分实验会失败，失败的测试同样有价值（终结无意义争吵、
```

```yaml
id: p20
title: 真正的用户增长 = 新增 − 流失
type: maxim
source_chapter: 第5章 留存与流失
source_quote: |
  一款产品一定存在流失用户，这是用户新老交替中不可避免的，但流失用户的比例和变化趋势能够
  说明产品满足用户的能力和在市场中的竞争力。实际上归根到底，真正的用户增长就是增长与流失
  的差值。
summary: |
  累积用户量是虚的（含流失水分），增长与流失的差值才是真增长。推论：一边拼命拉新、
  一边默默流失的"游泳池模式"是创业团队最常见的自欺。所有增长动作先看分母：
  流失率不变，拉新只是给漏水的池子灌水。
tags: [growth, retention, metric, core-definition]
```
