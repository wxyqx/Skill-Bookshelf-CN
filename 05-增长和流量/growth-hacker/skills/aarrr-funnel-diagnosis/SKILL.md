# AARRR 漏斗诊断定位法（元层框架）

## R — 原文 (Reading)

> "根据不同阶段用户参与行为的深度和类型，我们可以将增长目标拆分并概括为'AARRR'转化漏斗模型，即：Acquisition（获取用户）、Activation（激发活跃）、Retention（提高留存）、Revenue（增加收入）、Referral（传播推荐）。"
>
> — 范冰，《增长黑客》第1章 1.3 什么是"增长黑客"

---

## I — 方法论骨架 (Interpretation)

AARRR 漏斗在这里不是教科书概念，而是一台**定位仪器**：把增长目标拆成获取→活跃→留存→收入→传播五环，用指标链（访问→注册→激活→留存→付费→分享）把每一环的转化率算出来，找出最低的那一环——那就是当前最值得花实验预算的瓶颈。本书第 3-7 章各对应一环，第 8 章五个完整案例复盘的共同套路就是"先定位漏斗环节，再从该环的方法箱里选手段"。两个修正必须内建：其一，"获取排第一"是叙述顺序不是优先级——本书自己的核心命题是真增长=新增减流失，留存才是根基；其二，先做 PMF 判停检查，若留存曲线持续走低说明产品本身不过关，此时在漏斗任何一环做优化都是给漏水的池子灌水。本 skill 只做"找卡点、转专项"，不提供单环技术。

## A1 — 书中的应用 (Past Application)

### 案例 1: Airbnb 完整增长复盘（c19）
- **问题**: 供需平台冷启动"鸡与蛋"困境，且推荐计划被认定"实际成效不佳"。
- **方法论的使用**: 先定位各环卡点再对症：获取环卡住→技术借力 Craigslist 一键同步房源引流（借大平台）；信任/激活环卡住→接入 Facebook 社交关系（1650 万对好友关系）；转化环卡住→重构推荐系统文案（"利他"优于"利己"、加发送者照片）。
- **结论**: 同一产品不同阶段瓶颈在不同环节，手段完全不同——先诊断后开方。
- **结果**: 2015 年春超 1000 万用户、100 万房源；新推荐系统使部分地区订单量 +25%。

### 案例 2: 美丽说的分层增长（c22）
- **问题**: 女性时尚社区冷启动失败（测试二十几个人无一留存），且要维护社区氛围。
- **方法论的使用**: 识别出瓶颈在获取环的用户质量而非数量——付费请 QQ 群主带精准人群（每月 500 元/群主）先养出两个百人低流失小组，蔷薇粉主色调+禁止男性注册守住生态；获取稳定后再在传播环做微博小测试（结果须分享才可见，单款 10-30 万授权）。
- **结论**: 漏斗诊断的关键产出之一是"瓶颈在质量还是在数量"的区分。
- **结果**: 2011 年 2 月到年底指标增长至少 30 倍；2014 年 Q3 注册用户超 1 亿、日活超 1000 万。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 增长全面停滞，预算和人力有限，问"先从获取、活跃、留存还是传播下手"。
2. 各环数据都有，但团队各说各话（市场要投广告、产品要改引导），需要一个统一的诊断框架定优先级。
3. 新接手一个产品做增长"体检"，需要从指标链找第一刀切哪里。
4. 某环投入很大却不见整体增长，怀疑力气用错了环节。

### 语言信号 (用户的话里出现这些就应激活)

- "AARRR / 增长漏斗 / pirate metrics / funnel"
- "增长停滞/不涨了，该优化哪个环节"
- "转化率哪一环掉得最厉害 / 漏斗哪里卡住了"
- "先做拉新还是先做留存 / 增长从哪下手"

### 与相邻 skill 的区分

- 与 `retention-diagnosis` 的区别：那是留存环的深度诊断（真增长定义、三口径、40-20-10、流失五分类、有损服务）；本 skill 只回答"哪一环卡住"，定位到留存环后立即转出。
- 与 `viral-k-factor` / `external-viral-loop` 的区别：传播环定位之后的专项设计归它们；本 skill 不做传播技术。
- 与 `growth-metrics-system` 的区别：指标体系是诊断的地基（口径、North Star、虚荣指标排除）；本 skill 用现成指标链找卡点，口径本身有争议时先去那边。
- 与 `pmf-gate` 的区别：pmf-gate 是本 skill 的上游判停闸——未达 PMF 时漏斗优化整体冻结。

## E — 可执行步骤 (Execution)

1. **画出指标链并填数**
   - 列出访问→注册→激活→留存→付费→分享各环节的当期转化率与样本周期。
   - 完成标准：每一环都有数，口径明确（激活的定义、留存的口径日期）。
   - 判停条件：关键环节数据缺失或口径可信度差 → 先转 `growth-metrics-system` 补指标地基。

2. **定位瓶颈环节**
   - 对照品类常识找转化率最低/损耗最重的一环；同时算"真增长"（新增−流失）是否为正。
   - 完成标准：明确指出 1 个瓶颈环节，并给出对比依据。
   - 判停条件：若留存曲线持续走低、新增−流失为负 → 停止漏斗优化，转 `pmf-gate` / `retention-diagnosis`（产品本身不过关时任何环节的优化都是灌水）。

3. **只对瓶颈环节设计实验**
   - 从该环节的方法箱取工具：获取环→渠道/种子用户选型；活跃环→魔法数字/A-B；留存环→留存诊断；收入环→免费-收费决策；传播环→K 值/体外循环。
   - 完成标准：产出该环节的实验假设、单变量方案与预设判优标准，明确转交对应专项 skill。

4. **复测并滚动定位**
   - 完成标准：瓶颈环节转化率变化可测；若已修复，回到步骤 2 找下一个瓶颈，形成螺旋。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 未达 PMF 的产品：先过 pmf-gate，漏斗优化整体让位于产品验证。
- 把"获取排第一"当执行优先级：RARRA 等框架批评 AARRR 天然诱导重拉新轻留存，而本书自己的命题（真增长=新增−流失）恰恰反驳了这个排序——留存是根基。

### 作者在书中警告的失败模式

- 在非瓶颈环节浪费实验预算：案例复盘的共同教训是"先定位再开方"，而不是环环都撒网。
- 累计用户数、PV 等虚荣指标会污染漏斗各环读数（x19：刷榜、刷 PV、总用户数有水分）——填数前先验口径。

### 作者的盲点 / 时代局限

- AARRR 是 Dave McClure 的公共框架，本书贡献的是操作化用法；书中未讨论环节间的反馈回路（传播改善会反哺获取），也未做任何统计严谨性处理。
- **时效警示：2015 年快照。** 附录 A 的 26 项指标口径与渠道结构（Web 为主、应用商店权重）需按当代 MMP、LTV:CAC、隐私新政环境更新，各环节转化率基准**按当期重查**；本 skill 只保留"定位卡点→对该环单独设计实验→滚动复测"的判断逻辑层，以及与"真增长=新增−流失"的修正组合。

### 容易混淆的邻近方法论

- RARRA（留存优先于获客）：作为 AARRR 的当代修正，定位卡点时可用其修正优先级偏见，但漏斗链路诊断本身仍是最短路径。
