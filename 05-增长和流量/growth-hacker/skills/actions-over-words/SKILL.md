# "行胜于言"用户调研法

## R — 原文 (Reading)

> 用户说了什么固然重要，但更多心思应当花在分析他们做了什么。这就像是你询问 100 个人是否愿意为了健康而去健身房锻炼，有 99 个人会予以肯定的答复，但当真到了要掏钱的时候，他们就会畏首畏尾。
>
> — 范冰，《增长黑客》第2章 2.7 "行胜于言"的用户调研

---

## I — 方法论骨架 (Interpretation)

口头意见是一层被污染的信号：受访者受测试环境、提问方式和个人利益三重干扰——想讨好调研者、想显得理性、想引导产品朝对自己有利的方向走。所以决策权重必须重排：

1. **行为数据 > 口头表态**。判断一个功能该不该做，先看有没有人已经在用替代品、绕路方案或第三方插件解决问题——既有的绕路行为是最诚实的需求陈述。
2. **付费意愿是意见权重的校准标尺**。同样是建议，掏过钱的人与免费评论家的意见不等价；设置付费或付出门槛（预购、押金、付费内测）能把"嘴上支持"与"真会使用"分拣开。
3. **口头高度一致反而是失真警报**。调研中 100% 受访者都说某设计重要，恰说明大家都在给出"社会正确答案"，而非真实偏好。
4. **付费过程本身提升建议质量**。花过钱的用户对产品更认真，他们的反馈值得加权。

## A1 — 书中的应用 (Past Application)

### 案例 1: 追TA"一键标为已读"——全员支持却没人用（x03）
- **问题**: 社交应用里"女神"用户每天被搭讪塞爆屏幕，团队计划上线"一键标为已读"防骚扰按钮；先找两位女性朋友征询，回答都是支持。
- **方法论的使用**: 上线后看行为——使用频度远低于预期；群访复盘才揭开谜底：女性会向闺蜜"故作抱怨"大堆未读消息以炫耀异性缘，炫耀需求优先级高于防骚扰。
- **结论**: 口头意见受个人利益干扰，"做了什么"揭穿"说了什么"。
- **结果**: 该功能沦为低频摆设，成为作者亲历的调研陷阱样本。

### 案例 2: 强制填资料调研——100% 支持率与新用户吓退
- **问题**: 调研中近 100% 用户声称注册时强制填写详尽资料"很重要"。
- **方法论的使用**: 对照行为数据——真做出来却吓退了尚未建立信任的新用户。
- **结论**: 口头一致性是失真信号；留存行为才是裁判。
- **结果**: 放弃该设计倾向，回归对新用户行为路径的观察。

### 案例 3: Sendwithus 用点击投票替代访谈（c06）
- **问题**: 该做哪些功能，访谈问不出来（人人客气）。
- **方法论的使用**: 改用假门网站把候选功能做成按钮，用真实点击（行为）而非问卷（口头）做需求投票，配合 GA 点击追踪。
- **结论**: 行为投票给出了明确的功能优先级。
- **结果**: 92 人留资、28 美元完成验证，功能方向随之确定。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户访谈/问卷结果与团队直觉冲突，或不同调研的结论互相矛盾，需要裁决信哪个。
2. "用户都说想要深色模式"式的功能诉求：10 个访谈用户 8 个说想要，做不做？
3. 准备发起用户调研：需要在设计阶段就内置防失真手段（避免诱导性提问、设置付出门槛）。
4. 免费用户与付费用户的意见打架，需要排定权重。

### 语言信号 (用户的话里出现这些就应激活)

- "用户都说想要……""调研显示大多数支持……"
- "访谈结果可信吗？""问卷会不会失真？"
- "users asked for / survey says / 行胜于言 / 口是心非 / 付费意愿"

### 与相邻 skill 的区分

- 与 `mvp-validator` 的区别: 分工是"读数 vs 造实验"——actions-over-words 教你**如何解读**已有调研数据（信什么、加权谁）；mvp-validator 教你**构造**能产生行为数据的验证载体。拿着问卷结论来裁决找本 skill；想收集行为数据找 mvp-validator。
- 与 `demand-four-questions` 的区别: 四问是需求的**结构性拷问**（真伪/刚需/量与肥/变现），不处理调研数据的可信度；本 skill 的"真伪问"落地要靠行为证据，两者在"找行为证据"处衔接但层不同。
- 与 `ab-testing-protocol` 的区别: ab-testing-protocol 是**上线后**双方案并行的实验规范（单变量、预设判优）；本 skill 是**上线前**对调研结论的校验规范。样本是访谈/问卷找本 skill，样本是线上流量分流找 ab-testing-protocol。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **给每条口头主张标注证据等级**
   - 逐条盘点：该主张有没有对应的替代行为证据（用户在用第三方工具/绕路方案/既有功能数据）？
   - 完成标准: 每条主张标注"有行为证据 / 仅口头"两档。
   - 判停条件: 全部仅口头且涉及新功能 → 不直接排期，降级为待验证假设，转步骤 3。

2. **用付费/付出门槛校准权重**
   - 区分付费用户与免费评论家的意见；对争议功能设计小门槛（预购、付费内测、押金）让用户用钱包表态。
   - 完成标准: 输出加权后的意见排序，注明加权依据。
   - 警报条件: 某主张支持率接近 100% → 标记为社会正确答案嫌疑，降低置信。

3. **把待验证主张转为行为实验**
   - 移交 `mvp-validator` 设计假门点击/预购/内测使用率等行为实验，用结果回填裁决。
   - 完成标准: 进入开发的每个结论背后都有行为数据支撑；纯口头主张一律不直接进开发。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户在报告明确的 bug 与性能问题——行为与口头一致（说了也不该发生），直接修，不需要质疑其诚意。
- 法定合规、无障碍等"用户没提也必须做"的需求，不适用行为权重。
- 大流量在线场景的功能裁决——有条件直接 A/B，跳过调研解读环节走 `ab-testing-protocol`。

### 作者在书中警告的失败模式

- x03: 追TA"一键标为已读"——访谈全员支持、上线使用率远低预期；健身房之喻（99 人口头愿意、掏钱时畏缩）是本方法的原始意象。
- 相关警示：口头一致性越高越可疑（强制填资料 100% 支持率的教训）。

### 作者的盲点 / 时代局限

- 付费意愿标尺对免费社交产品、公益产品、网络效应早期产品适用性弱——很多关键行为（邀请好友、生产内容）没有付费通道可校准。
- 书中样本均为作者亲历的个别项目（追TA、云诺），n=个位数案例，归纳强度有限；且全书无统计严谨性讨论，本 skill 的加权规则是启发式而非实证结论。
- **时效警示（2015 年快照，全集群通用）**: 本 skill 只保留"行为优先 + 付费意愿加权"的判断逻辑层；案例涉及的社交产品形态与调研工具已迭代（问卷工具、埋点体系按当期重选），引用案例数据时带幸存者偏差前提。

### 容易混淆的邻近方法论

- 《精益创业》的"经证实的认知": 同向，但本书贡献是"付费意愿作为权重标尺"与"付费过程让用户更认真"两条可操作加权规则。
- Mom Test（Rob Fitzpatrick）: 同样质疑口头承诺，Mom Test 教提问技巧，本 skill 教裁决与加权规则，可组合使用。
