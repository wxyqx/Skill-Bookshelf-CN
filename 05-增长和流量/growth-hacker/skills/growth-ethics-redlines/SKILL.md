# 增长职业道德红线三闸

## R — 原文 (Reading)

> "这些依托技术手段玩出来的小花样，看似'用智商压制了用户'，却在道德上输得一败涂地。……身为本书作者，唯愿这本书中披露的案例和思路，不要将涉世未深的新手们误带到沟里去。"
>
> — 范冰，《增长黑客》后记 增长黑客的职业道德

---

## I — 方法论骨架 (Interpretation)

本书正文介绍的大量手法（垃圾邮件借力、Bug 营销、诱饵按钮、通讯录导入）存在道德灰色地带，作者在后记里给全书装了一个"压舱石"：增长手段在执行前要过三道闸。

1. **换位思考闸**（常识闸）：己所不欲勿施于人——站在用户立场自问"他们知道吗？会接受吗？愿意被朋友知道自己被这样对待吗？"能通过基本良知检验的手法才继续讨论。
2. **最小授权最大知情闸**（权限闸）：逐项审查每一次数据/权限索取——是否必要？用户是否已知？后果是否知情？取最少的数据、给最大的透明。
3. **契约精神闸**（长期闸）：今天"法无禁止即可为"的灰色空间是暂时的，监管和平台规则随时收紧；用手法的长期生存性倒推当下取舍。

任何一闸不过即砍或改设计。技术中立，但使用者不中立——增长手段的聪明程度不能成为豁免道德审查的理由。

## A1 — 书中的应用 (Past Application)

（本单元在聚类总表 A1 列为"—"，以下为 verified.md 单元 U21 的后记证据。）

### 证据 1: Path 通讯录上传与 SkillPages 群发邮件（后记，x18 附属案例）
- **问题**: 社交产品想靠通讯录快速建立关系链。
- **方法论的使用（反面）**: Path 未经许可上传用户手机通讯录；SkillPages 获取 Gmail 授权后向全体联系人广告群发——授权被挪作未经知情的他用。
- **结论**: 触发闸二"最小授权最大知情"——索取了必要之外的数据、且用户对用途不知情。
- **结果**: 均引发舆论风波与监管关注，成为后记点名的反面教材。

### 证据 2: 疯狂来往"艳照门"（后记，x18 主案例）
- **问题**: 游戏想用摄像头增强玩法。
- **方法论的使用（反面）**: 调用摄像头拍摄玩家游戏场面，未经授权擅自在玩家毫不知情时上传至官方优酷账号。
- **结论**: 连闸一的常识检验都不过；"法无禁止即可为"的擦边球在更严的监管环境下面临重罚。
- **结果**: 全民"艳照门"，优酷删除 3.6 万条不雅视频并封号——负面曝光性质是拿用户隐私做营销筹码。

### 证据 3: 正文与后记的张力本身
- **现象**: 正文欣赏 Airbnb 借 Craigslist 垃圾邮件获客、百度云 Bug 营销，后记却自我警醒"不要将新手误带到沟里去"。
- **结论**: 这是作者的自我校准——书中案例应先过道德筛再引用，而不是当作免检模板照搬。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 新功能想默认读取通讯录/上传用户数据/静默调用摄像头，问"能做吗、风险多大"。
2. 策划 Bug 营销、价格漏洞、诱导分享活动前的风险评估。
3. 设计了诱饵按钮（"残忍地拒绝"）、羞辱式注册、制造紧迫感等操纵性交互，要评估是否越线。
4. 团队用"别人都在做""法无禁止"为灰色手段辩护时的独立审查。
5. 复盘某增长手法引发的舆情/下架/封号危机。

### 与相邻 skill 的区分

- 与所有增长技术 skill（viral-k-factor、external-viral-loop、moment-marketing 等）的区别：它们回答"怎么做增长"，本 skill 回答"这个手段该不该做"——是前置守门闸，不是并列方法；冲突时红线优先。
- 与 `turn-penalty-into-reward` 的区别：那是把越轨用户（盗版者、钻漏洞者）当作准付费用户善意转化的设计，方向是善待用户；本 skill 是约束自己不作恶，一内一外。

## E — 可执行步骤 (Execution)

1. **闸一：换位思考**
   - 站在用户立场自问三个问题：他们知道吗？他们会接受吗？愿意被朋友知道自己被这样对待吗？
   - 完成标准：写出用户视角的具体回答（不是"应该没问题"的含糊话）。
   - 判停条件：明显越界（偷拍、偷传、欺诈）→ 直接否决，不进入后续闸，不给出"降低风险后执行"的变体。

2. **闸二：最小授权最大知情**
   - 对每一项数据/权限索取逐项回答三问：是否必要？用户是否已知？后果是否知情？
   - 完成标准：每项数据/权限都有三问答案，并给出"最小化后的收集清单"。

3. **闸三：契约精神与长期推演**
   - 推演：今天法无禁止，明天监管/平台收紧（个保法、ATT、平台封杀）时这个手法会怎样？是否与用户形成了可持续的信任契约？
   - 完成标准：给出至少 12 个月的监管/平台情景推演结论。

4. **裁决并记录**
   - 三闸结论合并：放行 / 修改设计后放行 / 否决。
   - 完成标准：明确裁决 + 修改项清单（如有）+ 留档理由。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 替代法律合规专项审查：GDPR/个保法/消保法的法务意见、安全评估须由专业合规流程承担；本 skill 是方法论层的前置筛，不是法律意见书。
- 当作"如何优雅地操纵用户"的操作指南：其产出必须是放行/修改/否决的裁决，而不是规避审查的技巧。

### 作者在书中警告的失败模式

- x18（疯狂来往艳照门、Path 通讯录、SkillPages 群发）："看似用智商压制了用户，却在道德上输得一败涂地"——负面曝光、封号、监管处罚。
- 正文与后记存在张力：作者一边欣赏 Airbnb 垃圾邮件、Bug 营销，一边自我警醒——引用本书任何增长案例前先过这条道德筛。

### 作者的盲点 / 时代局限

- 书中把诱饵效应（"残忍地拒绝"按钮）、羞辱式注册、徽章强迫症推送、制造紧迫感等行为操纵手法当作中性技巧介绍，与当代 dark pattern 批判直接冲突——按后记立场应整体降权引用。
- **时效警示：2015 年快照。** 本书写作早于 GDPR（2018）、加州 CCPA/ATT（2021）、中国《个人信息保护法》（2021）与主要平台的合规新政——2015 年的"法无禁止"地带如今大多已有明文规则与处罚案例。三闸的判断逻辑保留，法律参数（哪些须明示同意、哪些已明文禁止）**必须按当期法规与平台政策重查**。

### 容易混淆的邻近方法论

- 合规工程（privacy by design）：与本 skill 的闸二同向，但属工程与法务体系；本 skill 定位为增长决策的快速伦理筛。
