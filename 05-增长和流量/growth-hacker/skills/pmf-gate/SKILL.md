# PMF 前置决策门

## R — 原文 (Reading)

> 豪掷千金地大干快上，只是在更快更广地累积负面评价，加速它的垮塌。这就如同强行让一辆残破的二手车在高速公路上以全速冲刺，开得越快就越容易倾覆散架。……叮咚小区用 1 亿元的昂贵失败，为我们证明了 PMF 的重要性。
>
> — 范冰，《增长黑客》第2章 2.3 拒绝昂贵的失败

---

## I — 方法论骨架 (Interpretation)

PMF（Product/Market Fit）指产品切实满足用户某方面需求、被市场接纳的状态。本书的贡献不是发明这个概念，而是把它操作化为一道**决策门**：在出示 PMF 证据之前，三件事被明令禁止——

1. **禁止过早推广**：广告、地推、买量只会放大产品的缺陷，让负面口碑以推广的速度扩散；
2. **禁止过量优化**：在错误方向上精雕细琢，与在错误方向上高歌猛进同样昂贵；
3. **禁止烧钱扩张**：招人、铺城市、加预算都在放大沉没成本。

关键在于**用什么作证据**：不是用户的口头意愿（人人都说喜欢），而是硬证据——留存曲线趋于走平（不再持续下坠）、出现自发口碑推荐、有复购/重复使用。达成 PMF 之前的正途，是从一小部分早期用户获得反馈、以最低成本持续改进；三道禁令解除之后，才轮到 AARRR 漏斗各环的展开。

## A1 — 书中的应用 (Past Application)

### 案例 1: Instagram 从 Burbn 的绝境转型（c03）
- **问题**: Burbn 功能堆叠（签到+行程+游戏+照片分享），发布数周用户停在 1000 多人，无法用三言两语解释清楚——PMF 未达的典型症状。
- **方法论的使用**: 从数据发现用户只爱照片分享功能，砍掉其余，两周做出聚焦的照片应用；先从早期用户中筛 100 人邀请试用，验证后再放量。
- **结论**: 先用最小范围确认契合，再放开口子。
- **结果**: 上线一周注册破 10 万（Burbn 的 100 倍），551 天以 10 亿美元被 Facebook 收购。

### 案例 2: 叮咚小区——决策门失守的代价（x01/c04）
- **问题**: 1 亿元融资，上海地铁单月广告 1500 万，100 多人地推用小礼品换安装——推广火力全开，产品却注册繁琐、频繁闪退、功能贪大。
- **方法论的使用**: 作者复盘：先选几个目标小区试点、收束功能、验证留存与满意度，才应放量；叮咚恰好全程反向操作。
- **结论**: 缺乏成熟产品做依托，再强力的推广也无济于事。
- **结果**: 半年资金链断裂，京沪裁员 70%，几近破产。

### 案例 3: 你画我猜——爆红不等于 PMF（x14）
- **问题**: 病毒式蹿红、被 Zynga 高价收购，看似大功告成。
- **方法论的使用**: 用留存结构检验：缺乏持续吸引用户的长效引擎，新鲜感一过即崩。
- **结论**: 估值和收购价基于传播热度而非留存结构；引爆增长前必须先回答"新鲜感消退后用户凭什么留下来"。
- **结果**: 收购后不到两个月 DAU 从 1460 万跌至 1000 万，半年后不足 200 万。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 融资到账后的分配决策：先扩招/加投放，还是先把留存做实。
2. 增长焦虑：DAU/注册量停滞，团队本能反应是"再多拉点新用户"，需要有人喊停。
3. 资方/上级催放量：外部压力要求"跑马圈地"，需要一套证据语言来顶回去或照办。
4. 复盘失败案例：想知道叮咚小区式的崩塌为什么发生、自家有没有同样前兆。

### 语言信号 (用户的话里出现这些就应激活)

- "要不要开始推广/投广告？""现在能放量吗？""when to scale？"
- "PMF 了没有？""product-market fit 怎么判断？"
- "为什么钱烧完就垮？""过早扩张 / premature scaling"

### 与相邻 skill 的区分

- 与 `demand-four-questions` 的区别: 层次不同——四问筛**单个需求**真伪，是产品内的微观过滤器；pmf-gate 判**产品整体**与市场的契合度，是公司级的宏观决策门。用户问"这个功能做不做"→四问；问"这个产品能不能开始砸钱增长"→pmf-gate。
- 与 `retention-diagnosis` 的区别: retention-diagnosis 是 PMF 证据（留存）不达标时的**细分归因工具**（三口径、五分类、有损服务）；pmf-gate 只做门禁判定——证据够不够、放不放行。先过门禁，不达标再去诊断。
- 与 `aarrr-funnel-diagnosis` 的区别: aarrr-funnel-diagnosis 假设已过 PMF 门，在漏斗各环里定位转化卡点分配实验预算；pmf-gate 是它逻辑上的前置。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **收集 PMF 证据清单**
   - 逐项核对三类硬证据：①留存曲线是否走平（次日/7日/30日趋势，而非单点数值）②有无自发口碑（自然推荐、未经激励的分享与复购）③核心行为重复率。
   - 完成标准: 三类证据各标注"有（附数据）/无/未知"，禁止用用户访谈好感度替代。
   - 判停条件: 三类证据缺失或存疑 → 输出"禁止扩张"裁决，跳到步骤 3 的补救路径，不进入步骤 2。

2. **证据存疑时定量校验**
   - 用留存三口径对照品类基准（游戏 40-20-10、电商 20-30% 等），量化与达标线的差距。
   - 完成标准: 得出"距基准还有多远"的量化结论，并注明基准系圈内口传、仅作锚点。

3. **输出裁决与下一步**
   - 未过门: 冻结推广/扩张预算，把资源改道 `mvp-validator`（补验证）或 `retention-diagnosis`（补留存），并用 `demand-four-questions` 复查核心需求。
   - 已过门: 移交 `aarrr-funnel-diagnosis` 定位最弱环节，扩张预算只对瓶颈环节下注。
   - 完成标准: 裁决书面化，且每条资源改道建议都对应到具体工具与预期指标。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 产品已稳定盈利、留存健康，用户问的是增长效率问题——直接进漏斗诊断，不需要回门禁。
- 单个功能要不要做的讨论——那是需求层，走 `demand-four-questions`。
- 把"PMF"当作口头安慰剂：本 skill 的价值在"出示证据"，若用户只想给自己的扩张决定找背书，应先质疑动机而非套流程。

### 作者在书中警告的失败模式

- x01: 叮咚小区——未达 PMF 豪掷亿元，推广越猛，负面口碑扩散越快。
- x14: 你画我猜——爆红与高价收购都不构成 PMF 证据，留存结构才是。
- x12: Color——明星团队 + 4100 万美元融资救不了跑不通核心流程的产品。

### 作者的盲点 / 时代局限

- 书中未给出 PMF 的统一量化阈值，判据偏定性；40-20-10 等基准系圈内口传（Alex Schultz 分享）而非实证，只能作参考锚点。
- 幸存者偏差: Instagram 的转型成功被归因于手法，无数同样转型死掉的竞品被隐去，转型失败基率从未统计。
- **时效警示（2015 年快照，全集群通用）**: 本 skill 只保留"证据先行、三禁止"的判断逻辑层；案例中的 O2O 补贴环境、开放平台红利、渠道成本参数均已改变（补贴大战被监管终结、买量结构重写），扩张相关的具体参数按当期重查，案例数据引用须带幸存者偏差前提。

### 容易混淆的邻近方法论

- Eric Ries"转型（pivot）": pivot 是未过门时的转向动作，本 skill 管的是门禁判定与放行/冻结，转向执行交回 MVP 与需求层工具。
- RARRA 框架: 对 AARRR"获客优先"排序的修正；与本 skill 同向（留存优先），可在裁决后作为资源排序的补充视角。
