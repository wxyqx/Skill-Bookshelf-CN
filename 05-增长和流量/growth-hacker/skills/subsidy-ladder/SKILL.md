# 补贴阶梯：从现金到红包的演进与退出

## R — 原文 (Reading)

> "相较于现金补贴，红包补贴的本质区别在于其具有通过关系链进一步传播的能力。如果说现金补贴培养了单个用户的使用行为和忠诚度，那么红包补贴有助于让种子用户引来更多的潜在用户，同时加强了参与感与荣耀感。"
>
> — 范冰，《增长黑客》第4章（旷日持久的补贴大战）

---

## I — 方法论骨架 (Interpretation)

补贴有形态高低之分，核心判据只有一条：**这份钱花出去，除了影响当次决策，还能留下什么？**骨架是一张演进阶梯加一道预演题：

1. **阶梯第一级——直接返利**：压垮犹豫用户的"最后一根稻草"，适合转化临门一脚，但只影响单次决策。
2. **第二级——限期生效优惠券**：把有效期对准用户的预估流失周期，用于挽留"快要走了的人"，比无差别返利省钱且精准。
3. **第三级——撒钱式现金补贴**：能快速教育市场、抢份额，但"给补贴用户就多，不给补贴用户就少"，忠诚建立在价格而非产品上，是消耗战武器，只适合资本雄厚的各方都输得起的战场。
4. **第四级——红包补贴**：补贴必须分享到关系链才能使用，随机金额下"抢到最大红包的往往是从没用过你的人"——一份预算同时完成拉新（关系链二次传播）、留存（参与感与荣耀感）与传播，把经济交换升级为情感交流。
5. **退出预演**：任何补贴方案在设计时就该回答"停止补贴后留存曲线长什么样"——如果答案是断崖，说明补贴买的是行为假象，应尽早往阶梯高层升级并规划退坡节奏。

一句话：能用关系链流动的补贴，就别用打进账户的现金；设计补贴时同时设计它的退出。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 滴滴从现金大战到打车红包（c11）
- **问题**: 2014 年滴滴与快的现金互搏——用户每单补几元到十几元、司机每单补 7-20 多元另加每日 150 元，市场教育成熟了，但"补贴一停订单急剧下降"（程维自述），双方被拖入无底洞。
- **方法论的使用**: 把补贴升级为打车红包——红包不直接入账，必须分享到微信朋友圈或好友、被抢走并使用才能生效；随机金额机制使最大红包往往流向从未用过滴滴的新客。
- **结论**: 红包借关系链二次传播，让补贴从"单次决策的折扣"升级为"自带拉新与留存的机制"，摆脱纯价格消耗战。
- **结果**: 补贴停发后订单不再断崖式下滑，红包玩法被蜜淘、天猫等电商广泛复制成为行业标配（灵感源自微信红包 9 天发出 4000 多万封）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 有一笔有限的拉新预算，在"发现金券/满减券/分享红包"之间做形态决策。
2. 补贴已经跑了一段时间，发现停不下来：一停订单/活跃就掉，要诊断并升级形态。
3. 要设计补贴退坡计划（投资人说烧钱烧到某节点必须停）。
4. 竞品发起价格战，判断跟进撒钱还是换打法。

### 语言信号 (用户的话里出现这些就应激活)

- "补贴怎么设计 / subsidy / 发券还是发红包"
- "拉新预算有限，怎么花效果最好 / 获客成本太高"
- "补贴一停用户就跑 / 补贴依赖 / 烧钱大战"
- "补贴什么时候能停 / 退坡计划 / phase out"

### 与相邻 skill 的区分

- 与 `gamification-boundary` 的区别：游戏化用积分/徽章等**非金钱**激励做活跃，本 skill 专管**真金白银**的补贴形态与退出；两者可组合（补贴+游戏化玩法）但判据不同。
- 与 `freemium-decision` 的区别：免费/收费是**商业模式定价**问题（免费版要不要存在）；补贴是**推广预算**怎么花的问题，别混淆"免费"与"补贴"。
- 与 `external-viral-loop` 的区别：红包的传播性内嵌在补贴机制里；体外病毒循环是主产品之外另建独立增长体系（H5 小游戏等）。若用户想做的是活动策划而非补贴设计，归对方。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **明确补贴目标与预算约束**
   - 确认这次补贴主要解决什么：转化临门一脚（返利级）、防流失（限期券级）、抢市场份额（现金级）、还是拉新+留存+传播一体（红包级）；同时写下预算总量与可用时长。
   - 完成标准: 产出一句话目标声明 + 预算上限，且目标对应到阶梯的具体层级。

2. **按阶梯选形态并设计机制**
   - 目标是单次转化→返利/限期券即可（把有效期对准预估流失周期）；需要拉新与留存→红包：设计"必须经关系链流动才能使用"的机制（分享解锁、随机金额、可转赠）。
   - 完成标准: 补贴方案含形态、领取/使用门槛、流向机制，并说明为什么停在这一级而不是更高/更低。
   - 判停条件: 若团队没有关系链场景（如工具类产品无社交触点），跳过红包级，改为限期券+其他传播机制组合，勿硬做分享。

3. **预演停止补贴后的留存曲线**
   - 在方案评审时回答：补贴停止后第 1/4/12 周的订单与留存预计如何？哪些用户是价格敏感型（会走）、哪些是产品留住的？
   - 完成标准: 有带数字的退坡预演（哪怕粗略），并据此设定阶梯递减的退出节奏（如按周期递减额度、转红包拉新续池）。

4. **上线后按补贴流向校准**
   - 监控补贴流向判据："抢到大额补贴的是新用户还是老羊毛党"；若大额补贴被存量用户套走，调整随机区间与领取门槛。
   - 完成标准: 每周补贴流向报告（新客占比/复购率/单位拉新成本），并触发一次方案微调。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **产品核心价值未立住时用补贴遮短板**：补贴是短期杠杆，买不来留存；给漏水的池子灌水只会加速暴露问题。
- **无预算纪律的跟风价格战**：资本不具备消耗战条件时，跟进撒钱等于自杀，应转差异化打法。

### 作者在书中警告的失败模式

- 滴滴快的现金大战之鉴（x11）：现金补贴"给补贴用户就多，不给补贴用户就少"，忠诚建立在价格上，补贴一停订单急剧下降，双方陷入不能停的军备竞赛——补贴设计必须预演停止后的留存曲线。
- 补贴流向错配：若最大额补贴总被已有的价格敏感老用户套走而非流向新客，补贴的钱就在空转。

### 作者的盲点 / 时代局限

- 案例全部来自资本加持的巨头战争（滴滴/快的/微信红包），小团队既无补贴消耗战的资金池，也无微信级的关系链基础设施；书中未讨论补贴对供给侧（司机/商户）的扭曲与刷单套利问题。
- **2015 年快照时效警示**：O2O 现金补贴大战已被监管介入与资本周期终结，无门槛现金补贴在多地涉不正当竞争与合规风险——**只保留"阶梯演进+关系链流动+退出预演"的判断逻辑层，补贴形式、力度、行业合规要求按当期法规与市场环境重查**。

### 容易混淆的邻近方法论

- 游戏化（`gamification-boundary`）：非金钱激励的活跃放大器；免费/收费决策（`freemium-decision`）：定价结构而非推广预算；两者都常被泛称为"让利"，判据与工具完全不同。
