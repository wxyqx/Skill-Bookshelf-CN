# 唤醒机制：三通道选型与四策略内容

## R — 原文 (Reading)

> "唤醒机制是指互联网产品中专为召回流失用户而设计的产品机制。常用的唤醒机制包括：电子邮件唤醒、消息推送通知、移动网页唤醒应用等。"
>
> — 范冰，《增长黑客》第5章（设计唤醒机制）

---

## I — 方法论骨架 (Interpretation)

召回不是"多发几条推送"，而是一张"通道 × 内容"的选型矩阵加一条定位原则：

1. **通道按触达深度选**：用户流失后你还能碰到他的方式分三级——邮箱可达（EDM）、App 内推送权限仍在（推送通知）、只剩浏览器偶发访问（网页唤起 App，如 Url Scheme/Chrome Intent）。通道选错，内容再好也到不了人。
2. **内容从四策略里选一把刀**：①提供奖励（优惠码、付费功能试用）；②告知进展（用户离开期间积累的价值，如离线收集的数据）；③个性化推荐（按行为偏好推送他关心的内容，而非千篇一律群发）；④社交互动提示（"有人圈了你/给你留言"——书中实测此类邮件点击转化最高）。
3. **频控是生死线**：推送能把日启动率大幅拉高，但也曾让两成以上用户因推送直接卸载——唤醒与骚扰之间只隔一个频次设置。
4. **定位原则**：唤醒是**补救手段而非替代品**。产品本身不值得回来的话，任何通道和文案都是延缓死亡。

一句话：先分层找通道，再按流失原因配内容，最后用频控保住没流失的人。

## A1 — 书中的应用 (Past Application)

### 案例 1: 安迪·琼斯把 Twitter 邮件召回机制化（c02）
- **问题**: Twitter 早期的邮件提醒靠手动 Python 脚本群发，发 1000 万封要三天，召回全凭人力。
- **方法论的使用**: 把邮件唤醒做成自动化机制——新粉丝、被转发、被@时第一时间触发邮件召回，属于"社交互动提示"策略的机制化落地。
- **结论**: 唤醒要靠产品机制而非临时运营动作，触发时机绑定用户关心的社交事件。
- **结果**: 配合着陆页与新人引导改造，两年间活跃用户从 1 亿增至 5 亿。

### 案例 2: LinkedIn 用社交事件双向唤回（c10）
- **问题**: 早期高达 50% 注册用户是沉默用户，活跃度止步不前。
- **方法论的使用**: 设计"双重病毒循环"的第二环——新用户的注册动作（好友请求、资料被浏览通知）持续把老用户卷回产品处理请求；配合邀请邮件讲清"对对方的价值"，属社交提示+个性化组合。
- **结论**: 唤回老用户的最佳钩子是他在乎的社交关系事件，而非产品公告。
- **结果**: PV 提升 41%、站内搜索量提升 33%，新老用户互相唤回形成自维持循环。

### 案例 3 (反例): 新浪微博"越骚扰越流失"（x13）
- **问题**: 活跃下滑后用不必要的通知、生搬硬凑的话题、不合口味的推送强行召回。
- **方法论的使用**: 正是本 skill 警告的失败面——无频控、无个性化、无社交理由的打扰式唤醒。
- **结论**: 唤醒剂量加大只会加速流失，被媒体点名"请停止骚扰用户"。
- **结果**: 死循环固化，召回彻底失去信用。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 手里有一批 N 周/N 个月未打开的沉默或流失用户，要设计唤回方案。
2. 争论"该发邮件、发推送还是短信/私域触达"，或唤醒内容群发效果差。
3. 推送权限还在但打开率极低，怀疑频控或内容出了问题。
4. 想从网页/H5 访问把用户唤起回 App。
5. 评审召回活动方案时，要判断"这是补救还是饮鸩止渴"。

### 语言信号 (用户的话里出现这些就应激活)

- "流失用户怎么召回 / win-back / 唤回沉默用户 / 90 天未活跃"
- "召回邮件 / EDM 怎么写 / 推送文案 / push 召回"
- "推送会不会被卸载 / 频控怎么设 / 打扰用户"
- "网页唤起 App / deep link / 沉默用户激活"

### 与相邻 skill 的区分

- 与 `retention-diagnosis` 的区别：诊断管**为什么流失、先修什么**；本 skill 管**怎么把人拉回来**（通道与内容执行）。用户问的是流失原因分析归诊断，问的是召回方案设计归本 skill；若诊断结论是产品硬伤，先止血再唤醒。
- 与 `activation-aha-magic-number` 的区别：激活优化面向**从没用顺的新用户**（首日引导、魔法数字）；唤醒面向**用过之后离开的人**。"注册后没引导好"归激活，"老用户不回来了"归唤醒。
- 与 `subsidy-ladder` 的区别：唤醒四策略中的"提供奖励"若涉及真金白银的券/红包设计（形态、流向、退出），预算层问题移交补贴阶梯；本 skill 只管通道与内容机制。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **判停前置：确认产品值得回来**
   - 先问一句：用户回来后能体验到什么他当初没有的东西？若答案是"没有"，说明是留存硬伤而非召回问题。
   - 完成标准: 一句话写明"回来的理由"；写不出则停止唤醒设计，移交 `retention-diagnosis`。
   - 判停条件: 流失根因属性能硬伤/骚扰（见诊断五分类）时，先做止血与降噪，唤醒方案延后。

2. **按触达深度分层选通道**
   - 把目标流失用户按可达性分层：邮箱可用 / 推送权限在 / 仅网页触点，逐层匹配通道；不可达层明确放弃，不硬打扰。
   - 完成标准: 一张分层×通道的映射表，每层有预计触达规模。

3. **按流失原因匹配内容策略**
   - 从四策略中选主策略：价格敏感→奖励；离开期间有价值积累→告知进展；行为数据足够→个性化推荐；社交产品优先→社交互动提示。文案落到"对对方的价值"，不做产品公告式群发。
   - 完成标准: 每层通道有明确策略归属与一条可发出的样例文案。

4. **设频控并度量副作用**
   - 设定触达上限（如每人每周 ≤1 次）、退订入口与免打扰时段；监控唤醒回访率、退订率与卸载率。
   - 完成标准: 方案含频控参数 + 三个效果指标（回访/退订/卸载）与复查时间点；任一副作用指标恶化即降频或停发。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **产品留存硬伤未修时用唤醒续命**：唤醒是补救不是替代品，漏水的桶先补漏。
- **把唤醒当增长引擎冲 KPI**：召回对象是有限存量，撑不起新增目标；要新增去找获客方法。

### 作者在书中警告的失败模式

- 新浪微博之鉴（x13）：无频控、无个性化、无社交理由的暴力打扰，把召回做成"以骚扰用户为己任"，越唤越流。
- 推送的暗面：推送可大幅拉高日启动率，但也有 23% 用户曾因推送直接卸载——授权时机与频次比文案更要命。

### 作者的盲点 / 时代局限

- 书中案例集中于欧美邮件生态与 2015 年前的推送环境；未讨论法律层面（退订合规、隐私授权）与职业羊毛党对奖励型召回的套利。
- **2015 年快照时效警示**：EDM 四策略在欧美市场有效、国内邮件打开率极低——**通道层必须按目标市场替换**（国内以短信、App 推送、私域社群等替代邮件为主通道）；网页唤起的技术方案与平台政策（浏览器/OS 对 deep link 与通知授权的限制）按当期重查；社交事件触发的数据使用须过隐私合规。**skill 只保留"分层选通道×按因配策略×频控"的判断逻辑层。**

### 容易混淆的邻近方法论

- 唤醒（本 skill）≠ 留存诊断（`retention-diagnosis`，判断层）≠ 补贴设计（`subsidy-ladder`，预算形态层）。"发券召回"这类混合需求应显式拆成内容策略（本 skill）与补贴形态（对方）两层分别处理。
