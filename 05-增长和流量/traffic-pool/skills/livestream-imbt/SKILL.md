# 电商直播 IMBT（Livestream IMBT）

## R — 原文 (Reading)

> "IMBT是idea & IP（创意和IP）、media（媒介）、benefit（福利）、technology（技术）的首字母缩写。"
> "在90分钟的直播时间内，点赞量突破1820万。神州买买车卖出2717辆科鲁兹，订单金额高达2.28亿元，平均每分钟卖出11台。"
>
> — 杨飞，《流量池》第11章 直播营销的流量掘金

---

## I — 方法论骨架 (Interpretation)

直播带货不是"网红+一部手机+一个自拍杆"，而是一次以综艺真人秀规格生产的内容工程。IMBT 四个字母对应四件必须事前做好的事：Idea & IP——用综艺规格写分环节脚本（生日派对、模仿秀、教学环节等五六个环节，爆点密集），幕后有场控、导播、弹幕管理，呈现的是"粉饰的真实"；Media——平台选型看目标：综合型平台要声量、垂直型按行业、电商型要销量，预算充裕就用"电商平台落地+综合平台造声量"的组合；Benefit——福利是流量黏性的第一前提，红包雨节奏、半价车触发条件、买赠规则与物料必须前置设计，而不是开播后临场发挥；Technology——连麦、浮层特效、拍摄与导播保障，决定画面是否扛得住综艺规格。

内容上三指向：年轻化把人引进来、趣味性把人留住、爆点密集促转化。直播还要当一次完整的事件营销做项目制操作：直播前社媒预热造话题、直播后用微信服务号沉淀用户。

作者成书时观察到"直播营销趋冷"，但"综艺规格内容+福利刺激+电商闭环"的骨架恰在此后被直播电商大爆发验证——所以本方法只保留逻辑层，平台与玩法参数须按当期重查。

## A1 — 书中的应用 (Past Application)

### 案例 1: 神州买买车王祖蓝直播卖车（2017年1月）
- **问题**: 汽车新品牌要在直播间把高客单的车卖出去，此前直播卖车无先例可循。
- **方法论的使用**: I——借"买买舞"刷屏铺垫认知，脚本按综艺规格设计生日派对、模仿秀、教学买买舞等五六个环节；M——天猫直播（电商）为主、一直播（综合）为辅双平台同步，微博话题"王祖蓝0109生日快乐"预热居话题榜第一；B——4 轮共 5 万元红包雨、买车送 iPhone 7、每 50 单送半价车，福利规则与物料全部前置；T——专业拍摄与场控保障。
- **结论**: 综艺规格内容+福利规则前置+电商闭环能把曝光直接压成订单；流量规模本身不是转化的原因（对照 papi 酱首秀 2000 万在线零转化）。
- **结果**: 90 分钟点赞 1820 万、售出 2717 辆科鲁兹、订单金额 2.28 亿元、平均每分钟 11 台，获当年天猫年度营销案例奖。同年 5 月"喵了个车"再战：下订 1408 台、付款成功 1038 台——约 26% 的下订-付款缺口提示"订单口径"须审视。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 公司要策划第一场带货直播：平台怎么选、脚本怎么写、福利怎么设、技术怎么保。
2. 直播观看人数高但下单少，要诊断内容与福利环节哪里断了。
3. 争论"预算先投头部主播还是先做脚本和福利池"。
4. 要为直播配套直播前的预热话题与直播后的私域沉淀。

### 语言信号 (用户的话里出现这些就应激活)

- "直播策划/直播脚本/带货直播怎么搞""直播间没人下单""福利怎么设计""直播预热"
- "livestream commerce / live selling / 直播转化"
- "请主播还是自播""红包雨/秒杀/半价怎么安排"

### 与相邻 skill 的区分

- 与 `bd-traffic-exchange` 的区别（互斥对）: CL19 管品牌间商务合作与流量互洗的谈判与分层推进；本 skill 只管**直播这一形式的项目操作**。若合作产出是"两个品牌联合做一场直播"，执行层用本 skill、合作关系层用 CL19。
- 与 `event-marketing-five-boosts` 的区别: CL14 是通用事件营销程序（热点、五爆点、借势/造势决策）；本 skill 是直播的具体形式落地。判断"要不要做、怎么借势"用 CL14，"这场直播怎么做"用本 skill。
- 与 `wechat-service-superapp` 的区别: CL12 管直播后微信端的沉淀与运营；本 skill 管直播战役本身。

## E — 可执行步骤 (Execution)

1. **定目标与平台选型**
   - 写清本场直播的唯一主目标（声量还是销量），按三类选型：综合型平台要声量、垂直型按行业、电商型要销量；预算充裕用"电商落地+综合造声"组合。
   - 完成标准: 主平台与副平台确定，各有考核口径（观看/互动 vs 下单/GMV）。

2. **IMBT 四环逐项交付**
   - I: 综艺规格分环节脚本（5~6 个环节、每环节有爆点）；M: 资源位与多平台同步方案；B: 福利池、触发规则（红包雨节奏/满赠/秒杀）与物料清单前置定稿；T: 拍摄、连麦、浮层、场控、弹幕管理清单。
   - 完成标准: 四环各有一份可执行交付物。
   - 判停条件: 脚本或福利规则任一未定稿——不开预约、不投预热（对照 papi 酱首秀：有流量无内容设计则零转化）。

3. **事件化操作**
   - 直播前社媒预热话题上线；直播中多平台同步；直播后微信服务号/私域承接沉淀（沉淀运营归 wechat-service-superapp）。
   - 完成标准: 预热内容与沉淀承接位在开播前就绪。

4. **以转化口径复盘**
   - 复盘用全漏斗：观看→互动→下订→付款（注意区分"下订"与"成交"口径）。
   - 完成标准: 有一份漏斗数据与下一场的改进假设清单。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 品牌间异业合作、互相导流、资源置换——归 bd-traffic-exchange；本 skill 不处理合作关系本身。
- 没有销售/转化目标的纯内容直播（节目、发布会走流程）——先回到 event-marketing-five-boosts 判断要不要做、怎么借势。
- 日常店铺自播的排班与话术 SOP——书内方法论是"战役式"单场项目制，日常店播只可借其内容与福利逻辑，不可照搬项目规格。

### 作者在书中警告的失败模式

- papi 酱首秀与杜蕾斯 AIR（反例 x34）: 八大平台 2000 万在线的 papi 酱首秀因"没有内容规划"零转化；杜蕾斯三小时直播"搬了一小时床、聊了一小时天、做了一小时操"，空有流量数据——"粗制滥造的营销直播，很难带来真正收效"。
- "发布会+直播"噱头（反例 x35）: 直播只是采编流程附属，内容形式传统专业，"直播在整个过程中成为一个可有可无的宣传手段"；另一极端是停留在看脸秀场模式——没有福利打通就"只有品牌曝光量而没有实际销量"。

### 作者的盲点 / 时代局限（时效警示：2018 年快照，直播判断已被推翻）

- **本书为 2018 年快照，直播判断与平台规则已被 2019 年后的业态推翻，只保留判断逻辑层，参数层须按当期重查**: 作者写作时观察到"直播营销趋冷、天猫把直播按钮降权"，2019 年后直播电商爆发直接推翻该判断——但"综艺规格内容+福利刺激+电商闭环"的骨架恰被验证，故本 skill 只保留此逻辑层。
- 书内平台（天猫直播、一直播）、玩法参数（红包雨金额、半价车触发、多平台同步策略）均已换代（抖音/快手/淘宝/视频号直播、投流与达人分销机制）；引用前必须按当期平台规则与合规要求（广告法、价格法、直播营销管理办法）重查。
- 2.28 亿是"下订"口径而非交付（对照"喵了个车"付款缺口约 26%），引用书内战报数据须注明口径水分；书中所有战报均为甲方单方口径、无第三方审计。

### 容易混淆的邻近方法论

- 网红/达人营销: 达人合作是媒介采买逻辑，IMBT 是内容工程逻辑；请了头部主播不等于做了直播营销。
- 电视购物: 形似而神不同——电视购物是单向叫卖，直播的转化依赖互动、福利节奏与电商闭环。
