# 拒绝—退让策略 (Door-in-the-Face)

## R — 原文 (Reading)

> "先提出一个比较大的、我极可能会拒绝的请求。然后，在我拒绝了这个请求之后，你再提出那个小一些的、你真正感兴趣的请求。"
>
> — Cialdini, 第二章 · 互惠

---

## I — 方法论骨架 (Interpretation)

策略分两步：先提一个大请求（预期被拒），再提真正感兴趣的小请求。被拒后的退让被对方感知为"让步"，触发互惠原理使其也做出让步（答应小请求）。同时认知对比原理使小请求在对比下显得更无足轻重。

两个机制叠加使该策略异常有效：互惠驱动"你让步了我也要让步"的义务感，对比放大"小请求显得更小"的感知。更危险的是两个副产品——受害者对协议更有责任感（"是我促成的，我争取到了让步"）和更高满意度（"对方终于让步了"），因此更可能履行承诺并继续合作。

关键边界：最初的大请求不能太极端，否则被视为无诚意而使策略失效。

## A1 — 书中的应用 (Past Application)

### 案例 1: 童子军巧克力 (c07)

- **问题**: 作者为什么会买下自己完全不喜欢、不需要的巧克力？
- **方法论的使用**: 童子军先推销5元门票（大请求，被拒），退到1元巧克力（小请求，真实目标）。互惠（对方"让步"了→我也要让步）+ 对比（1元 vs 5元显得无足轻重）双重作用
- **结论**: 作者买了完全不需要的东西，且对协议有责任感和满意度
- **结果**: 作者购买后意识到自己中了圈套

### 案例 2: 水门事件决策 (c08)

- **问题**: 为什么尼克松团队会批准一个荒唐的闯入计划？
- **方法论的使用**: 利迪先后提出100万、50万、25万三个计划。前两个被否决后，25万在对比下显得"可以接受"，米切尔和马格拉德在互惠+对比双重作用下批准了。唯一反对的拉如没有参加前两次会议
- **结论**: 拒绝退让在重大政治决策中同样有效。未被锚定的人（拉如）能看清荒谬
- **结果**: 导致了尼克松总统下台的政治灾难，验证了策略在重大决策中的破坏力

### 案例 3: 策略的两个副产品

- **问题**: 为什么受害者不仅答应了，还更满意、更可能履行承诺？
- **方法论的使用**: 实验显示，被拒绝退让策略说服的人比直接被小请求说服的人对协议更有责任感和满意度。因为他们认为"是我促成了这个更好的协议"
- **结论**: 策略的真正危险不只是让你答应一次，而是让你相信这是你自己的选择，因此更可能履行并继续合作
- **结果**: 这解释了为什么拒绝退让策略的受害者很少事后反悔

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户在谈判中对方先报极端条件再"让步"，需要判断是否被操纵
2. 用户在销售场景中对方先展示高端套餐再推荐中端套餐
3. 用户在 fundraising/募捐场景中对方先问大额捐款再问小额
4. 用户在职场中老板先提不可能的任务再"降低"到加班要求

### 语言信号 (用户的话里出现这些就应激活)

- "他先提了个大的再退到小的""对方让步了""先大后小"
- " door-in-the-face ""拒绝退让""他先报高价再打折"
- "对方降低了要求我就觉得该答应""他让步了我不好意思拒绝"
- "感觉是我争取到的让步""是我促成的"

### 与相邻 skill 的区分

- 与 `reciprocity-defense` 的区别: 互惠防御关注一切利用互惠原理的场景（包括不请自来的礼物），本 skill 专指"先大后小"这一特定策略。拒绝退让是互惠+对比的组合应用
- 与 `contrast-principle` 的区别: 认知对比是底层感知机制，拒绝退让是装了对比+互惠双引擎的具体策略

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **识别策略结构**
   - 回溯对方是否先提了另一个请求（被拒/被否决）后再提当前请求
   - 完成标准: 能说清"对方先提了X（大），我拒了，然后提了Y（小=当前请求）"
   - 判停条件: 若没有前置的大请求，则不是拒绝退让策略，跳到 reciprocity-defense 或 contrast-principle

2. **评估锚定效应**
   - 忽略第一个请求（锚），独立评估当前请求本身的合理性
   - 问："如果对方一开始就提Y，没有X作对比，我还会觉得Y合理吗？"
   - 完成标准: 能给出一个不依赖与X对比的独立判断

3. **消除责任感错觉**
   - 识别"是我促成的"这个副产品——对方的"让步"不是给你做的好事，是策略的一环
   - 问："这个'让步'是对方主动的善意，还是设计好的退路？"
   - 完成标准: 能区分"真诚让步"和"策略性退让"

4. **做出独立决策**
   - 基于当前请求本身的优劣做决定，不因对方的"让步"而感到义务
   - 完成标准: 能坦然接受或拒绝，不伴随"我欠他的"感觉

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 正常讨价还价——双方协商中的让步是善意协商，不是单方面设计的圈套
- 直接请求——如果对方只提了一个请求，没有前置的大请求，不适用此 skill
- 无"拒绝"环节——策略的关键是"被拒后退让"，如果大请求被接受了就不需要退让

### 作者在书中警告的失败模式

- **两个副产品使人持续合作**: 责任感（"是我促成的"）和满意度（"对方终于让步了"）使受害者更可能履行承诺并继续合作。即使识破了策略，这两个副产品仍可能在潜意识层面影响行为
- **最初请求太极端会失效**: 如果第一个请求明显不真诚（如"给我100万"），策略会被视为无诚意而失效。有效的拒绝退让需要第一个请求"大到不太可能被接受，但不至于被视为荒谬"

### 作者的盲点 / 时代局限

- 拒绝退让在B2B大额谈判中的效力可能比日常消费场景弱（企业有更完善的决策流程）
- 数字时代的"倒计时优惠"（先显示原价再显示折扣价）是对比+互惠的简化变体，但缺少"拒绝"环节

### 容易混淆的邻近方法论

- **入门策略 (foot-in-the-door)**: 方向相反——入门策略是从小请求开始递增到大请求，拒绝退让是从大请求退到小请求。两者利用的原理也不同：入门利用承诺一致，退让利用互惠+对比
- **抛低球 (low-ball)**: 抛低球是先给好条件诱使承诺再拿走，拒绝退让是先提大请求被拒再提小请求——前者是"先甜后苦"，后者是"先苦后甜"
