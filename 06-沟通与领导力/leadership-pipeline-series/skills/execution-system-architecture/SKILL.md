# 执行三基石与三流程整合架构

## R — 原文 (Reading)

> "执行是目标与结果之间的桥梁。"……"不是简单的战术，而是一套通过提出问题、分析问题、采取行动的方式来实现目标的系统流程；一门将战略与实际、人员与流程相结合，以实现预定目标的学问。"
>
> — 博西迪/查兰/伯克，导言·执行的定义（L202、L208）

> "执行的三大基石是领导者的七项基本行为、企业的文化变革框架和知人善任。"
>
> "执行的三大流程是人员选育流程、战略制定流程和运营实施流程。"
>
> — 同上，导言（L369、L371）

>
> — 同上，第1章（L572）

## I — 方法论骨架 (Interpretation)

执行不是"把事做好"的战术细节，而是一套系统：它有地基，也有管道。

- **三基石**是地基：①领导者的七项基本行为（了解企业、实事求是、定目标排优先序、持续跟进、赏罚分明、教练辅导、了解自己）；②文化变革框架（目标→条件→奖励→教练/处置）；③知人善任（岗位标准→面试核验→事实评估→梯队培养→处置不胜任者）。缺任何一块，流程都会退化成形式主义。
- **三流程**是管道：人员选育、战略制定、运营实施。它们不是三个部门的职能，而是三条必须互相咬合的流程——人员按战略与运营需求来选，战略必须经过执行能力检验，运营把战略目标分解为可跟进的任务。
- 三流程的共同实践者必须是领导者本人；一旦外包给规划、HR 或财务，系统就失去真实信息与判断力。
- 诊断用法：出现"目标与结果之间的鸿沟"时，不叠加新工具，而是逐环查找脱钩点——先定位最弱环，再修那一环。
- 全书骨架：基石决定流程能不能转，流程决定目标能不能落地。

## A1 — 书中的应用 (Past Application)

### 案例 1: CEO 乔——战略完美却丢饭碗
- **问题**: 乔请顶级咨询公司做了战略、完成了一系列并购、确定了阶段性目标，由 CFO 把数字传达给执行者，自己对季度数字保持密切关注；用传统管理分析标准看，他"没有做错任何事"，但目标全面落空。
- **方法论的使用**: 作者用三流程＋行为逐环复盘：目标没有征得实施者认同、也没有人回答"如何实现"（运营流程缺参与与计划）；他只盯数字、不追问根因（行为缺"了解企业"与"持续跟进"）；选人不当（人员流程失效）。
- **结论**: "根据执行型企业的标准，他几乎一无是处"——问题不在战略质量，而在执行系统整体缺失；执行能力是战略的前提而非结果。
- **结果**: 九个月四次下调收益预期，董事会解雇了他。继任者出身生产部门，带团队与工厂经理共同确定阶段目标并持续跟进后，情况好转。

### 案例 2: 戴尔 vs 康柏——执行是战略的基础
- **问题**: 康柏前任 CEO 法伊弗最早看到 Wintel 体系的市场潜力，通过兼并天腾与数字设备公司把康柏在六年内从高价位 PC 制造商变为世界第二大计算机公司，到 1998 年已"为成为行业主宰做好了充分准备"。
- **方法论的使用**: 作者用此案例说明：战略本身往往不是失败的原因——"康柏公司根本无法将兼并到的公司进行整合"，而且法伊弗与继任者卡佩拉斯都没有采取及时的执行措施；戴尔的直销与按订单生产方式则被贯彻为商业战略的核心，其成功的真正秘诀是量身定做服务、一流的执行水平与对成本的密切关注。
- **结论**: 战略与执行能力必须匹配；不能落到执行环节的战略，无论设计得多完整都无法兑现。
- **结果**: 戴尔年存货周转率高达 80 次（竞争者最多 10–20 次）、运营资本几乎为负；2002 财年第四季度收入 81 亿美元、运营边际收益 7.4%、现金流量 10 亿美元；2001 年投资回报率 355%，并于 2001 年成为世界最大 PC 制造商。康柏则在 PC 日趋家用商品化的过程中错失市场机会。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 组织已经上了 OKR/季度复盘/BI 看板，目标还是完不成，用户想换工具或再上一套系统。
2. 用户观察到"战略讲得漂亮、落地一塌糊涂"，想弄清楚断在哪一环。
3. 用户所在的团队出现"会上都同意、会后没人动"、"材料越做越厚、关键问题无人能答"等形式主义症状。
4. 用户要为自己的公司做一次执行体检，或向老板汇报"执行体系"的诊断结论。
5. 用户在评估一个空降变革者/新流程是否可行，需要判断组织的执行底座是否具备。

### 语言信号 (用户的话里出现这些就应激活)

- "战略落地不了 / 目标完不成 / 为什么执行不下去？"
- "我们上了 OKR，还是不行，是不是该换工具？"
- "三条流程哪一环断了？/ 到底缺人、缺战略还是缺运营？"
- "strategy doesn't land" / "why can't we execute" / "execution gap" / "where is the breakdown"

### 与相邻 skill 的区分

- 与 `b5-f01 leadership-pipeline-six-passages` 的区别: 后者诊断的是"某个人/某一层级是否在正确的层级上工作"；本 skill 诊断的是"组织这套执行系统哪一环脱钩"，对象是系统不是个人层级。
- 与 `b2-f03 performance-pipeline-interview-build` 的区别: 后者定义"每层该交什么业绩"；本 skill 判断"业绩交不出来时是哪条流程断裂"。
- 与 `b1-f03 question-to-reality` 的区别: 追问是领导者获取现实的动作，本 skill 是把三大流程当作地图来决定"往哪里追问"。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **画出用户组织的"三基石×三流程"地图**
   - 完成标准: 逐项列出——人员流程如何做（选/评/育/处置）、战略流程如何做（谁制定、拿到哪里评审）、运营流程如何做（目标、计划、预算、跟进），并标注每项的实际运行频率与负责人。

2. **逐环查找脱钩点**
   - 完成标准: 对每条流程写出"输入—输出—与另两条流程的连接点"；连接点空缺（如战略文件里没有人才与能力清单、运营计划前几页不是战略摘要）即记为脱钩。

3. **判定最弱环，而非罗列所有问题**
   - 完成标准: 给出一个排序：哪条流程的脱钩最直接地解释了目标与结果之间的差距，并写出证据（具体事件、会议记录、材料）。
   - 判停条件: 若三条流程都基本完好但仍落空，跳到步骤 4 查基石。

4. **检查三基石状态**
   - 完成标准: 用可观察证据为每块基石的现状打勾/打叉——领导者是否亲自参与（时间证据）、文化是否"目标—条件—奖励—处置"闭环（奖励与行为是否透明挂钩）、用人是否有标准并处理不胜任者。

5. **输出"修最弱环"的行动清单，明确不叠加新工具**
   - 完成标准: 每项行动写明责任人、时限、检验方式；并在结论中显式声明"在现有工具上修补"而非新增系统。
   - 判停条件: 若诊断显示领导者本人不愿亲自参与（基石一缺位），先向用户说明：该情况下任何流程改造都会退化为形式，需先解决参与问题。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户的问题本质是技术故障、单点流程瓶颈或市场突变，不是系统性执行问题——用系统框架会掩盖具体因果。
- 用户想要的是"帮我快速拍板一个具体业务决策"，而非诊断；此时本框架给不出决策。
- 组织规模很小（几十人以下）、层级与流程尚未成型时，套用本书取自大型分权公司的三流程架构会产生大量空转动作。

### 作者在书中警告的失败模式

- **只管理不领导**: 领导者把执行全部交出去，只做战略思考、激励演讲与对外关系，"他只是在管理，这种领导者实际上只是在完成一半的工作"（b1-ce01）。
- **微观管理**: 把"亲自参与"误解为"代替下属工作"，降低员工自信、扼杀独立思考（b1-ce02）。
- **无原则奖励**: 领导者希望被爱戴、缺乏情感强度做客观评价，甚至为业绩不佳者创造新岗位，结果组织被奖励政策搞得晕头转向（b1-ce05）——这是"人员流程"整环失效的典型。
- **选拔"空谈家"**: 因口才、魅力、学历或与上司的融洽而提拔，忽视其从未通过他人完成工作、无法建立团队的事实（b1-ce07）。
- **「交易商」式 CEO**: 靠并购与资本市场叙事获得声望，但没有经营能力、并购后整合不落地，董事会最终要求其辞职（b3-ce07，跨册反例）——三流程中战略与运营的连接被交易叙事替代。
- **流程空转型官僚主义**: 人员、战略、预算流程照常运转却毫无实效，战略材料六英寸厚却没有战略信息（b1-ce11）——这正是只有流程外壳、没有基石与咬合的结果。

### 作者的盲点 / 时代局限

- **单因论倾向**: 本书把复杂组织失败压缩为"没执行"，对组织政治、股权结构、董事会约束、行业周期、运气等结构性变量处理很薄；"领导者有勇气就能解决"忽略了治理制约（BOOK_OVERVIEW 批判节）。
- **科层制预设**: 三流程架构以大型、分权管理的美国公司为原型；对扁平化、平台型、项目制组织的适配未加讨论。
- **成功样板的选择偏差**: 联信、EDS、戴尔等正面样板在后续十年各有起伏，缺乏实施失败企业与对照组。

### 容易混淆的邻近方法论

- 与"OKR/平衡计分卡"等目标管理工具的区别: 那些是流程内部的工具，本框架负责先判断工具该装在哪一环、是否该装。
- 与"变革管理八步法"的区别: 后者是推动变革的通用程序；本框架是执行系统的结构诊断。
