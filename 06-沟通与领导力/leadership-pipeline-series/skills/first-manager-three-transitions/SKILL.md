# 初任经理三项工作转型（通过他人完成任务）

## R — 原文 (Reading)

> "实际上，第一次担任经理要想获得成功需要一个重大的转变，即他们的工作成果不再是通过自己亲自做去获得，而是通过下属和团队的努力去获得。……典型的表现是，他们往往因为自己擅长某项工作而直接插手下属的工作。"
>
> — 第2章 第一阶段（fulltext L9957）

> "◆ 界定和布置工作，包括与上司、员工沟通，需要他们做什么，以及工作计划、组织结构、人员选拔和工作授权。◆ 通过监督、指导、反馈、获取资源、解决问题和交流沟通，提高下属的胜任能力，从而高效开展工作。◆ 建立与下属、上司和相关部门坦率交流与相互信任的合作关系。"
>
> — 第2章「转型可以概括为以下三个方面」（fulltext L9997–L10001）

> "答：可能不是。你至少要花一半的时间在管理工作上，才算得上经理。如果你大部分时间都用于从事技术工作或专业性工作，那你只达到'管理自我'的最高层级。"
>
> — 第2章 常见问题（fulltext L10167–L10169）

## I — 方法论骨架 (Interpretation)

这条方法论针对人数最多、也最容易被忽视的一次晋升：从"我自己把活干好"到"我让团队把活干好"。它把这个抽象的转型拆成三件必须做、且可以检查的工作：

1. **界定和布置工作**——与上司和员工沟通清楚"要做什么"，并把工作计划、组织结构、人员选拔、工作授权安排到位。很多新任经理的失败不是不努力，而是把"把要求弄准"和"把活分对"这两步跳过了。
2. **提高下属的胜任能力**——靠主动的监督、指导、反馈、给资源、解决问题和沟通，让下属能干、愿干、越干越强。关键区别：下属拿来问题时，你的第一反应是**教他解决**还是**替他解决**。
3. **建立合作关系（三类）**——对上（含所有层级的上司）先换位思考，从对立视角转为理解视角，以获得资源与信息；对下建立相互尊重与支持的关系（正直诚实是底线）；对外（供应商、客户及相关方）以双赢方式打交道。这项转变"主要是基于价值观的转变"，若公司文化把"建立关系"等同于拉帮结派，就需要上司专门指导。

三条配套判据：
- **成功标准改写**："必须把通过他人完成任务作为自己取得成功的关键"——这是理念层面的转变，也是三个阶段中最难的一环。
- **"一半时间"法则**：管理性工作时间不到一半，说明人虽在经理岗、层级还停在"管理自我"。
- **失败症状清单**：把下属提出的问题看成障碍、补救下属的失误而不是教会他、拒绝与下属分享成功（对问题与失败避而远之）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 巴里——销售明星升销售经理，挣扎两年后回退做销售
- **问题**: 巴里原是高自主性的销售，升任八人销售团队的经理后，不得不花大量时间观察销售员工作、招聘培训、开会、写报告，失去签单的心理满足感。当下属渴望指导时，"巴里并没有给予他们有力的支持"；尽管他知道某些销售员处理客户关系不当，"但他很难把问题向他们解释清楚"，下属的自我防卫意识很快令他厌倦。
- **方法论的使用**: 对照三项工作看他缺什么——②提高下属胜任能力几乎缺位（不会指导、不愿反馈）；由此也印证①界定与布置工作没有真正发生（他要的不是"把要求讲清、把人教好"，而是自己继续签单）。
- **结论**: "在巴里的管理层级上遇到的领导力问题是可以防止和解决的"——他"可能不是天生的管理者，但如果能够获得及时的教练辅导和帮助，他还是有可能胜任"；公司缺的是评估机制，"巴里就可能步入'超级销售员'的发展轨道，或者专门为他设计一个培养方案"。
- **结果**: 巴里辞去销售经理职务，到另一家公司担任销售代表（另获更高薪酬与自主性）——管理岗与个人双输，本可避免（b5-c16；L10066–L10070）。

### 案例 2: 玛丽——程序员升研发经理，360 度反馈加教练辅导后学会授权
- **问题**: 程序员玛丽升任研发小组经理后，在交付压力下"忘记了自己的角色"，要求下属每天汇报、常命令下属听从自己的想法而不是教练他们；她甚至认为"如果她亲自编写程序，所有的问题都能迎刃而解"。结果"玛丽的越俎代庖削弱了小组成员的积极性，剥夺了他们得到指导的机会。他们不仅没有按时完成任务，而且开发的系统漏洞百出"。
- **方法论的使用**: 上司持续教练辅导并引入 360 度评估——当听到熟悉的小组成员说她"管得太细、不善于分配工作"时，玛丽非常震惊；她开始按三项工作重新定位（把工作分出去、教会人、建关系）。
- **结论**: 从"自己做出来"到"帮下属做出来"的转变"并非易事但可以做到"；她在帮助下属成功中获得了与做技术同样的满足感——这正是成功标准改写的过程。
- **结果**: "她花了好几个月的时间才学会有效授权，放手让下属去做重要的工作"（b5-c17；L10072–L10076）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户**刚被提拔为一线经理/团队主管**，发现"活自己干最快"，或正在纠结要不要替下属收尾。
2. 用户的下属**反过来抱怨"上级没有足够的支持"**、员工感到压力很大——这是作者给出的第一层级问题的明确信号。
3. 用户作为**上司/HR 要辅导新任经理**，需要一份"这三件事做了没有"的检查清单与失败症状清单。
4. 用户在讨论**明星个人贡献者该不该提拔**："他个人业绩最好，但是不是愿意/能够通过他人成功？"（配套问题：可在任命前用组长/项目经理岗位考察其对别人成功负责的能力和意愿）
5. 用户在做**新任经理培训/岗位说明**设计，需要把"通过他人完成任务"落成可讲、可考的三块内容。

### 语言信号 (用户的话里出现这些就应激活)

- "我刚当上经理 / 第一次带团队 / new manager / first-time manager"
- "我自己做更快 / 教他还不如我做 / 下属做不好我就接手"
- "下属不成长 / 什么事都来问我 / 他们压力很大 / 抱怨没有支持"
- "算不算真的经理 / 一半时间 / 管理时间占比 / 经理该干什么"
- "通过他人完成任务 / get work done through others / 从个人贡献者到管理者"

### 与相邻 skill 的区分

- 与 `three-dimension-transition`（本册）：那条是三把尺子的通用体检，本条是**第一层级的具体内容清单**（三项工作+一半时间法则+症状）；用户问"新经理该做什么"用本条，问"他卡在技能/时间/理念哪一维"用对方。
- 与 `manager-transition-tactics-three-steps`（本册）：那条站在**上司**角度（准备—监督—干预），本条站在**新任经理**角度自我对照；同题的另一套操作语言。
- 与 `performance-pipeline-interview-build`（册2）与 `functional-vp-four-results`（册2）：业绩梯队的层间契约，层级不同（本条只讲一线经理）。
- 与 `coaching-two-tracks`（册3）：那是教练辅导技术；本条的"提高下属胜任能力"是角色职责而非教练方法论。
- 与 `dual-track-management-technical`（本册）：当发现此人确实不适合管理岗时，双轨发展（超级销售员/专家轨道）是替代路径而不是失败。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **判定是否真是"经理"：算管理时间占比**
   - 让用户列出典型一周的工作，标出哪些是管理性工作（计划、分配、指导、反馈、协调、评估），算占比。
   - 完成标准: 得出占比数字。判停条件: 若管理性工作不足一半，先按"名不副实"处理——确认其是否只是头衔经理（对应 b5-ce05 头衔化风险），再谈其余三步。

2. **逐项检查三件工作是否真的做了**
   - ①界定和布置工作：目标任务、工作方案、人员与授权是否说清楚并落到安排上；②提高胜任：有无主动的监督/指导/反馈/资源支持，遇下属求助时是教还是替；③三类关系：对上是否只带对立视角、对下是否只有单向命令、对外是否维持双赢。
   - 完成标准: 每项有/无、证据是什么；三项各写出1条具体欠缺。

3. **用失败症状清单交叉验证**
   - 检查三个症状：把下属提出的问题看成障碍、补救下属失误而不是教会他、拒绝分享成功/对下属的问题与失败避而远之。
   - 完成标准: 症状逐条打勾并给实例；症状 2 条以上即判定转型未完成。

4. **把成功标准从"我做出来"改写为"团队做出来"**
   - 与当事人做一次对话：明确他的成功以团队成果与被培养者的成长度量（例如"你今年最重要的产出是几个人能独立扛事"）；同时给出"帮下属做出来"的即时替代满足点（在帮助他人成功中获得成就感，如玛丽案例）。
   - 完成标准: 双方就新的成功标准达成一致表述，并落到考核或反馈中。

5. **出具体动作（含替代路径）**
   - 每项欠缺配 1 个动作（如：把最难的活交回并教会方法；建立固定的反馈节奏；去与相关部门谈一次合作）；若判定不适合管理岗，则提出专家/超级销售员轨道的替代方案。
   - 完成标准: 动作可在 30 天内启动并有验收方式；结论只作发展用途，涉及转岗/解除须依当地劳动法与公司程序。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **越级治理**：这三项只适用于一线经理（管理他人）层级；用它去衡量部门总监、职能主管会错配（各层另有专属要求）。
- **把它当"必须事事放手"的教条**：作者明确"偶尔帮助下级员工解决某个问题，同时教授他们学会解决的办法，这样做是可取的"；失败判据是长期替代与竞争，不是任何一次亲自上手。
- **把"建立关系"理解成搞关系**：作者判定这项主要是价值观转变（正直诚实、双赢、对上换位），不是社交技巧，更不是拉帮结派。
- **用它给个人下处置结论**：诊断只作发展对话输入；涉及调岗/解除须有书面证据与合法程序（系列级伦理边界）。若此人确实不适合管理岗，优先走专家/双轨而非淘汰。
- **对象是知识型/技术型个人的短周期项目角色**：团队领导者若在人员选择与奖励上没有决定权、工作重点是技术或专业问题，作者明确不把它算作一个独立转折阶段——不要硬套经理标准。

### 作者在书中警告的失败模式

- **与下属竞争、替代下属做事（b5-ce02）**："当他们对自己的工作方法感到不满时，便亲自去做，这在无形中产生了与下属的竞争"；经理接下本属于下属的工作，会剥夺下属的成长机会与职权，导致下属受抑、依赖、越过上司直接找更高层；经理自己忙于"做事"，没有人做管理。
- **一线经理的三个显著失败迹象（b5-ce03）**：把下属提出的问题看成是障碍；补救下属的工作失误，而不是教会他们如何正确去做；拒绝与下属分享成功，对他们的问题和失败避而远之。
- **头衔化（b5-ce05）**：经理越来越多、直接下属越来越少，"管理工作很少。结果，他们并没有真正学会如何管理，徒有经理的职务，却不会真正地管理工作"；"如果管理职务代表的是地位而不是一系列的管理工作要求，公司的管理就变得'形同儿戏'"。
- **放任自流式放权（b1-ce03）**：把"不做微观管理"错用成"不参与"，项目启动后领导者再不出现、只有年度评估没有阶段检查。

### 作者的盲点 / 时代局限

- **科层制与"全职经理"预设**：模型假定经理有足够的管理幅度（书中自己批评"直接下属越来越少"的趋势却未给解法）；在矩阵/项目制、知识工作者自主性高的场景，"通过他人完成任务"未必是唯一成功定义。
- **2000 年代初美国大公司语境**：案例（制药、通信、金融）与"经理摇篮"式晋升阶梯属于稳定科层环境；对远程团队、零工/外包混合团队的授权与指导问题的适用性未讨论。
- **"一半时间"是经验阈值而非研究结论**：作者未给出依据；不同岗位（如技术带头人的"player-coach"）比例本就不同。
- **关系维度被置于价值观层面讨论**：缺少对组织政治、权力不对等（如跨部门弱势方如何建立双赢）的处理。
- **案例缺失对照**：巴里、玛丽故事均无对照组，说服力依赖作者的经验权威。

### 容易混淆的邻近方法论

- 与 `three-dimension-transition`（本册）：通用三把尺子 vs 第一层级的三项具体工作。
- 与 `manager-transition-tactics-three-steps`（本册）：上司侧流程 vs 经理侧内容（常组合使用）。
- 与 `performance-pipeline-interview-build`（册2）：业绩契约（每层交什么结果）vs 能力转型（每层要会什么）。
- 与 `dual-track-management-technical`（本册）：不适合管理时的替代轨道。
- 与 `coaching-two-tracks`（册3）：教练技术 ≠ 一线经理角色清单。
