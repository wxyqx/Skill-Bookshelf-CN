# 领导缺陷四因与组织三缺失

## R — 原文 (Reading)

> "尽管导致缺陷的原因很多，而且其中一些是无法完全避免的（例如，消费者喜好突然改变），大部分原因还是可以预防或有效解决的。……下面就从造成缺陷的四种最常见的原因开始：◆ 选错人才；◆ 让表现不佳者留在岗位上太久；◆ 不善于倾听反馈意见；◆ 不善于定义工作。"
>
> — 查兰/诺埃尔/德罗特，第11章（L12112–L12124）

> "和其他很多公司一样，这家公司缺乏三个能够防止组织缺陷的关键因素。因素一，领导力框架。……因素二，讨论问题的语言。……因素三，评估绩效的标准。"
>
> — 同上，第11章（L12220–L12236）

> "缺陷本质上是公司层面的问题，应当用适合的方法处理。查清事实，做出适当的调整，消除障碍，如果有必要，撤除现任负责人。如果上司不处理问题，对问题的诊断过程本身多完美也毫无意义。"
>
> — 同上，第11章（L12264）

## I — 方法论骨架 (Interpretation)

当一位被寄予厚望的领导者失败时，最快的结论是"他能力不行"；这套框架要求先按四个可预防的原因逐条排查，再把组织层面的三个缺失翻出来。

**四因（个人侧，其实是组织选与管的结果）**：

1. **选错人才**——把"在一个层级上做出成绩"当作提拔的主要依据，忽视相邻层级在技能、时间、理念上的重大差别。要问：他是否在明显不同的环境中做出过成绩？能否接受新理念？是否具备新技能并愿意重排时间？
2. **让表现不佳者留在岗位上太久**——出于忠诚或错误的恻隐，反复指望"曾经的英雄"重新焕发魔力。两条检测线：是否开始重复上一层级带来成功的行为；直接下属是否不再进步、绩效不再提高、纷纷离职。
3. **不善于倾听反馈**——高管欢迎业务反馈、抗拒关于自身的反馈（"不喜欢听到他人评论他们该如何领导"）；职位越高，主动给反馈的人越少，防卫摧毁的正是仅存的反馈渠道。
4. **不善于定义工作**——"总是假定承担这些管理职位的人员应该知道要做些什么"，尤其在事业部总经理与公司高管层级没有既定章程，职责围绕人而非岗位设定；"我以为他知道"是缺陷发生后最常见的评论。解法是主动界定工作并反复向上司确认。

**组织三缺失（制度侧）**：缺领导力框架（领导力被简化为一句口号如"每个人都要销售"，各层级做同样的事，重要任务无人负责）；缺共同语言（无法精确讨论某层级该做什么）；缺分级绩效标准（基层与事业部总经理用同一方式考核）。三者叠加，失败不可避免。

**归因翻转**：四因与三缺失共同指向一个结论——"缺陷本质上是公司层面的问题"。作者还补充了第五因：创造不适当的工作环境（缺乏坦诚），"当真实的对话发生在会后的走廊中而非会议里，领导者迟早会失败"。同时警告：承认缺陷会出现在每个人身上是好事，认为缺陷无法弥补才是坏事——错位不可避免，无视才致命。

## A1 — 书中的应用 (Past Application)

### 案例 1: 杰瑞与蒂姆——18 个月损失 10 亿美元（四因之一：选错人）
- **问题**: CEO 杰瑞因蒂姆在事业部总经理任上营收与赢利俱佳，把他提升为公司高管；蒂姆照搬旧法，大举投资所有未开发市场，"打赌至少赌中一个"，团队进入既不熟悉又无资源的领域，执行力崩溃。
- **方法论的使用**: 用层级标准复盘：相邻层级要求总体相近但具体差别重大——职能部门理念问"我们能做到吗"、事业部总经理问"我们应该做吗"、公司高管问"哪个选择能在现在和将来带来最好结果"；蒂姆的理念比岗位低了两级。
- **结论**: "在一个层级上做出成绩不应成为选择某人担任更高层级职务的主要原因"；杰瑞的错误是只看绩效单因素，而非候选人能否在明显不同环境中复制成绩、能否接受新理念。
- **结果**: 蒂姆在任 18 个月后被撤职，公司损失 10 亿美元。

### 案例 2: 杰瑞与文斯——业绩英雄留任过久（四因之二：留太久）
- **问题**: 文斯曾创建一项业务、成为多国市场的首个提供者；升任公司高管后像"闯进瓷器店的公牛"，强行扩张、免掉两位事业部总经理、把业务重组回自己舒服的形态；第三年末市场份额、利润、客户满意度一落千丈，第四年又有两位优秀经理辞职。
- **方法论的使用**: 作者指出杰瑞若用公司高管与事业部总经理的层级标准评估文斯，很快就能发现他在不合适的层级工作；两条检测线（是否依赖前一层级行为、直接下属是否流失）早就亮了红灯——"出于忠诚度的考虑或是错误的恻隐之心，管理人员允许员工逃脱重大损失的责任"。
- **结论**: 缺陷识别需要层级标准，拖延只需要"再等等看"；杰瑞缺的不是才干，而是"一个预防和处理领导者失败的机制"。
- **结果**: 公司市场份额创历史新低、爆发资金危机，需缩减几十亿美元成本、成千上万员工被解雇，董事会要求杰瑞提前退休。

### 案例 3: 某大型计算机公司——三缺失导致研发停滞无人负责
- **问题**: 高管培训中讨论"创新不足"：实验室里有很多新产品，却无法从实验室走向市场；问谁该负责，回答是"参与的人很多，不可能精确地指定究竟是谁该为此负责"。
- **方法论的使用**: 用三缺失框架诊断：公司把领导力简化为"每个人都要销售"（缺框架→各层做同样的事、重要任务无人负责）；无法精确讨论某层级该做什么，例如事业部总经理的职责是规划未来、创造持续销量（缺语言）；对基层管理者与事业部总经理用同一方式考核（缺分级标准）。
- **结论**: 三者叠加使失败不可避免；用领导梯队的语言（技能/时间/理念）才能把"谁该负责什么"说清楚。
- **结果**: 该案例成为"组织缺陷三缺失"的标本，用于说明缺陷首先要在系统层面修补，而不是责怪某人。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 一位高薪空降高管/新提拔的负责人半年到一年就明显不行了，用户要复盘"这到底怪谁"。
2. 公司连续几任同一岗位的人失败，用户想搞清是"人不行"还是"系统在制造失败"。
3. 高层出现业绩下滑，但没人敢处理，用户需要一把可用于催促行动的分析尺子。
4. 用户要做组织健康体检，想知道"我们的领导力框架、共同语言、分级标准"是否齐全。
5. 复盘会已经开过，但结论停在"他执行力不行"，需要把结论升级为可行动的机制修复。

### 语言信号 (用户的话里出现这些就应激活)

- "空降的高管半年就不行了，复盘该怪谁？/ 这到底是不是他的问题？"
- "为什么我们提拔的人总是失败？/ 公司为什么总缺领导？"
- "没人敢跟老板说真话 / 问题都堆在走廊里说"
- "leadership failure" / "deficit review" / "why do our promotions fail" / "post-mortem on a failed hire"

### 与相邻 skill 的区分

- 与 `b5-f19 diagnosis-five-steps` 的区别: 五步法是通用诊断程序（从工作查起、倒序排查）；本 skill 是一张针对"领导者失败"的专用归因清单（四因＋三缺失），适合复盘场景直接套用。
- 与 `b5-f21 role-clarity-gaps-overlaps` 的区别: 后者处理"职责边界画错/画漏/画重"这一具体病症（对应四因之四的前半段）；本 skill 覆盖选、留、反馈、定义四类原因与组织制度面。
- 与 `b1-f15 underperformer-tiered-handling` 的区别: 那个 skill 回答"表现不佳者怎么分层处理"；本 skill 回答"缺陷从哪来、为什么该系统会反复制造缺陷"——先归因再处置。
- 与 `b4-p16 leadership-is-work-not-honor` 的区别: 后者讲个体层面的伦理与自我认知（领导是工作而非荣誉）；本 skill 把镜头转向组织，强调缺陷首先是公司层面的问题。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **过四因清单，逐条找证据**
   - 完成标准: 对每个原因写出"有/无＋具体证据＋证据来源"：① 选拔时是否以单一绩效为依据；② 是否已亮起留任过久的两条检测线（重复旧层级行为、下属停滞或流失）；③ 是否存在只欢迎业务反馈、抗拒关于自身反馈的行为；④ 岗位职责是否被主动定义过、是否向上司确认过。
   - 判停条件: 若四因均不成立且岗位适配无疑，转到组织三缺失排查（步骤 2），不要强行归因个人。

2. **排查组织三缺失**
   - 完成标准: 逐项判断——是否有领导力框架（各层级职责要求是否被界定、是否有人在做"重要但无人负责"的任务）；是否有共同语言（能否精确讨论某层级该做什么）；是否有分级绩效标准（各层级是否用同一套考核）。
   - 完成标准 (第五因): 单独观察坦诚指标——真话是否只发生在会后的走廊里、上报材料是否系统性报喜不报忧、下属是否不敢在会上提反对意见。

3. **做归因翻转并写成一句话结论**
   - 完成标准: 结论默认以"缺陷本质上是公司层面的问题"开头，说明组织在哪一环缺失或被绕过；同时明确区分不可抗力（如消费偏好突变）与可预防原因，不把一切失败都塞进框架。

4. **决定并推动处置动作**
   - 完成标准: 输出四步动作——查清事实、做出适当调整、消除障碍、必要时撤换负责人；同时指定推动人（上司必须处理，"如果上司不处理问题，对问题的诊断过程本身多完美也毫无意义"）。
   - 判停条件: 若涉及绩效改进计划、解雇、降职、调岗等动作，声明须依当地劳动法与公司程序执行，并保留绩效记录与合法流程——本框架只做管理诊断，不构成人力资源法律意见。

5. **建立预防回路**
   - 完成标准: 把岗位职责定义与确认、反馈渠道（教练辅导）、分级绩效标准纳入常规制度；把 HR 定位为"预警系统"，要求其报告角色转型失败与错位信号；每个层级主管关注低两级的评级。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 失败主因明确是不可抗力（市场崩盘、政策变化、消费偏好突变）——作者本人把这些排除在可预防范围之外，硬套四因会冤枉人。
- 用户想要的是"帮我给某个人定性/找理由开除"：本框架禁止被用作处置借口；处置必须另有合法流程。
- 只做一次性复盘而不改动制度：作者强调缺陷会反复发生，单次处理等于让系统继续生产失败。
- 缺少基本坦诚的组织里直接启动"四因复盘"：会变成互相甩锅，应先修会议说真话的条件。

### 作者在书中警告的失败模式

- **CEO 失败的首要原因：不能快速处理绩效提升问题**: "对于没有完成预期业绩目标或者工作方法不当的直接下属，即使是最强硬的首席执行官，在对付他们时也会遇到麻烦。……问题越拖越糟"（b5-ce19，第7章 L11325）——伦理提示：涉及绩效改进计划、解雇等高敏感人事操作，须依当地劳动法与公司流程执行；本书仅为管理框架（b5-ce19 ethics_legal_note）。
- **以一个层级的成绩作为提拔的主要依据**: "相邻两个层级的总体要求可能相近，但在具体的领导技能、时间管理能力和工作理念方面则显示出重大的差别"；"在一个层级上做出成绩不应成为选择某人担任更高层级职务的主要原因"（b5-ce21，第11章 L12143–L12147）。
- **让表现不佳者留任太久**: "出于忠诚度的考虑或是错误的恻隐之心，管理人员允许员工逃脱重大损失的责任。或许他们在自欺欺人，一次又一次地指望曾经出色的某人能够重新焕发魔力再次爆发出显著业绩。"（b5-ce22，第11章 L12147–L12165）——处理"留任过久"须有绩效记录与合法流程；不得基于主观印象即时解雇，避免违法解除风险（b5-ce22 ethics_legal_note）。
- **不善于倾听关于自己的反馈**: "他们并非讨厌某类反馈……他们没有积极征求的——或他们充耳不闻的，是他人主动提供的针对他们自身的反馈意见。"（b5-ce23，第11章 L12174；汤姆案例 15 个月被解雇并拖累他人）
- **不善于定义工作**: "大部分情况下，人们的懒惰或无能不会招致缺陷，缺陷之所以发生是因为人们晋升到新的领导层级时不了解自己的职责。"（b5-ce24，第11章 L12199–L12207）；"'我以为他知道'是缺陷发生后最常见的评论。"（L12268）
- **组织三缺失**: 领导力被简化为口号、无法精确讨论层级职责、所有层级同一套考核——"如果以同样的方式考核所有的领导者，失败是在所难免的"（b5-ce25，第11章 L12216–L12236）。
- **缺乏坦诚（第五因）**: "认识到缺乏坦诚是缺陷即将出现的最重要的危险信号。……当真实的对话发生在会后的走廊中而非会议里，领导者迟早会失败。"（b5-ce26，第11章 L12266）

### 作者的盲点 / 时代局限

- **单因论倾向**: 把复杂组织失败压缩为"层级错位/缺陷"，对组织政治、股权结构、董事会约束、行业周期、运气等结构性变量处理很薄（BOOK_OVERVIEW 批判节）。
- **责任归属的个人化**: "领导者要主动界定自己的工作"在制度失败时存在把系统性风险转嫁给个体的倾向；本框架虽主张"缺陷在公司层面"，但其落地动作（主动定义、主动征求反馈）仍大量落在个人身上。
- **可执行性依赖组织政治条件**: 模型最需要的前提（坦诚、上司愿意处理）恰恰最难满足；作者自己承认错位有时已成为"沾沾自喜的文化"。
- **治理与合规边界被轻描淡写**: 让表现尚可但"没有潜力"的现任让位、撤换负责人等操作的劳动法、程序公正与治理合规风险，书中只提示"如何尊重地做"，未讨论申诉机制与合规底线。

### 容易混淆的邻近方法论

- **绩效改进计划（PIP）/纪律处分流程**: 那是执行动作；本 skill 只做归因与机制修复，不能替代人事程序。
- **根因分析（5 Why/鱼骨图）**: 通用根因工具用于事件与流程；本框架专用于"领导者失败"，且强制把归因从个人翻转到组织制度面。
- **人才盘点/九格矩阵**: 那是预防性评估；本 skill 是失败后的复盘归因，两者互补但触发时机不同。
