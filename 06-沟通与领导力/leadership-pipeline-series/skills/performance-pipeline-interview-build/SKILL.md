# 业绩梯队建队六步骤（含名词提取与标准双栏）

## R — 原文 (Reading)

> "建立业绩梯队模型的流程包括以下六个步骤：·明确建立业绩梯队的目的：首先要弄清楚你想要实现什么样的业绩；·收集数据和信息……·允许业绩梯队模型有一定的灵活性：允许不同的工作团队根据其具体需求调整业绩衡量的标准。"
>
> — 斯蒂芬·德罗特，第1章（fulltext L3333–L3345）

> "从访谈回答中挑选出所有的名词，因为名词反映的就是企业的业绩，比如战略、销售、团队、供应商、费用以及人才这些词都会提供一定的线索，说明处在某一职位上什么工作最为重要，什么工作是该职位工作的焦点、是需要衡量的。"
>
> — 斯蒂芬·德罗特，第1章·整理分析步骤（fulltext L3493）

> "一般来说，我们会根据企业当年的运营计划以及执行该年度企业战略所需要的工作任务，从中选取20～25项最重要的工作任务，然后为这些任务的完成情况设定衡量标准。……通常，在开始建立业绩梯队时，很容易把衡量标准设定得较低，但之后如果想提高标准，就比较困难了。"
>
> — 斯蒂芬·德罗特，第1章·设定衡量标准步骤（fulltext L3561）

## I — 方法论骨架 (Interpretation)

公司业绩问题的根子常在"组织架构的纵向设计"：同一层级有人做上一层的事、有人只做下一层的事，层间出现管理空当或微观管理重复。业绩梯队就是给每个层级写清"独特目的＋该交的业绩＋衡量标准＋向下传递的关键结果"，让每层领导在自己层级交付正确结果。

自建标准不是等HR发模板，而是一条六个步骤的流水线：
1. 先定目的——写清要解决什么业务问题（放权、培养某层、变革、扩张），目的会决定后面选什么业绩。
2. 分层标准化访谈——每层5~10人、高管全覆盖、每人约90分钟，含保密声明；这是搜集"真实工作"而非"职位说明书"。
3. 整理分析——先通读一个人的全部记录，再从回答里抽名词（名词＝业绩线索：战略、人才、供应商……），归入运营/财务、管理、领导、关系等类别（类别可自定义）。
4. 定义各层业绩与标准——做四栏表：工作重点变化、全面业绩、卓越业绩、技能知识经验（或能力模型、或"不正确的表现"）。标准围绕当年运营计划选20~25项，宁少而高。
5. 集体确认——开集体验证会，不是与个人逐一确认；会上讨论、统一关键概念、形成主人翁感。
6. 留灵活性——允许团队按需调整；术语本地化（按公司实际层级数与头衔替换）。

两个次序洞察：首次建梯宁可先少选任务但把标准定高（事后抬高比初始定高难得多）；不必等HR全系统改造，经营层可先用它做业绩管理、继任与辅导。一个懂业务的小组约10个工作日可完成一轮。

## A1 — 书中的应用 (Past Application)

### 案例 1: 快速消费品公司：把事业部总经理从"孤立层级"里救出来
- **问题**: 访谈几位事业部总经理后发现，他们的能力之所以没发展起来，是因为上级不给宽泛的工作任务，且只用营业收入和营业量两项片面指标评价他们。
- **方法论的使用**: 用六步流程重新界定事业部总经理的目的与标准，把人才培养、战略制定与执行、流程改进等业绩写进标准；同时向上调整集团总经理标准、把部分工作向下移给事业部副总与部门总监。
- **结论**: 一次只改一层会牵动上下各层，必须全局规划；改一层几乎要一年。
- **结果**: 扩展后的业绩标准落地，事业部总经理的发展路径被打开。

### 案例 2: 软件公司：第四栏写"不正确的表现"
- **问题**: 公司处于快速成长期、管理文化未定型，经理们需要额外指导；一线经理常见的错误是"所有上班时间都待在办公室、闭门不出""自己亲自解决所有业务难题"。
- **方法论的使用**: 在标准表第四栏（通常放技能/知识/经验）改放"影响过渡到下一层级的不正确的表现"，把边界明确写出来。
- **结论**: 第四栏不必是能力清单，也可承载"负面清单"；这种设计对初创、快速成长或变革管理方式的企业特别有用。
- **结果**: 软件工程部拿着这套标准提前投入使用，比人力资源部的计划实施时间更早。

### 案例 3: 三家不同行业公司：业绩类别可以自定义
- **问题**: 通用类别（运营/财务、管理、领导、关系）需要适配不同行业。
- **方法论的使用**: 大型金融服务公司用"金融业绩、客户有效性、管理、领导、关系、全球有效性"六类；建筑与海洋产品公司用"交付、健康安全环境、人员和团队、亲自管理、客户导向、开放直接对话"；保健公司用"使用者或病患业绩"等。
- **结论**: 步骤3的类别应服务业务现实，允许创造新类别。
- **结果**: 三家公司各自跑通了本地化分类，模型没有变成教条。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 新任CEO/CHRO 或业务负责人发现"层级职责一团乱"：有人越俎代庖做下级工作、有人只做技术活，想从零建立各层级业绩标准。
2. 公司战略刚变，旧KPI与岗位描述失效，用户问"怎么把新战略翻译成各层该交的结果"。
3. 要推进继任计划或领导力发展，却发现"没有业绩标准就选不准人"。
4. 咨询顾问/HRBP 接到了业绩梯队或"岗位价值标准"项目，需要一套可操作的访谈与定标流程。
5. 用户单位里同一层级的岗位标准各自为政、口径不一，想通过集体讨论统一。

### 语言信号 (用户的话里出现这些就应激活)

- "各层领导到底该交什么结果？" / "what should each level deliver?"
- "业绩梯队怎么建？" / "how to build a performance pipeline?"
- "层级职责不清、上下错位、越俎代庖" / "roles overlap between levels"
- "澄清访谈怎么做、标准怎么定？" / "job standards / performance standards by level"
- "全面业绩和卓越业绩怎么区分？" / "full performance vs excellent performance"

### 与相邻 skill 的区分

- 与 `job-essence-two-factors` 的区别: 后者是六步流程第3步里判断"两个岗位是否同一种工作"的访谈判据（决策权＋障碍），是子工具；本 skill 是完整建队流水线。
- 与 `performance-dialogue-evidence` 的区别: 后者用既有标准做月度讨论与证据记录；本 skill 的产出物正是它要用的那套标准。
- 与 `role-clarity-gaps-overlaps`（b5-f21，册5）的区别: 后者在既有层级框架下澄清一个岗位/团队的职责空当与重叠；本 skill 是从目的出发重建整条纵向标准。若用户只想澄清个别岗位，优先 b5-f21。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **明确目的**
   - 写出一页纸："要解决什么业务问题、期望什么业务结果"（放权/加快某层发展/扩张/变革）。
   - 完成标准: 用户能用一句话说出要解决的业务问题；若说不出，判停，先做目的澄清。

2. **设计访谈方案**
   - 定标准化提纲（含工具性问题1~6，其中3A/3B/4用于工作本质判断）、访谈对象（每层级5~10人、高管全覆盖）、时长（约90分钟/人）、保密声明与公开口径。
   - 完成标准: 受访名单与提纲定稿，保密与反馈规则已向组织宣布。

3. **分层访谈并记录**
   - 重点采集：他实际做什么决策、要克服什么障碍、时间花在哪、哪些工作没被任何人做。
   - 完成标准: 每个层级至少5份完整访谈记录。
   - 判停条件: 若访谈发现"没有任何人提及某项最重要的企业要务（如文化变革/创新）"，回到步骤1修订目的，并把该要务补入标准。

4. **整理分析（通读→抽名词→归类）**
   - 先按人通读全部记录；抽出所有名词（名词＝业绩线索）；按类别归类（运营/财务、管理、领导、关系；可自定义特殊类别，如增长、安全、全球有效性）。
   - 完成标准: 产出"各层级名词→业绩类别"清单与各类别的原始证据引用。

5. **定义各层级业绩与衡量标准（四栏）**
   - 每层填四栏：①工作重点变化；②全面业绩（称职线，含衡量标准）；③卓越业绩（远超期望＋同事标杆＋可为部分相关但完全创新之事，并非每项都需要）；④技能知识经验，或能力模型，或"不正确的表现"。
   - 标准数量围绕当年运营计划取20~25项最重要任务；首次建立时宁少而高。
   - 完成标准: 每层得到一份四栏标准表草稿，附20~25项衡量标准清单。

6. **集体确认**
   - 开集体验证会（不是与个人逐一确认），设引导者与记录员；目标是统一关键概念、让问题当场浮现；不要在会上解决公司所有问题。会上标准可能不降反增（更具体化），属正常。
   - 完成标准: 会议记录、修订后的标准表、参会者对关键概念的统一理解。

7. **留灵活性并本地化**
   - 允许团队按需调整标准；用公司自己的头衔与术语替换模型术语；按实际存在的层级重新分配任务（没有集团高管就把该层业绩分给CEO与事业部总经理）。
   - 完成标准: 定稿版标准表＋一份"本地化替换说明"。

8. **启动使用（可不等HR）**
   - 经营层可先用它做业绩管理、继任计划、组织发展与下属辅导；第一年也可只用于领导力发展以让大家熟悉概念。
   - 完成标准: 确定首批使用场景与时间表，明确与运营计划/预算流程的衔接。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 公司尚未想清楚"要解决什么业务问题"：硬建标准只会得到一份精美但无人使用的表格；先做目的澄清。
- 组织正处于大规模重组、层级架构还在变：先把层级结构定下来，否则标准会随组织图反复作废。
- 用户真实需求只是给单个岗位写职位说明书或考核表：用更轻的工具（b5-f21 职责澄清、或直接改职位描述），不要动用全公司访谈工程。
- 只有十几人的小公司、无实际管理层级：六阶段/七层业绩契约没有对应物，简化处理或不用。
- 把本流程当作"控制员工"的工具：作者明确标准要与激励、辅导、继任连用，单做考核会失败。

### 作者在书中警告的失败模式

- **选错人（b2-ce02）**：没有业绩数据、没有有效评估方法、没有勇气做匹配，企业就会做"安全的选择"或按资历、忠诚、政治权宜选人。业绩标准定得再好，选人环节崩塌同样无救——标准必须进入选拔与继任流程。
- **组织设计不佳（b2-ce07）**：岗位角色定义不清、授权不足、一有问题就成立委员会，会把本该由管理者承担的挑战性工作转给临时机构，微观管理随之而来。
- **标准数量贪多**：25项标准全用于考核会过于烦琐（书中原话"这种做法显得过于烦琐"）；第一年宜先用于发展而非考核。
- **集体确认会失控**：作者提醒验证会议需要引导技巧、记录员，且不要试图在会上解决公司所有问题。

### 作者的盲点 / 时代局限

- **科层制预设**：模型以GE式大型多层级公司为原型；对扁平化、平台型、项目制/矩阵制组织，"每层独特目的"是否成立、以什么形态存在，书中未正面处理（系列级批判：中层消失与敏捷自治团队的挑战）。
- **"定义业绩"不是万能钥匙**：标准写得清楚并不自动带来业绩；标准在复杂环境中会被博弈，书中对这一点只在证据与情景分析处轻描淡写。
- **咨询顾问的样本偏差**：作者以本模型为核心咨询产品，书中案例均为其参与企业，缺少实施失败者与对照组；"10个工作日完成"是理想条件。
- **美国大公司语境**：案例几乎全为美国白人男性高管、稳态大公司节律；中国/非美语境须先提示科层语境差异，并对照公司自身干部管理与劳动合规要求调整做法。

### 容易混淆的邻近方法论

- 与 `role-clarity-gaps-overlaps`（b5-f21）：后者是"明确职责三步"，在既有层级内定位空当；本 skill 是重建整条业绩标准线。两者可串联：先用 b5-f21 定位层级，再用本流程写标准。
- 与 `performance-dialogue-evidence`（b2-f22）：两书分工是"建标准 vs 用标准"；用户若已有标准并要求月度复盘，勿调用本流程。
- 与 `talent-review-meeting-mrr`（b1-f12）：后者评估人（人才盘点会）；本 skill 界定工作，不是评价个人。
