# 追问到现实（提问式领导）

## R — 原文 (Reading)

> "你打算通过什么途径来实现这些增长呢？你准备通过什么产品来实现这一目标？客户对象是哪些人？他们为什么要购买你的产品？你的竞争对手会采取什么措施？你是否制定了什么阶段性目标？"
>
> — 博西迪/查兰/伯克，第1章（L665）

> "你是否选派了适当的人来负责项目的执行？他们的责任清晰吗？你需要什么帮助？你的激励回报系统是否有效？"

## I — 方法论骨架 (Interpretation)

提问式领导不是"多问几个问题"，而是一套有固定顺序的下钻程序，目标是把对方口中的目标翻译成可证伪的现实：

1. **第一层（业务逻辑）**：你打算通过什么途径实现？靠什么产品？客户是谁？他们为什么买？竞争对手会怎么反应？阶段性目标是什么？——把"增长 8%"这类数字拆成一条条可检验的因果链。
2. **第二层（执行能力）**：谁负责？责任清晰吗？需要什么帮助？回报系统有效吗？——若对组织能力存疑，继续往下钻。
3. **判据**：一直追问，直到某个前提暴露出来（答不上来、答得前后矛盾、或答案与已知事实冲突）。
4. **不越位**：暴露漏洞后并不代替对方改方案，而是当场给具体、有用的改进建议——一针见血的问题＋可用的建议＝一次教练辅导。
5. **收尾**：被追问者应受到"激励"而非羞辱；一次成功的追问会让在场所有人学到分析过程，并当场承诺重做方案。

关键区别：常识式提问为了解信息；本方法为了让计划的前提无处藏身，并同步完成对下属的评估与培养。

## A1 — 书中的应用 (Past Application)

### 案例 1: 德国市场份额计划——六个问题拆穿一个"野心勃勃"的方案
- **问题**: 某跨国公司的部门主管在计划评估会上宣布要把本部门在欧洲的市场占有率从第三位提高到第一位，关键在德国市场；而德国正是最强劲对手（规模为本部门四倍）的总部所在地。
- **方法论的使用**: CEO 先按第一层追问——"你准备采取什么具体步骤？要争取的客户群体是哪些人？用哪些产品扩大份额？有哪些竞争优势？"对方显然没考虑过。再往下钻到能力层："你们有多少销售人员？"——十名；"你们的主要竞争对手的销售人员数量是多少？"——两百；最后一句是陈述式的追问："现在你的部门的德国分部由谁负责？他不是几个月前刚调过去的吗？你在制定计划之前征求过他的意见吗？"
- **结论**: 仅凭几个简单而挑剔的问题，CEO 已充分暴露了该战略中的不足；这些不足在实际操作中足以毁灭整个计划。
- **结果**: CEO 没有止步于羞辱，而是给出市场细分、找对手产品线缺口等具体建议；主管受到足够激励，90 天后拿出了新的、比较现实的计划书；与会者同时学到了整套战略分析过程。

### 案例 2: 传感器工厂视察——一句追问点破汇报关系
- **问题**: 博西迪视察伊利诺伊州佛里波特市的传感器工厂，与工厂经理深谈时发现质量监督人员要向制造部门负责人汇报工作。
- **方法论的使用**: 他没有下指令，而是用一句比喻式的追问点破问题："这就像让狐狸去看管鸡窝一样。质量监督人员的工作是监督制造部门。"随后继续追问：为什么企业发展部门负责人没有出席今天的会议？"你要进行一些并购，而他却在忙其他事情，如果不听取他的建议和意见，你怎么能确定一项发展方案呢？"再追问预测系统——发现经理使用的行业生产指数与所在行业关联度只有 74%，"这根本不能作为预测的参考指数"。
- **结论**: 一连串尖锐问题暴露出汇报线设计、关键人员缺席与预测方法三类问题；该经理随后也同意这些地方需要改进。
- **结果**: 经理虽被提出诸多问题，仍获得共识与鼓舞，整体评价为"工作思路正确"；双方就未来工作任务达成共识，视察本身成了一次培训练习。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 下属呈上一份 PPT 精美、数据齐全的业务计划，用户需要在会上当场检验它。
2. 用户觉得某人的汇报"听着都对，但心里没底"，说不出哪里不对。
3. 用户要审核一份新市场/新产品/新渠道的方案，需要快速找到它的假设漏洞。
4. 用户在做教练型领导，希望不替下属做方案，又要把问题点透。
5. 用户自己要向上汇报，想先自问一遍，把计划里的空想提前挤掉。

### 语言信号 (用户的话里出现这些就应激活)

- "这个计划靠谱吗？/ 怎么审这份方案？"
- "他讲得头头是道，可我总觉得有问题。"
- "怎么问才能问出真相？/ 该问他什么？"
- "probe the assumptions" / "how do I challenge this plan" / "what questions should I ask"

### 与相邻 skill 的区分

- 与 `b1-f04 field-visit-protocol` 的区别: 视察是在现场（车间、分公司）用眼睛与开放问答获取未过滤信息；本 skill 是在会议室里对一份计划做逐层下钻。
- 与 `b1-f17 strategy-review-question-set` 的区别: 后者是战略评审会的固定问题清单与会议程序；本 skill 是可迁移到任何一次对话的追问顺序与教练节奏。
- 与 `b3-f12 coaching-two-tracks` 的区别: 教练双轨讲的是按人与事两条线设计辅导；本 skill 是"用追问完成辅导"的具体手法。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **先听完，不表态**
   - 完成标准: 让对方完整陈述目标与"如何实现"；听完前不打断、不承诺、不否定。

2. **按顺序下钻第一层六问**
   - 完成标准: 逐条拿到答案——实现途径、产品、客户对象、购买理由、竞争对手反应、阶段性目标；对每个答案追一个"为什么/凭什么/数据从哪来"。
   - 判停条件: 若某问答不上来或答案自相矛盾，停下来标记此为前提暴露点，不继续往下问。

3. **若对组织能力存疑，下钻第二层四问**
   - 完成标准: 拿到负责人、责任边界、所需帮助、激励与回报安排四项答案；责任含糊不清即记为第二暴露点。

4. **把暴露点翻译成教练内容**
   - 完成标准: 给出 2–4 条具体的改进建议（不是泛泛的"再想想"），并明确"由谁重做、什么时候交"。
   - 判停条件: 若对方是下属且暴露的是能力/态度问题而非信息问题，转入 `b3-f12 coaching-two-tracks` 或 `b1-f15`。

5. **书面收尾并设复查点**
   - 完成标准: 会后一句话总结共识（谁、做什么、何时、下次检查），并约定复查时点（书中的示范为 90 天）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 紧急处置场景：需要立刻行动止损时，先指挥、后复盘，不能边追问边等答案。
- 对方不具备回答条件（刚接手、信息不在其手上）：此时追问只会制造羞辱，应改为向正确的人取材。
- 文化或权力距离高的场景：上下级悬殊时，"追问"极易被体验为审讯；需先建立安全边界，或用书面提问替代当面连环追问。

### 作者在书中警告的失败模式

- **机械式（唯数字）业绩评估**: 只比对目标值与实际值，就会奖励运气好的人、冷落在逆境中表现出色的人、漏掉"从未来借债"的人——追问必须问到"完成任务的方式"（b1-ce06）。
- **走马观花式的提问**: 只做礼貌攀谈与简单问题（"你们的收入水平如何"），既暴露不了问题，也让优秀下属泄气（b1-ce12，属视察场景的同类失败）。
- **只挑错不给建议**: 书中明确警告，可以在这些问题上结束谈话、让经理难堪，但"这种做法恰恰使他们失去了一个很好的教练辅导机会"。

### 作者的盲点 / 时代局限

- 本方法默认"追问→暴露→对方改进"的链路成立，但未讨论被追问者若无改进动机或被当众羞辱后的反向效果；权力不对等下的"提问式领导"可能被体验为压迫。
- 书中示范以美国大公司面对面会议为场景，未处理跨文化沟通中"当面对质"的适用差异。

### 容易混淆的邻近方法论

- 与"苏格拉底式提问"的区别: 本 skill 有固定的业务顺序（途径→产品→客户→竞争→阶段目标→人员激励），不是随机反问。
- 与"事后复盘"的区别: 本 skill 用于计划实施前，追问的对象是未来承诺而非既成事实。
