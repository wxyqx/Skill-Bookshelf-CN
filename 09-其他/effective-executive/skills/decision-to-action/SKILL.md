# 化决策为行动：四问与激励同步

## R — 原文 (Reading)

> "决策的第四个要素，是化决策为行动。考虑边界条件，是决策过程中最难的一步；化决策为行动，则是最费时的一步。然而打从决策开始，我们就应该将行动的承诺纳入决策中，否则便是纸上谈兵。"
>
> — 彼得·德鲁克，第6章“决策的要素”（L1600）

> "若要化决策为行动，首先必须明确无误地回答下面几个问题：谁应该了解这项决策？应该采取什么行动？谁采取行动？这些行动应如何进行，才能使执行的人有所遵循？特别是第一个和最后一个问题，通常最容易被人忽略，以至于即使有了结果，也是灾难性的。"
>
> — 同上，第6章（L1606）

> "如果某一新计划应有某项行为，实际上却在鼓励另一类行为的话，则人人都会明白：原来高层的期望不过如此，所谓变革只是空口说说而已。"
>
> — 同上，第6章（L1626）

## I — 方法论骨架 (Interpretation)

德鲁克把“执行”前置进“决策”里：行动承诺不是决策做出之后另起一段的工作，而是决策本身的组成部分。判据很硬——“一项决策如果没有列举一条一条的行动步骤，并指派为某某人的工作和责任，那便不能算是一项决策，最多只是一种意愿而已”（L1602）。

操作核心是**四问**：

1. 谁应该了解这项决策？（最容易漏；不知道的人会继续按旧规则行动）
2. 应该采取什么行动？
3. 谁采取行动？
4. 这些行动应如何进行，才能使执行的人有所遵循？（最容易被省略，结果是“有了结果也是灾难性的”）

两条附加判据：

- **行动必须与执行者的能力相适应**：决策再对，若执行者做不到，就会以失败或走样收场；设计行动时要考虑“这一决策应由谁来执行、他们能做些什么”。
- **衡量与激励必须同步改变**：当决策要求改变行为习惯和态度时，绩效衡量标准与激励制度若不变，组织成员会读信号而不是读口号——“人人都会明白：原来高层的期望不过如此”。

所以化决策为行动的输出不是一份执行计划书，而是一张把“谁知道、做什么、谁做、怎么做、拿什么衡量、拿什么奖励”全部对齐的清单。

## A1 — 书中的应用 (Past Application)

### 案例 1: 停产设备三年后仍积存 8–10 年零件（“谁应该了解”被忽略）
- **问题**: 某制造生产设备的大厂决定停产某一型号，因老客户订单多，决定未来三年继续供货、三年后停售。这是一项清楚、提前量充足的决策。
- **方法论的使用**: 决策做出后，整个公司上下“谁也没有想到这一决策应让什么人知道”——采购部门不知道，采购人员仍按销货金额比率照常订购零件。
- **结论**: 第一问（谁应该了解这项决策）被忽略，决策在传递环节失效。
- **结果**: 正式停产那天，库房积存了足够 8 到 10 年的零件库存，“这笔损失真是相当可观”。

### 案例 2: 非洲两厂的转售成败（行动必须与执行者能力相适应）
- **问题**: 某化学公司资金被冻结在非洲两国，决定就地投资设厂加工水果，两国工厂都经营成功；几年后外汇解冻，公司准备把工厂转售给当地企业家。
- **方法论的使用**: 甲厂厂长过于卖力，设定了过高的技术和管理水平，决策时未考虑“这一决策应由谁来执行？他们能做些什么？”；乙厂厂长充分考虑当地人员水平，程序简单、管理容易，能聘到当地人才。
- **结论**: 两厂加工程序与经营方式基本相同，差别只在决策时是否考虑执行者能力。
- **结果**: 水准极高的甲厂因当地无人能接管，只落得清算；水准平平的乙厂被当地投资人竞相购买，公司收回资金并大获其利。

### 案例 3: 费尔的服务标准 vs 老公司的变革落空（衡量与激励同步）
- **问题**: 贝尔公司总裁费尔提出“以服务为目的”的新决策；另一家老化的大公司董事长提出新的组织结构和目标。
- **方法论的使用**: 费尔同时设计出可以衡量管理绩效的服务标准（此前贝尔以盈利或成本为衡量标准），新目标才顺利被人接受；那家大公司却在变革期把三位老派人物提升为副总裁，“应有某项行为，实际却在鼓励另一类行为”。
- **结论**: 决策要求改变行为时，衡量与激励必须同步改变。
- **结果**: 费尔的决策落地并长期有效；该公司变革计划落空，员工议论“他们不是真想变革！”

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 发布了新政策/新流程，一段时间后没人执行，或执行走样，需要回查环节断在哪。
2. 要把一项已定的决策（降本、改组织、上系统、换流程）翻译成“谁做什么”。
3. 决策要求人们改变行为习惯，但考核、晋升、奖励还是老一套，用户感觉“喊不动”。
4. 决策会开完、纪要发完，用户不确定“这算不算已经决策了”。
5. 执行方案设计出来，用户担心“执行的人做不到”——需要检查行动与执行者能力的匹配。

### 语言信号 (用户的话里出现这些就应激活)

- “文件发了三个月，根本没人执行，怎么就落不了地？”
- “这项决策谁来负责？谁该知道？”
- “考核没改，光喊口号有什么用？”
- “nobody acted on it” / “how do we make this happen” / “who owns this” / “we announced it but nothing changed”

### 与相邻 skill 的区分

- 与 `decision-five-elements` 的区别: 后者是五要素全程审计（问题性质→边界条件→正确方案→行动→反馈）；本 skill 把要素四做成专项，处理“决策落不了地”一类问题。
- 与 `decide-and-act-fully` 的区别: 后者管决策两端的门槛（要不要做）与收尾（绝不只做一半）；本 skill 管中间环节——把已定决策翻译成行动承诺与激励对齐。
- 与 `feedback-and-inspect` 的区别: 本 skill 在行动之前设计“谁做什么”；后者在行动之后设计“拿什么检验”，两者接力使用。
- 与 `boundary-conditions` 的区别: 边界条件定“必须达成什么”（行动要满足的规范）；本 skill 定“由谁怎样达成”（行动本身）。
- 与 `one-thing-at-a-time` / `priority-and-posterior` 的区别: 后者决定做什么、不做什么；本 skill 只处理已入选事项的落地机制。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **回答第一问：谁应该了解这项决策**
   - 完成标准: 列出所有需要知道的人与岗位（含执行链之外但会受影响的部门，如案例中的采购），明确通知方式与责任人；不能只以“发文/公告”代替逐一确认。
   - 判停条件: 若答不出“谁该知道”，说明决策尚未成型，退回 `decision-five-elements`。

2. **回答第二、三问：什么行动、谁采取行动**
   - 完成标准: 逐条列出行动步骤，每一步指派到具体的人（姓名/岗位），并写明完成时点或先后顺序；产出物形态确认——“有步骤、有责任人才算决策，否则只是意愿”。

3. **回答第四问：行动如何进行（执行者如何遵循）**
   - 完成标准: 给出执行者可以照做的操作说明（谁来教导、依据什么、遇到例外怎么办）；抽查一位执行者能否复述“我明天该做什么”。
   - 判停条件: 若第四问答不上，行动会走样——先补操作设计，不进入推行。

4. **检查行动与执行者能力是否匹配**
   - 完成标准: 对每步行动确认执行者具备所需能力与资源；不匹配时，或调整方案复杂度、或换人、或先补能力（非洲两厂判据：“这一决策应由谁来执行？他们能做些什么？”）。

5. **要求行为改变时，同步修改衡量与激励**
   - 完成标准: 逐条对比“新决策要求的行为”与“现行考核、晋升、奖励信号”，列出并落实需改动的条目；无法改动的，向决策者明示“行为不会真变”的后果。
   - 判停条件: 若决策者拒绝调整衡量与激励且坚持推进，则把该项列为已知风险写入决策记录（参照“他们不是真想变革”的教训）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 还没决定要不要做这项决策：先走 `decide-and-act-fully`；本 skill 是决策做出后的翻译工序。
- 纯信息通报、例行通知：不需要四问的完整处理。
- 把四问当项目管理模板用：排期、甘特图、资源平衡属于项目管理工具；本 skill 的独特动作是“行动承诺写进决策本身 + 衡量激励同步”，不是执行排期。
- 无权可指的场合：如果用户既不能指派责任人、也无法影响衡量与激励（典型如跨部门螺丝钉），应改为向决策者提交四问清单，而不是假装可以替其落地。

### 作者在书中警告的失败模式

- **决策没有行动承诺**（ce28）：无步骤、无责任人、无人知道（政策颁布后“你看看我、我看看你，以为上级只不过是说说罢了”）；“一项决策如果没有列举一条一条的行动步骤，并指派为某某人的工作和责任，那便不能算是一项决策，最多只是一种意愿而已”。
- **宣布变革却不改变衡量与激励**（ce29）：要求新行为却继续用旧标准衡量绩效、按旧逻辑发薪晋升；组织成员读“激励信号”而非“口号”，据此判定变革是假的。
- **行动与执行者能力不匹配**：非洲高标准工厂无人接手只能清算，与“行动必须与执行人员的工作能力相适应”形成教训（L1610–1618）。
- **过多政策说明令人困扰**：“决策中没有行动的承诺，没有指定何人负责执行”（L1604）。

### 作者的盲点 / 时代局限

- **高管视角与可指派权假设**：四问预设决策者有权指名道姓、有时间盯落实；对没有下属、没有预算权的知识工作者（本书定义下的“管理者”多数如此），四问的有效部分是“向谁澄清、与谁对齐”，而不是“指派谁”。
- **激励同步对激励设计权的依赖**：衡量与激励的改动通常超出中基层管理者的权限；德鲁克只描述了原则，没有给“无权限者如何推动”的路径。
- **政治因素被排除**：组织内故意不执行、阳奉阴违、派系抵制等情形不在分析范围；把“落不了地”全部归因于决策环节，可能低估政治与利益冲突（BOOK_OVERVIEW 立场盲点）。
- **时代语境**：案例来自 1960 年代前后的美欧大企业与工业场景，通知链条、信息系统与当代远程/异步组织差异大，判据可迁移、细节不可照搬。
- **证据声明**：本书证据以作者顾问观察与轶事为主，无对照实证；本方法应按经验判据使用（BOOK_OVERVIEW 批判节）。

### 容易混淆的邻近方法论

- 与“执行四原则/OKR 落地”的区别: 那类工具从目标拆解与追踪入手；本 skill 从“决策本身是否包含行动承诺”入手，且强调衡量与激励同步是决策的一部分。
- 与“变革管理八步法”的区别: 后者提供阶段性流程与动员手段；本 skill 是一个决策收尾判据，可嵌入任何流程。
- 与 `feedback-and-inspect` 的区别: 见上，一个管行动设计、一个管反馈设计。

## 相关 skills

**depends-on**（使用前提）: 无硬依赖；若决策尚未拍板，先走 `decide-and-act-fully` 过门槛——本 skill 是"决策已做出"之后的翻译工序。

**contrasts-with**（同境况二选一）: 无。

**composes-with**（配合使用/先后接力）:

- `decision-five-elements` — 本 skill 是要素四的深挖；全景审计走那边。
- `feedback-and-inspect` — 行动设计（本 skill：谁做什么）→ 反馈设计（那边：拿什么检验），相邻两步接力。
