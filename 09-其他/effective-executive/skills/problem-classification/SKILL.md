# 问题四分类（"先假定它是经常性问题"）

## R — 原文 (Reading)

> "有效的决策人首先需要辨明问题的性质：是一再发生的经常性问题呢，还是偶然的例外？……倘若是经常性的老毛病，就应该建立原理原则来根治；而偶然发生的例外，则应该按情况做个别处置。"
>
> — 彼得·德鲁克，第6章·问题的性质（L1492）

> "除了上述第三类'真正偶发的特殊事件'之外，其余三类均需要一种'经常性的解决方法'。换言之，需要制订一种规则、一种政策或一种原则。一旦有了正确的原则，一切类似问题的解决就将易如反掌。"
>
> — 彼得·德鲁克，第6章·问题的性质（L1516）

> "一位有效的决策者碰到问题，总是先假定该问题为'经常性质'。他总是先假定该问题是一种表面现象，另有根本性的问题存在。他要找出真正的问题，不会只满足于解决表面现象这类问题。"
>
> — 彼得·德鲁克，第6章·问题的性质（L1544）

## I — 方法论骨架 (Interpretation)

德鲁克的问题分类轴不是大小、急缓、影响，而是"是否重复出现（或表象下是否隐藏重复结构）"。他给出四类：

第一类，真正经常性的问题——个别事件只是表面现象（库存、管子接头坏了这类反复出现的生产问题）。第二类，在特殊情况下偶然发生、但实质仍是经常性的问题（某公司只会接到一次的合并建议，但"企业并购"本身是经常性事件，应按原则并参考他人经验决策）。第三类，真正偶然的特殊事件——概率极小、发生一次几乎不会再发生（他举大停电与沙立度胺悲剧为例，但同时说这两例"直到今天我们才判定其为经常事件之首次出现"，说明归类要被证据修正）。第四类，首次出现的"经常事件"——看似偶发，实则是一个新问题类别的第一例。

用法上有一条不对称的默认假设：先假定它是经常性/表面现象，另有根本问题存在；即使确认是偶发，也要先怀疑它是不是新的经常问题的首次出现。只有第三类才个别处置，其余三类都要建立规则、政策或原则。

这个分类决定决策类型：该立规则的做了个案处理，或该个案对待的却立了错规则，都是类别错误——"如果类别错了，其决策必为错误的决策"。推论是决策总量的下降：规则建好了，管理者实际上没有做太多决策的必要；天天做决策恰恰说明其疏懒和无效。检验机制：新规则执行后要回看同类事件是否消失；当出现规则无法解释的新事件、或结果与预期不符时，回头重新检讨问题本身。

## A1 — 书中的应用 (Past Application)

### 案例 1: 军医留不住高素质医务人员——问错了问题
- **问题**: 二战后美国军方屡次研究"为何留不住高素质军医"，提出不知多少建议，问题依旧。
- **方法论的使用**: 所有研究都建立在"问题在于待遇不够"的假定上——这是一个似是而非的问题界定。德鲁克指出真正的原因在军医的传统制度：晋升阶梯只能往行政方向爬，与医学研究脱节；年轻医生的真正需要是"能有发展医学才干、成为一位专门医师的机会"。也就是说，军方把"如何提高待遇"当成了问题，而问题实质是"职业发展通道设计"，属经常性制度问题，应通过制度改革（而非待遇补丁）来解决。
- **结论**: "对某些根本性问题的界定似是而非"是常见错误；界定错误则所有制研究都白做。
- **结果**: 德鲁克断言：除非军方接受"这是一项重要决策"，否则年轻有为的医生始终会外流。

### 案例 2: 东北部大停电——用旧原则处理新问题
- **问题**: 1965 年 11 月美东北部全面停电，起初只限于纽约与安大略一带，后滚雪球式扩展到整个东北部。
- **方法论的使用**: 纽约市的电力工程师起初按"只适用于正常负荷情况的旧原则"处理，把新问题当旧病复发；详细检查发现非比寻常的现象后，才知道必须用非常方法解决。事后判定其为"经常事件之首次出现"——电力技术与医学知识已然具备，若寻求经常性的解决方法（规则），此类悲剧应不至于一再发生。
- **结论**: 把真正的新问题误认为旧病复发、沿用旧原则，会使事态滚雪球式扩大。
- **结果**: 该书把它作为"第二种常见错误"的标准案例，与肯尼迪处理古巴导弹事件（看准是非常事件、用非常手段，因而成功）形成正反对照。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 客服/运维/质量连续收到同类问题，每次单独立案处理，下周同类再来。
2. 用户要用"上次也是这么办的"处理一个看上去熟悉的新情况。
3. 用户要做政策、流程或产品规则设计，但没人检验其背后假定（项目立项、合规规则、审查流程）。
4. 用户困惑"这事到底是个案还是我们流程有病"，或统计发现某个问题反复出现而想找根本解。

### 语言信号 (用户的话里出现这些就应激活)

- "同类问题又来了 / 这个已经发生第三次了 / recurring issue again"
- "每次都是单独处理，效率太低 / ad hoc fix, patch"
- "这是偶发还是系统性问题 / one-off or systemic, root cause"
- "上次也是这么办的 / we handled it this way last time"

### 与相邻 skill 的区分

- 与 `decision-five-elements`（f16）的区别：f16 是全景五要素审计；本 skill 只做第一要素（问题定性）的深挖。用户若已有明确议题要跑全套审查 → f16；问题本身"是什么性质"没搞清 → 本 skill。
- 与 `time-waste-institution-scan`（f04）的区别：f04 扫的是"重复危机、人员过多、会议过多、信息不健全"四类时间浪费病灶；本 skill 是更一般的分类方法，凡重复出现的问题都要先定性再谈解法。时间类的重复危机处理可视为本 skill 在时间领域的应用。
- 与 `boundary-conditions`（f18）的区别：定性解决"这是哪种问题、用什么类型的决策"，边界条件解决"这个决策最低要达成什么"；顺序上先 f17 后 f18。
- 与 `decide-and-act-fully`（f24）的区别：f24 判"是否需要决策"（保持现状会怎样；不做也是选项）；本 skill 判"如果要做，该以规则还是个案的方式做"。鸡毛蒜皮式的量级判断走 f24。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **建立问题案例簿**
   - 记录本次问题的现象，并回查：同类问题此前发生过几次？各次处理方式与结果？
   - 完成标准: 有发生次数与历次处置记录（没有历史记录的先立记录再判断）。
2. **按四类定性（默认经常性）**
   - 逐条判断：真正经常性问题（个别只是表象）／特殊情况下的经常性问题（一次性外壳、经常性本质）／真正偶发事件（概率极小）／经常事件的首次出现（新类别第一例）；拿不准时先假定为经常性。
   - 完成标准: 写出归类与理由；凡归入第三类的，须论证其"发生一次后不太可能再发生"。
3. **按类别选择决策类型**
   - 前三类：建立规则、政策或原则——并写出规则本身及其假定；第三类：个案处置。
   - 判停条件: 若归类为第三类但发现"同类曾有先例"或"现象下隐藏结构" → 退回第 2 步重新定性（防"真偶发"被当成借口不建规则）。
   - 完成标准: 产出规则草案（前三类）或个案处置方案（第三类），且规则附带其成立假定。
4. **验证规则**
   - 规则执行后回看：同类事件是否消除？规则的解释力是否覆盖所有同类事件？"这一解释能说明所有同类的事件吗？"
   - 完成标准: 有一个可观察的验证指标与观察期。
5. **定期复审与重开**
   - 当出现规则无法解释的新事件、或结果与预期不符时，回头重新检讨原来的问题。
   - 判停条件: 若新事件表明原定性错误 → 从第 2 步重来。
   - 完成标准: 复审时点与触发条件已写明。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已有明确规则且问题确在规则覆盖内：直接执行，不需要重新定性（避免"为分类而分类"）。
- 寻找技术性根因：5 Whys、鱼骨图、故障树等机械工具解决"为什么发生"，本 skill 解决"该以何种决策类型应对"；两者可连用但职责不同。
- 危机现场：先用预案处置事态，分类留待事后复盘。

### 作者在书中警告的失败模式

- **问题性质误判四型（ce26）**：①经常问题当偶发处理（肯尼迪政府的"实用主义"：成功只靠古巴导弹事件一次）②新问题沿用旧原则（大停电初期处理）③对根本问题界定似是而非（军医留人归因待遇）④只见部分不见全貌（汽车安全只抓道路与驾驶训练，忽略车辆设计，而 3/4 事故由酒驾与高风险驾驶者造成）。"一知半解有时比全然不知更为可怕。"
- **预警信号**：同类问题反复出现却每次单独立案解决；用"上次也是这么办的"处理新情况；政策设想听来头头是道但无人检验其假定。
- **归类随证据修正的义务**：书中对"大停电、沙立度胺"的处理是"直到今天我们才判定其为经常事件之首次出现"——分类不是一锤定音，证据变化时须回头修订（对应第 5 步复审）。

### 作者的盲点 / 时代局限

- **"电脑使人易犯新错误"的时代语境（ce36 关联）**：德鲁克在 1966 年预言电脑使人"误将真正的偶发事件视为例行情况"（L1861）。这是 1960 年代大型机时代的判断，非当代技术结论；作为 Boundary 只保留"判断不可外包给工具"的一般含义。
- 案例（大停电、肯尼迪政府、军医制度、汽车安全）均为 1960 年代美国公共事件的轶事级证据；德鲁克对肯尼迪政府"只做了一件成功的工作"的评语是论断性的，无系统评估支撑。证据等级声明：本书证据以作者顾问观察与轶事为主，无对照实证。
- 四分类未覆盖"结构性政治问题"（谁受益谁受损的再分配冲突）：书中把公共组织的目标冲突当作管理糊涂而非政治必然（BOOK_OVERVIEW 批判节），在多方利益冲突场景下，本 skill 可能把政治问题误判为技术问题。
- 高管视角：默认用户有建立规则的权限；无权限者需把分类结论转化为对有权者的建议。

### 容易混淆的邻近方法论

- "具体问题具体分析"式流行智慧：与本 skill 的默认假设（先假定经常性）方向相反——德鲁克要求先怀疑个案性，找不到重复结构才放行个案处置。
- 四象限分类（重要紧急）：那是排序工具，不回答"该立规则还是做个案"。
- 与 `f04` 口径区分：f04 的四病灶是时间浪费领域的收窄清单；本 skill 是通用分类法。若用户问题正是"重复危机/人员过剩/会议过多/信息不健全"，用 f04 更直接。
