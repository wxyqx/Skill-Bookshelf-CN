# 战略评估会议的问题框架

## R — 原文 (Reading)

> "战略评估会议上的讨论必须回答这样几个关键问题：这份计划是否合理？它是否前后一致？你的组织是否具备必要的能力来执行它？"
>
> — 博西迪/查兰/伯克，第8章（L2251）

>

## I — 方法论骨架 (Interpretation)

战略评审会的价值不在"过一遍材料"，而在用固定顺序的问题把计划的三个层面剥开：

1. **总纲三问**：这份计划是否合理（对市场与竞争的理解成立吗）？是否前后一致（资源、人员、节奏自洽吗）？组织是否具备必要的能力来执行它？——第三问必须被当成评审对象，而不是会后才想的执行问题。
2. **逐项检查清单**：竞争形势（对手将如何反击、对手领导层背景、可能的并购与联盟）；执行能力（人才、技术、成本结构；用 1–10 分打分，低于 6 分即视为不具备能力）；聚焦度（是否超负荷运营、是否同时进入太多市场）；发展思路（四问：与市场现实一致吗、组织有条件执行吗、是否过于贪婪、能否带来利润）；战略与人员、运营的联结（组织调整、资源分配、季度项目与资金来源）。
3. **关键问题前置**：每家企业约有六个关键问题；会前先交换问题清单并电话确认，会议以这些问题开场。
4. **产出要求**：会上必须有争论、必须得出结论、必须明确责任人与跟进；"留待以后解决的问题"要显式列出并另行安排会议。
5. **定位**：这是领导者观察下属战略思考能力与教练辅导的场所，也是实施前的最后补救机会。

## A1 — 书中的应用 (Past Application)

### 案例 1: AT&T 与阿姆斯特朗——四个战略前提全部落空
- **问题**: 1997 年阿姆斯特朗任 CEO 后制定新战略：收购光纤公司直接接触客户、提供捆绑式服务、尽快获得收入抵消长途业务下滑、充分利用 1996 年电信条例。
- **方法论的使用**: 作者事后用本框架复盘，逐项检验该战略的假设：收购成本被长途业务价格下跌推高；消费者对捆绑服务的热情不及预期且营销不到位；执行周期大大超出预期；政府执法力度不够、地区性电信公司毫无顾忌地进入长途市场——四项前提全部落空。
- **结论**: "公司的所有战略前提都是建立在错误的假设之上的"；战略从根本上脱离内部与外部现实，既未验证假设，也未预先制定备选方案，更未评估自身竞争能力。
- **结果**: 耗资 1000 亿美元的光纤业务以 690 亿美元出售给 Comcast（含 250 亿美元债务）；股价从 44 美元跌至约 18 美元；HR 部门的疏忽使不胜任的主管在岗三年。

### 案例 2: 工业公司收购分销商转做零售——发展思路本身错了
- **问题**: 一家市值 60 亿美元的工业公司原本通过小型分销商网络销售、边际利润较高；为追求增长，它买下许多分销商、决心自建销售链条，并把欧洲执行官调回总部，原分销网络骨干先后离开。
- **方法论的使用**: 用"发展思路四问"检验：它与市场现实一致吗（该公司根本不了解零售业）、组织有条件执行吗（不知道如何在低边际利润、强物流专业要求的行业赢利，也没有准备管理新业务的团队）、是否过于贪婪、能否带来利润。
- **结论**: "进军零售业就是一个错误的选择"；无论执行得多好，发展思路不适配时失败风险都很高。
- **结果**: 公司开始赔钱，股价下跌 1/3。

### 案例 3: 霍尼韦尔汽车部门——用三个关键问题开场
- **问题**: 2001 年霍尼韦尔汽车产品面临价格持续下降、成本压力与制度障碍。
- **方法论的使用**: 评估从三个关键问题开场："针对目前汽车市场价格不断下降的情况，我们是否能够在压低成本的前提下仍然保持一定水平的边际利润？""领导团队是否可以考虑把制造环节转移到劳动力成本较低的地方？""我们会面临怎样的制度障碍？"
- **结论 / 结果**: 讨论聚焦在可能成为绊脚石的问题与发展机遇上，而非数据罗列——这是"关键问题前置"的标准做法。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户要审一份并购标的的业务计划书或部门战略，需要一套不遗漏的检验清单。
2. 用户主持的战略评审会正在变成"念 PPT、无人争论、无结论"。
3. 用户想评估某个部门的战略是否具备执行能力支撑（人、技术、成本结构）。
4. 用户发现计划"什么都想要"，需要检验聚焦度与项目顺序。
5. 用户要在会上同时完成对下属战略思考能力的观察与教练。

### 语言信号 (用户的话里出现这些信号就应激活)

- "战略评审会怎么开才有用？"
- "这份业务计划书怎么审？"
- "评审会就是念 PPT，问不出问题。"
- "strategy review meeting" / "challenge the business plan" / "is this plan executable"

### 与相邻 skill 的区分

- 与 `b1-f16 bedrock-strategy-one-pager` 的区别: 后者是构建与表达（把战略压成基石与一页纸）；本 skill 是评审（用问题清单检验他人交来的战略），二者为表里。
- 与 `b1-f22 assumptions-and-contingency` 的区别: 前提假设显性化处理的是计划背后的假设与应急方案；本 skill 是会议层面的整体检验程序，其中包含对假设的追问。
- 与 `b5-f19 diagnosis-five-steps` 的区别: 诊断五步面向组织与个人领导力问题的通用诊断；本 skill 专门针对战略评审会议。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **会前交换关键问题清单**
   - 完成标准: 要求汇报方提交约六个"可能成为发展绊脚石"的关键问题，并与其电话确认清单，确保评估会围绕这些问题开场。
   - 判停条件: 若对方交不出关键问题或清单全是成绩汇报，先退回补充。

2. **用总纲三问开场**
   - 完成标准: 对"合理性、前后一致性、执行能力"各取得明确回答，且每个回答都带证据（市场数据、竞争对手动向、人才与能力清单）。

3. **逐项过检查清单**
   - 完成标准: 依次检验竞争形势（对手可能如何反击、其领导层背景、可能的并购与联盟）、执行能力（按 1–10 分打分，低于 6 分即视为不具备）、聚焦度（是否超负荷、项目数量与顺序；书中示范为联合利华把 1600 个品牌减到 400 个后边际利润与收入增长明显增加）、发展思路四问、战略与人员/运营联结（组织结构、资源、季度项目与资金来源）。

4. **当场得出结论与责任人**
   - 完成标准: 会议结束前形成结论、行动条目与责任人；把"留待以后解决的问题"单独列出并约定专门会议。

5. **书面固定并跟进**
   - 完成标准: 会后向与会者发信/备忘录，逐条总结共识与待办；设定跟进时点（详见 `b1-p08`）。
   - 判停条件: 若评审发现组织能力不足（打分低于 6 分）却仍要推进，明确向用户指出这是"目标与能力之间的鸿沟"，需先补能力或改战略。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 一对一阅读材料、非会议的快速判断：用简化版三问即可，全套清单会显得笨重。
- 战略尚未成形、还在创意阶段：此时应先用 `b1-f16` 把战略构建出来，再评审。
- 会上没有讨论文化、只允许汇报的场合：本框架要求争论与责任落地，若形式无法支撑，先改变会议规则。

### 作者在书中警告的失败模式

- **目标脱离执行能力（未做组织能力评估）**: "很多企业失败的原因都在于它们的领导者没有对自己企业的执行能力做出符合实际的评估，比如说施乐、朗讯和美国电话电报公司公司"（b1-ce17）。
- **忽视竞争对手反应 / 过高估计对手**: 竞争分析停留在过时的行业结构数据，不预测对手的实时行动；或把恐惧当事实（b1-ce15）。
- **同时启动过多项目 / 不熟悉的行业豪赌**: 组织消化能力被忽略，资源摊薄、失败互相放大（b1-ce14）。

### 作者的盲点 / 时代局限

- **会议机制假设了坦诚文化**: 框架要求争论与举证，但作者自己承认"错位已经成为一种沾沾自喜的文化"；在缺乏心理安全与坦诚的组织里，清单会被形式化地走过场（BOOK_OVERVIEW 最强反对意见 4）。
- **"执行能力打分法"缺乏效度证据**: 1–10 分的打分是启发式判断，可能与真实执行能力脱节，且易被乐观情绪污染。
- **单因论与事后归因**: AT&T 案例的复盘是在结果已知后进行的，"四前提全落空"既能解释失败，也可能忽略治理、竞争与技术迭代等其他解释（BOOK_OVERVIEW 批判节）。
- **美国大公司语境**: 清单以工业公司与电信业为背景，对平台型/研发驱动型业务（边际成本近零、网络效应）并不直接适用。

### 容易混淆的邻近方法论

- 与"尽职调查清单"的区别: 尽调清单以核实事实为主；本框架以检验战略的内在逻辑与可执行性为主。
- 与"红队演练"的区别: 红队做对抗性推演；本框架是结构化提问＋当场结论，两者可组合使用。
