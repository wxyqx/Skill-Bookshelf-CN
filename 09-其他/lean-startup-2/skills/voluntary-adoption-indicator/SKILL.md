# 自愿参加是领先性指标

## R — 原文 (Reading)

> "参不参与不强迫。各部门的新系统测试采取自愿原则。事实上，很多部门自愿参加测试，这本身就是一个成功的领先性指标。"
>
> — 埃里克·莱斯，第 8 章

> "员工可以自己选择参不参加培训。……最后有3万多人主动报名。"
>
> — 埃里克·莱斯记 GE 日常 FastWorks，第 8 章

---

## I — 方法论骨架 (Interpretation)

一项新制度好不好，强制的世界里测不出来：强制切换只能测出合规——人们在行政命令下会完成培训、登录系统、出席例会，但那些行为只证明命令有效，不证明制度有价值。更糟的是，强制烧掉了纠错信息：不满者不会说"这流程不行"，只会沉默地应付，你失去了本可以免费拿到的问题清单。

本书的指标发明是把"自愿加入率"当作制度质量的测量仪：不需要说服每个人，只需要数有多少部门、多少团队在没有命令的情况下愿意来。自愿流入证明价值主张成立；长期零流入证明制度没解决真问题——这两个读数都比部署率诚实。

执行上有两个配套。其一，入口必须便宜：小团队可加入、旧轨并行可用、退出无损失——否则"自愿"只是门槛测试而不是偏好显示。其二，读数要驱动决策：净流入为正就扩大投放，趋零就回到设计与环境端回修，而不是加大行政压力把数字做上去。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: PD@GE 绩效新法的部门自愿扩大
- **问题**: 新绩效考核法在小群验证成功后，是下令全公司切换，还是等各部门自己来？
- **方法论的使用**: 参不参与不强迫；公司问已参与部门"希望如何扩大规模"，对未参与部门只邀请派小团队加入。自愿参加本身就是成功的领先性指标。
- **结论**: 迁移的部门是自己"用脚投票"进来的——这比任何推广 KPI 都更早证明制度有价值。
- **结果**: 使用新系统的团队从 5500 人增至约 90000 人，试用"不评级"考核法的人从 1000 人升至 30000 人，2016 年新法全面应用、评级制废除。

### 案例 2: 日常 FastWorks 的 3 万人报名
- **问题**: 把工作法推广到全公司员工，是下命令强制受训，还是开放报名？
- **方法论的使用**: 员工自选网课或 6-8 小时现场培训，不强制参加。
- **结论**: 报名数成为方法吸引力的直接读数，公司据此决定资源配置。
- **结果**: 3 万多人主动报名；GE 据此确定全职 FastWorks 辅导员的编制——自愿数据直接转化成了资源投放决策。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 新流程/新工具试点成功，管理层在争"强制全员切换"还是"双轨并行"，需要一个裁决依据。
2. 验收指标讨论会：有人提议用"部署率/覆盖率/完成率"考核推广成果，有人觉得不对但说不出该用什么。
3. 制度上线后表面平静：没人反对，也没人真的用——需要一种能区分"服从"与"接受"的测量。
4. 各部门对推广的反应两极：个别团队追着要接入，多数观望——判断这是成功信号还是长尾问题。
5. 设计内部平台/培训/社区的增长策略：要不要开放注册、要不要设退出机制。

### 语言信号 (用户的话里出现这些就应激活)

- "强制全员上，还是先让大家自愿试试"（mandatory vs opt-in）
- "双轨并行要并行到什么时候"（parallel run / migration）
- "部署率 90% 了，可总觉得没人真在用"（adoption vs actual usage）
- "有多少部门/团队主动报名了"（opt-in rate / voluntary sign-ups）

### 与相邻 skill 的区分

- 与同书 `behavior-before-tools`（技术只是手段：先改行为与文化，再上工具）的区别: `behavior-before-tools` 管"怎么推"（行为证据先于工具部署的顺序），`voluntary-adoption-indicator` 管"推得好不好读什么数"（自愿迁移率作头号指标）。决策"先试点还是先铺开"是 `behavior-before-tools`；决策"用什么指标验收推广"是本 skill。
- 与同书 `bingo-card-diagnostic`（宾果卡）的区别: 宾果卡是"规模×阶段"的组织级诊断矩阵（实施→行为→用户影响→财务影响）；自愿率是"行为变化"格最前哨的一个信号。逐格下钻诊断是 `bingo-card-diagnostic`，只读"有没有人自愿来"是本 skill。
- 与同书 `one-team-success-is-enough`（只要一个团队成功就是胜利）的区别: `one-team-success-is-enough` 是对试点结果的事前期望管理；`voluntary-adoption-indicator` 是推广过程中持续读取的采纳信号——一个防"要求全胜"，一个防"强制验收"。
- 跨批提示: 与 `three-stage-transformation`（转型三阶段路线图）的区别——`three-stage-transformation` 决定转型整体推进到哪一阶段；本 skill 是第二阶段"扩大规模"里推广手法的度量细则。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **替换验收指标**
   - 完成标准: 推广方案的验收指标表中，"自愿迁移率/自愿报名数"列首位；"部署率、覆盖率、完成率"降级为过程量或删除。凡以覆盖率为唯一验收的方案退回。

2. **把入口做便宜**
   - 完成标准: 参与规则满足三条——可以小团队为单位加入（不必全员）、旧轨并行可用（不必二选一）、退出无损失（记录不追责）。缺任一条则"自愿"失真为门槛测试。

3. **周期性读数并驱动决策**
   - 完成标准: 每个推广周期记录净自愿流入（新增报名-退出），并明确对应动作：流入为正→扩大投放与辅导员配置；趋零→回到设计/环境端回修（衔接 `behavior-before-tools`），禁止用加大行政压力的方式把数字做上去。

4. **捕捉异议信息**
   - 完成标准: 对未加入的团队做至少一次非正式访谈，把"为什么不进来"记录为改进清单——自愿机制的主要红利是这份免费的纠错信息，只读数字不听理由等于白设双轨。

5. **判停**: 若管理层坚持强制全员切换，明确书面告知：该决策只能测出合规、测不出价值，且烧掉纠错信息（ce15 噪声测量）；把该警告写进会议纪要后再执行，同时保留事后回读自愿率的机制。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 安全、合规、审计类必须全员执行的上线：强制是义务而非选项，自愿率无意义；此类场景只谈使用质量不谈参与自愿。
- 自愿率低立即判死刑前：先查入口成本与信息透明度——入口难找、流程不清、需要层层审批都会压低自愿率，此时低读数是入口问题不是价值问题。
- 不能用自愿率替代后端测量：自愿参加只是"行为变化"格的前哨，后续的用户影响与财务影响仍需 `bingo-card-diagnostic` 宾果卡逐格验证——自愿的人多不等于用得好。

### 作者在书中警告的失败模式

- ce15 跳过关键问题的强制推广：命令全公司试用以"测生产力影响"，或只统计"多少人完成了培训"——谁都没真的在用新产物时，一切后期指标都是噪声。
- 验收指标错位：部署率/覆盖率/完成率构成的指标组测量行政执行力，与制度价值零相关；用它们考核会反向激励强制。
- ce02 式信号失真：口号倡导自愿、考核惩罚不参与时，"自愿报名"会变成新的表演，读数作废。

### 作者的盲点 / 时代局限

- "3 万人主动报名"发生在 GE 转型第三年、有 CEO 背书与配套激励之后——把成熟期的自愿率当普适指标，忽略了启动期的冷启动问题；冷启动期读数天然偏低。
- 自愿参加者多为乐观者，存在自选择偏差；沉默多数为何不来（BOOK_OVERVIEW：对被旧文化塑形的多数沉默员工转化机制着墨不足）书中未给机制。
- 案例来自作者深度合作的 GE，利益关联与幸存者偏差须打折看待。

### 容易混淆的邻近方法论

- 与《精益创业》正传的区别: 正传不谈组织内推广——其"验证"面向外部用户；本书把"员工愿不愿意用"变成了内部制度的验证信号，验收对象从产品换成了制度本身。
- 与 NPS/满意度调查的区别: 满意度测表达偏好，自愿迁移测显示偏好——行为（要不要花时间加入）比打分诚实；问卷高分与报名挂零可以并存。
- 与 A/B 测试的区别: A/B 是外部流量分桶；双轨并行是组织内的迁移观察，读的不是转化率而是迁移率，且必须保留退出自由——无退出自由的"双轨"仍是强制。
