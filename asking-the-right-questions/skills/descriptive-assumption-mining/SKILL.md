# 描述性假设挖掘

## R — 原文 (Reading)

> "描述性假设就是对这个世界过去、现在或未来是什么样的想法。"（第5章）
>
> — 布朗 & 基利，《学会提问（原书第10版）》第5章

> 定义性假设是"想当然地认定一个可能有多重意思的术语中的一个意思"。（第5章）
>
> — 布朗 & 基利，《学会提问（原书第10版）》第5章

> "假设越可疑，推理和结论的相关程度也就越小。"（第6章）
>
> — 布朗 & 基利，《学会提问（原书第10版）》第6章

---

## I — 方法论骨架 (Interpretation)

理由与结论之间几乎总有一道没铺桥的鸿沟——**描述性假设**是对"世界如何运作"的未言明信念，是理由得以推出结论的隐形纽带。它不是花招，而是论证的合法部件，只是没人把它说出来而已。

挖掘工序有四个环节。第一，**定位**：先理由后结论——缺口只存在于两者之间，别处发现的"假设"多半是无效目标。第二，**补桥问句**："如果理由成立，要得出这个结论还需要哪些东西成立？"把答案写成一句完整的、可检验的世界信念（"企业无法消化上升的工资成本"），而不是一个名词短语。第三，**两道过滤器**：不言自明的假设（作者当然相信自己的理由为真、相信词句可理解）直接跳过；把理由换个说法贴上"假设"标签的，不算产出。第四，**定义性假设单列**：默认多义术语取某一义（"他开过这种车"里的"驾驶"是山路拖挂还是郊区买菜）——它是歧义排查在假设层的延伸战场。

评估规则收尾：假设越可疑，结论越可疑。挖出假设后，原断言通常要从"必然如此"降级为"在这些假设成立时如此"——这一步降级本身就是分析的主要产出。

## A1 — 书中的应用 (Past Application)

### 案例 1: 汽车广告的两条隐含假设（第5章）
- **问题**: "这辆车一定会将你送往目的地，不论目的地在哪里。我在各种情况下都驾驶过这种型号的汽车。"——推荐语听着顺，说不出凭什么。
- **方法论的使用**: 补桥问句拆出两条：其一，连接假设"年复一年该型号质量始终如一"——否则旧年份的驾驶经验指导不了买新车；其二，定义性假设"推荐者说的驾驶与你的驾驶是同一种"——若他只在安静郊区开去杂货店，就与你在山道拖挂重车无关。
- **结论**: 问"你怎么从这个理由得出这个结论""如果理由成立，还需要什么成立才行"，缺口立刻现形。
- **结果**: 一句广告词暴露出两层未言明信念，购买决定从"听着靠谱"变为"待检验"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 审广告与推销话术："我试过有效，所以你也会有效"——从个例经验跳到普遍承诺。
2. 审团队规划与方案论证："头部公司都这么干，所以我们照搬也会成功"——隐含的运作模型没说出来。
3. 审因果断言与预测："提高最低工资必然导致失业""装了监控效率自然提升"——理由到结论缺桥。
4. 自己写方案、论文或答辩，想提前补上会被质疑的逻辑缺口。

### 语言信号 (用户的话里出现这些就应激活)

- "这中间缺了什么 / 凭什么推出这个结论"
- "他的隐含前提是什么 / 他默认了什么才敢这么说"（unstated assumption / hidden premise）
- "就算理由是真的，结论就一定成立吗"

### 与相邻 skill 的区分

- 与 `value-assumption-mining`：价值假设是"应该怎样"的取舍（规定性论证），本 skill 是"世界怎样"的事实信念（描述性论证）；规定性论证优先走价值侧。
- 与 `fallacy-three-questions`：滑坡这类"理由依赖错误假设"的花招位于两个 skill 交界——先在本 skill 挖出假设，再到谬误判别定性作废。
- 与证据类审查：假设是没说出来的前提，证据是说出来的支撑物；缺前提补桥，缺证据查证据，两件事不能互相顶替。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定位缺口**
   - 操作: 写出结论与理由各一句，问"从这条理由到这个结论，中间缺了什么桥"
   - 完成标准: 一句话描述缺口位置；判停：只有断言没有理由（纯观点）→ 无缺口可挖，先转 `identify-reasons` 追问理由
2. **补桥与反串**
   - 操作: 问"如果理由成立，要得出结论还需要哪些东西成立？"逐条写下隐含信念；站到反方视角重新推演——反对者会立刻咬住哪个没说出来的信念？
   - 完成标准: 产出 1–3 条写成完整陈述句的假设（可检验的世界信念，非名词短语）
3. **过滤器检验**
   - 操作: 逐条检查——是否只是理由的换装复述？是否不言自明、人人同意？是则剔除；多义术语被默认取的某一义单独标注为定义性假设
   - 完成标准: 留下的每条假设都满足"有争议 + 位于理由与结论之间"；判停：全部被剔除 → 说明论证没有隐藏缺口，毛病在别处（证据或谬误）
4. **可信度评估**
   - 操作: 把每条假设当作可检验断言评估——日常经验支持吗？有反例吗？"假设越可疑，结论越可疑"
   - 完成标准: 输出"假设清单 + 各自可信度 + 对结论的打击方式"，并说明原断言降级为有条件成立

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 纯观点（无理由的断言）——没有理由就没有缺口，先要理由
- 用户把"理由证据不足"报成"有假设"——证据强弱是证据审查的事，未言明前提是结构分析的事
- 数学演算、形式化推导——前提全部显式给出，无隐藏假设可挖

### 作者在书中警告的失败模式

- 把理由换个说法贴上"假设"标签——看似完成分析，实则原地踏步，是假设挖掘最常见的自我欺骗
- 纠察无意义假设（作者当然相信理由成立、术语可理解）——浪费火力；要找的是有争议的连接前提
- 忘记定义性假设——整条推理可能建立在多义术语被默认取的某一义上而不自知

### 作者的盲点 / 时代局限

- 书中假设都埋在单层短论证里；现实中的长文档与多方对话里假设链条嵌套多层，一次补桥未必够用
- 补桥高度依赖分析者自己的世界知识——本书未提供"领域知识不足时如何不瞎补"的规程，补错桥会冤枉原本成立的论证

### 容易混淆的邻近方法论

- 阅读理解里的"言外之意"——那是作者有意暗示的内容；描述性假设是作者自己都未必意识到的前提
- 抬杠式"万一呢"——有效补桥要求假设"有争议且承重"；任意抬杠出的假设不满足承重性
