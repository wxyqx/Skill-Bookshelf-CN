# 理由识别（理由是模具）

## R — 原文 (Reading)

> "所谓理由，即我们为什么要相信某个结论的解释说明或逻辑依据。"（第3章）
>
> — 布朗 & 基利，《学会提问（原书第10版）》第3章

> "理由是模具，结论据此得以成型和修改。"（第3章）
>
> — 布朗 & 基利，《学会提问（原书第10版）》第3章

> "结论站不站得住脚主要取决于理由的扎实与否。薄弱的理由必然导致薄弱的推论。"（第3章）
>
> — 布朗 & 基利，《学会提问（原书第10版）》第3章

## I — 方法论骨架 (Interpretation)

论证有两大柱石：结论是"要我信什么"，理由是"凭什么信"。理由是**被用作结论支撑的陈述**——看法、证据、隐喻、类比都可以充当理由；"因为我就是这样认为的"不算，任何孤立的想法只有在承担支撑功能时才是理由。

标准工序有三步。第一步**问为什么**：先钉住结论，再逐段问"作者为什么相信它"；提示词（因为、由于、根据、研究显示、第一，第二）负责定位，没有提示词时就逐句判"这句在支撑哪一句"。第二步**复述与编号**：长论证里把每条理由用自己的话复述成"因为 X，所以结论"，并在页边编号（理由 1、理由 2……），嵌套结构才不散架。第三步**登记不裁决**：识别阶段只把理由一条条登记在案——书里特别交代，把每个好像在支撑结论的观点都先当成理由，哪怕你不信它撑得住；好不好是评价阶段（谬误、证据）的事。

两个理论落点决定这个 skill 的分量。其一，**理由是模具**：结论的质量被理由的质量封顶，薄弱的理由必然导致薄弱的推论——所以理清理由本身就是评价的前置条件。其二，**逆向逻辑是它的镜像敌人**：先抱定结论再回头搜罗理由，理由沦为马后炮、随结论变形；广告与辩护式发言是重灾区，识别信号是被追问一个理由就当场换另一个。

## A1 — 书中的应用 (Past Application)

### 案例 1: 飞行员辣椒喷雾器与胚胎基因筛查（第3章开篇）
- **问题**: "有 57% 的飞行员认为辣椒喷雾器将增加飞行安全，因此航空公司应该要求飞行员随身携带。"读者能感觉到论证单薄，却说不清理由到底有哪些。
- **方法论的使用**: 先标记结论，再问"作者为什么相信它"——理由是那条调查证据。胚胎基因筛查一例进一步展示：除"人们无权捉弄上帝"外，"我有两个患自闭症的孩子，他们都活得很快乐"这样的个人经历**也算理由**，同样要登记。
- **结论**: 理由的类型可以千差万别（调查、信念、亲身经历），但工序相同：钉住结论问为什么，一条不漏地登记。
- **结果**: 理由清单成立后，"结论站不站得住取决于理由扎实与否"的评价才有对象。

### 案例 2: 公共泳池健康隐患的复述练习（第3章练习）
- **问题**: 一篇短文结论是"公共泳池是健康隐患"，理由埋在数据和描述里，读者读完抓不住结构。
- **方法论的使用**: 用提示词"研究显示"锁定理由（60% 泳池氯含量不达标 + 游泳者用后生病），再把两条理由逐一复述成支撑句；练习同时示范对"强制社区服务"这类结论警惕先有结论再编理由的逆向逻辑。
- **结论**: 复述把长论证压成可检查的骨架；薄弱理由一目了然。
- **结果**: 巩固"薄弱的理由必然导致薄弱的推论"的评价习惯，为第 6–8 章的深查铺路。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 已经知道对方主张什么（结论清楚），但说不清他到底给了哪些依据。
2. 对方论证绕来绕去、理由和例子混在一起，需要一条条理出来才能评价。
3. 自己写论证或提案，要检查是不是先定了结论再凑的理由，或被要求"把论据列清楚"。
4. 面对广告、推销、辩护式发言，怀疑理由是临时编的、随追问变形。

### 语言信号 (用户的话里出现这些就应激活)

- "他的理由是什么 / 凭什么让我信"（what are the reasons, on what grounds）
- "帮我把论据一条条列出来"（list the premises）
- "这句话是在支撑哪一句"（which claim does this support）
- "他是不是先定了结论再找的理由"（backward logic, motivated reasoning）
- "理由听着有点单薄"（weak grounds）

### 与相邻 skill 的区分

- 与 `locate-issue-conclusion` 的区别：先由它定位"要我信什么"（结论），再进本 skill 找"凭什么信"（理由）——顺序固定，不可跳过。
- 与 `critical-question-master-list` 的区别：总纲管全流程编排；本 skill 是清单第 2 问的深耕。
- 与 `fallacy-three-questions`、`evidence-grade-triage` 的区别：理由"是什么"归本 skill；理由"好不好"（谬误、证据效力）由下游承接——识别阶段只登记、不裁决。
- 与 `strong-sense-self-audit` 的区别：检查**自己**是否逆向逻辑（先有结论再补理由）时，由它接管自查视角；本 skill 提供检测信号（理由随结论变形）。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **锚定结论**
   - 动作: 一句话写出"作者/说话人要我相信 X"；定位不到就先转 `locate-issue-conclusion`
   - 完成标准: 结论句明确，且确认它有支撑诉求（否则是纯观点，见步骤 4 判停）
2. **问为什么 + 抓提示词**
   - 动作: 逐段问"他为什么相信它"；用提示词（因为/由于/根据/研究显示/首先）定位理由，无提示词时逐句判"这句在支撑谁"；个人经历、类比、信念都登记
   - 完成标准: 理由条目化（理由 1/理由 2/……），每条能脱离原文复述
3. **复述整理结构**
   - 动作: 把每条理由复述成"因为 X，所以（结论）"的支撑句；多重理由嵌套时画出层级（哪条支撑哪条）
   - 完成标准: 能向第三方转述整个论证结构而不看原文
4. **逆向逻辑检测与薄弱预警**
   - 动作: 检查理由是否随结论变形（追问时当场换理由=结论先行信号）；对明显单薄的理由做直觉标注
   - 完成标准: 每条理由标注"待深查 / 明显薄弱"；深查路由 `fallacy-three-questions`、`evidence-grade-triage`
   - 判停: 材料只有断言、给不出任何支撑陈述——标记为纯观点，正确动作是向对方追问"凭什么"，而非替他编理由

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 纯观点输入（无任何支撑诉求）——没有理由可找，硬找就是脑补
- 小说、散文等叙事文本——叙述不承担"支撑结论"的功能
- 用户只想摘要信息——提取大意不是识别理由

### 作者在书中警告的失败模式

- 逆向逻辑（ce39）：先抱定结论再搜罗理由——理由是追加的马后炮，会随结论而变化；自查信号：动笔前已有结论、同一结论的理由在不同场合版本不同、从不写下"什么证据会让我改变结论"
- 无证据断言冒充理由（ce06）：把纯观点和孤立论断登记进理由栏——问"你怎么知道"得不到支撑陈述，情绪强度与证据数量成反比；此时理由栏是空的，别硬填
- 跳过识别直接开火：不先理清理由就评价，打中的常常是自己脑补的对象

### 作者的盲点 / 时代局限

- BOOK_OVERVIEW 批判段：默认说服以论证形式发生——广告、身份政治、群体认同常根本不走论证通道，理由识别在这类输入上会扑空，需要先降级为"识别宣传"再谈
- 美国中心案例（第 3 章练习语境），迁移到其他文化需先做本地化转译
- 时代局限：社交媒体上"理由"常以点赞数、弹幕共识、转发量的形态出现——提示词方法需要扩展到互动数据信号

### 容易混淆的邻近方法论

- 金句摘抄：理由≠说得响亮的句子，而是承担支撑功能的陈述——最响的那句常常是结论
- 动机揣测：找"他为什么这么说"（利益、立场）≠找"他凭什么让你信"（论证理由）；动机分析是人身攻击谬误的入口，不在本 skill 范围
