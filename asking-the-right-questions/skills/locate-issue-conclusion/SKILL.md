# 论题与结论定位

## R — 原文 (Reading)

> "找不准作者的结论，你就会曲解别人的意图。"（第2章）
>
> — 布朗 & 基利，《学会提问（原书第10版）》第2章

---

## I — 方法论骨架 (Interpretation)

任何想说服你的材料都只有两块承重结构：**结论**（作者要你接受的那个判断）和挂靠它的**理由**。审查论证的第一步不是评价对错，而是先把这两块定位出来——定位不到，你回应的可能是你脑补的对象。

操作上有三个要点。第一，先给论题分类：**描述性论题**（"世界是什么样"：有没有、是多少）和**规定性论题**（"该不该、对错好坏"）——类型决定后面用什么标准审。第二，论题常常不直说，此时最有效的路径是**先找结论再反推论题**：抓指示词（因此、所以、表明、由此可知）、盯开头结尾两个高发位置、排除不可能当结论的成分（数据、例句、定义、背景），最后用"所以呢？"逼出隐含结论。第三，区分**结论**与**纯观点**：没有任何理由支撑的断言只是观点，对它不需要论证式回应，只需要追问"凭什么"。

对写作者镜像适用：动笔前把论题收窄——一篇短文塞多个大问题注定全说不清；并且老老实实把结论说出来，别让读者猜。

## A1 — 书中的应用 (Past Application)

### 案例 1: 儿童广告论证的结论定位
- **问题**: 一篇主张干预儿童广告的短文，读者容易被其中的情绪描述带跑，忽略作者真正要什么。
- **方法论的使用**: 先分类（规定性论题："该不该管理"），再抓结论句："以儿童为对象的广告应该加以管理和控制"——后续所有审查（理由、假设、证据）都挂靠这一句。
- **结论**: 定位完成后，评价对象从"整篇文章的感觉"收缩为"这个主张 + 它的理由"。
- **结果**: 书中以此类示范贯穿 12 章，每章练习第一篇都从"找到结论"起步。

### 案例 2: 影评与影评家的分歧（第1章引入）
- **问题**: 影评家们对同一部电影结论相反，听众不知道信谁。
- **方法论的使用**: 与其比较"谁名气大"，先问每位影评人的结论是什么、论题是描述性（这部电影好不好看）还是规定性（你该不该花时间看）。
- **结论**: 结论定位让分歧从"各说各话"变成可比的判断。
- **结果**: 引出全书的关键问题清单。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 读到一篇观点文章 / 公众号长文 / 热帖，感觉"哪里不对"但说不清，需要先拆结构。
2. 开会听汇报、看 PPT、读邮件，想知道对方的核心主张到底是什么。
3. 自己要写议论文、提需求、发声明，需要先收窄论题并明确表态。

### 语言信号 (用户的话里出现这些就应激活)

- "他到底想说什么 / 这文章的中心论点是什么"
- "帮我分析一下这篇文章的论证 / 观点"
- "我要写个议论文 / 提个主张，怎么下笔"（main point, what's the conclusion）

### 与相邻 skill 的区分

- 与 `identify-reasons` 的区别：本 skill 只找"要我信什么"（结论）；找"凭什么信"（理由）是下一步。
- 与 `scrutiny-worthiness-filter` 的区别：先判断这份材料值不值得审（影响甚微就不启动），再进入定位。
- 与 `ambiguity-loaded-words` 的区别：歧义排查发生在结论与理由定位**之后**——连结论在哪都不知道，谈不上检查关键词。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **分类论题**
   - 完成标准: 能用一句话说出论题内容 + 类型（描述性"是什么" / 规定性"该不该"）；两者都不明说时转入步骤 2
2. **用六条线索找结论**
   - 问论题（看标题开头）→ 抓指示词（因此/所以/表明/由此可知）→ 查开头结尾 → 排除非结论成分（数据、例句、定义、背景）→ 查作者背景与语境立场 → 问"所以呢？"逼隐含结论
   - 完成标准: 一句话写出"作者要我相信 X"
3. **判定结论 vs 纯观点**
   - 完成标准: 检查有无理由支撑该结论。若有理由 → 转入 `identify-reasons`；若无 → 标记为"纯观点"，向用户说明对纯观点的正确动作是追问理由而非辩论
4. **写作侧自查**（仅当用户在创作）
   - 完成标准: 论题是否足够窄（一篇只说清一个问题）？结论是否明说（不用读者猜）？两项任一不满足即给出修改建议

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 纯信息查询（"Node 22 有什么新特性"）——没有论证结构可拆
- 小说、散文、说明文——叙事与描写不承载"要你相信"的主张
- 用户只是分享情绪、求安慰——此时分析结构是答非所问

### 作者在书中警告的失败模式

- 找不准结论就急着评价 → 曲解对方意图，回应驴唇不对马嘴
- 论题贪多 → "拿起笔就写、贪多嚼不烂，自己还浑然不知"（写作侧）
- 把数据、例句、背景当结论 → 它们是理由或装饰，不是承重结构

### 作者的盲点 / 时代局限

- 本书成书于社交媒体与算法推荐兴起前夜：短视频、信息流中的说服常常是"结论 + 情绪"且根本没有理由段，定位后仍需 `evidence-grade-triage` 接力判断值不值得较真
- 美国中心案例（大选季、控枪），在其他文化语境需先做本地化转译

### 容易混淆的邻近方法论

- 金句摘抄：结论≠说得漂亮的那句；结论是承重的那句
- 主题概括：概括是复述内容，定位是为审查服务——对象是"主张"，不是"大意"
