# 决策五要素（审计清单）

## R — 原文 (Reading)

> "1.要确实了解问题的性质，如果问题是经常性的，那就只能通过一项建立规则或原则的决策才能解决。2.要确实找出解决问题时必须满足的界限，换言之，应找出问题的'边界条件'。3.仔细思考解决问题的正确方案是什么……然后再考虑必要的妥协、适应及让步事项……"
>
> — 彼得·德鲁克，第6章·决策的五个要素（L1480–1484）

> "4.决策方案要同时兼顾执行措施，让决策变成可以被贯彻的行动。5.在执行的过程中重视反馈，以印证决策的正确性及有效性。"
>
> — 彼得·德鲁克，第6章·决策的五个要素（L1486–1488）

> "他们知道最骗人的决策，是正反两面折中的决策，他们能分辨正反两面的差异。他们知道在整个决策过程中，最费时的不是决策的本身，而是决策的推行。一项决策如果不能付诸行动，就称不上是真正的决策，最多只是一种良好的意愿。"
>
> — 彼得·德鲁克，第6章·开篇（L1404）

> "有效的管理者不做太多的决策。他们所做的，都是重大的决策。……他们给人的印象，是决策往往需要宽松的时间。……他们需要的是决策的结果，而不是决策的技巧；他们需要的是合乎情理的决策，而不是巧妙的决策。"
>
> — 彼得·德鲁克，第6章·开篇（L1402）

## I — 方法论骨架 (Interpretation)

德鲁克把有效决策定义为一套系统化的程序，有明确的要素和步骤，并且顺序不可倒置。五个要素构成一张审计清单。

一、辨明问题性质：先问这是一再发生的经常性问题，还是偶然的例外——经常性问题的解决方式是建立规则/政策/原则，偶发问题才个案处置。归类错误，决策必错（展开见 problem-classification）。

二、找出边界条件：决策必须满足的最低规范是什么（"最低限度应该达成什么目的"）。不符合边界条件的方案，无论看起来多好，都是无效决策（展开见 boundary-conditions）。

三、研究"正确"方案：先抛开"别人能不能接受"，把正确的方案想清楚，再谈必要的妥协、适应与让步——因为不知道正确是什么，就无法辨别"正确的折中"与"错误的折中"（展开见 correct-before-compromise）。

四、化决策为行动：决策在做出时必须自带行动承诺——谁应该了解、应采取什么行动、谁采取行动、如何行动，并与执行者的能力相适应；要求改变行为的，衡量标准与激励制度必须同步改变（展开见 decision-to-action）。

五、建立反馈：在决策中设计反馈制度以经常印证预期成果，且最可靠的反馈是亲自视察而非批阅报告（展开见 feedback-and-inspect）。

两个总纲性的修正：有效的管理者不做太多决策，只做重大的、观念层面的少数决策；最费时的不是决策本身而是决策的推行——所以决策必须接近工作层面、力求简单。德鲁克还诚实注明：这套步骤希波克拉底、亚里士多德、伽利略早已提出，本书的任务是给出"应该做什么、按什么顺序做"。

## A1 — 书中的应用 (Past Application)

### 案例 1: 费尔的四项战略决策（贝尔电话公司）
- **问题**: 20 世纪初，电话系统在世界各国多被收归国营；贝尔公司虽享垄断且市场饱和，如何保持民营并在风险中成长？
- **方法论的使用**: 费尔任总裁近 20 年做了四项决策，每项都让德鲁克看到五要素的影子：①断定"平安就是福"守不住，主动确立"预测并满足社会大众的服务需求"为公司目标（问题性质是行业生存规则，不是某次危机）；②反其道把"公众管制"变成公司目标——与其被收归国营，不如主动接受监管（边界条件设得清楚）；③设立贝尔研究所，第一个以"更新现有产品"为己任的研究机构，并放弃防御性研究；④开创面向"莎莉姑妈"式中产投资人的大众资本市场（AT&T 普通股）。四项决策都与当时"众所周知"的看法大不相同，各遭激烈反对。
- **结论**: 有效决策是一套有要素、可循步骤的程序，且往往与流行意见相左。
- **结果**: 贝尔成为唯一经得起风险并能在风险中飞速成长的公共事业公司；AT&T 普通股成为中产投资人 50 年的投资对象。

### 案例 2: 斯隆的分权制度（通用汽车）
- **问题**: 1922 年通用汽车一盘散沙，各分公司"酋长不听王命"，合并后的整合陷入混乱。
- **方法论的使用**: 斯隆看清问题的根本：这不是合并过渡期的偶发问题，而是大型企业常见的经常性问题（要素一）；传统办法是调离或放任，他改为设计分权制度——既保证分公司经营自主权，又体现总公司方向与政策指导（要素二、三：以"如果解除各独立部门的自主权，能满足本公司的需要吗？"反证边界条件，答案是不能，故需新制度）。反证法：通用唯一没采用分权制度的领域（对政治兴趣与政府政策预测），恰是其最差劲的一步。
- **结论**: 判断问题性质是结构问题还是人事问题，决定决策的类型；正确的方案先立，制度随之设计。
- **结果**: 分权制度使通用成为大企业典范（德鲁克亦注明：该制度今日需重新检讨）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户要处理一次重大决策（并购、业务重组、重大投资、战略转向），需要一套审查框架或尽调清单。
2. 用户发现决策"开会定了但推不动/执行走样"，要回查哪一环漏了。
3. 用户面对"先按这个方案落地再改"的提议，需要判断这个决策是否合格。
4. 用户在做决策复盘：想知道从问题定性到反馈的全流程哪里出了错。

### 语言信号 (用户的话里出现这些就应激活)

- "帮我搭一个决策框架 / 这类决策怎么审 / decision framework, review checklist"
- "这个决策定了但推不下去 / why isn't it being executed"
- "重大决策该考虑哪些要素 / what makes a decision effective"
- "先落地再迭代行不行 / can we decide now and fix later"

### 与相邻 skill 的区分

- 与 `problem-classification`（f17）、`boundary-conditions`（f18）、`correct-before-compromise`（f19）、`decision-to-action`（f20）、`feedback-and-inspect`（f21）的区别：五个兄弟 skill 各管一个要素的深挖；本 skill 是全景审计——先跑五步定位薄弱环节，再按需下钻到对应 skill。用户已明确卡在某个要素时直接用兄弟 skill。
- 与 `decide-and-act-fully`（f24）的区别：f24 判"是否需要一次决策"以及"行动就做全"；本 skill 假定决策确需做出，管的是怎么系统化地做出。通常 f24 在前（是否做），f16 在后（怎么做）。
- 与 `opinions-first`（f22）、`dissent-as-resource`（f23）的区别：那两个处理决策的见解来源与异议机制（第7章）；本 skill 是第6章的要素程序。决策前期争论用什么、怎么听异议 → f22/f23；定案的系统化审查 → f16。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **要素一：辨明问题性质**
   - 判定：经常性问题（→ 建规则/政策/原则）还是偶发例外（→ 个案处置）；拿不准时先假定为经常性（并由 f17 配合）。
   - 完成标准: 写出问题分类及理由；经常性问题的解决形式（规则/原则）已被指明。
2. **要素二：找出边界条件**
   - 问"最低限度应该达成什么目的、必须满足什么条件"；检验"如果这个临时办法被长期执行下去，我会愿意吗"；写清边界条件以便日后抛弃（配合 f18）。
   - 完成标准: 边界条件书面化、可检验；临时措施有失效/复审条款。
3. **要素三：先研究"正确"方案**
   - 先计算满足边界条件的正确方案（不先想"别人能不能接受"），再谈妥协与让步；区分仍满足边界条件的折中与不满足的折中（配合 f19）。
   - 判停条件: 若讨论中"各方能接受"成为首要标准 → 停下来先补做"正确方案"分析，否则会落入错误的折中。
   - 完成标准: 有一个明确的"正确方案"及其满足的边界条件；折中方案按边界条件标注为可接受/不可接受。
4. **要素四：化决策为行动**
   - 回答四问：谁应该了解这项决策？应采取什么行动？谁采取行动？如何行动使执行者有所遵循？并检查行动与执行者能力匹配、衡量标准与激励制度同步（配合 f20）。
   - 完成标准: 行动步骤有姓名与时限；该知道的人都在名单上；激励/衡量如有冲突已列出修改项。
5. **要素五：建立反馈**
   - 设计反馈：用什么信息、什么频率、由谁收集；明确"最可靠的反馈是亲自视察"，安排现场察看（配合 f21）。
   - 完成标准: 反馈机制写进决策文本；有一次现场察看被排入日程。
6. **收尾复核（顺序与体量）**
   - 复核顺序未被倒置；决策数量上做减法（重大决策才动用此清单）；推行力求简单、接近工作层面。
   - 完成标准: 五步记录齐全；产出一页可执行的决策要点。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 日常小决定、可逆的琐碎选择：先过 f24 的"是否需要决策"（不做也是决策）；对小毛病大动干戈本身是失败模式（对应 ce35 的"小题大做"）。
- 用户只是卡在某个单一要素：直接下钻兄弟 skill，避免用五要素清单淹没问题。
- 危机响应中的即时决策（火灾、事故、市场闪崩）：五要素是"宽松时间"下重大决策的规范（德鲁克自己说有效的决策者"给人的印象是决策往往需要宽松的时间"），当场的应急判断不适用完整程序。

### 作者在书中警告的失败模式

- **折中决策（ce25）**：在弄清"正确"之前先行折中、怕被反对而自我审查，落入"错误的折中"；预警信号：方案以"各方都能接受"为首要标准，一有反对声就调降目标。
- **决策没有行动承诺（ce28）**：只发目标与要求，没有步骤、责任人、"谁知道"（停产设备三年后采购部门仍在订零件，积存 8–10 年库存）；预警信号：决策文件只有目标，执行失败后被解释为"下面执行不力"。
- **宣布变革却不改变衡量与激励（ce29）**：人人都会读出"他们不是真想变革"；预警信号：新决策只发文件，不改考核与奖励，变革期反而提拔旧模式代表人物。
- 配套警戒（ce26/ce27/ce30 分别对应要素一/二/五的典型误判）：问题性质误判、临时措施永久化、只批阅报告不亲自视察。

### 作者的盲点 / 时代局限

- 德鲁克自己承认：这套程序无法给出"如何识别例行事件、找出边界条件"的具体方法（L1914"本书并无具体说明……具体的方法，也视个别情况而异"）——五要素是方向与顺序的标准，不是算法。
- 案例以 1900–1960 年代美国大企业与政府为主；《纽约时报》分节的故事他本人"不大相信"（L1568），说明部分案例属轶事转述；证据等级声明：本书证据以作者顾问观察与轶事为主，无对照实证。
- "最费时的不是决策本身而是推行"的断言缺乏量化证据；"有效的管理者不做太多决策"是规范主张，不是经验规律。
- 五要素源自希波克拉底—亚里士多德—伽利略的传统（书中自述），德鲁克的特有增量在要素顺序与"先正确后折中"的强调；越出本书语境时不应把方法标记为德鲁克独有发明。

### 容易混淆的邻近方法论

- 教科书决策流程（搜集事实→拟定方案→选择）：德鲁克明确否定"从事实开始"（见 f22 见解为先），两者起点相反。
- 商业尽调清单（财务/法务/商业三维度）：那是内容检查；五要素检查的是决策的形式合格性（问题、边界、正确性、行动、反馈）。
- 与 f24 的"两项原则"：f24 管行动前的阈值与收尾的"做全"，与五要素的第四要素相邻但机制不同——f24 判"要不要动手/做完"，f16 的要素四管"如何把决策装进行动"。

## 相关 skills

本 skill 是决策要素的总审计：五个要素各有一个深挖单元，按需下钻；决策的两端（是否做、做全）由 `decide-and-act-fully` 处理。

**depends-on**（使用前提）: 无 — 五要素清单自足。

**contrasts-with**（同境况二选一）: 无 — 与五个兄弟单元是"全景—专项"关系。

**composes-with**（配合使用/先后接力）:

- `effectiveness-five-habits` — 总纲第五习惯（有效决策）的展开；整体诊断走到"决策"一面时下钻到本 skill。
- `problem-classification` — 要素一（问题性质）的深挖；问题定性没搞清时先下钻它。
- `boundary-conditions` — 要素二（最低必须达成什么）的深挖；并产出"何时抛弃"的触发器。
- `correct-before-compromise` — 要素三（先"正确"后折中）的深挖；辨别"半片面包"与"半个婴儿"。
- `decision-to-action` — 要素四（化决策为行动四问与激励同步）的深挖。
- `feedback-and-inspect` — 要素五（反馈制度与亲自视察）的深挖。
- `decide-and-act-fully` — 决策两端的前后判据：先由它过"是否需要决策"的门槛，定案后再回到它做"行动或不行动、绝不只做一半"的收尾。
