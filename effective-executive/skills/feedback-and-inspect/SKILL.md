# 反馈制度与亲自视察

## R — 原文 (Reading)

> "决策的最后一个要素，是应在决策中建立一项信息反馈制度，以便经常对决策所预期的成果做实际的印证。"
>
> — 彼得·德鲁克，第6章“决策的要素”（L1630）

> "在军队里，长官发了命令，总得亲自检查命令的执行，至少也得派遣代表去检查，而不会坐在总部等候报告。这不是说军人不信任下属，而是经验告诉他们，“报告或沟通”不一定靠得住。……这就是为什么营长常到食堂去亲自品尝菜肴的道理。"
>
> — 同上，第6章（L1642、L1644）

> "那么如何才能找出适当的衡量方法呢？一如本书前文所述，只有依靠“反馈”的制度。不过这里的所谓反馈，是决策前的反馈。"
>
> — 同上，第7章“有效的决策”（L1701）

---

## I — 方法论骨架 (Interpretation)

反馈在德鲁克这里是**两层**，多数组织只做了中间一段。

1. **决策前的反馈**（最独特的一层）：反馈先于决策而设计，用途是检验“衡量方法本身”是否适当。德鲁克说有效的决策人通常必先假定传统的衡量方法并非适当的衡量方法——“传统的衡量方法反映的是昨天的决策”。人事的“平均数”、汽车安全的“每公里事故率”，都是亲自查看后被推翻的衡量法；找出适当的衡量方法“不是数学方法所能解决的，这是一项带有风险的判断”。
2. **执行中的反馈（亲自视察）**：报告与沟通“不一定靠得住”；抽象资料只有经过实践的检验之后才是可靠的。营长到食堂尝菜、长官亲自检查命令的执行，都是同一判据：决策者离现场越远（组织越大、职位越高、越依赖电脑与报表），越需要亲自视察。
3. **前提审计**：反馈的最终指向是“赖以做出决策的前提是否仍然有效”。前提迟早会过时——费尔与斯隆那样的大决策，到后来也只剩下费尔“以服务为目的”一项仍然可用（L1634）。前提变了，按边界条件抛弃或重做决策。

一句话：反馈不是事后复盘，而是决策自带的可修正机制——先检验你拿什么在看，再亲自确认你看到的是不是真的。

## A1 — 书中的应用 (Past Application)

### 案例 1: 杜鲁门评艾森豪威尔 / 营长到食堂尝菜（亲自视察）
- **问题**: 军人出身的艾森豪威尔当选美国总统后，杜鲁门评论：“可怜的艾克……只怕他发布命令之后，一件事也做不成。”总统的命令为何难以贯彻？
- **方法论的使用**: 差别不在权力，而在反馈制度：军事组织早就知道仅发布命令没有用，必须同时建立可以检讨命令执行的机制，而“最可靠的反馈，却在于亲自视察”——长官发令后亲自检查，至少派代表去检查，不坐在总部等候报告。
- **结论**: 报告或沟通不一定靠得住；亲自视察是最可靠的反馈形式（营长尝菜的道理）。
- **结果**: 该案例成为决策第五要素的收束例证：决策者若只批阅报告，与执行现场越来越脱节。

### 案例 2: 人事“平均数”与汽车安全衡量（决策前反馈：衡量方法本身被推翻）
- **问题**: 人事管理长期用“平均每百人停工事故数”“缺勤率”“病假率”等平均数衡量；汽车业用“平均每行车公里交通事故件数”衡量安全。
- **方法论的使用**: 德鲁克指出，管理者若肯亲自出去看一看，会发现需要的是另一套衡量方法——停工事故可能集中在某一两个部门，缺勤集中于某个单位，病假限于某类人群，按平均数推动全厂措施无效甚至更糟；汽车业若亲身查看，会发现应以“人体伤残情况”衡量，重点在改良车辆设计。
- **结论**: 衡量方法的选择是带风险的判断，不是数学问题；反馈要先检验衡量方法。
- **结果**: 文中作为“决策前反馈”的标准判例，说明“适当衡量方法”只能靠反馈找出。

### 案例 3: 费尔与斯隆的大决策会过时（前提审计）
- **问题**: 决策由人做出，人难免犯错；再了不起的决策也不可能永远正确，即使最有效的决策总有一天也会被淘汰。
- **方法论的使用**: 德鲁克用两位公认最有创新力与魄力的决策者做检验：费尔与斯隆的几项大决策，到书中写作时只有费尔“贝尔公司以服务为目的”一项仍然可用——AT&T 普通股因机构投资人兴起而大改、贝尔研究所因技术与竞争变化而无法独立研究、公众管制的各州立法已不合时代；斯隆的分权制度也“显然有待重新检讨”。
- **结论**: 决策会过时失效，必须在决策中建立反馈制度，经常印证预期成果。
- **结果**: 两个案例支撑第五要素的必要性，并示范“何时该重做决策”的判断方式。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 想判断一年前定的战略/政策的前提今天是否还成立，或该不该重做。
2. 报表、仪表盘、满意度调查等数字看起来都正常，但用户对“实际情况”心里没底。
3. 用户长期用某一套指标衡量业务，怀疑它已经不能反映现实（“指标是不是失效了”）。
4. 决策即将拍板时，被要求设计“怎么知道它后来对不对”的检验机制。
5. 决策者与执行现场之间隔着多层汇报或系统平台（远程团队、多级组织、外包），需要判断如何补上直接反馈。

### 语言信号 (用户的话里出现这些就应激活)

- “当初的前提还成立吗？”“数据看着挺好，但实际情况呢？”
- “这个衡量指标是不是早就该换了？”
- “要不要亲自下去看看/走一趟？”
- “is the premise still valid” / “the metrics may be wrong” / “get out and see” / “reports vs reality”

### 与相邻 skill 的区分

- 与 `opinions-first` 的区别: 后者要求把见解当假设并先回答“相关标准/衡量标准是什么”；本 skill 提供找出适当衡量方法的机制（决策前反馈），并补上“亲自视察”一层。
- 与 `decision-to-action` 的区别: 后者设计“谁做什么”（行动承诺）；本 skill 设计“拿什么检验”（反馈），是决策五要素中的相邻两步。
- 与 `results-outside-the-organization` 的区别: 后者是结构性定律（成果在组织之外，注意力天然向内），本 skill 是该定律在决策环节的操作动作之一（亲自视察、接触外部）；两者方向一致但层次不同。
- 与 `decision-five-elements` 的区别: 后者是五要素全程审计；本 skill 是要素五的专项展开。
- 与 `time-waste-institution-scan` 的区别: 后者诊断信息功能不健全造成的时间浪费；本 skill 关注决策前提与衡量方法的有效性。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **为决策写明反馈设计**
   - 完成标准: 每条决策都有一行“我们如何知道它对了/错了”：预期成果、检验指标、检验时点与责任人；不能只有“到时再看看”。
   - 判停条件: 若决策涉及重大前提，进入步骤 2 先检验衡量方法；日常小决策可跳到步骤 3。

2. **做决策前反馈：检验衡量方法本身**
   - 完成标准: 逐条质问现行衡量方法——“它反映的是昨天的决策吗？”“还有哪些方法能交叉验证？”（投资三法并测是范例）；选定方法时记录理由与其局限。
   - 判停条件: 若发现现行指标集中度异常（如平均数掩盖局部问题），换用能暴露分布/重点的方法，再回到步骤 1。

3. **以亲自视察补上执行反馈**
   - 完成标准: 对关键决策安排一次（或周期性）现场查看：去食堂尝菜式的直接接触，而非只看报告；明确“我会亲自看什么、什么时候看”。
   - 判停条件: 若无法亲自到现场（远程、层级隔离），指定可信的现场检查人并说明其独立性；仅有同级汇报不算满足。

4. **审计前提是否过时**
   - 完成标准: 列出该决策赖以成立的前提，逐条标注“仍有效 / 待观察 / 已变化”；已变化者进入步骤 5。
   - 完成标准附加: 引用“费尔斯隆”判据——再好的决策终究会过时，不要假设它仍然有效。

5. **前提已变时抛弃或重做**
   - 完成标准: 按边界条件决定抛弃、重做还是调整，并更新步骤 1 的反馈设计。
   - 判停条件: 若前提变化属于趋势的转变而非趋势（外部的质变），移交 `results-outside-the-organization` 的观察框架处理。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 日常执行进度跟踪、项目状态汇报：那属于运营管理工具，不需要“检验衡量方法”这一层。
- 纯数据分析/取数任务：先有决策问题与假设，再谈反馈设计。
- 把“亲自视察”变成微观管理或走马观花式的检查：德鲁克的要求是获取未被报告过滤的现实，不是替代执行者做事或对细节发号施令。
- 无现场可到的知识型决策（如内容策略、算法指标）：改用其他直接证据渠道，不要硬套“营长尝菜”。

### 作者在书中警告的失败模式

- **只批阅报告、不亲自视察**（ce30）：依赖报告与数字化反馈，与执行现场脱节；决策前提过期了也不知道——“许多早该修改的措施始终没有修改，其原因主要就是管理者不肯亲自去了解情况”（L1650）。
- **固守传统衡量方法与单一衡量方法**（ce32）：用旧方法（军需以总项数/总金额、人事以平均数、汽车以每公里事故率）看待新问题，只见平均数不见分布；德鲁克要求“任何方法都只能显示某一层面”，须多法交叉。
- **指望电脑替代判断（含“迷恋电脑”）**（ce36）：把“上系统”当解决决策问题的方案；大量量化信息反而使管理者与外界的实际隔离。**时代语境声明**：该段含 1966 年的大型机技术判断（“电脑只能做简单和明显的工作”等），不可作为当代技术结论；本 skill 仅在“判断与现场觉察不可外包”这一边界意义上引用它。

### 作者的盲点 / 时代局限

- **亲自视察的可规模化问题未讨论**：德鲁克以营长、总统为例，未回答大组织高管如何在不成为微观管理者、不挤占执行者时间的前提下保持直接接触；现代远程与跨国组织中该动作的成本更高。
- **“决策前反馈”对小决策过重**：为每个决策设计衡量方法检验，在快节奏业务中不现实；书中未给分层标准（哪些决策值得）。
- **外部“质变”不可量化的立场需更新**：1966 年的“外部情况无法量化”在当代可计算域扩展后已有反例；保留下来的洞见是“趋势的转变先于数据”，而不是“外部不可量化”。
- **案例与证据**：案例集中于 1900–1960 年代美国军政与企业，证据以顾问观察与轶事为主，无对照实证（BOOK_OVERVIEW 批判节）。
- **无时间自主权岗位**：需要出差/到现场的视察对无时间自主权者不可行，其替代动作是“与产出使用者直接对话、争取现场轮岗或安排一次实地访问”（与时间类 skill 的边界声明一致）。

### 容易混淆的邻近方法论

- 与“PDCA 复盘”的区别: 复盘在事后检查目标达成；本 skill 的独特动作是反馈先于决策设计（检验衡量方法）并以亲自视察对抗报告过滤。
- 与“管理仪表盘/数据中台”的区别: 仪表盘提供抽象资料；德鲁克强调抽象资料只有经过实践检验才可靠，两者互补而非替代。
- 与 `results-outside-the-organization` 的区别: 见上，一个观察外部，一个检验决策内部前提。
