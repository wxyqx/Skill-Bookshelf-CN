# 管理上司（Manage Your Boss）

## R — 原文 (Reading)

> "有效的管理者常问：'我的上司究竟能做些什么？他曾有过什么成就？要使他发挥他的长处，他还需要知道些什么？他需要我完成什么？'至于上司不能做些什么，那就不必细究了。"
>
> — 彼得·德鲁克，第4章·如何管理上司（L1189）

> "人大致可以分为两种类型：'读者型'和'听者型'。……我们面对'读者型'的人侃侃而谈，那是徒费口舌，因为他只能在读过之后才能'听'得进去。"
>
> — 彼得·德鲁克，第4章·如何管理上司（L1195）

> "要使上司能发挥其所长，不能靠唯命是从，应该从正确的事情着手，并以上司能够接受的方式向其提出建议。……协助上司发挥其所长，是促使管理者有效的最好方法。"
>
> — 彼得·德鲁克，第4章·如何管理上司（L1187、L1201）

---

## I — 方法论骨架 (Interpretation)

德鲁克把"管好上司"定义成下属自己的责任，而不是逢迎术。起点是一个方向反转：不问上司不能做什么、怎么改变他，只问—他能做什么、曾有什么成就、要发挥长处他还需要知道什么、他需要我完成什么。

第二层是"方式研究"：每个上司都自成一套有效的方式，可能是习惯或态度，但客观存在。要判断的维度：读者型还是听者型；要一页纸的浓缩报告还是六十页的完整推演；喜欢及早知道还是等方案成熟；习惯听口头汇报还是看文字。

第三层是呈现设计。德鲁克的关键句：向上提建议，与其说是"提什么建议"的问题，倒不如说是"如何提出这一建议"的问题——重要的不只是轻重是非，更是**陈述的先后顺序**。比如上司长于政治，报告就把政治问题放前面，让他容易抓住重心、发挥所长。

前提判断：上司不升迁，下属通常无法上升；帮助上司有成效，就是让下属自己的贡献能被采纳、精力能集中到贡献上。

界限：不是唯命是从——从正确的事情着手，只在"如何提出"上适配他的接受方式。上司的短处不去改造，而是设法使它不产生影响。

## A1 — 书中的应用 (Past Application)

### 案例 1: 政府机构新到任的领导
- **问题**: 能干的高级官员习惯以老师姿态对待新到任的领导，设法让领导克服缺点；新领导被当成"需要被改造的对象"，双方都无效。
- **方法论的使用**: 德鲁克指出有效管理者的做法是调转问题："这位新领导能做些什么？"——若答案是"他擅长应对，与国会、白宫、社会各界关系都好"，下属就该设法让他的这方面长处充分发挥（因为最好的行政与决策，若无政治技巧表达出来就等于零），同时该领导也会很快就政策与行政采纳官员们的意见。
- **结论**: 把资源放在上司的长处上，比修补其短处更能让组织产出。
- **结果**: 领导知道下属支持他，双方形成互补：下属贡献政策内容，上司贡献政治能力。

### 案例 2: 艾森豪威尔与"一页报告"——按上司的类型设计材料
- **问题**: 不同的上司对信息形式的要求差异极大，一份材料适合 A 却让 B 无法工作。
- **方法论的使用**: 德鲁克归纳出类型判据：有人（如艾森豪威尔）只要浓缩为一页的报告，有人要六十页的完整推演；有人喜欢及早了解情况以便做判断，有人非要等研究成熟才听。有效的管理者会设法探寻上司属于哪一套方式，再按其方式提交。
- **结论**: "与其说是'提什么建议'的问题，倒不如说是'如何提出这一建议'的问题"——陈述顺序与形式是设计变量。
- **结果**: 这段分析成为向上沟通的通用判据（读者型/听者型、篇幅、时机三组参数）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 换了新上司，或长期搞不定直属上级：提案被当场否决、汇报被打断、"再想想"。
2. 用户想"改造"上司——常抱怨他不懂、不行、不给支持，却没有研究过他的工作方式。
3. 要向上级做重要汇报或提案（预算、立项、改革方案），反复改稿仍不合对方口味。
4. 用户意识到"上司不升我就升不上去"，想知道该为上司做什么。

### 语言信号 (用户的话里出现这些就应激活)

- "怎么说服我老板 / 怎么让上司批这个方案 / how to pitch my boss, manage up"
- "我上司就是不听、不懂、老否我的提案 / my boss doesn't get it, always shuts me down"
- "汇报他到底要看什么？一页纸还是详细报告？/ does he want a one-pager or a deck"
- "我该不该帮他、怎么帮他？他升不上去我也没戏 / I can't get promoted if my boss won't"

### 与相邻 skill 的区分

- 与 `make-output-usable`（f08）的区别：f08 处理专业产出交给使用者的交付设计（前者的"用户"不一定是上级）；本 skill 专用于向上级提建议/汇报的呈现顺序与接受方式。若对方是平级使用你产出的同事，用 f08。
- 与 `dissent-as-resource`（f23）的区别：当内容是"反对上司的方案/提不同意见"时，走 f23 的异议纪律（先理解再判是非、防俘虏）；本 skill 处理常规建议的提出方式，且前提是不唯命是从、从正确的事着手。
- 与 `strengths-based-staffing`（f09）的区别：f09 是向下用人（择人、容忍短处、职位设计）；本 skill 是向上用长（方向相反的同一原理）。
- 与 `contribution-question`（f06）的区别：f06 是"我能贡献什么"的总问句；本 skill 是其向上维度的专章操作（"他需要我完成什么"是 f06 与 f11 的接口）。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **做四项事实调研**
   - 写下：上司能做些什么？他曾有过什么成就？要发挥长处他还需要知道什么？他需要我完成什么？
   - 完成标准: 四问各有具体事例（不是评价词），且第一问只写长处。
2. **判定上司的接收方式**
   - 三组参数各给一个判定 + 一个证据：读者型/听者型；一页纸/全文推演；早了解/等成熟。
   - 完成标准: 每个判定都能举出一次实际经历佐证；证据不足时设计一次小实验（分别用两种形式提交同一信息观察反应）。
3. **重排陈述顺序**
   - 按上司的长处与关注点重排建议：如他长于政治就政治面先行；他重数字就先给边界条件与数据。
   - 完成标准: 产出"按他的顺序"的版本，与原始顺序并列对照；材料形式匹配第 2 步判定。
4. **以他的方式提出，并先问"你需要我完成什么"**
   - 提交时先对齐期望，再谈方案。
   - 判停条件: 若上司要求与"正确的事情"冲突 → 不唯命是从，按 f23 的异议流程处理（先理解其立场、再判是非），而不是简单照办或硬顶。
5. **复盘接受度**
   - 记录这次与之前同类提案的差异（拍板速度、修改次数）。
   - 完成标准: 能指认一处"调整方式后结果改善（或恶化）"的具体证据，供下一轮迭代。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 上司存在正直问题（侵占、欺骗、系统性打压）或职场霸凌：这不是"沟通方式"能解决的问题，应转入组织渠道、合规投诉与法律路径；本 skill 的适配动作以双方善意与合法为前提。
- 用户真正需要的是职业选择判断（要不要换岗、离职）：本书不涉及职业规划，本 skill 不回答"该不该走"。
- 没有稳定沟通渠道的岗位（实习、外包、矩阵多头汇报）：向上设计动作有限，先确认你面对的"上司"是谁——多头汇报时先锁定影响力最大的那个人，或改用 f06 的贡献问句做总定位。

### 作者在书中警告的失败模式

- **只从上司短处着眼、试图改造上司（ce13）**：把有效性绑在无法改变的对象上；"上司强调下属的短处"与"下属强调上司的短处"结果都是一无所成。预警信号：常议论"我上司不懂/不行"；从不研究他是读者型还是听者型、把什么算作有效。
- **唯命是从的另一个极端**：德鲁克明确"不能靠唯命是从"——适配的是方式，不是放弃判断。
- 配套警戒（ce13 机制）：上司不升迁则下属通常无法上升；把希望寄托于"换一个好上司"通常落空（继任者多来自别部门并带来自己的班底）。

### 作者的盲点 / 时代局限

- 秘书/助理假设（BOOK_OVERVIEW 批判节）：书中的"一页报告""整理材料"默认有文书支持；无秘书的今天，这层工作要自己做，需自行折算工作量。
- 全书管理者一律为男性、案例集中于 1966 年前后的美国大企业与政府；"上司不升迁下属无法上升"是大科层组织的观察，在流动市场与跳槽文化下部分失效（仍适用于内部晋升通道）。
- 高管视角：方法默认用户有发言机会与稳定业务关系；对基层与不稳定雇佣关系，本 skill 的"方式研究"成本可能高于收益。
- 证据等级声明：本书证据以作者顾问观察与轶事为主，无对照实证、无失败者对照（BOOK_OVERVIEW 批判节）。

### 容易混淆的邻近方法论

- "向上管理"流行版本（预期管理、情绪价值、汇报话术）：德鲁克的特有结构是"发挥上司的长处是下属的责任"＋"陈述顺序"设计，不是讨好与姿态管理。
- 与读者型/听者型的流行误用（当性格分类学）：它是沟通设计的自变量（给谁、怎么给），不是身份标签。
