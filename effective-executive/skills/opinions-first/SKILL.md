# 见解为先：把见解当假设，先定衡量标准

## R — 原文 (Reading)

> "大部分关于决策的著作，开宗明义，第一步总是说“先搜集事实”。但是卓有成效的决策者都知道，决策的过程往往不是从搜集事实开始的，而是先从其本人的见解（opinions）开始的。所谓见解，乃是“尚待证实的假设”……但要确定什么才是事实，必须先确定相关的标准，尤其是有关的衡量标准。"
>
> — 彼得·德鲁克，第7章“有效的决策·个人见解和决策的关系”（L1673）

> "先要搜集事实是很难做到的。因为没有相关的标准，就不可能找到什么事实。事件本身并非事实。"
>
> — 同上，第7章（L1677）

> "有效的管理者会问：“要验证某一假设是否为真，我们该知道些什么？”“要验证某一见解，应有些怎样的事实？”……最关键性的问题应该是：“相关的标准是什么？”"
>
> — 同上，第7章（L1687、L1689）

---

## I — 方法论骨架 (Interpretation)

德鲁克推翻的是教科书的第一步“先搜集事实”，理由是逻辑上的：**事件本身并非事实**——没有衡量标准，就无从认定什么算相关事实（物理学家、厨师、画家面对同一物体，“味”与“色”各有不同的事实认定）。因此要求人“从事实出发”既做不到、又会变成自欺：他既然先有了结论，必能搜集到许多事实（所以干过统计的人往往最不相信统计数字）。

正确程序是三步：

1. **承认见解为先**：允许并要求有经验者先提出见解——在某一领域经验丰富却毫无见解，只说明此人观察力迟钝；把自己的见解也摆上台面。
2. **把见解转成假设**：见解＝“尚待证实的假设”；假设不必辩论，但必须经得起验证，经不起验证者就放弃。
3. **先问标准，再谈事实**：每个提出见解的人负责回答“要验证它，我们需要知道什么、需要观察到什么、相关的衡量标准是什么”。

由此推出对衡量方法的态度：**有效的决策人通常必先假定传统的衡量方法并非适当的衡量方法**——“传统的衡量方法反映的是昨天的决策”；衡量方法的选择是带风险的判断，不是数学问题，故须多方案并测（投资三法并举），再选最适当的一种。

## A1 — 书中的应用 (Past Application)

### 案例 1: 麦克纳马拉的军需库存衡量法改革（挑战传统衡量）
- **问题**: 朝鲜战争以来，美国军用物资的采购与库存政策一直不理想，军方多次研究无果、每况愈下——因为一直以“物资项目总项数和总金额”为衡量基础。
- **方法论的使用**: 麦克纳马拉向传统衡量方法发起挑战，改用另一种衡量方法：发现极少数项目（约占总项数 4%）是高价物资，其采购金额占总额 90% 以上；另有约 4% 的重要物资足以维持 90% 的战备；两相合并，全部重要物资不过占总项数 5%–6%。
- **结论**: 重要物资分别管理、严加管制；其余 95% 按“例外原则”管理。
- **结果**: “立刻成为军需物资采购和库存的高度有效决策，也使整个后勤制度为之改观。”

### 案例 2: 人事“平均数”与汽车安全衡量（重新定义相关标准）
- **问题**: 人事管理用停工事故数、缺勤率、病假率等“平均数”衡量；汽车业用“平均每行车公里交通事故件数”衡量安全。
- **方法论的使用**: 德鲁克指出，管理者若亲自查看，会发现平均数掩盖了分布（事故集中于某部门、缺勤集中于某类人群），需要的是另一套衡量方法；汽车业若亲身查看，会发现交通事故应以“人体伤残情况”衡量。
- **结论**: “平均数适用于保险公司的需要，但是对人事管理的决策没有意义，甚至有时还误导人们”；找出适当衡量方法是带风险的判断。
- **结果**: 以此说明“衡量方法决定看到什么事实”，为“见解为先”提供实例判据。

### 案例 3: 企业投资的三种衡量方法（多方案并测的范例）
- **问题**: 企业投资决策通常有多种衡量方法：回收期、获利能力、投资收益的“现值”。
- **方法论的使用**: 有效的管理者不会仅以其中某一方法为满足——即使会计部门强烈推荐某一种“最科学”，他也知道任何方法都只能显示投资决策的某一层面；他坚持分别用三种方法计算，才判定“某一衡量方法对这个投资决策来讲是最适合的”。
- **结论**: 判断必须先有两项以上方案可选；“如果没有考虑每一个可能方案，就是偏颇”。
- **结果**: 成为“先定衡量标准、多法交叉”的标准操作范例。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 团队争论要不要做某件事，双方都声称“我有数据”，僵持不下。
2. 有人（包括用户自己）说“先别带观点，先把事实收集齐”，但收集范围与判断标准从未谈清。
3. 要为一个决策选考核/评估指标，各方对“用哪个指标”争执。
4. 汇报或评审中，用户发现结论早就定了，数据只是用来支持结论的“弹药”。
5. 用户要设计一项研究、调研或试点，需要明确“要验证什么假设、什么事实能证伪它”。

### 语言信号 (用户的话里出现这些就应激活)

- “双方都说自己有数据，谁对？”
- “我们先收集事实再决策吧。”“拿数据说话。”
- “这个指标到底该用哪个？相关的标准是什么？”
- “let's start with the facts” / “which metric is right” / “what would prove this wrong” / “our opinion vs theirs”

### 与相邻 skill 的区分

- 与 `dissent-as-resource` 的区别: 本 skill 确立“见解为先、先定衡量标准”的规则；后者是在此基础上主动制造互相冲突的见解并给出处理纪律，序列上先本后彼。
- 与 `feedback-and-inspect` 的区别: 后者提供“找出适当衡量方法”的机制（决策前反馈）与现场核实；本 skill 解释为什么必须把衡量方法本身作为议题（没有标准就没有事实）。
- 与 `decision-five-elements` 的区别: 后者是五要素全程审计；本 skill 是决策起点的专项——决策不从事实开始这一反教科书主张。
- 与 `problem-classification` 的区别: 后者先辨问题的性质（经常/偶发）以决定决策类型；本 skill 处理“事实与标准”的关系，两者都在决策链前端但对象不同。
- 与 `make-output-usable` 的区别: 后者是让产出为使用者可用（沟通设计）；本 skill 是让决策的证据基础可用（认识论设计）。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **摊开各方见解（含用户自己的）**
   - 完成标准: 每个相关方用一句话写出自己的判断；确认“有经验者应有见解”不是罪过，禁止用“要保持客观”压制见解表达。
   - 判停条件: 若各方只重复“我要看数据”，说明见解未被摊开，流程无法继续。

2. **把每条见解转写成“尚待证实的假设”**
   - 完成标准: 每条见解改写成一个可证伪命题（什么结果会证明它对、什么结果会证明它错）；无法改写者，标注“不可检验，暂不作为决策依据”。
   - 判停条件: 若某方拒绝转写（只坚持结论、不谈证伪条件），记录为异常并进入步骤 6。

3. **先回答“验证它需要什么事实、相关标准是什么”**
   - 完成标准: 每个假设对应一份“需要观察/研究/验证什么”的清单，且明确相应的衡量标准；把衡量方法本身列上议题桌，而不是当作默认背景。

4. **复核传统衡量方法是否适当**
   - 完成标准: 对现行指标做“今日体检”——它反映的是不是昨天的决策？能否暴露分布与重点？（参照平均数、每公里事故率的判例）；认定不适当时换方法并记录理由。

5. **多衡量方案并测，选定最适当者**
   - 完成标准: 对重要决策至少列出两种以上衡量方案（投资三法并测为范例），说明各方法的局限，记录选择理由。
   - 判停条件: 若只有一种衡量方法可选，注明“偏颇风险偏高”，并在反馈设计中优先复核该方法的适用性。

6. **防操纵判停：识别“以见解为盾”与“以数据为拖”**
   - 完成标准: 出现以下信号时升级裁定并记录：反复要求“再多收集数据”却始终不定义验证标准；以“见解不必辩论”拒绝给出证伪条件；用无穷多的新指标拖住结论。
   - 判停条件: 若操纵信号持续且无法在约定时限内完成验证设计，按现有最优证据做决定并留反馈记录，不无限期研究（与 `decide-and-act-fully` 的“再研究研究”判停配套）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 纯事实查询与可数据直接回答的问题（库存多少、页面转化率是多少）：直接查数，不需要见解—假设流程。
- 把“见解为先”当拒绝取证的挡箭牌：德鲁克的完整主张是“见解＝尚待证实的假设，必须经得起验证”；经不起验证的见解只有放弃。
- 立场已经不可协商的对抗场合：本方法假设各方愿意把见解交给验证。
- 为“先有结论再找材料”背书：那正是德鲁克所批判的（“他既然先有了结论，必能搜集到许多事实”），本 skill 恰恰要求事前写明证伪条件。

### 作者在书中警告的失败模式

- **从“搜集事实”开始决策 / 先结论后找材料**（ce31）：假装从事实出发，实则按既有结论筛选事实，收集到的是支持材料而非验证材料；研究方案里只列“要收集哪些数据”，没有“要验证什么假设、什么事实能证伪它”。
- **固守传统衡量方法与单一衡量方法**（ce32）：用旧方法看待新问题，看不见真正的重点；只用一种方法即“偏颇”；衡量方法选择本身是“带有风险的判断”而非数学问题。
- **指望电脑替代判断**（ce36，判断不可外包的维度）：把决策前提的认定外包给系统与数字，不再判断前提是否仍成立。**时代语境声明**：该书相关段落含 1966 年大型机时代的技术判断，不可作为当代技术结论；此处仅在“判断不可外包”的边界意义上引用。

### 作者的盲点 / 时代局限

- **两个都“经得起验证”的见解如何裁决，书中无程序**：德鲁克只给出“先定标准、多法并测”，当验证结果互相矛盾时（不同标准导致不同结论），没有说明如何选出裁判标准；实践中需补充决策责任人裁定或引入外部判据。
- **“至诚假设”缺乏防操纵设计**（BOOK_OVERVIEW 最强反对意见 4）：把不同意见预设为善意、又允许“不合格的数据”被不断要求补足，在不健康组织里可能被用来无限拖延与推卸责任；本 skill 已在 E6 补判停标准，但书中没有。
- **见解的“经验门槛”未讨论**：德鲁克说“凡在某一领域具有经验者，都应该有他的见解”，对经验不足者（新人、跨领域者）的见解地位未加说明，也未讨论资历如何压制新见解。
- **高管与时代语境**：案例集中于 1900–1960 年代美国企业与军政（麦克纳马拉、贝尔、汽车业），判据可迁移、产业细节不可照搬。
- **证据声明**：本书证据以作者顾问观察与轶事为主，无对照实证；本方法应按经验判据使用（BOOK_OVERVIEW 批判节）。

### 容易混淆的邻近方法论

- 与“数据驱动决策（data-driven）”的区别: 后者默认数据在中立地说话；德鲁克指出没有衡量标准就找不到事实——先定标准，再看数据。
- 与“假设驱动（hypothesis-driven）”的区别: 精益式假设驱动重在实验设计与快速验证；本 skill 更前置一层——先争衡量标准与相关事实的认定，再谈验证。
- 与 `dissent-as-resource` 的区别: 见上，一个立规则、一个用规则制造并处理冲突见解。
