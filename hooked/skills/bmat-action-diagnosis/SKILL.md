# B=MAT 行动诊断与"先补能力"排序

## R — 原文 (Reading)

> "要使人们行动起来，三个要素必不可少。第一，充分的动机；第二，完成这一行为的能力；第三，促使人们付诸行动的触发。……动机、能力、触发这三样缺一不可，否则，人们将无法跨过'行动线'，也就是说，不会实施某种行为。"
>
> — 第3章 上瘾模型中的行动阶段（L811–L813）

> "答案始终是：先解决能力问题。……实际情况是，增强用户的使用动机往往耗时又费钱。……你应该简化操作过程，推动他们进行实践，这远比强化他们的动机、吊足他们的胃口要管用得多。"
>
> — 第3章 动机和能力——你该先解决哪一个（L1007–L1011）

> "要增加预想行为的发生率，触发要显而易见，行为要易于实施，动机要合乎常理。"
>
> — 第3章 牢记并分享（L1136）

---

## I — 方法论骨架 (Interpretation)

一个行为没有发生，永远只有三类原因，而且它们是**相乘**关系而非相加：动机（想不想）、能力（能不能）、触发（想没想起来）。任何一项为零，乘积为零——这就是福格行为模型 B=MAT。它的价值不在预测，而在**归因**：行为缺失时，把笼统的"用户不感兴趣"拆成三个可分别检查的假设——够不着（能力受阻）、不想做（动机不足）、没注意到（触发缺失）。

埃亚尔在此之上加了两条可操作的增量：第一，**诊断顺序**——三要素对应上瘾模型的前三个阶段，触发先查（有没有被唤起），能力次查，动机最后查；第二，**修复排序**——当确认要补时先补能力，因为提升动机耗时费钱且不可控，而简化流程是设计者完全可控、见效最快的变量。三准则（触发显而易见、行为易于实施、动机合乎常理）是这套诊断的操作化压缩版。

## A1 — 书中的应用 (Past Application)

### 案例 1: 手机响了为什么没接（福格的诊断示范）
- **问题**: 同一个行为缺失——"手机响了却没接"，表面归因是"不想接"，但作者借福格的例子示范如何系统归因。
- **方法论的使用**: 逐项检查三要素：手机在包里够不着→能力受阻；以为是电话推销员→动机不足；手机静音→触发没有出现。三种解释对应三种完全不同的修复动作。
- **结论**: 行为缺失不能笼统归因于"用户不感兴趣"，必须先定位是哪一要素为零；不同归因导出不同解法（找得到手机/换来电策略/开铃声）。
- **结果**: 该例成为全书第 3 章的定锚示范（L815–821），后续 Twitter 主页演变、桌面网站之败等案例都沿用此归因法。

### 案例 2: Twitter 主页三次演变
- **问题**: 2009 年的 Twitter 主页以激发用户动机为目标——堆满解释性文字，说服访客"你应该用 Twitter"。
- **方法论的使用**: 2012 年战略重心从动机转向行为：简洁界面、140 字符自我介绍、只留"登录/注册"两个行动召唤、移动端下载引导——即放弃吊胃口，直接降低行动门槛让用户"真刀真枪试一次"。
- **结论**: "与其推销，不如让用户直接体验"——先解决能力问题比强化动机更管用。
- **结果**: 简化后的主页成为行业范本，作者用它论证"先补能力"的优先级规则（L1015–1040）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 转化漏斗诊断：广告/推送点击率正常，但注册、下单、提交在中途陡降——"来了人却不行动"。
2. 调研与行为背离：用户访谈都说"需要"，上线后就是没人用——需要区分"不想用"还是"用不动"。
3. 增长需求评审上的路线之争：团队在"改文案（动机）还是改流程（能力）还是加推送（触发）"之间争论不下。
4. 新功能/新习惯推行失败：员工或用户被要求做某个动作（填表、打卡、用新系统），完成率极低。

### 语言信号 (用户的话里出现这些就应激活)

- "点击了但没完成 / 用户说要但不用 / 漏斗在哪断了"（funnel drop-off, users say they want it but don't use it）
- "该改文案还是改流程 / 动机还是门槛"（motivation or friction? which to fix first）
- "B=MAT / 福格行为模型 / Fogg behavior model / 行动公式 / 缺一不可"

### 与相邻 skill 的区分

- 与 `f04-external-triggers-four-types` 的区别：f04 研究触发器本身的分类与拉新/留存分工；f07 是行为未发生时的总归因程序，触发只是被排查的三要素之一。
- 与 `f08-three-core-motivations` 的区别：f08 是动机杠杆的选型工具（M 的展开）；f07 负责判定问题是否出在动机上——多数"不行动"其实卡在能力。
- 与 `f09-six-simplicity-elements` 的区别：f09 是能力项内部的六项摩擦清单（A 的展开）；f07 先归因到能力，再转给 f09 找最短板。
- 与 `f20-habit-test-three-steps` 的区别：f20 是上线后用数据验证习惯是否形成的测量装置；f07 是行为不发生时的归因诊断，二者一后一前。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **锁定目标行为**
   - 完成标准: 用一句话写清"谁、在什么场景、做什么动作"（如"新注册用户在首日完成一次数据导入"）。写不出即先澄清需求，不进入诊断。

2. **按"触发→能力→动机"顺序逐项归因**
   - 完成标准: 每个要素给出"通过/存疑"判定并附证据（数据或用户观察，不凭想象）。触发：行为召唤是否出现、是否可见、时机对不对；能力：完成该行为需要什么，用户缺什么；动机：用户有没有理由现在做。
   - 判停条件: 若触发未出现或不可见，先修触发（转 `f04-external-triggers-four-types` / `f05-internal-trigger-anchoring`），能力与动机的排查推迟。

3. **按"先补能力"排序修复方案**
   - 完成标准: 能力存疑时，转 `f09-six-simplicity-elements` 定位六要素中的最短板并做减法；动机修复只对"确实不想做"的确认人群设计（转 `f08-three-core-motivations` 选杠杆），且优先级低于能力项。

4. **乘法复测**
   - 完成标准: 修复上线后按同一行为指标复测；若行为仍未恢复，回到步骤 2 重新归因——B=MAT 是乘法，修好一项后其余项仍可能为零，不得一次修完就宣布诊断结束。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户根本没有需求（0→1 阶段）：行为公式只解释"为什么不行动"，不解释"要不要做"。先验证需求存在，再谈三要素。
- 纯触达量问题：曝光不足时归因于能力/动机是浪费，先回到触发端。
- 动机本位的产品场景：奢侈品、社交货币型产品的购买动机本身是价值来源，"先简化"可能稀释其吸引力——本方法的排序规则最适合工具性与习惯养成类行为。

### 作者在书中警告的失败模式

- 触发成功但循环断裂（ce22）：设计者发现"就算触发生效，动机强烈，用户仍常常不按照设计者期望的轨迹前进"，原因是可行性不足。典型警兆：点击率高、完成率低；漏斗在注册/首用处陡降；需要用户"学习"才能用。把曝光误当行动、归因于用户懒惰而非流程摩擦，是本方法要拦截的头号错误。
- 载体不可及（ce13）：内容与动机俱在，但桌面网站无法在"启示时刻"出现在用户手边——B=MAT 中触发与能力两要素因设备不在场同时不成立（第7章圣经应用先败后成的教训）。

### 作者的盲点 / 时代局限

- 公式源自福格行为模型（作者在第3章明引，L809–813），属二手框架；埃亚尔的增量是诊断顺序与"先补能力"的优先级规则，引用时应注明出处而非当作埃亚尔原创。
- 成书于 2014 年硅谷移动 App 语境：诊断默认"用户装了 App、图标在首屏"，对小程序/超级 App 内嵌生态、算法推荐分发等后继形态未覆盖。
- "心理学实验可直接外推到产品场景"的假设未经验证：本书证据多为转引实验与幸存者案例，无对照研究（阶段 0 批判节）。

### 容易混淆的邻近方法论

- 通用漏斗/转化率分析：数据工具回答"哪一步掉了多少人"，B=MAT 回答"为什么掉"（行为学归因顺序），后者先于前者给出修复方向。
- `f08-three-core-motivations`、`f09-six-simplicity-elements`：本 skill 的两个子工具，不要在归因完成前直接跳入子清单。
