# 储存价值五形式（内容/数据/关注者/信誉/技能）

## R — 原文 (Reading)

> "用户对产品的投入不仅可改进产品服务质量，增加用户再次使用产品的可能性，还能令储存价值以内容、数据资料、关注者、信誉或技能等形式自然增长。"
>
> — 第5章 牢记并分享（L1812）

> "如果我们能让用户输入哪怕一点点信息，他们变成回头客的可能性都会更大。"
>
> — 第5章 数据资料（LinkedIn 高级产品经理乔希·艾尔曼，L1689）

> "科技行业的许多观察家都认为该产品实际上比Twitter更好。但是，与其他企图复制服务的尝试一样，App.net并没获得成功。这是为什么呢？"
>
> — 第5章 关注者（L1704）

## I — 方法论骨架 (Interpretation)

留存的另一条支柱不是"每次体验多有趣"，而是"用户已经把多少自己存进了产品"。投入会沉淀为五类资产，每类都是一条独立的转换成本：内容（iTunes 曲库、写过的帖子）；数据资料（LinkedIn 简历、Mint 聚合的账户——输入越多服务越准）；关注者（Twitter 的关注网络，改换服务等于社交资产清零）；信誉（eBay/Airbnb 的评分决定待遇，重建成本极高）；技能（Photoshop 熟练度无法迁移到竞品）。

两件事让它区别于"提高切换成本"的管理学口号。第一，**迁移性是每类资产的独立判据**：技能不可迁移、内容可导出、关注者几乎不可迁移、信誉需要重新积累——五类的防流失强度天然不同，诊断时要分清用户究竟被哪条绳索拴住。第二，**合法性的前提是"投入真实提升后续服务质量"**：储存价值来自"改换产品=放弃自己的一部分"，而不是来自导出门被焊死。这使五形式清单有两个用法——防守时盘点自家产品让用户存了什么（答案若是"什么都没有"，流失就没有摩擦）；进攻时盘点竞品用户的储存价值，理解为什么"更好的复制品"依然打不动人。

## A1 — 书中的应用 (Past Application)

### 案例 1: App.net——功能更好的 Twitter 复制品之死
- **问题**: 一个"没有广告、观察家公认更好"的产品，为什么取代不了 Twitter？
- **方法论的使用**: 用储存价值视角盘点 Twitter 用户的资产：关注网络、历史推文、多年经营的社会资本都留在原产品——"创建公司所需的技术一天之内就能建成"，但关注网络无法复制。
- **结论**: "对自己辛辛苦苦建起并精心呵护维持的关注群，没有人舍得放弃"——功能优势对冲不了储存价值损失，改换服务意味着一切重新开始。
- **结果**: App.net 失败，成为"关注者"类资产防御力的标准例证（L1694–1714）。

### 案例 2: LinkedIn 的点滴信息投入
- **问题**: 用户不愿意花时间填完整简历，资料类投入还能成立吗？
- **方法论的使用**: LinkedIn 的做法是把资料完善切成沿使用旅程自然发生的微小请求：每次使用按提示多添加一点。其早期产品经理艾尔曼总结为"哪怕一点点信息"判据。
- **结论**: 数据资料的储存价值从第一笔就开始累积，"即使点滴努力都会打造出一个强有力的钓钩，将人们牢牢钓回服务之中"；LinkedIn 发现输入信息越多的用户回访频率越高。
- **结果**: 该判据成为"数据资料"类的操作规则（L1689–1691），与 Mint 的账户聚合例共同支撑五清单的第二类。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 流失与续约诊断：订阅制/协作工具续约率下滑，要弄清用户留下的理由是价值还是惯性，以及哪类资产缺失。
2. 竞品攻防：对手功能更漂亮、定价更低却撬不走用户（或反过来，我们要撬在位产品的用户）——评估双方转换成本结构。
3. Onboarding 与资产冷启动：新用户注册后没有沉淀任何东西，要设计"第一笔资产"的投入点。
4. 数据与功能规划：讨论要不要做导出、开放 API、评分体系、进阶技能学习路径时，判断其对留存的含义。

### 语言信号 (用户的话里出现这些就应激活)

- "怎么防止用户流失 / 续约率 / 防流失"（churn, retention, renewals, switching cost）
- "用户在我们这里沉淀了什么 / 迁移成本 / 换起来麻烦吗"（what do users accumulate, migration cost, lock-in）
- "储存价值 / stored value / 竞品比我们好用怎么留人"（stored value, why users stay despite a better rival）

### 与相邻 skill 的区分

- 与 `f14-investment-changes-attitude` 的区别：f14 解释投入为什么会在心理上抬高价值（宜家效应等三机制），f15 盘点投入实际沉淀成哪五类资产、迁移性如何。机制 vs 资产，一虚一实。
- 与 `f16-load-next-trigger` 的区别：投入有两个去向——沉淀为储存价值（f15）与生成下一次召回的触发（f16）；f15 管"留下什么"，f16 管"何时被想起"。防流失用 f15，做召回用 f16。
- 与 `f02-habit-zone-frequency-first` 的区别：频率轴解释行为是否进入习惯区间，f15 解释进入后为何难以离开；低频产品做不成习惯，但可以（如亚马逊）靠高可感知用途与资产沉淀守住用户。
- 与 `f13-finite-infinite-variability` 的区别：新鲜感耗尽后（体验侧无解），储存价值是资产侧的留存支柱；UGC 平台两者兼得，但"用户腻了"与"用户没沉淀"是两个不同诊断。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **逐类盘点五资产**
   - 完成标准: 对内容/数据资料/关注者/信誉/技能逐项回答"用户在产品里存了什么"，每类给出有/无/弱判定与具体证据（数据或用户访谈）。
   - 判停条件: 若五类全空（或近乎全空），产品是一次性应用——先设计投入点（转 f17 的粒度规则与 f14 的机制），而不是做流失挽回。

2. **定位最薄弱资产并设计对应投入点**
   - 完成标准: 选出对留存最关键且当前最弱的一类，给出投入点设计：内容→创作/收藏入口；数据→导入/配置/点滴填写（"哪怕一点点"判据）；关注者→关注关系/邀请机制；信誉→评分/成就/历史记录体系；技能→进阶功能与学习路径。方案可落地可测。

3. **评估各类资产的迁移性**
   - 完成标准: 对每类标注"用户带走的难度"（技能不可迁移/内容可导出/关注者不可迁移/信誉需重积累），形成自家转换成本结构图；进攻场景则对竞品做同一张图，找出对方资产最薄的一类作为切入口。

4. **合规检查（判停条件）**
   - 完成标准: 逐项确认挽留手段没有依赖"阻止导出/阻止删除账户/人为制造迁移障碍"；若有，停止该设计——储存价值的正当性前提是投入真实提升后续服务质量，锁定不等于价值。处置拿不准的灰色设计（如人为拖延的导出流程），转 `manipulation-matrix` 复核后再定。

5. **验证资产-留存相关性**
   - 完成标准: 对比流失用户与活跃用户的资产存量（各类数量/完整度），确认"存得越多留得越久"在本产品成立；不成立则回到步骤 2 换资产类别重试。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 隐私敏感场景的盲目加码：健康、财务数据的"存得越多越准"与隐私风险同增，储存价值设计必须与最小化采集原则权衡。
- 低频工具的强行造资产：计算器、查询工具不必为留存硬塞社交关系或信誉体系，先确认产品是否有自然沉淀面。
- 把"锁定"当产品策略：焊死导出、报复性删除流程属于恶意锁定，不是储存价值设计。

### 作者在书中警告的失败模式

- "略胜一筹"的产品幻觉（ce05）：创业者以为功能好 10%–20% 就能撬走用户，但切换意味着重学+放弃储存价值，微弱优势被切换成本吞没——进攻前不计算对方的储存价值是头号误判。
- App.net 复制之死（ce15）：差异点全在产品侧、无一在用户资产侧，目标用户与在位产品重合度极高且未提供资产迁移方案。
- 一次性应用陷阱（ce14）：五类资产全空的产品，首次新鲜感耗尽后没有任何回访理由，会被高频应用挤出首屏。
- 旧习惯回转（ce04）的对照：储存价值是防回转的结构性防御，没有沉淀的习惯替代品会"后进先出"地被旧产品夺回。

### 作者的盲点 / 时代局限

- 未区分"用户真心获益的留存"与"被迫锁定的留存"：书中把"产品好用"与"设计出了依赖"混为一谈，数据越多也可能意味着隐私风险越大、切换成本由"锁定"而非"价值"支撑（阶段 0 批判节）。
- 监管环境巨变：GDPR（2016/2018）与数据可携带权使"资产天然不可迁移"的前提收紧，部分迁移性如今是法律义务；成书于 2014 年的案例（iTunes 曲库等）未预见订阅制与云端同步对内容类资产的改写。
- 技能类资产的行业局限：Photoshop 例在专业软件成立，但跨平台工具（通用笔记、表格）的技能迁移成本远低于书中暗示，判据需按行业校准。

### 伦理红线（投入/储存价值专用）

**储存价值设计不得用于绕过用户自主权、不得制造强迫性使用**：不得以剥夺数据可携带、账户可删除、服务可退订为手段留住用户——价值留存与恶意锁定的分界线是"用户是否随时保有退出权且投入真实改善了后续体验"；为用户侧提示：识别自己"舍不得离开"的成分中哪些是真实价值、哪些是锁定效应，是本清单的合法第二用法。

### 容易混淆的邻近方法论

- 管理学"转换成本/锁定效应"（switching cost/lock-in）：泛指一切离场代价，本书的可区分结构是把锁定拆成五类**迁移性不同**的资产并给出各类的投入点设计。
- `f14-investment-changes-attitude`、`f16-load-next-trigger`、`f17-investment-timing-granularity`：投入阶段四件套——机制（为何有效）、资产（沉淀为何）、召回（何时想起）、时机粒度（怎么提要求），盘点时按问题选件，不要互相替代。

## 相关 skills

本 skill 是投入阶段四件套中的"资产"件：盘点投入沉淀成什么、迁移性如何，与机制、时机、召回三件分工明确。

**depends-on**（使用前提）: 无。

**contrasts-with**（同境况二选一）: 无。

**composes-with**（配合使用/先后接力）:

- `investment-changes-attitude` — 资产与机制互补：f14 解释投入为何在心理上抬高价值（一虚），本 skill 盘点投入实际沉淀的五类资产（一实）；五类全空时先转 f17 的粒度规则与 f14 的机制设计投入点（E 段判停）。
- `investment-timing-granularity` — "哪怕一点点信息"判据的施工规则：点滴式资产沉淀按 f17 的小步+预填落地（每次一个字段、进度可视）。
- `load-next-trigger` — 投入的两个去向：沉淀为储存价值（本 skill，管"留下什么"）与生成下一次召回（f16，管"何时被想起"）；防流失用本 skill，做召回用 f16。
- `finite-infinite-variability` — 留存双支柱的资产侧：体验侧多变性耗尽后（f13 判定无解时），储存价值是独立的留存支柱；"用户腻了"与"用户没沉淀"是两个不同诊断。
