# 机会四策源地：照镜子 / 新生行为 / 促成性技术 / 界面更改

## R — 原文 (Reading)

> "保罗·格雷厄姆建议企业家抛开听起来十分诱人的经营理念，要根据自己的需求开发产品，'不要问"我应该解决什么问题"，要问"我希望其他人为我解决什么问题"'。"
>
> — 第8章 习惯测试和寻找机会·寻找机会（L2211）

> "许多突破性技术和公司，例如飞机技术和空中食宿公司，一开始都被评论家们当作玩具或利基市场而嗤之以鼻。在早期用户当中寻找新生行为模式往往可以发现新的、有价值的商业机会。"
>
> — 第8章 寻找机会（L2246）

> "要想找到界面更改点，Y-Combinator 公司的合伙人保罗·布赫海特鼓励企业家们'生活在未来'。……只要预先考虑到界面将会发生更改的地方，富有进取心的设计者就能找到新的方法培养用户习惯。"
>
> — 第8章 寻找机会（L2274）

## I — 方法论骨架 (Interpretation)

把"找需求"从灵感叙事变成四路定向扫描，每路自带判据：①照镜子——研究自己的烦恼，因为设计者至少与一个用户（自己）保持直接沟通；判据是格雷厄姆的那句反问，问"我希望别人为我解决什么"，而不是"我能解决什么"。②新生行为——被主流当作玩具或利基的边缘行为可能越界成为主流习惯；配套证据是一串专家看走眼的史料（电话、飞机、布朗尼相机、互联网），所以扫描时问"谁在天天做这件'没用'的事"，而不是"这有没有用"。③促成性技术——新技术让某个行为骤然变容易之处就是机会，看的是行为的成本曲线拐点。④界面更改——人与技术交互方式的重大迁移（图形界面、简化搜索、相机+手机）会批量制造新习惯入口，配套心法是布赫海特的"生活在未来"。四路产出汇总后再进可行性过滤，扫描与过滤是两道工序。

## A1 — 书中的应用 (Past Application)

### 案例 1: Buffer 的诞生
- **问题**: 创始人加斯科因想多分享好内容，但手动按时间表发推烦不胜烦。
- **方法论的使用**: 照镜子——从自己反复忍耐的烦恼出发做工具，"将要发布的推文提前编入时间表，其效率要远远高得多"。
- **结论**: 自己的真实需求是可靠的机会信号源，设计者与这个用户始终保持直接沟通。
- **结果**: Buffer 上线后用户超过 110 万，成为"照镜子"方向的实证（L2213–2219）。

### 案例 2: 新生行为史料的四次打脸
- **问题**: 如何判断边缘新行为值不值得押注？
- **方法论的使用**: 作者引一组看走眼史料：邮政总工程师断言"美国不需要电话，我们有足够的信差"；福煦元帅称"飞机是很有趣的玩具，但毫无军事价值"；1995 年斯托尔写《互联网？我呸！》；再对照 Facebook 从复刻哈佛线下"花名册"长成十亿用户产品。
- **结论**: 早期用户的边缘行为可能就是主流习惯的雏形，"有没有用"的直觉是坏过滤器。
- **结果**: 支撑"新生行为"方向成为四个机会策源地之一（L2232–2246）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 找下一个习惯产品机会：团队 brainstorm 有热情没方法，需要定向扫描面。
2. 红海切入：大厂林立的赛道里问还能切哪里。
3. 判断"看起来像玩具"的新东西（小众工具、新交互、新硬件）值不值得持续关注。
4. 技术浪潮评估：新模型、新传感器、新平台出现，问哪个行为会因此变容易。

### 语言信号 (用户的话里出现这些就应激活)

- "有什么机会 / 下一个点子 / 习惯产品创意"（product opportunity, habit-forming product ideas, where's the next opportunity）
- "新生行为 / 早期用户 / 小众玩法会不会成主流"（novel behavior, early adopters, niche to mainstream）
- "界面变化 / 交互迁移 / 技术让什么变容易 / 生活在未来"（interface shift, enabling technology, what just got easier, live in the future）

### 与相邻 skill 的区分

- 与 `f20-habit-test-three-steps` 的区别：同属第 8 章的两件工具——f22 是"找新机会"（产品之前），f20 是"验证现有产品"（产品之后）。问"下一个做什么"用 f22，问"现在这个行不行"用 f20。
- 与 `f01-hook-model-four-stages` / `f02-habit-zone-frequency-first` 的区别：f22 只负责点子的来源（从哪找），拿到候选后是否可行交给 f01 五问与 f02 习惯区间过滤——先扫描后过滤，两道工序别混。
- 与通用头脑风暴/风口判断的区别：f22 的四方向各带判据（自己的烦恼/边缘行为/骤然变容易/交互迁移点），不是发散联想，也不预测技术热度曲线。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **照镜子扫描**
   - 完成标准: 列出自己在工作/生活中反复忍耐的 ≥3 个烦恼，逐一改写为"我希望有人为我解决 X"的句式；只收自己的真实行为证据，不收想象需求。

2. **新生行为扫描**
   - 完成标准: 找到 ≥2 个"看起来没用但有人天天做"的行为，写清谁在做、做了多久、为何被主流视为玩具；明确不用"有没有用"做初筛，只用"有没有人在做、频率多高"。

3. **促成性技术扫描**
   - 完成标准: 写出最近一项新技术让哪个行为从"难/贵/慢"变为"易/廉/快"，并说明该行为此前如何被硬扛（替代方案是什么）。

4. **界面更改扫描**
   - 完成标准: 指认当前正在发生的人机交互迁移点（新终端/新输入方式/新默认入口），并回答"该迁移让哪类习惯入口批量出现"。

5. **汇总与过滤（判停）**
   - 完成标准: 四路扫描合并为候选清单，逐个过 f02 习惯区间（频率×用途）与 f18 操纵矩阵两道闸；任一关不过即弃——扫描产出的是候选，不是结论。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 现有产品的留存与习惯验证——那是 f20 的领地，方向相反。
- 给点子做可行性过滤——交给 f02（习惯区间）与 f01（五问），f22 只回答"从哪找"。
- 纯商业模式探索（怎么赚钱、怎么定价）——作者明言本书不涵盖商业模式与客户获取（L2206 附近），扫描出的机会仍缺商业设计。

### 作者在书中警告的失败模式

- 专家式看走眼（反向教训）：用"这没用"过滤掉新生行为——史料组的直接教训；但须防对称错误：多数"玩具"就是玩具，作者未给出生行为的证伪标准（证据以幸存者叙事为主），押注前仍需自设验证。
- 照镜子自我放大：设计者≠目标人群，自己的烦恼可能毫无市场——格雷厄姆判据须配合"还有谁与我同痛"的验证；书中未强调这一点（阶段 0 批判节：硅谷精英与男性视角，样本高度同质）。

### 作者的盲点 / 时代局限

- 2014 年语境下的界面更改例（可穿戴设备、Google 眼镜、Oculus、Pebble）后来并未成为主流习惯入口——作者对界面迁移的预测同样会错；本 skill 给的是扫描法，不是预言术。
- 案例集中于消费互联网；AI 时代的"对话即界面""模型即内容"不在书内——扫描法可平移，样本与判例需自行更新（阶段 0 批判节）。
- 幸存者叙事偏置：Buffer、Facebook、Instagram 都是成功者回溯，未讨论按同法扫描后失败的多数。

### 容易混淆的邻近方法论

- Gartner 技术成熟度曲线 / 风口判断：f22 不预测技术热度，只扫描"行为变容易"的落点；前者是时间轴判断，后者是行为机会定位。
- 用户访谈/需求调研：照镜子是设计者第一人称，不替代对真实用户的验证；两路互补不可互替。
- `f20-habit-test-three-steps`：见 A2 区分——扫描（f22）与验证（f20）是产品生命周期的两端。
