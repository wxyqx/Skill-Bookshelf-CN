# 投入阶段设计：时机与颗粒度（酬赏之后、小步开始、可加摩擦）

## R — 原文 (Reading)

> "与行动阶段形成鲜明对照的还有一点，投入阶段会增加摩擦。这无疑打破了产品设计界的传统思维，即一切用户体验都应该越'轻松简单'越好。……在投入阶段，应该在用户享受过形式多样的酬赏之后再提出让其做一些小小投入的要求，而不是之前。要求用户进行投入的时机至关重要。"
>
> — 第5章 投入：通过用户对产品的投入，培养"回头客"（L1652）

> "将设计者希望用户所做的投入逐步分解成小块任务，先从小而简单的任务开始，然后在上瘾模型的连续循环过程中逐步加大任务难度。"
>
> — 第5章 投入：通过用户对产品的投入，培养"回头客"（L1740）

> "第二组顾客——卡上已经免费打过两次孔的顾客，完成这八次消费的人数比第一组高出了 82%。这一研究证明了目标渐近效应的存在，当人们认为自己距离目标越来越近时，完成任务的动机会更强烈。"
>
> — 第3章 行动：人们在期待酬赏时的直接反应（L1107）

## I — 方法论骨架 (Interpretation)

行动与投入是一组被行业教条掩盖的对称结构：行动阶段求即时满足，要把摩擦减到极致；投入阶段（填资料、授权、设置、连接）关乎未来回报，可以有摩擦——因为动手付出本身制造价值感。"体验永远越顺滑越好"只对了一半，正确的做法是分段处理。在这个分段之内有两条硬规则：一是时序，投入要求必须排在酬赏之后——用户先尝到甜头，付出才不构成"被索取"；顺序颠倒会同时撞上逆反心理与信任赤字。二是粒度，把期望的投入拆成小块、先小后大，随一个个循环逐级加深，能预填则预填——目标渐近效应（洗车卡实验）说明"看见自己接近目标"本身就是动力。若用户没做你想要的投入，默认诊断不是"用户懒"，而是"设计者要求太多"。

## A1 — 书中的应用 (Past Application)

### 案例 1: 洗车卡实验与 LinkedIn 资料进度条
- **问题**: 如何让用户持续完成需要多步的投入（办卡消费、填资料）？
- **方法论的使用**: 对照实验——两组同样需消费 8 次，"10 次卡已免费打 2 孔"的组完成人数高出 82%；LinkedIn 用"资料完成条"而非数字比例让用户直观看见自己接近目标。
- **结论**: 目标渐近效应成立：预填进度、可视化接近感是投入设计的直接杠杆。
- **结果**: 该实验成为第 3 章启发法与第 5 章"投入小步规则"之间的证据桥（L1105–1109）。

### 案例 2: 《圣经》应用的读经计划
- **问题**: 整本《圣经》很难读下去，用户坚持不了。
- **方法论的使用**: 把读经切分成每日一小段的计划，"读者的注意力会集中在手头的这一丁点儿任务"，先从最小步开始。
- **结论**: 小步分解+每日节奏能撑起长期投入。
- **结果**: 配合多日链条的人为推进效应，读经计划成为该应用 1 亿台设备下载的核心抓手（第 7 章，L2054–2056）。

### 案例 3: Any.do 的首用投入
- **问题**: 移动应用 26% 下载后只用一次，何时开始要投入？
- **方法论的使用**: 第一次使用就以简练方式教用户上手（先给酬赏：祝贺与掌握感），随即引导做一个小投入——连接日历。
- **结论**: 投入要早，但排在首次酬赏之后、且小到一步可完成。
- **结果**: 连接日历为后续所有循环装上了召回触发（第 5 章，L1753–1763）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. Onboarding 决策：注册后要不要立刻让用户填 20 项资料 / 开通知 / 连通讯录？
2. 付费墙与授权请求的位置：弹窗被拒率高，怀疑是时机不对。
3. 用户在投入环节流失：设置向导完成率低、资料完善率长期停滞。
4. 进度与激励设计：要不要给用户看"已完成 60%"、要不要预填。

### 语言信号 (用户的话里出现这些就应激活)

- "注册后要不要让用户填……/什么时候要资料/授权时机"（when to ask for profile, permission timing）
- "步骤太多/流程太长/小步开始/拆步骤"（break into small steps, micro-tasks, progressive onboarding）
- "先给甜头再要求/酬赏之后/进度条/预填"（after the reward, progress bar, pre-filled progress, goal gradient）

### 与相邻 skill 的区分

- 与 `f14-investment-changes-attitude` 的区别：f17 管"何时提、拆多细"（时机与粒度规则），f14 管"投入为什么改变态度"（宜家效应/一致性/文饰作用三机制）。f14 的 A2 已声明此分工。
- 与 `f15-five-stored-values` 的区别：f15 回答投入沉淀成什么资产（内容/数据/关注者/信誉/技能），f17 回答投入以什么方式提出。
- 与 `f16-load-next-trigger` 的区别：f17 结束于用户完成一次小步投入；f16 从投入接续到下一次召回触发——同一条投入链的上下游。
- 与 `f09-six-simplicity-elements` 的区别：f09 是行动阶段减摩擦的六要素诊断；f17 允许投入端有摩擦。两者都可能出现"流程 friction"字样，判据是该环节求即时满足（行动，减摩擦）还是蓄未来价值（投入，可加摩擦）。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定位该环节的性质**
   - 完成标准: 明确该步骤是"行动"（求即时满足）还是"投入"（蓄未来价值）；行动步骤一律减摩擦，不得混入资料收集；定性含糊则先回 f07 做 B=MAT 归因。

2. **检查时序（判停点）**
   - 完成标准: 写出该投入要求之前用户获得的最后一个酬赏事件。
   - 判停条件: 若找不到任何酬赏（用户尚未获得价值），停止推进——先移到酬赏之后，或先设计酬赏。

3. **拆粒度**
   - 完成标准: 把投入拆成单步任务（每步一个字段/一次授权/一个小动作），第一步成本极低；给出后续循环中逐级加深的阶梯表（今天收藏→明天关注→下周发布）。

4. **应用目标渐近**
   - 完成标准: 有进度可视化（完成条、已预填项），能预填的默认预填，让用户做"减法确认"而非填空；给出可衡量的完成率预期。

5. **逆反自检（判停条件）**
   - 完成标准: 对照警告信号逐项检查——断签清零或示警、记录动作本身无酬赏、用户产生"欠债感"、要求不可跳过；任一命中即重构或放弃该投入设计（ce10 的教训）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 行动阶段的转化问题（点击多完成少、checkout 放弃）——那是 f07 B=MAT / f09 六要素的诊断对象；本 skill 的"投入可加摩擦"绝不适用于行动环节。
- 以提高沉没成本为目的故意设置繁琐步骤阻止用户离开——那是恶意锁定，不是投入设计；此类请求应拒绝，必要时转 `manipulation-matrix` 复核。
- 尚无价值交付的新产品急着设计投入阶梯——先回答"用户凭什么留下"（f01/f12）。

### 作者在书中警告的失败模式

- 强迫式记录触发逆反（ce10，MyFitnessPal）：把帮助设计成审计，漏记一天即前功尽弃——投入无酬赏支撑、粒度无阶梯、时序上全程索求，最终"要么臣服，要么放弃"。
- "对用户要求太多"归因：作者原话指出用户在投入阶段没按设计行动，原因多半是设计者要求太多（L1740），不是用户懒——诊断顺序先查自己的粒度。
- Quora 强制公开（ce09）的时序教训：未提示、无选择、全量强推——时机与方式双双违背本规则。

### 作者的盲点 / 时代局限

- 证据为转引的小样本行为实验（洗车卡等），写作期正值心理学复制危机发酵而书中未提；效应量与边界条件未验证；"小步"的最佳粒度无跨行业推导（阶段 0 批判节）。
- 2014 年语境把授权与预填当作纯设计问题；GDPR/ATT 之后，预填、默认授权在多个法域有合规边界——今日必须先过隐私合规再谈设计。
- "投入可加摩擦"在增长行业被挪用为"增加退出成本"的话术——作者原意是摩擦产生价值感（宜家效应），不是制造锁定；引用时须回到 g14"投入=提升后续服务质量"的定义。

### 容易混淆的邻近方法论

- 行业教条"friction 一律有害 / onboarding 要顺滑"：本书的精确修正正是分段处理——行动减、投入可加；抹掉这个分段，规则就会被用反。
- `f07-bmat-action-diagnosis`：投入步骤做不动时同样可用 B=MAT 归因（L1740 明示），但那是诊断工具；f17 是设计规则，二者可接力不可互替。
- 目标渐近效应的通识版（"进度条有用"）：本书增量在于把它接到投入时序与粒度规则上——预填是手段，酬赏之后才要投入才是前提。
