# 三种多变酬赏与动机对齐规则

## R — 原文 (Reading)

> "所谓社交酬赏，是指人们从产品中通过与他人的互动而获取的人际奖励。所谓猎物酬赏，是指人们从产品中获得的具体资源或信息。所谓自我酬赏，是指人们从产品中体验到的操控感、成就感和终结感。"
>
> — 第4章 牢记并分享（L1514–L1518）

> "这说明，驱使我们采取行动的，并不是酬赏本身，而是渴望酬赏时产生的那份迫切需要。"
>
> — 第4章 多变的酬赏（L1204）

> "在设计酬赏时，务必要考虑到用户使用该产品的原因，确保它与用户的内部触发和使用动机相吻合。"
>
> — 第4章 多变的酬赏不免费（L1404）

---

## I — 方法论骨架 (Interpretation)

驱动重复使用的不是酬赏本身，而是"渴望酬赏时的迫切需要"，而可预测的奖励恰恰消灭渴望——所以激励设计的第一个问题是"变量从哪来"，第二个问题是"给哪一种"。本书把酬赏压成三条机制各异的通道：社交酬赏的内核是部落的接纳（被认同、受重视），点赞、威望值、勋章都只是载体；猎物酬赏的内核是追逐过程本身（资源与信息只是追到的猎物），信息流与老虎机共享这一机制；自我酬赏的内核是任务闭合的终结感（清空邮箱、升到下一级）。

两条使用规则让它区别于泛泛的"给用户奖励"。第一，**对齐规则**：酬赏必须回应"用户为什么来"，为解闷而来的用户发积分是错位给药；先明确内部触发与动机，再选通道，最后才谈变量。第二，**通道选择规则**：社交认同的引力通常远大于金钱——金钱会重新定义行为性质（从兴趣变成低薪打工），把真动机挤出；顶级产品往往三线并发（如查邮件同时满足社交、猎物、自我三种渴望），但起点永远是那条与动机对齐的通道。

## A1 — 书中的应用 (Past Application)

### 案例 1: Mahalo vs Quora——奖金打不过投票
- **问题**: 问答社区如何持续获得高质量贡献？经济悬赏看起来最直接。
- **方法论的使用**: 同赛道对照：Mahalo 用虚拟货币悬赏，最佳答案可得现金；Quora 一分钱不奖励，靠投票系统建立稳定的社交反馈。
- **结论**: "人们对于社交酬赏以及同伴认同的渴望要远远大于对经济利益的期待"（L1398）；误判核心动机是激励设计的头号错误——把行为触发当作经济利益，"那还不如直接去做小时工"。
- **结果**: Mahalo 月访问冲到 1410 万后迅速冷却衰落；Quora 反超并成为问答社区主导者（L1386–1398）。

### 案例 2: Stack Overflow 的威望值与勋章
- **问题**: 如何让用户每天无偿提交 5000 条高技术含量的回答？
- **方法论的使用**: 用投票累积的威望值与达标解锁的勋章作为社交酬赏——认可是不确定的、靠同伴给出的，"不确定因素将寻常任务变成诱人的游戏"。
- **结论**: 社交认同足以支撑重劳动，前提是酬赏通道对准了技术社区成员真正渴求的地位与特许权利。
- **结果**: Stack Overflow 成为程序员问答的事实标准（L1261–1271）；作者在第 4 章末用电子邮件案例补充说明三线并发的检查法（L1495–1501）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 激励体系评审：产品要上积分商城/徽章/排行榜，需要判断这套游戏化会不会有效。
2. 社区与 UGC 运营：贡献者流失、内容供给下滑，要重新设计贡献者的回报。
3. 黏性诊断：用户用完即走，留存数据表明酬赏单一且可预测，要重排酬赏结构。
4. 教学与训练设计：课程、练习、训练营的反馈机制怎么让学员"想要更多"。

### 语言信号 (用户的话里出现这些就应激活)

- "用户激励怎么做 / 奖什么才能留住人"（user incentives, what to reward, reward design）
- "积分/徽章/排行榜有没有用 / 游戏化方案"（gamification, points, badges, leaderboard）
- "多变的酬赏 / variable reward / 三种酬赏 / 怎么让人持续贡献"（variable rewards, keep contributors engaged）

### 与相邻 skill 的区分

- 与 `f13-finite-infinite-variability` 的区别：f12 回答"给哪一种酬赏"，f13 回答"变量从哪来、会不会耗尽"。先选通道（f12），再查变量的来源与存续（f13）。
- 与 `f08-three-core-motivations` 的区别：f08 是行动**之前**的拉力（用什么打动用户来），f12 是行动**之后**的反馈（给什么让他再来）；两者都谈"动机"，环节不同。
- 与 `f05-internal-trigger-anchoring` 的区别：f05 找到用户带着什么情绪来；f12 的对齐规则正以 f05 的结论为输入——说不出内部触发就无从对齐。
- 与 `f15-five-stored-values` 的区别：f15 是酬赏之外让用户留下的资产侧设计（投入沉淀）；两者常被混为"提升留存"，一在体验侧一在资产侧。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **写下"用户为什么来"**
   - 完成标准: 用情绪词一句话表述内部触发与使用动机（如"贡献者要的是同行认可"）。说不出内部触发则判停——先转 `f05-internal-trigger-anchoring` / `f06-five-whys-emotional-root` 做触发研究，再回来设计酬赏。

2. **把候选酬赏归入三通道并检查对齐**
   - 完成标准: 每个酬赏想法标注通道（社交/猎物/自我）+ 它回应了哪条动机；错位酬赏（与内部触发不吻合的，如为解闷而来的用户发积分）删除或重设计。保留项都能说出对齐理由。

3. **对金钱/积分类候选做社交替代性检查**
   - 完成标准: 凡候选酬赏是现金、优惠券、积分，先回答"社交认同或自我酬赏能否替代"（Mahalo 教训）；确认保留金钱时，说明为何该场景金钱不会重定义动机（如劳动密集型任务）。

4. **加入变量并转交多变性检查**
   - 完成标准: 保留的酬赏机制中有不可预测元素，且变量来源明确（同伴行为/内容/对手）；随即转 `f13-finite-infinite-variability` 检查变量会不会耗尽。
   - 判停条件: 若所有酬赏都只能靠运营手工上新维持，标记"有限多变性"风险，方案中必须给出结构性出路或降低留存预期。

5. **伦理红线复核**
   - 完成标准: 过 `f18-manipulation-matrix` 两问自查；确认没有用赌博式变量机制针对易感人群制造强迫性使用，酬赏不用于替代产品真实价值。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 产品核心价值不成立时：游戏化元素"是否奏效，完全取决于它们是否能够抓住用户内心的'痛痒'"——没有真实需求，再多的积分徽章都无济于事，只会放大"任务毫无意义"的认知。
- 行动前的文案与说服设计：那属于 f08 的动机杠杆选择，酬赏是行动后的反馈，混用会把"拉人来"和"留住人"做成一回事。
- 一次性工具型产品：计算器、查询工具"用完即走"是正当的，强行塞酬赏只会增加噪音。

### 作者在书中警告的失败模式

- 金钱挤出真动机（ce08，Mahalo 之败）：单纯经济刺激不具备持久吸引力，补贴一停贡献即停、用户公开计算时薪、社区氛围交易化，都是警兆。
- 无的放矢的游戏化（ce12）：先有积分体系后有需求分析；徽章无人炫耀、排行榜头部固化尾部无感——载体无处附着。
- 可预见反馈回路无效（ce06）：冰箱门实验——结果可预料就不会"没完没了地重复"，固定奖励只产生工具性使用。

### 作者的盲点 / 时代局限

- 证据为转引的心理学实验（斯金纳、克努森等）与幸存者案例，2014 年转引、复制危机背景、效应量未验证；"多巴胺=渴望引擎"是当时流行心理学的简化表述。
- 算法推荐时代的适配问题：推荐流让用户无须投入即可获得个性化多变酬赏，三通道之外出现了"算法供给的猎物酬赏"这一本书未描述的形态；AI 对话产品的酬赏同时是猎物（信息）与拟社交（陪伴），三分类边界被挑战。
- 文化外部效度：社交酬赏的形态（公开点赞 vs 匿名威望值）依赖文化规范，书中证据全部来自美国市场。

### 伦理红线（酬赏设计专用）

本 skill 涉及"让用户上瘾"的核心机制，红线必须写明：**酬赏设计不得用于绕过用户自主权、不得制造强迫性使用或病理性依赖**。习惯可以有益，成瘾"最终会使人走向自我毁灭"（L476）——当设计以挤占生活功能、令用户主观失控为目标时，任何酬赏优化都已越线（习惯≠成瘾之辨，g20）；赌博式变量机制对未成年人与易感人群的使用等同成瘾设计。每次落地前过操纵矩阵（f18）两问自查。

### 容易混淆的邻近方法论

- 通用游戏化框架（PBL：点数/徽章/排行榜）：PBL 是载体清单，本书给出的是载体之前的选择规则（对齐动机、社交大于金钱、变量来源），载体本身不是答案。
- `f08-three-core-motivations` 与 `f13-finite-infinite-variability`：分别是酬赏的上游（动机）与下游（变量存续），本 skill 居中，三者构成完整的激励设计链。
