# 维生素→止痛药路径与"无法使用即痛苦"判据

## R — 原文 (Reading)

> "在你确定这些全世界数一数二的科技公司兜售的究竟是维生素还是止痛药之前，请先明确一点：如果你因为无法实施某种行为而感到痛苦，那说明习惯业已形成。"
>
> — 第1章 维生素 vs 止痛药（L468）

> "至于科技公司究竟是兜售维生素还是止痛药，我的看法是二者皆有。科技公司提供的服务在初期更像是锦上添花的维生素，可一旦它成为用户日常生活的一部分，那就会像止痛药一样抚平人们内心的'痒'。"
>
> — 第1章 维生素 vs 止痛药（L472）

> "实际上，我们所要描述的体验更接近于'痒'，它是潜伏于我们内心的一种渴求，当这种渴求得不到满足时，不适感就会出现。"
>
> — 第1章 维生素 vs 止痛药（L470）

---

## I — 方法论骨架 (Interpretation)

投资人问"维生素还是止痛药"时预设这是道单选题，且正确答案永远是止痛药。作者把这个二分拆开重装：对习惯养成类产品，这不是产品属性的二选一，而是同一产品在不同时间点的两种状态——入场时是维生素（可有可无），习惯养成后是止痛药（不可或缺）。

真正值钱的是那条**转变判据**：不看留存曲线，不看用户口头评价，只问一个行为学证据——用户是否在"无法实施这个行为"时感到痛苦。注意作者刻意降调：多数产品安抚的不是剧痛，是"痒"——潜伏的、平时不被觉察的轻微渴求，产品只是比"忍着"更快地挠了它。

这个判据的用法是双向的：向前看，维生素阶段是正当起点而非失败判决，早期数据难看不等于没救，关键是"痒"的联结有没有被建立；向后看，"不用就难受"是习惯已成的金标准，比任何态度数据都硬。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 给 Facebook/Twitter/Instagram/Pinterest 做判别
- **问题**: 投资人和总经理像守门员一样用"维生素还是止痛药"筛选项目，按此标准当红的消费科技公司全都答错——怎么解释它们的价值？
- **方法论的使用**: 作者逐一点名这四家公司：多数人会答"维生素"，因为用户行为不外乎提升社交地位，"没人会在半夜爬起来大呼小叫地更新自己的状态"（L466）。然后用判据反转：只有当服务融入生活后，人们才发现自己多么需要它。
- **结论**: 二者皆有——初期是维生素，成为日常生活一部分后是止痛药；检验标准是"无法实施即痛苦"，不是融资答辩话术。
- **结果**: 这条判据成为全书的机会识别伏笔：第 8 章用它重估新生行为——许多突破性技术和公司"一开始都被评论家们当作玩具或利基市场而嗤之以鼻"（L2246–2248），维生素阶段恰恰是观察者最容易被骗、设计者最该耐心经营的时间窗。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 留存诊断的定性判断：产品上线数月，用户说好但看不到"离不开"的迹象，要判断是结构性没救还是习惯未成、仍在设计窗口。
2. 融资/立项答辩：被投资人问"你这是维生素还是止痛药"，需要知道这个老问题的正确打开方式（阶段论回答 + 判据），而不是硬编止痛药故事。
3. 依赖真实性验证：用户口头上都说喜欢、不愿卸载，但要验证"依赖"是真习惯还是客气话。
4. 新生行为重估：看到被嘲"玩具"的新产品/新行为（自己或别人的），判断该不该因其"维生素相"而否定。
5. 跨域自查（个人习惯）：某个行为"不做就难受"是习惯已成的自查信号（刷牙式习惯 vs 尚在坚持的意志力行为）。

### 语言信号 (用户的话里出现这些就应激活)

- "维生素还是止痛药 / vitamin or painkiller / 我们算刚需还是锦上添花"（nice-to-have vs must-have）
- "用户离不开 / 没有它就难受 / 停不下来 / 断了会难受吗"（can't live without it, painful to stop）
- "痒 / itch / 挠痒 / 伪需求 / 是没救还是没到时候"（itch, pseudo-need, too early or doomed）
- "用户都说好但感觉没人惦记 / 口头喜欢不算数"（users like it but nobody needs it）

### 与相邻 skill 的区分

- 与 `habit-zone-frequency-first` 的区别：f02 向前看，判断该行为**能不能**成为习惯（入场过滤）；f03 向后看，判断习惯**已经成了没有**（证据判据）。频率不足的产品连维生素阶段都熬不到——别拿"维生素阶段"当留存差的借口。
- 与 `internal-trigger-anchoring` 的区别：f03 是检测器（习惯是否形成的证据），f05 是安装器（怎么把情绪和产品绑成反射弧）。"痒"的来源是内部触发——f03 验收，f05 施工。
- 与 `habit-test-three-steps` 的区别：f20 是上线后的定量测量程序（5% 基准 + 习惯路径），可为 f03 的定性判据提供数据佐证；f03 是单一判据的快速判断，不替代测量。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **写出目标行为与中断情境**
   - 完成标准: 一句话描述该产品对应的具体行为（谁、何时、做什么），并设定一个中断测试情境（用户一周用不了会怎样）。

2. **过"痒"判据三问**
   - 完成标准: 逐问给出**行为证据**（访谈原话、使用数据、行为观察），不接受态度数据：
     a. 特定不适出现时，用户会不会**自动想起**产品（没人提醒的前提下）？
     b. 中断使用（度假一周）后，回来是难受还是"也没什么"？
     c. 有没有用户自发的替代/绕路行为（产品坏了时的焦躁、用竞品时的不适感）？

3. **定位阶段并分支**
   - 完成标准: 按判据结果二选一：
     a. 判据未过（维生素期）→ 列出"痒"的来源假设（对应哪条内部触发），转 `internal-trigger-anchoring` / `five-whys-emotional-root` 挖掘施工；明确这是设计窗口而非失败判决。
     b. 判据已过（止痛药期）→ 转保护性动作：防中断、防竞品截胡、防旧习惯回转，别再盲目加功能。

4. **判停条件**
   - 判据已过但使用频率仍在下滑 → 问题不是"习惯没成"而是习惯被替代，查新竞品与使用情境变化，跳过步骤 3a。
   - 行为本身频率不足（一年一两次）→ "痒"判据永远过不了，先回 `habit-zone-frequency-first` 判断路线，本 skill 判停。

5. **输出结论**
   - 完成标准: 给出阶段定位（维生素期/止痛药期）+ 判据证据清单 + 下一步动作（施工/保护/转路线）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 强止痛药产品硬套阶段论：支付、杀毒、报税这类一开始就解决显性痛点的产品，不必从维生素起步，本判据的价值在情感需求类产品。
- 把"维生素阶段"当万能安慰剂：低频行为（与 `habit-zone-frequency-first` 联动）频率不足，永远不会变止痛药——阶段论不豁免频率判据。
- 用态度数据过判据：NPS 高、"用户说喜欢"、不愿卸载都不是"无法实施即痛苦"的证据；判据只认行为。

### 作者在书中警告的失败模式

- "痛苦"概念被滥用的风险：作者明言"痛苦"在商学院讲堂和营销学书籍上"多少有些言过其实"（L470）——别把"痛点"故事讲成剧痛，多数习惯产品安抚的是低烈度的痒；把痒夸大成痛会误导资源分配。
- 把早期流量高峰当习惯已成：回馈型触发带来的销量飙升"很容易使企业盲目乐观，认为这就算大功告成，实则不然"（L604，与 ce02 同源）——维生素期的数据噪声特别容易冒充止痛药证据。
- 习惯与成瘾之辨（L476）："成瘾"是长期且被动的依赖，最终使人走向自我毁灭；"无法使用即痛苦"若伴随失控与伤害，已越过习惯红线，不是本判据要奖励的状态。

### 作者的盲点 / 时代局限

- 循环定义问题（BOOK_OVERVIEW 最强反对意见 3）："痒"被定义为"想用产品时的不适"——若不适感本身是被上一次使用制造的（戒断样反应），模型描述的就不是"满足需求"而是"制造需求再满足它"。用本判据验收时，要区分"原有不适被缓解"与"使用本身制造的不适"。
- 相关不等于因果：Facebook 等案例是幸存者叙事，"维生素→止痛药"的成功路径无法排除"产品本来就有用"的解释（BOOK_OVERVIEW 未证假设 1）——判据能给证据，不能给归因。
- 2014 年消费社交语境：书中判据案例全是社交 App；算法推荐时代"止痛药化"可由可刷性捷径达成（无须用户投入），判据照用，但达成路径已与书中"投入→储存价值"的路径不同。

### 容易混淆的邻近方法论

- PMF（product-market fit）：PMF 问"需不需要"，本判据问"缺了难不难受"；有 PMF 不等于有习惯。
- "真需求/伪需求"二分：作者反用这对隐喻——维生素不是伪需求，是尚未长成的真需求；用阶段论替代真伪二分。
- 痛点（pain point）：痒≠痛点，痒是轻微、常不被觉察的持续渴求；套用 KANO 基本型/兴奋型需求模型时注意"痒"横跨两者。

### 伦理红线

本 skill 判据直接关联"上瘾"边界，红线：**不用于绕过用户自主权的设计**——不得人为制造戒断样不适（先把用户养出"痒"再收要挟性租金）；不得以"止痛药化"为名设计让用户失去控制感的产品；对未成年人不做诱导依赖设计。判据验收出"痛苦"信号后，落地动作必须先过操纵矩阵（`manipulation-matrix`）两问：我会用吗？能否提升用户生活质量？
