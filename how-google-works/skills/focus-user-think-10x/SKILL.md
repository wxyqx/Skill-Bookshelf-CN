# 聚焦用户，往大处想（10 倍思维与注意力纪律）

## R — 原文 (Reading)

> "'聚焦用户'这句话只说了一半，完整的句子应该是：'聚焦用户，一切水到渠成。'" / "如果你要造一款省1/10汽油的车，只需对现行设计做些改动；但如果你想造一款每加仑油可以跑500英里的汽车，那就得从头开始了。"
>
> — 施密特、罗森伯格，第六章《聚焦用户》/《往大处想》

---

## I — 方法论骨架 (Interpretation)

这个 skill 把三条纪律拧成一股：方向对准谁、目标放多大、注意力放在哪。

①**方向：聚焦用户，且先分清用户与客户**。用户是使用产品的人，客户是付钱的一方；两者分离时（运营商定手机规格、采购部门定软件去留），需求信号会被付费方接管——此时永远站使用者，并相信"为用户做对的事，钱会水到渠成"：对用户明显有利的改进，不必等财务模型齐备才放行。

②**量级：把想法放大 10 倍**。省 1/10 汽油的车改改就行，每加仑 500 英里的车必须从头设计——量级一换，渐进思维被强制解除，人被迫回到基本原理推演可行性，而不是用"不可能"提前否决。反面是"一连串输得起的小赌注"：每个团队都做得出"还不错"，于是没有一款必须伟大。附带收益：巨大的挑战本身就是顶尖人才的磁铁。

③**注意力：竞争当燃料不当路标**。盯着对手只能换来渐进改良，半路总会杀出不在乎市场份额的颠覆者；对手的动向可以保持警醒，但立项理由必须来自用户。配套装置是近乎遥不可及的 OKR：关键成果可量化、不含日常工作，全绿=定低了，完成 70% 胜过松垮的 100%，打分只用于诚实自评——注意力锁进自设的目标，就无暇被竞争者牵着走。

## A1 — 书中的应用 (Past Application)

### 案例 1: 必应来袭，谷歌没有跟
- **问题**: 2009 年微软发布必应搜索引擎，跟不跟？
- **方法论的使用**: 把竞争当保持警醒的燃料而非路线图，将全部努力投向自家引擎的加强，而非模仿必应。
- **结论**: 竞争对手可以促使你前进，但注意力应放在用户与自己产品的改善上。
- **结果**: 催生 Google Instant（输入即显结果）、以图搜图等新功能，搜索质量再上台阶（c40）。

### 案例 2: 收购锁眼——商业模式的问题"压根儿没想过"
- **问题**: 谢尔盖提议收购地图初创公司锁眼（Keyhole），董事会追问"如何从这项技术中获利"，连产品负责人也答不上来。
- **方法论的使用**: 基于产品与用户潜力拍板收购，把赢利问题后置。
- **结论**: 聚焦用户，赢利水到渠成。
- **结果**: 约 8 个月后谷歌地球问世并大受欢迎，随后被桑达尔·皮查伊找到可观变现路径（c73）。

### 案例 3: 反面——摩托罗拉的"客户"不是用户
- **问题**: 收购摩托罗拉后，产品评估会上反复出现"客户需求"，却与手机使用者的真实需求相去甚远。
- **方法论的使用**: 追问之下发现其"客户"是威瑞森、AT&T 等运营商而非使用者；对照谷歌"两者冲突时以用户利益为重"的准则。
- **结论**: 不先回答"你的用户是谁"，聚焦就无从谈起；为付费方做产品的企业难有卓越产品。
- **结果**: 印证摩托罗拉的衰落逻辑，2014 年谷歌将其转售联想（c74，另见 ce52）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 团队提案"竞品上了某功能我们也得上"，需要判断该不该跟进。
2. 制定季度/年度目标（OKR），人人写的目标都"有把握完成"，想知道多激进才对。
3. 付费方（客户/渠道/采购方）与实际使用者的需求冲突，需要站队依据。
4. 产品方向讨论陷入渐进改良（"留存再提几个点""加个功能"），需要被逼着重想量级。
5. 评估一个"登月式"大想法值不值得立项。

### 语言信号 (用户的话里出现这些就应激活)

- "竞品都做了我们也要做 / 被对手牵着走 / 别人有的我们不能没有"
- "用户要的和付费的客户要的不一样 / 听谁的"
- "把目标放大10倍 / think 10x / moonshot / 登月项目 / 想得不够大"
- "OKR 全绿 / 目标定低了 / 完成 70% 也好过 100%"
- "渐进优化还是从头设计 / 赌注下大点还是下小点"

### 与相邻 skill 的区分

- 与 `technical-insight-first` 的区别：那个回答"凭什么做成"（技术洞见是根基与第一道过滤器），本 skill 回答"为谁做、做多大"（方向与量级）。先有洞见再放大，所以 depends-on；缺洞见的大想法只是浪漫。
- 与 `resource-70-20-10` 的区别：本 skill 定方向与目标量级；那个把定好的方向切成 70/20/10 的资源比例。先有 10 倍目标，再谈往哪个桶里放多少钱。
- 与 `innovation-chaos` 的区别：那个管"创意从哪来"（不可指派、给自由空间），本管"方向选什么、目标定多大"。
- 与 `ask-hard-questions` 的区别：那个是组织自检与危机感提问（"5 年后可能会怎样"），本 skill 是具体产品/目标的方向纪律。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **辨用户，定标尺**
   - 完成标准：写出"谁在用、谁在付钱"各是谁；若分离，明确冲突场景站使用者。为核心产品定义一组可感知的标尺（谷歌的五把标尺是速度、准确、好用、全面、新鲜——替换成本产品的对应项），后续讨论对齐标尺而非对齐竞品。
   - 判停条件：若用户与客户统一、讨论只关乎执行排期 → 本 skill 价值有限，转常规规划。
2. **审查注意力指向**
   - 完成标准：把提案中所有"竞品已经/对手正在"改写为用户侧语言；竞品信息只用于警醒（要应对就必须吃透对方的技术洞见与打法，无视只短期有效），不作为立项理由。
3. **放大 10 倍重写目标**
   - 完成标准：用"每加仑 500 英里"式问句把目标重写一次；量级切换后方案必须"从头设计"才成立，只靠加功能达成的说明仍是渐进；可行性用基本原理推演，禁止用"不可能"提前否决。
4. **过登月三圆过滤器**
   - 完成标准：大挑战（影响数亿人）、方法与现存方案截然不同、技术近期可行——三项各写一句论证，且目标市场足够大（勿在无人问津处孤军奋战）；缺任一项就降级为普通迭代，不冒充登月。
5. **用 OKR 锁定注意力**
   - 完成标准：关键成果可量化、不含日常工作；自评全绿即判定目标定低了、重设；打分只用于诚实自评、不挂薪酬考核。若方案只是几个互不威胁的小赌注，回到第 3 步重来（赌注悖论）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **纯竞品调研/市场信息查询**——需要的是信息汇总，不是方向纪律；强行套用会把情报工作变成布道。
- **合规、安全、资金安全等不可试错的底线问题**——赌注悖论不适用于拿生存与合规试错的场景。
- **缺技术洞见支撑的"大想法"**——先过 `technical-insight-first`，否则"放大 10 倍"只是放大浪漫。

### 作者在书中警告的失败模式

- 摩托罗拉机海战术：几十款机型按人群细分各自做到"还不错"，没有一款必须伟大——一连串互不威胁的小赌注的归宿是平庸（ce51）。
- 摩托罗拉的"客户"是运营商：付费方定义需求，用户声音没有制度入口，产品能力退化为"满足渠道"（ce52）。

### 作者的盲点 / 时代局限

- "聚焦用户，一切水到渠成"以 AdWords 印钞机为前提（幸存者偏差）；现金流紧张的组织照搬"先不问钱"，可能先于"水到渠成"而破产。
- 书中正面范例并非都经得起时间检验：Google+（自下而上的最大赌注）2019 年关停、谷歌眼镜未能大众化——"往大处想"不保证"成"。
- "把想法放大 10 倍"出自拉里本人——与"别听河马的话"存在未调和的张力：10 倍指令也可能只是一句河马发言，量级要求仍需论据检验。

### 容易混淆的邻近方法论

- 精益创业/MVP：本书不反对小步迭代，反对的是用"一连串安全的小赌注"替代大方向——两者分层使用而非互斥。
- BHAG（柯林斯式宏伟目标）：方向相近；本书独特在"放大 10 倍=从头设计"的量级论证与"OKR 全绿=定低了"的自检判据。
- 蓝海战略：方向相反——本书明确要求去大市场，"勿在无人问津处孤军奋战"。
