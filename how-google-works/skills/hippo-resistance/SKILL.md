# 别听河马的话（HiPPO 抗性：让数据与论据说话）

## R — 原文 (Reading)

> "从本质上来讲，薪金的高低与决策能力完全无关。……如果把'河马'的声音屏蔽掉，有价值的观点就会受到重视。" / "我们不希望以'我觉得'这句话来服人，而是用'请看数据'这句话来服人。"
>
> — 施密特、罗森伯格，第一章《别听"河马"的话》/ 第四章《用数据做决策》

---

## I — 方法论骨架 (Interpretation)

会议室里有一个隐形的权重分配器：谁薪水最高，谁的意见分量就越重——这个现象被命名为 **HiPPO（Highest-Paid Person's Opinion，河马）**。它的危害不是"领导错了"，而是双向的：决策质量随发言者的职级（而非论据质量）分配；同时让掌握事实的人闭嘴，会议沦为表态会。

抗性机制有三条。①**以数据开场**：会议用公布数据作为开场，让所有人先站在同一份事实面前；幻灯片是数据的载体，不是论点的主宰。②**质疑是义务**："如果员工对某个问题存在疑义，就必须把自己的顾虑提出来"——把它写成硬性规定而非可选项，沉默即失职；论据要针对观点而非职位。③**信赖一线**：最了解数据的是工作在第一线的员工，而不是管理层——话语权应向离事实最近的人倾斜。

组织设计是配套防线：扁平结构（见 `org-design-rules`）让管理者无法远离一线数据，从源头削弱河马的"信息霸权"。

## A1 — 书中的应用 (Past Application)

### 案例 1: 斯里达尔对谢尔盖说"不"
- **问题**: 创始人谢尔盖（全场最高薪的"河马"）提出一个构想，产品负责人斯里达尔怎么接？
- **方法论的使用**: 斯里达尔以论据不足为由拒绝，把争论拉回事实层面。
- **结论**: 河马被论据而非职位说服，最终让贤。
- **结果**: 谷歌内部形成"谁有理听谁"的示范案例（c17）。

### 案例 2: 角落里的年轻女员工
- **问题**: 大人物云集的合作伙伴会谈，如何让讨论不被身份主导？
- **方法论的使用**: 让资历最浅的年轻女员工开场讲数据——数据不针对个人，最无资历者获得话语权。
- **结论**: 数据开场天然屏蔽职级权重。
- **结果**: 会议被几项数据主导，决策效率提升（c55）。

### 案例 3: 反面——"年资制"企业
- **问题**: 河马一言九鼎的公司是什么样？
- **方法论的使用**: 作者对照"年资制（tenurocracies）"企业：有数据的一方噤声。
- **结论**: 不设抗性机制，决策质量随"职级与实情的距离"下降（ce11）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 设计评审会/产品评审/架构评审的规则，担心"领导一开口就没讨论了"。
2. 复盘一次失败决策，发现"其实一线早就知道，但没人敢说"。
3. 组织里年轻同事/基层员工有数据有论据，但不敢或不愿在会上说。
4. 要主持一场有大老板在场的会议，想让讨论基于事实而非表态。
5. 制定会议规范（开场方式、发言顺序、质疑规则）。

### 语言信号 (用户的话里出现这些就应激活)

- "领导一说话就没人敢反驳 / 一言堂 / 拍脑袋"
- "会上没人说真话 / 都在附和"
- "以数据开场 / data-driven / 用数据说话"
- "年轻人有好想法但不敢提 / 基层的声音传不上去"
- "HiPPO / 河马 / 最高薪者的意见 / obligation to dissent"

### 与相邻 skill 的区分

- 与 `real-consensus` 的区别：本 skill 解决"谁的意见有权重"（权力对讨论的污染）；那个解决"如何达成真共识"（讨论的组织方式）。会议规则通常两个一起用：先防河马，再走共识。
- 与 `default-open-candor` 的区别：那个是组织级的信息透明与讲真话的安全环境（文化底座）；本 skill 是会议级的具体抗性机制。
- 与 `expel-villains-protect-stars` 的区别：河马不是恶棍——河马可能是好人，只是职位带来的权重扭曲了讨论；不要用整人的方式解决会议结构问题。

## E — 可执行步骤 (Execution)

1. **识别河马场景**
   - 完成标准：指出这次会议/决策中谁是事实上的河马，以及上次讨论被其权重扭曲的具体时刻。判停条件：与会者职级平坦、无隐形权力差 → 无需本 skill，直接进入正常讨论。
2. **改为数据开场**
   - 完成标准：会议前 10 分钟由最接近一线的人公布数据（而非最高职级者定调）；幻灯片只承载共享数据，不承载结论。
3. **把质疑写成义务**
   - 完成标准：会议规则明文"有疑义必须提出"；每条反对意见附数据或事实；主持人在收尾前主动点名尚未发言的人（沉默=失职，要给台阶而不是追责）。
4. **裁决只认论据**
   - 完成标准：决策记录中每条采纳/否决的理由都指向数据或事实，不出现"因为××总说/资历深"；河马最后表态而非最先表态。
5. **复盘权重污染**
   - 完成标准：回看决策记录，若结论与一线数据相悖且无法解释，归因到机制（谁先说话、数据有没有进场）而非个人，修正下一次会议规则。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **紧急事故处置**——指挥链清晰是救火的前提，"谁的职级高听谁的"此时是特性不是缺陷。
- **纯愿景/审美拍板**——创始人对方向的直觉本就允许主观，强行"拿数据来"会制造虚假的客观性。
- **数据尚未存在的全新领域**——先用小实验造数据，而不是在空数据上互喷"请看数据"。

### 作者在书中警告的失败模式

- 河马一言九鼎的"年资制"企业：有数据的一方噤声，决策质量随职级与实情的距离下降（ce11）。
- "摇头娃娃"式附和：表面点头掩盖虚假一致（ce34，与 `real-consensus` 共用边界）。

### 作者的盲点 / 时代局限

- 书中案例全部来自谷歌式高利润、高人才密度环境；在层级文化根深蒂固、职业安全感低的组织里，"质疑是义务"若没有配套的心理安全与免责机制，执行会走形。
- 本 skil 解决"发言权重"，不解决"发言资格"——谁该在这间屋子里，是 `hiring-quality-bar` 与组织设计的问题。

### 容易混淆的邻近方法论

- Amazon 的" disagree and commit"：结论相近，但本书把重心放在**会前与会中**（数据开场+质疑义务），而不是会后服从。
- 数据驱动决策（data-driven decision）：泛指用数据；本书的独特处是把"数据"与"发言权分配"绑定——数据是反河马的工具，不只是决策输入。
