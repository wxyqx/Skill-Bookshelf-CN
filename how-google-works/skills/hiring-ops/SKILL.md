# 招聘组织化（全员出动 / 招聘委员会 / 30 分钟面试）

## R — 原文 (Reading)

> "谷歌特地成立了招聘委员会来做招聘决策……委员会的决策以数据为根据，而不看谁的关系硬或谁说话算数。" / "有谁规定面试时间必须要持续一个小时？走进面试现场不过几分钟，你往往就能判断出应聘者于这家公司和这项工作都不适合。……正因如此，谷歌的面试只有半个小时。"
>
> — 施密特、罗森伯格，第三章《设立招聘委员会》/《将面试时间设为 30 分钟》

---

## I — 方法论骨架 (Interpretation)

这套流程回答一个问题：**为什么录用不能由用人经理一人拍板**。因为层级招聘有内生缺陷：直接上司的个人利益（面子、晋升）与组织利益（得到更强的人）错配，于是每一层都在系统性地招进比自己弱的人。解法是把决策去利益相关化，四件套：

①**招聘委员会定夺**：4-5 名背景多样、以公司利益为唯一出发点的成员按数据表决；用人经理只有一票否决权，没有决定权，且需回避亲故；升职决策同理交委员会。②**信息包是唯一依据**：标准化、120 秒可读完；每条结论必须附具体事实，无事实支撑的意见不进包；包外内容（会上的口才、私下留的"必杀技"）一律不予考虑。③**面试的硬参数**：30 分钟一场、至多 5 位面试官（4 轮之后每加一人，准确度提升不足 1%）、面完立刻反馈；面试官必须亮明立场——中庸的骑墙分是推卸责任。④**全员出动**：物色人才人人有责，举荐与面试表现计入考核；面试官经培训+陪面才有主持资格，把面试从人人逃避的杂货变成特权。

配套纪律：因机制制约而扬言离职的管理者，不用也罢。

## A1 — 书中的应用 (Past Application)

### 案例 1: 招聘委员会的缘起
- **问题**: 谷歌大量引才后发现部分新人能力与预期存在差距；层级招聘制让经理不敢招比自己强的人。
- **方法论的使用**: 参照美国大学教职评审建立招聘委员会（4-5 人、数据化信息包、经理仅保留否决权）；顶层设拉里的"一人委员会"终审每份录用。
- **结论**: 录用决策必须与私人利益脱钩，为质量而非效率设关卡。
- **结果**: 员工超 4.5 万人后仍坚持"没有什么比招聘质量更重要"（c50）。

### 案例 2: 30 多轮面试的失策与流程再设计
- **问题**: 刚加入谷歌时对一位应聘者面了 30 多轮仍下不了决心；面试又沦为没人爱干的杂活，反馈拖延。
- **方法论的使用**: 按数据设限（4 轮后边际提升不足 1% → 5 位封顶、30 分钟一场）；建面试官委员会，按面试次数、可信度、反馈质量与速度评分，允许挑战者取代在任者。
- **结论**: 用硬参数终结"再多看一个人"的拖延，用特权化解决面试动力问题。
- **结果**: 面试流程标准化，面试质量全面提升（c49）。

### 案例 3: 同一原理的跨章复现——数据主导的会议
- **问题**: 与合作公司 CEO 会谈，高管们为技术问题争论不休，谁说了算？
- **方法论的使用**: 资历最浅的年轻谷歌人用几项数据明确立场——决策由数据与事实主导，而非由职位主导。
- **结论**: 这正是招聘委员会"以数据为据、不看谁说话算数"的原理在会议场景的复现。
- **结果**: 讨论由数据与洞见主导（c55）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 设计或改革公司招聘流程：offer 谁拍板、几轮面试、多久一场。
2. 面试轮数失控、反复"再加一轮"，候选人快被别家抢走。
3. 面试官反馈全是"感觉不错""挺聪明"，没有一个具体例子，决策会吵成一团。
4. 用人经理与 HR/招聘官争录用决定权，或高管想插手指定人选。
5. 面试官集体打中庸分、无人愿意为判断署名；想推动全员内推但没人动。

### 语言信号 (用户的话里出现这些就应激活)

- "招聘委员会 / hiring committee / offer 谁说了算 / 用人经理拍板还是 HR"
- "面试几轮合适 / 面试多久 / 30 分钟 / 5 位面试官 / 面了七八轮"
- "面试反馈写不出来 / 都是'感觉不错' / 没有具体例子 / 打分都差不多"
- "全员招聘 / 内推没人动 / 招聘 KPI 怎么定"
- "面试官不想面 / 面试是杂活 / 谁来当面试官"

### 与相邻 skill 的区分

- 与 `hiring-quality-bar` 的区别：本 skill 管"决策权结构与流程参数"（谁定、几轮、多久、依据什么）；那个管"标准多高、拿不准怎么办"。流程是质量律的保障装置，所以 depends-on。
- 与 `talent-portrait` 的区别：本管流程与权责；那个管面试的内容设计（问什么问题、看什么信号）。
- 与 `decision-timing-discipline` 的区别：30 分钟/5 位上限本质是决策时限纪律在招聘场景的复现；若用户的痛点是通用决策拖延机制（响铃/80-80/PIA），转那个。
- 与 `real-consensus` 的区别：委员会按规则与数据表决，不追求人人同意——不要把招聘委员会开成共识会。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **收走决定权**
   - 完成标准：录用决策明确归属 4-5 人、背景多样、与该岗位无汇报/亲故关系的委员会；用人经理只有一票否决权；因制约而扬言离职的管理者按"不用也罢"处理。
   - 判停条件：若争议其实是"该不该降低标准/要不要将就" → 转 `hiring-quality-bar`。
2. **定流程硬参数**
   - 完成标准：单场面试 30 分钟、至多 5 位面试官（4 轮后每增一人准确度提升不足 1%）、面完立刻反馈；"再加一轮"式拖延被明文禁止，每轮追加必须给出新的信息理由。
3. **建信息包**
   - 完成标准：每位候选人一份标准化信息包，120 秒可读完；每条结论附具体事实，无事实支撑的意见不进包；包外信息一律不予考虑。
4. **强制表态**
   - 完成标准：每位面试官只给 hire / no-hire 加事实辩护；中庸骑墙分视为失职；委员会每条采纳/否决都有事实依据，决策不靠分数平均。
5. **全员出动与面试官特权化**
   - 完成标准：举荐与面试次数、反馈质量计入绩效考核；面试官经培训+陪面后才有主持资格，资格稀缺化（"得不到主持面试的机会本身就是一种惩罚"）；升职决策同样交委员会。小团队最小实现：2 位与岗位无利益相关的同事 + 同一信息包 + 独立结论（推演，非书中原文）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **彼此共事多年、互相知根知底的创始合伙人遴选**——决策天然去利益相关，委员会的形式成本高于收益。
- **薪酬谈判、背调、入职手续等事务**——流程之外的话题，套流程解决不了。
- **绩效不达标者的处理与裁员**——那是留汰范畴（`retention-playbook`），不是录用流程；用流程掩盖入口错误是方向性错位。

### 作者在书中警告的失败模式

- 层级招聘制：录用权在直接上司手里时，"招比自己强的人"败给人性，每层都在系统性地招弱者（ce22）。
- 30 多轮面试：以"再多看一人"化解决策犹豫，边际信息不足 1%，候选人被别家抢走（ce28）。
- 集体 3 分骑墙：人人不置可否=无人负责，平庸者靠平均分通过（ce29）。
- 把招聘完全委派给招聘官：招聘官按交差逻辑拿平庸者充数，奇才从未进入漏斗——全员出动是它的解药（ce32）。

### 作者的盲点 / 时代局限

- 委员会+信息包是重装备：书中未给小型组织的最小可行版本（E 段第 5 步的"最小实现"是下游推演）；招聘量小的公司照搬会付出形式成本。
- 每个录用都过委员会与第四章"少做决策"存在时间张力；委员会本身也可能沦为新的官僚节点。
- 4.5 万人的谷歌有品牌与利润引擎兜底；雇主品牌弱的公司"全员出动"的杠杆有限（幸存者偏差）。

### 容易混淆的邻近方法论

- 亚马逊 Bar Raiser：同构（跨部门制衡一票）；本书独特在信息包唯一依据、面试官委员会特权化、升职决策也交委员会。
- 招聘流程外包（RPO）：本书立场相反——招聘必须内化为全员职责，外包给招聘官会导致平庸充数（ce32）。
