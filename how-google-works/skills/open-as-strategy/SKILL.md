# 开放为王与选择封闭的前提

## R — 原文 (Reading)

> "我们可以将开放当作一种战略措施，问问自己：开放能否帮助扩张业务和赚取收入？" / "如果用户可以轻松选择退订你的服务，那么你就得付出努力，让他们愿意继续留下来。"
>
> — 施密特、罗森伯格，第二章《开放为王》/《选择封闭系统的前提》

---

## I — 方法论骨架 (Interpretation)

这个方法论先把一个被道德化的话题拉回生意场：**开放与否无关善恶，是一道可计算的战略选择题**，唯一的问题是"开放能否帮助扩张和收入"。

**开放是默认项**，因为它带来四种收益：用控制权换规模与创新、吸收全球最聪明的头脑（他们大多在为别人效力）、降低互补元素的成本、对创意精英展示公平的竞争环境。

**封闭是例外**，且只有两个合法前提：一是产品有明显的技术洞见优势、又身处高速发展的新兴市场——这时不开源也能快速成长（苹果 iOS、早期的谷歌搜索）；二是开放会实质损害质量或用户利益（搜索算法公开反被操纵）。两个前提都不成立还坚持封闭，动机通常是 MBA 式的"关闭城门、严防死守"——省力但放弃生态。

**一条反锁定条款贯穿两种选择**：给用户随时退订的自由。不用切换成本留人，逼自己靠产品优势赢得忠诚——这几乎没有企业照做，是本书真正反直觉的操作规则。慷慨分成（让合作伙伴多拿）是同一家族的动作：短期让利换扩张。

## A1 — 书中的应用 (Past Application)

### 案例 1: 安卓开放决策——鲁宾要封闭，谢尔盖要开放
- **问题**: 2005 年收购安卓后，系统应开放还是封闭，高管各执己见。
- **方法论的使用**: 谢尔盖论证：开放能帮谷歌在四分五裂的手机操作系统市场快速扩张——正是"能否助扩张与收入"这一问。
- **结论**: 谷歌没有非同寻常的封闭资本，选开放；同年苹果凭 iOS 的洞见优势选封闭，也赢了。
- **结果**: 安卓成为市场领先的手机操作系统，封闭与开放在各自前提下同时成立（c39）。

### 案例 2: Netflix 百万美元大奖赛
- **问题**: Netflix 内部人员商量不出更好的推荐算法。
- **方法论的使用**: 把 1 亿条匿名评分的专有数据公开，设 100 万美元奖金办开放竞赛，成绩榜公开。
- **结论**: "世界上最精明的人才大多都在为别人效力"——开放能把成千上万人的头脑为你所用。
- **结果**: 三年内找到比原算法准确 10% 以上的解法（c38）。

### 案例 3: Map Maker 与用户翻译——开放给用户共创
- **问题**: 加州工程师不懂小语种翻译，许多地区没有完备地图。
- **方法论的使用**: 把翻译开放给志愿者，研发 Map Maker 让任何人完善地图信息（核实后收录）。
- **结论**: 用户即生产力；开放的集体智慧能低成本解决大规模问题。
- **结果**: 草根制图者两个月绘出巴基斯坦境内 25000 公里道路（c85）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 决定 API/SDK/代码/数据集要不要开放或开源，内部吵成"命根子不能交出去"与"不开放在等死"两派。
2. 战略会上争论护城河：靠锁定用户与标准，还是靠生态与产品优势。
3. 设计产品的退订、注销、数据导出与迁移政策，法务/增长主张抬高退出门槛。
4. 与合作伙伴谈分成与接入政策，纠结让利比例。
5. 有人把"开放"当道德正确或公关口号，有人把"封闭"当落后，需要一个去道德化的决策框架。

### 语言信号 (用户的话里出现这些就应激活)

- "开源 / 开放平台 / open source / open API / 开放生态 ecosystem"
- "封闭 / 护城河 / moat / 城墙花园 / walled garden / 锁定 lock-in"
- "切换成本 / 退订 / 注销 / 数据导出 / 迁移走"
- "要不要开放我们的核心引擎/数据"
- "开放是不是道德问题 / 开放等于正确吗"

### 与相邻 skill 的区分

- 与 `default-open-candor` 的区别：中文都叫"开放"，最容易抢调用——那个是**组织内部**的信息共享与讲真话的安全环境（信息怎么流）；本 skill 是**产品、代码、平台层面**的战略选择（生意怎么做）。"公司该不该透明"找前者，"产品该不该开源"找本 skill。
- 与 `technical-insight-first` 的区别：封闭前提①"明显技术洞见优势"要先过洞见之问——本 skill 消费它的结论，两个 skill 串联而非二选一。
- 与 `focus-user-think-10x` 的区别：退订自由的用户立场与那个相通，但那个管方向与量级，本 skill 管分发与生态策略。

## E — 可执行步骤 (Execution)

1. **去道德化，转译为一问**
   - 完成标准：把"我们应不应该开放"改写为"开放能否助扩张与收入"，列出开放收益清单（换规模、吸收外部头脑、降低互补成本、吸引创意精英）与封闭收益清单。
2. **检验封闭前提①：洞见优势 + 高速新兴市场**
   - 完成标准：用"请阐述你的技术洞见"检验产品是否有明显优势；确认市场是否仍在高速成长。两项同时成立才可考虑封闭。
3. **检验封闭前提②：开放是否损害质量**
   - 完成标准：回答"公开后会不会实质损害产品质量或用户利益"（如搜索算法类）；给出证据而非直觉。
   - 判停条件：前提①②均不成立 → 选开放，进入第 4 步；任一成立 → 可选封闭，仍执行第 5 步。
4. **设计开放的形状**
   - 完成标准：明确开什么（代码/数据/标准/大奖赛/用户共创）、对谁开、怎么核验质量；涉及合作方时评估慷慨分成（让利换扩张）的空间。
5. **反锁定自检**
   - 完成标准：无论选哪边，回答"用户能随时轻松退订并带走数据吗"；若退订方案被拒，指出这是在用切换成本而非产品优势留人，要求重议。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **组织内部的信息公开问题**——"项目坏消息该不该让全员知道"是 `default-open-candor` 的领地，与本 skill 无关。
- **把开放当公关姿态**——道德光环至多是副产品，把它当决策依据就违背了本 skill 的第一原则。
- **开放直接违反隐私承诺或法规**——合规与用户利益红线优先于战略计算，先排除再谈开放。

### 作者在书中警告的失败模式

- "关闭城门"的默认思维：把锁用户、封标准当战略默认项，封闭换来的短期控制权以生态吸引力为代价——AT&T 固话网封闭多年毫无创新，被迫开放后才出现传真机与调制解调器（ce09）。

### 作者的盲点 / 时代局限

- 书中开放案例均为赢家叙事（安卓、Map Maker），存在幸存者偏差：开放并不自动带来胜利，生态碎片化、监管与反垄断等变量书中未充分讨论（BOOK_OVERVIEW 批判节）。
- "给用户随时退订的自由"以产品确有优势为前提；产品平庸时，反锁定条款会加速流失——这不是缺陷，但使用者需自知。

### 容易混淆的邻近方法论

- `default-open-candor` 的"开放"：同词不同层——信息透明 vs 战略开放，中文语境必然撞车，靠"对象是组织还是产品"切分。
- 平台网络效应理论：解释为什么开放常赢；本书独到处是给出封闭的两个合法前提与"退订自由"这一反锁定操作条款。
