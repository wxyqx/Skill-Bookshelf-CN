# 共识的真正含义（共识≠人人同意：挺身支持）

## R — 原文 (Reading)

> "'共识'并不是指人人都必须同意，而是指共同达成对公司最有利的决策，并围绕决策共同努力。" / "如果会议上所有人一致点头，这并不意味着大家意见一致，而只是说明你下面坐了一群'摇头娃娃'。"
>
> — 施密特、罗森伯格，第四章《共识的真正含义》/《谨防"摇头娃娃"的附和》

---

## I — 方法论骨架 (Interpretation)

这套方法论纠正一个普遍误读：共识不等于全票通过，也不等于举手表决的多数。真正的共识有两个组成部分——过程上人人充分发言（分歧被逼到台面上），结果上人人愿意挺身支持（即使自己的方案输了）。

三条机制把"共识"从表态变成流程：

- **负责人最后亮立场**：开场表态等于给讨论定调，之后只会收到附和；主持者的任务是抛开职位差异鼓励每个人发言。
- **点名沉默者**：三缄其口的人是最大风险源，异议必须赶在决策期限逼近前"现形"，否则它会在执行期以消极怠工的形式回来。
- **拍板后修复败方**：论据再扎实也不足以让聪明人接受自己不同意的决定，还要动之以情——先肯定败方论点中确实可取的部分（"你们两边说得都对"往往也是事实），再给两条明路：保留异议执行，或公开向上申诉；不允许的只有"走廊里反对"。

靶心是"对公司最有利的正确决策"，而不是为凑一致同意而稀释出的最低标准，也未必是领导自己的偏好。反面教材是"摇头娃娃"：会上以相同步调点头，会后牢骚满腹、不去执行。

## A1 — 书中的应用 (Past Application)

### 案例 1: 谷歌退出中国的周日会议
- **问题**: 2009 年底谷歌遭高级黑客攻击（波及 Gmail 账号），是否撤出中国是全书最艰难的战略决策。
- **方法论的使用**: 埃里克在周日下午 4 点召开紧急会议，让全员充分讨论并投票，把分歧全部摆上台面，而非由高层先定调。
- **结论**: 当晚 9 点达成共识——暂不立即撤出，并以最大透明度公开攻击事件；持异议的埃里克本人转向执行。
- **结果**: 2010 年 3 月关闭 Google.cn 搜索，流量转向香港站点；决策过程让全员理解并接受这个代价沉重的选择（c54）。

### 案例 2: "这是作恶"——拍桌叫停利润提案
- **问题**: 一项可能带来丰厚利润的广告体制改动摆上桌面。
- **方法论的使用**: 一位工程负责人当场拍桌："这是在作恶，这事我们不能做！"——像丰田的安灯绳一样，质疑作为义务即时生效，全场围绕该异议展开讨论后提案被否决。
- **结论**: 异议不因利润诱惑而豁免：让质疑畅通是共识流程的原料，"提出疑义是义务，不质疑等于失职"。
- **结果**: 提案被否决；"人人可用道德指针叫停决策"被固化为文化（c29）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 决策"全票通过"，但执行期各部门打折扣、走廊里全是牢骚——典型的摇头娃娃后遗症。
2. 要主持一场重大决策会，自己心里已有倾向，想让真实意见都摆出来而不是都顺着说。
3. 团队讨论"要不要追求人人同意"：有人提议投票表决、少数服从多数，有人要求一致同意。
4. 拍板之后败方不服：消极配合、私下抱怨、架空决议。
5. 异步/远程协作中评审零反对、执行期全是抵触（成排无理由的 LGTM）。

### 语言信号 (用户的话里出现这些就应激活)

- "会上都同意、会后不执行 / 点头娃娃 / 虚假一致"
- "全票通过 / 没人反对反而慌 / 走廊里全是反对"
- "怎么让输了的人也支持决定 / disagree and commit / 挺身支持"
- "要不要投票表决 / 少数服从多数 / 共识是不是人人同意"
- "obligation to dissent / 质疑的义务 / 让异议早现形"

### 与相邻 skill 的区分

- 与 `hippo-resistance` 的区别：那个解决"谁的意见不该有权重"（职位对讨论的污染），本 skill 解决"讨论如何组织成真共识"（流程）。口诀：问题是"领导一开口就定"→ hippo；问题是"都点头但没有共识"→ 本 skill。一场像样的决策会通常先防河马、再走共识。
- 与 `decision-timing-discipline` 的区别：那个管"讨论什么时候结束"（响铃），本 skill 管"讨论的质量"（异议是否真实现形）。议而不决去那边，点头而不执行来这边。
- 与 `default-open-candor` 的区别（本 skill 依赖它）：那是文化底座——敢不敢讲真话的安全环境；本 skill 是决策会上的流程动作。没有心理安全，"点名沉默者"只会收获表演性发言。

## E — 可执行步骤 (Execution)

1. **审视"一致"的真伪**
   - 完成标准：对照摇头娃娃警报——本次决策里还有谁没发言、谁负责的环节会受阻于该决定；能具体点出尚未现形的异议来源。判停条件：异议已公开且经过交锋 → 跳到步骤 3。
2. **逼出异议**
   - 完成标准：负责人藏起自己的倾向、最后表态；主动点名未发言者——每个人要么说出"同意，因为 X"，要么指出一处风险；每条关键干系人的立场都留下记录。
3. **按靶心拍板**
   - 完成标准：结论对照"对公司最有利"而非最低标准的折中或领导偏好；决策记录写明结论与理由，理由指向事实而非职级。
4. **情感修复 + 两条明路**
   - 完成标准：先肯定败方论点中确实可取的部分（"你们两边说得都对"），再让每位败方明确选一条：保留异议执行，或公开记录反对理由向上申诉；不允许停留在"走廊反对"状态。
5. **复查挺身支持**
   - 完成标准：设执行检查点回看；若决议被消极执行，回溯是哪一步漏了异议（没点名？领导先表态？败方没被接住），修正下一次的共识流程而非只追责个人。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **紧急事故处置**——没有时间走全员发言流程，先按指挥链止损，事后复盘再补共识。
- **琐碎、可逆的小决定**——共识流程的开销（会议、点名、记录）远超收益。
- **纯愿景/审美拍板**——创始人对方向的直觉本就允许主观，强行"人人发言"制造虚假的民主。
- **试图用投票或一致同意替代共识的场合**——本 skill 恰恰要反对"举手表决式共识"，别把它的机制当成表决仪式。

### 作者在书中警告的失败模式

- ce34 摇头娃娃式附和：会上点头、会后牢骚、执行版本与会议版本完全脱节——附和是职场低风险策略，没有强制异议机制时点头只是礼貌而非承诺。
- ce35 负责人先亮立场：议题从"什么是对的"变成"如何同意领导"，反对意见转入私下渠道。
- "最低标准折中"：竭力争取大家一致同意而稀释出的决策，往往谁都不同意（p132 的靶心警告）。

### 作者的盲点 / 时代局限

- BOOK_OVERVIEW 批判指出："共识"决策与"少做决策"之间存在作者未调和的张力——共识流程消耗的是高管时间，谁的时间够用？在会议密集型组织照搬"全员发言"会拖垮日历（时限问题归 `decision-timing-discipline`，但张力本身未被作者解决）。
- 书中案例全部来自高心理安全、高人才密度的谷歌；在职业安全感低的组织里，"点名沉默者"若被感知为抓典型，会适得其反——所以本 skill 依赖 `default-open-candor` 先行。

### 容易混淆的邻近方法论

- Amazon 的 "disagree and commit"：口号已被普及，本书独特在另一半机制——分歧义务化（不质疑=失职）、负责人最后表态、点名沉默者、败方情感修复与公开申诉通道。
- 一致同意/投票制（consensus 的常见误读）：本书明确把"人人同意"排除在共识定义之外。
