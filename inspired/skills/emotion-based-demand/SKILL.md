# 情感需求分析（恐惧·贪婪·欲望）

## R — 原文 (Reading)

> "消费者购买产品大多源于情感需求。优秀的产品经理和销售人员明白其中的道理，懂得产品应该满足用户的情感需求。企业级消费者出于恐惧和贪婪购买产品：如果不买这款产品，竞争对手会超过我，黑客会攻破我的防火墙、客户将弃我而去；如果买了，我会赚得更多、省得更多。"
>
> — Marty Cagan，第34章《恐惧、贪婪、欲望》

---

## I — 方法论骨架 (Interpretation)

产品经理谈需求时习惯列功能、比参数，作者把这件事翻了个面：掏钱的决定多数由情感做出，产品工作的底子是心理学。这套分析分三步走。

第一步，按买家类型识别情感。企业级客户为恐惧与贪婪买单——怕被对手超过、怕被黑客攻破、怕客户流失，或者想赚得更多、省得更多；大众消费者的情感更多样——交友化解孤独、约会满足爱、展示照片和音乐获得自豪感。

第二步，带着情感视角重新扫描产品，回答四个问题：用户通过什么途径满足这类情感？哪种视觉设计能抓住它？哪些功能在满足它？哪些特性反而阻碍情感的宣泄？同一种产品里，不同用户的情感并不相同——eBay 上阔绰买家、折扣买家、竞价刺激买家的动机各有各的来路，每次原型测试都应顺带追问"是什么驱动他使用产品"。

第三步，问"谁还能满足用户的这种情感"。答案里常常没有同类软件——真正的竞争对手往往是大众的线下生活方式。苹果的四层服务链（硬件为软件服务、软件为用户体验服务、用户体验为情感服务、产品为真正的需求）把这套逻辑推到顶点：情感是终点，前面每一层都为它让路。

## A1 — 书中的应用 (Past Application)

### 案例 1: 四百美元的 iPhone 情感溢价
- **问题**: 苹果凭什么在个人电脑、音乐播放器、手机三个主流市场独领风骚？四百美元的定价为什么挡不住购买欲？
- **方法论的使用**: 作者不谈功能细节，用四层服务链解剖——硬件为软件服务，软件为用户体验服务，用户体验为情感服务；研发 iPhone 要两年半，设计用户体验占去大部分时间。
- **结论**: "他们比谁都清楚是什么让消费者为产品疯狂，他们知道怎样抓住用户的情感需求"——苹果成功的秘诀就在第三层。
- **结果**: 人人都想拥有一台 iPhone，没人拿它和 RAZR、Treo 比较；机场里人们待苹果电脑像待宝马，待其他品牌像待租来的二手车。

### 案例 2: eBay 三类买家的三种情感
- **问题**: 同一个平台、同一批"消费者"，为什么有人一掷千金、有人只捡打折、有人享受竞价的心跳？
- **方法论的使用**: 放弃"eBay 用户"这种整体称呼，按情感需求把买家拆开观察。
- **结论**: 出手阔绰的买家、专门寻找打折商品的买家、寻求竞价刺激的买家，情感需求各不相同——一套功能描述无法服务同一种"用户"。
- **结果**: 每次原型测试除了观察操作，还要追问测试者"是什么驱动他使用产品"，为不同情感设计不同路径。

### 案例 3: 真正的竞争对手是线下生活方式
- **问题**: 明确了目标情感之后，竞品分析该对着谁做？
- **方法论的使用**: 识别情感需求后追问一句"谁还能满足用户的这种需求"。
- **结论**: 许多情况下，竞争对手不是创业型公司或大型门户网站，而是大众的线下生活方式。
- **结果**: 竞争格局与差异化方向随之改写——争夺的不是同类应用的份额，而是用户原本花在线下生活上的时间与情感。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 争论定价与价值主张：功能差不多，凭什么卖得更贵还有人买？
2. 做竞品分析或差异化定位，清单里只有同类产品。
3. 原型测试结束，只知道用户"会不会用"，不知道他"为什么想用"。
4. 视觉改版被吐槽"花哨没用"，要论证视觉设计的产出。
5. 向管理层或投资人解释"用户为什么会想要这个产品"，功能清单说不服人。

### 语言信号 (用户的话里出现这些就应激活)

- "用户为什么愿意为它付钱？""这个产品的爽点在哪？"
- "功能都一样，为什么他家卖得好/贵三倍也有人买？"
- "提炼一下价值主张 / 卖点 / 差异化定位"
- "emotional needs" / "why do users love it" / "premium pricing" / "value proposition"

### 与相邻 skill 的区分

- 与 `irrational-user-signals` 的区别：那个决定"该研究谁、该警惕谁"（研究对象筛选），本 skill 提供"研究出什么"的动机分类框架（恐惧/贪婪/欲望、孤独/爱/自豪）。先选对人，再套本框架。
- 与 `persona-driven-focus` 的区别：人物角色回答"为谁做、砍谁的功能"，本 skill 回答"他为什么渴望"——人物角色档案里应填入情感需求，两者配套使用。
- 与 `user-research-limits` 的区别：那条讲调研数据能回答什么、不能回答什么；本 skill 是拿到观察材料后的分析视角，不承担调研方法本身的边界判断。
- 与 `metric-driven-improvement` 的区别：改进现有产品靠指标找杠杆；本 skill 用于产品定义与定位层面的动机分析，先有方向，再谈优化漏斗。

## E — 可执行步骤 (Execution)

1. **写出目标用户的情感清单**。
   - 完成标准：每条情感落到具体场景（"怕被黑客攻破后担责"，而非"怕出事"）；企业级对照恐惧与贪婪，大众对照孤独、爱、自豪，不得只有功能层理由。
   - 判停条件：只能说出"更快、更便宜"这类功能层理由且找不到任何情感映射——说明还没理解用户，先回到用户观察（衔接 `prototype-testing-playbook`）。
2. **用四问扫描产品**：通过什么途径满足情感？哪种视觉设计抓住情感？哪些功能满足情感？哪些特性阻碍宣泄？
   - 完成标准：四问各有具体答案，且至少指出一个"阻碍情感宣泄"的产品特性（通常是广告、复杂度或流程摩擦）。
3. **追问"谁还能满足这种情感"，重写竞争对手清单**。
   - 完成标准：清单至少包含一个非同类产品或线下替代方式，并据此校准差异化方向；结论接入价值测试的验证问题（衔接 `product-validation-trio`——用户是否渴求、愿不愿意付钱）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 把"情感需求"当包装话术，为已经想好的功能找心理学借口——本 skill 的用途是倒推需求，不是给方案背书。
- 纯基础设施、内部工具这类没有终端用户情感可谈的对象。
- 对外传播文案、情绪板、品牌调性层面的"情感"工作——那是产品营销的领域；本书的情感分析服务于产品定义。

### 作者在书中警告的失败模式

- 理工科/经济学背景的从业者只谈功能和技术，无视情感需求——第34章开篇对行业自我的诊断。
- 照猫画虎模仿苹果：只复制功能清单和外观，学不到"用户体验为情感服务"这一层，形似神非（第31章）。
- 把视觉设计当"花哨的外表"——作者明确反对：视觉设计本身满足情感需求，同功能的两款原型，视觉好的那款用户反应截然不同（第36章）。

### 作者的盲点 / 时代局限

- 案例库停留在 2008 年（iPhone、eBay、iPod）；"恐惧/贪婪/欲望 + 孤独/爱/自豪"的分类粗于后来的情感研究，未覆盖成就感、归属感、身份认同等更细谱系，使用时可按产品补充。
- 作者举政客利用恐惧的例子说明底层情感的力量，但"利用恐惧做产品"的伦理边界书中没有展开；当下关于暗黑模式与成瘾设计的讨论是必要的补充维度。
- "真正的竞争对手是线下生活方式"在服务型产品上成立；纯工具型、协议型产品的竞争仍可能就是同类实现，需个案判断。

### 容易混淆的邻近方法论

- 诺曼的情感化设计三层次（本能/行为/反思）：那是设计心理学分层，指导设计执行；本 skill 是需求分析起点，回答"为什么买"。
- KANO 模型：分类的是满意度与功能的关系（兴奋型/期望型/基本型），不解释购买动机，两套坐标系不可互替。
- 品牌定位与情绪板：作用于传播与视觉层；本 skill 作用于产品定义层——先有情感需求结论，再谈表达。
