# 非理性消费者信号（警惕技术爱好者·新生测试）

## R — 原文 (Reading)

> "技术爱好者(即技术创新者)购买产品，仅仅是因为产品采用了新的技术。这类消费者容易误导产品经理，因为他们的需求与普通大众的不同。……非理性消费者(即尝鲜者)的情感需求与大众的相同，但是更强烈。愤怒、恐惧、孤独这类消极情绪被放大后，会导致非理性的消费行为。"
>
> — 杰夫·邦弗特（Marty Cagan 访录），第35章《情感接纳曲线》

---

## I — 方法论骨架 (Interpretation)

用户研究最大的坑是"声音大的先赢"：社区里最热情、提需求最多、最先掏钱的人，往往被当成目标用户本人对待。邦弗特（访谈时任雅虎副总裁）的情感接纳曲线给了一副区分眼镜——按情感状态而非技术态度把用户分成五类：技术爱好者（为新技术本身掏钱，对产品要解决的问题不关心）、非理性消费者（情感与大众相同但被放大，肯为解决问题付出超常成本）、理性消费者（早期大众，务实，只买性价比合适的）、超理性消费者（后期大众，半点不合意就不掏钱）、观望者（约15%，只买公认好用的）。

两个反常识的排序。其一，技术爱好者与尝鲜者会同时抢先购买、嗓门也最大，但技术爱好者是"最没有参考价值的人群"——他们会误导产品经理；其二，最值得研究的是非理性消费者：大众的消费动机与其类似，只是程度较轻，他们的情感需求正是产品跨越鸿沟的动力。

配套两条纪律。第一，不要用年龄、性别等人口统计标签划分情感人群——金融领域的非理性群体主要由退休女性构成；第二，用"新生测试"审视需求：像中学第一天那样清空经验与成绩，用初来乍到的敏锐，重新感受每天折磨大众的孤独、恐惧、挫折与不满。

## A1 — 书中的应用 (Past Application)

### 案例 1: 普锐斯的两种买家
- **问题**: 同样抢购普锐斯，谁的需求才代表大众？
- **方法论的使用**: 用五分类拆解购车动机——技术爱好者买的是新电池技术；狂热的环保主义者（非理性消费者）花两万美金，买的是被放大的信念。
- **结论**: 环保主义者本可买摩托车同样减排，却"为昂贵且不实际的解决方案买单"——这种迫切心情暴露了情感需求的强度；大众不会因为痴迷电池技术买车，消费动机与环保主义者类似。
- **结果**: 产品经理应研究非理性消费者的行为，避免被技术爱好者误导；有些创业公司混淆两者，"不知道产品究竟要满足谁的需求"，因此陷入困境。

### 案例 2: Skype 成功，网络摄像头遇冷
- **问题**: 同是通信领域，为什么一个引爆、一个平淡？
- **方法论的使用**: 不看标准是否完善、技术是否先进，只看领域内积蓄的愤怒与不满。Skype 面对的长途通话领域不满积蓄已久；网络摄像头"几乎不存在不满和愤怒的情绪"——它满足的是马斯洛金字塔顶端的需求（想看看孩子），不普遍，替代方式又多。
- **结论**: Skype 团队抛开无关变量，一心解决领域内的愤怒和不满，成功到"人们再也离不开"；Skype 后来加入视频通话反响平淡、用户增长有限——没有不满情绪可以利用的领域，鸿沟跨不过去。
- **结果**: "愤怒的用户决定着产品未来的发展方向"成为选品的前置检查：先评估领域内不满情绪的强度，再谈机会。

### 案例 3: 新生测试
- **问题**: 从业多年、对行业习以为常的人，怎么重新感受到用户的烦恼？
- **方法论的使用**: 回想踏入中学的第一天——小学的成绩和奖励全部作废，一切新鲜，"这时你最敏感，最容易感受到细微的变化"。带着这种感觉审视日常。
- **结论**: 带着新生的感觉去发掘每天折磨大众的情感——孤独、恐惧、挫折、不满，"你离发现新产品的日子就不远了"。
- **结果**: 新生测试成为把"研究愤怒的用户"落到个人自省的操作工具，与创新机会清单（电信、银行、信用卡、税务、政府机构、航空公司、健康保险）配合使用。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 社区/论坛里最活跃的极客用户提交了一长串需求清单，要决定优先级。
2. 种子用户口碑极好，正式推向大众却没人接——回头检查早期用户构成。
3. 用年龄、性别、地域等人口统计标签定义目标人群与用户画像。
4. 多个候选产品方向都在"风口"上，需要决定押注哪个领域。
5. 团队成员自己就是产品深度用户，讨论时拿自己的感受代替用户需求。

### 语言信号 (用户的话里出现这些就应激活)

- "核心用户/铁杆粉丝说要加 X，做不做？"
- "种子用户反馈很好，为什么大盘不动？"
- "技术爱好者/极客/尝鲜者会不会误导我们？"
- "early adopter" / "tech enthusiast" / "angry users" / "freshman test"
- "该观察哪类用户？目标用户画像谁来定？"

### 与相邻 skill 的区分

- 与 `emotion-based-demand` 的区别：那个提供情感需求的分类框架（研究"什么"）；本 skill 决定研究对象与警示对象（研究"谁"）。典型顺序：先用本 skill 选对人，再用情感框架做分析。
- 与 `charter-user-program` 的区别：特约用户计划管招募与使用规则（6人、不收费）；本 skill 提供筛选标准——特约用户必须是潜在目标用户，技术爱好者型尝鲜者恰恰要排除。
- 与 `prototype-testing-playbook` 的区别：那个管测试怎么主持（鹦鹉技巧、判停）；本 skill 管测试者名单里该有谁、不该有谁（第29章：观察实际用户，不要尝鲜者，更不要公司同事）。
- 与 `user-research-limits` 的区别：那条划调研方法的边界（能答什么、不能答什么）；本 skill 在"观察"内部做对象分层——一个管方法，一个管对象。

## E — 可执行步骤 (Execution)

1. **给当前发声用户分类**：把社区活跃者、最早付费者、投诉最多者逐个标注五分类归属。
   - 完成标准：能对每个主要发声者说出"他为满足什么情感、付出了多大成本"；明确指出产品当前的需求输入主要来自哪一类。
   - 判停条件：发现需求输入几乎全部来自技术爱好者、又说不出任何非理性用户的不满场景——先暂停需求排期，回到用户观察。
2. **找到非理性消费者，记录其超额行为**：寻找为解决问题付出远超常理成本、情绪被放大的用户。
   - 完成标准：至少掌握 1~3 个具体记录（付出了什么超额成本、愤怒或恐惧的是什么、用过什么替代方案），而非笼统印象。
3. **跑一遍新生测试**：清空自己的经验与成绩，以初来者视角重走用户旅程，列出"习以为常但其实让人愤怒"的烦恼。
   - 完成标准：列出至少 3 个日常烦恼并标注情感类型（孤独/恐惧/挫折/不满），其中至少 1 个附有"大众正在忍受它"的证据（如替代方案的糟糕程度）。
   - 判停条件：某个候选领域怎么找都找不到不满情绪（网络摄像头式领域）——按作者的结论调低其优先级，成功产品需要不满情绪可以利用。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 平台产品把开发者当客户时——开发者社区本身就是产品的一部分，简单套"技术爱好者最没参考价值"会误伤（平台客户的排序问题见第39章的处理）。
- 企业级产品的采购决策研究——买单者与使用者分离，需另行区分客户与用户（第38章），本 skill 的五分类针对消费大众。
- 已经由特约用户计划锁定目标用户的常规测试执行——此时按 `charter-user-program` 的规则操作即可，不必每轮重复对象筛选。

### 作者在书中警告的失败模式

- 被技术爱好者误导：他们只为新技术本身痴迷，"最没有参考价值"；有些创业公司混淆技术爱好者与非理性消费者，不知道产品要满足谁，陷入困境（第35章）。
- 用人口统计划分情感人群：认定非理性消费者是 18~30 岁男性——"这是不对的"，金融领域的非理性群体主要由退休女性构成（第35章）。
- 按尝鲜者的需求做产品：他们容忍缺陷，据此做出来的东西很可能只适合他们自己（第15章）。
- 开发"最酷"的技术去迎合技术爱好者——雅虎的选择是服务超理性核心用户，同时加深对非理性消费者的理解。

### 作者的盲点 / 时代局限

- 五分类与"观望者约15%"的比例出自邦弗特的经验访谈，没有抽样数据支撑——把分类当透镜用，别当普查表用。
- 访谈背景是 2008 年前后的雅虎消费互联网业务；对 B2B、开发者工具、专业软件，"理性买家"的声音可能恰恰关键，"警惕技术爱好者"不能照搬为"警惕专业用户"。
- 书中默认"愤怒"是可靠的需求信号，未讨论愤怒用户的代表性偏差（极端不满者未必是大众的情感样本），需与 `prototype-testing-playbook` 的行为观察互相校验。

### 容易混淆的邻近方法论

- 摩尔《跨越鸿沟》的技术接纳曲线：本 skill 正是对它的情感补充——同一批人的另一面；技术接纳曲线解释采用阶段，情感接纳曲线解释动机，两者并用而非互斥。
- NPS 净推荐值：度量推荐意愿的输出指标，不区分发声者属于哪类用户，替代不了本 skill 的对象筛选。
- 用户画像/人口统计细分：按属性分群；本 skill 恰恰警告属性标签推不出情感人群。
