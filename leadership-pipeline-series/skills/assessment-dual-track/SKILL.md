# 数字导向的绩效考核不能替代领导力评估（评估双轨）

## R — 原文 (Reading)

> "绩效考核主要是检查已经发生的业绩表现，从而决定相应的报酬，这是在事后判断领导人才完成了什么，而且通常是采用量化的指标。……业绩考核几乎从未关注领导人才的天赋与潜质。"
>
> — 查兰，第5章（L8316）

> "大多数人认为，以数字来评估最客观，但单纯的数字可能产生误导，依赖于数字的评估常常很肤浅，有时候甚至很危险……在经济形势一片大好的情况下，平庸的经理人也能完成数字指标；反之，在经济衰退的情况下，最优秀的经理人也可能无法完成考核目标。"
>
> — 同上，第5章（L8473）

> "某位接班人的销售业绩目标是10亿美元，他实际上完成了11亿美元，考核时就必须分析为什么他能完成这个业绩，仅仅是因为市场需求旺盛，还是因为他帮助一名地区销售经理更加重视客户需求，从而提高了市场份额。"
>
> — 同上，第5章（L8426）

---

## I — 方法论骨架 (Interpretation)

这套方法把"评价人"拆成两条互不替代的轨道，并规定各自看什么、干什么用。

**第一轨：业绩考核**——看已发生的数字，事后结算，用途是报酬。它必要但不足：数字客观、易比较，因此组织容易产生"公平感依赖"，但数字几乎从不关注天赋与潜质，也不回答"他是如何完成的、在什么条件下完成的"。

**第二轨：领导力评估**——看能力、潜质与因果关系，用途是发展与安排。它要回答三类问题：①他是怎么做到的（追因）——完成 11 亿是因为市场需求旺盛，还是因为他帮助某位地区销售经理更重视客户需求从而提升份额；②他表现出了哪些领导才能、其他人如何看待他、下一步该如何培养；③在明显不同的环境中能否复制成绩。实施载体是年度"领导力评估会"：不属于绩效考核，是"其他以数字为导向的考核之外增设的考核会议"，用集体讨论、行为证据与一页评估表，专门修正上级个人的误判、防止不适合者被寄予过高期望。

**反向推论（为什么要双轨）**：好年份平庸者也能达标，坏年份最优秀者也可能失手；因此"达标"不能直接推出"有能力"，"未达标"也不能直接推出"没能力"。同理，有的公司自设的个人领导能力考核标准"很少能反映领导力的关键所在"。

**落地要求**：两轨必须在会议、证据与用途上分开，并且要嵌入经营节奏——书中给定做法是持续跟踪（至少每季思考一次"他发展如何、下一步去哪"）、每岗留 3～5 年让贡献显现、以及一年一循环的评估会（如汤姆森公司把人才评估与战略／预算节律咬合）。评估之后必须有动作：更新一页评估表与成长路径图、据此改进培养方案和岗位安排。

## A1 — 书中的应用 (Past Application)

### 案例 1: 上海会议后的追因反馈（第5章）
- **问题**: 一位业务部门领导汇报中国业务高速成长，数字漂亮、预期乐观。
- **方法论的使用**: 上级没有停在"汇报非常好"的表扬上，而是给出一个具体的业务性洞察——报告中的人均收入用的是官方汇率，若改用购买力平价分析，需求增长预测将大幅增加，因此在中国市场应更积极抓机会。作者点评这类反馈"针对性强、很关键、很及时，并且以这位领导人才容易接受的方式表达"，并且"沟通的内容却是由商业头脑决定的"。
- **结论**: 双轨的第一轨（数字与汇报）之上必须叠加追因与业务洞察；好的评估同时给出"哪里做得好"和"下一步怎么更好"。
- **结果**: 下属获得了可直接改进的方法与更积极的决策方向，"极大地促进了这位领导者的发展"（b4-c18）。

### 案例 2: 汤姆森公司——把评估嵌进全年经营节律（第5章）
- **问题**: 一家集团如何保证人才评估不被业务压力挤掉，且不沦为一次性填表？
- **方法论的使用**: 建立全年循环：1 月高层共议年度工作重点→春季评估战略、寻找机会→夏季检查组织状况与领导梯队（讨论具体高潜的发展）→秋季跟踪预算执行；日常讨论业务时自然追问"这是哪个人或者哪个团队完成的？"，并在有新机会时推荐可能适合领导它的人；会议最后由 CEO、CFO、CTO、COO 与 HR 主管共同讨论人才状况，多角度、多场景反复评估——"对领导人才的反复评估是一整年持续不断的工作"。产出是一页评估表与成长路径图，每次评估会或职务变动后立即更新。
- **结论**: 双轨中的领导力评估轨不靠额外项目，而靠与战略／预算咬合的固定节律；数字（预算）与判断（人的能力）在同一流程中并行而不互相替代。
- **结果**: 被作者列为"反复评估是一整年持续不断的工作"的实践样本（b4-c21、b4-c20）。

### 案例 3: 凯伦的一页评估表（第5章）
- **问题**: 一位被视为"七八年后可成为 CEO"的高潜即将晋升业务群组总裁，如何描述她的能力与风险？
- **方法论的使用**: 高层集体讨论后形成一页表，把优势与边界并列：优势——高度职业化、业务重振转型专家、善于处理外部利益相关人关系（包括危机处理）、沟通与知人善任；边界——"她的业务管理幅度有限，因为她的主要经历是领导处于逆境、需要重振转型的业务"；待发展——驾驭多个业务单元的领导者、放弃萎缩业务、开拓新业务、不靠专业知识领导；待观察——培养业务领导者的能力、洞察力。
- **结论**: 一页表的价值在于把"提拔决定"变成"适配判断＋观察清单"；讨论"应该勾勒出一个人的领导力本质，突出他的天赋和优势，反映出未知的部分，但并不苛责他的缺点"。
- **结果**: 高层据表判断其对新岗位的适配与下一步观察重点，而不是仅凭业绩数字决定晋升（b4-c22）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户在讨论某人的提拔，但理由只有 KPI 与业绩排名，被问"他是怎么做到的"时没人答得上来。
2. 公司只有一套年度绩效考核，用户发现它无法回答"谁该被培养、下一步放哪"，想加一套评估机制。
3. 销售冠军今年数字翻倍，用户纠结是否直接提拔，需要判断是市场红利还是他带人的成果。
4. 用户想设计或改造评估流程：谁来评、看什么证据、多久一次、与报酬如何分离。
5. 用户观察到某位管理者在好年份表现亮眼、坏年份失手，想知道怎么评价其真实能力。

### 语言信号 (用户的话里出现这些就应激活)

- "他业绩很好，是不是可以直接提？"
- "考核只看数字不行吗？数字最客观。"
- "今年市场好，他的数字是真好还是运气好？"
- "考核和评估有什么区别？为什么不能一次做完？"
- "performance vs potential" / "beyond KPI" / "how do we assess leaders" / "his numbers were great — should he be promoted"

### 与相邻 skill 的区分

- 与 `b1-f12 talent-review-meeting-mrr` 的区别: MRR 是评估会议怎么开的机制（会前材料、会中举证、会后信函）；本 skill 解决"为什么需要两套机制、各看什么、各干什么用"，是给评估会定用途与证据标准。
- 与 `b5-f29 nine-box-actions` 的区别: 九格矩阵是把绩效与潜能两轴合起来分类；本 skill 论证两轴为什么必须分开取证，是九格矩阵的前置纪律。
- 与 `b2-f22 performance-dialogue-evidence` 的区别: 业绩讨论与证据法聚焦业务结果的对话；本 skill 聚焦"业绩之外还要评能力与潜质"。
- 与 `b4-f03 deliberate-practice-feedback-loop` 的区别: 反馈闭环是日常一对一的成长机制；本 skill 是组织层面的评估制度设计。
- 与 `b4-p03 developing-talent-is-every-leaders-job` 的区别: 那条讲"谁被考核育人"；本 skill 讲"评估要看什么、别把两件事混在一起"。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行：

1. **把问题重新表述为两条轨道**
   - 完成标准: 明确本次要产出的是哪一轨的结论——报酬与结算（业绩轨）还是能力、潜质与下一步安排（领导力轨）；两者不可互相替代。
   - 判停条件: 若用户实际要的是薪酬或合同决定，转由 HR 制度处理，本 skill 只提供评估证据标准。

2. **在业绩轨上补"追因"**
   - 完成标准: 对每个关键数字回答三问——在什么条件下完成的（市场、政策、竞争、资源）？他是如何完成的（哪些行为、帮助了谁、改变了什么）？如果换一个人或换一年，结果会怎样？

3. **在领导力轨上定义证据与判据**
   - 完成标准: 用行为与决策证据（而非自我陈述）写出——展现了哪些领导才能、他人如何评价、待发展项与待观察项；可借助一页评估表（优势／边界／待发展／待观察）与成长路径图。

4. **设计两轨的机制分离**
   - 完成标准: 业绩考核按原有周期与用途运行（报酬）；领导力评估设独立会议（如年度领导力评估会），有独立的讨论形式与产出，并明确"这不是决定报酬的会议"。
   - 判停条件: 若组织规模小、无法支撑两套会议，可用同一会议的两个议程段落实现分离，但结论与记录必须分开。

5. **把领导力评估嵌入经营节律**
   - 完成标准: 在年度日历上安排节点（如与战略评审、组织检查、预算跟踪咬合），并在日常业务讨论中加入"这是哪个人／哪个团队完成的"这类追问。

6. **处理两轨结论冲突的情形**
   - 完成标准: 明确规则——数字好但证据显示能力／行为不足：不直接提拔，转培养或补历练；数字差但证据显示能力强：保留并调整岗位／环境，而非放弃；并把结论写入人才名单更新。

7. **评估后必须有动作**
   - 完成标准: 每次评估产出一页评估表与成长路径图更新、下一步岗位／发展重点，并指定责任人与检查点；对评估中发现的顶格优势者与待观察者分别给出后续安排。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 纯业务复盘（该季为何未达标）：那需要业务与运营分析，不是人才评估问题。
- 薪酬结构、奖金公式、股权激励的设计：本 skill 只论证"数字与评估要分开"，不提供薪酬方案。
- 涉及个人隐私或对个人的心理诊断式评价：评估证据应限于工作行为与结果，避免越界。
- 组织连基本的业绩数据都不清晰时：先把业务与财务口径理清，否则双轨都无从谈起。

### 作者在书中警告的失败模式

- **数字导向的绩效考核替代领导力评估**：只用数字评价人——好年份平庸者也达标、坏年份最优者也失手；无法识别天赋与潜质，也无法发现行为／价值观问题，人才决策失去准确性；警示信号包括"提拔讨论只引用 KPI""无人能说明他是如何／在什么条件下达成的""领导力评估会缺失或流于形式"（b4-ce05）。
- **反馈太晚**：纠正窗口在行为偏差出现时就存在，拖到年度评估已经错过（跨册反例 b3-ce12）。
- **官僚填表式人才流程**：表格数据填得齐、讨论会无人敢下判断，人才名单与真实提拔结果脱节（b4-ce09）。
- **以分析与表达／学历误认领导潜质**：评估若只看专业成就与汇报表现，就会把个人贡献者推上领导岗位（b4-ce25，与 `b4-f04` 共用）。
- **集体讨论若无证据与主持人，会滑向印象与游说**：作者要求讨论"深入了解候选人表现背后的因素"，并要求对空泛评价追问举例（第7章相关做法可迁移到一般评估会）。

### 作者的盲点 / 时代局限

- **对"领导力评估"效度的过度自信**：作者批评数字肤浅，但对自家评估法的效度证据同样薄弱——"潜能"与"领导才能"的判断标准缺乏预测效度验证，且存在评估者偏见与政治联盟的空间（BOOK_OVERVIEW 批判节：把"背后议论公开化"视为优点，未讨论被评估者知情权与程序公正）。
- **被评估者的位置**：全书由上级与组织视角单向评估，个人的自评、申诉与知情权几乎没有位置。
- **中国语境的本地化落差**：国企干部考察程序、360 度评价制度与"公开评估、按业绩排名"之间需要本地化调和；照搬美式做法可能触碰劳动关系与程序公正要求。
- **单因论与样本偏差**：把人才问题主要归于评估机制，对资源、市场与组织政治等结构性因素处理薄。

### 容易混淆的邻近方法论

- 与"360 度评估"：360 度是证据来源之一；本 skill 关注的是"评估结果用于什么、与报酬如何分离"，若把 360 度结果直接挂钩奖金，就会退化为业绩轨的变体。
- 与"人才盘点／校准会（calibration）"：校准会通常是绩效评级校准；本 skill 要求另设领导力评估的用途与讨论，不要让校准会吞掉发展轨。
- 与"绩效改进计划（PIP）"：PIP 是管理程序；本 skill 是常态化的发展性评估制度。
