# 前提假设显性化与应急计划

## R — 原文 (Reading)

## I — 方法论骨架 (Interpretation)

计划的质量等于前提的质量。本方法把评审对象从"数字"换成"判断"：

1. **显性化**：把预算/运营方案背后的假设全部摆到桌面上，逐条念出来——客户对象与购买习惯、竞争反应、供应商与渠道、经济与汇率、政策与法规。
2. **限定数量**：任何一项计划的前提性因素一般不超过六个；找出它们之后可以说："如果所有这些条件都满足，我们就一定能实现目标；否则就可能完不成。"
3. **取证**：对每条前提找证据——对象可以是客户、供应商或其他来源；作者示范是"打很多电话、收集大量信息"。取证要穿透链条：客户的客户、客户的客户的客户，终端需求决定你的需求。
4. **以最坏情况为起点**：把"最可能变化的前提"挑出来，预设应急方案（触发条件、措施、负责人）；不假设经济会自动恢复，宁可把收益目标调回保守水平。
5. **驱逐"希望"**：讨论的基础是现实，不是希望，更不是梦想；对"第四季度会好转"式的说法要追问"如果没好转怎么办"。

## A1 — 书中的应用 (Past Application)

### 案例 1: 霍尼韦尔——"9·11"后按最坏情形重做 2002 年计划
- **问题**: "9·11"后航空业陷入危机（仅第四季度损失就高达 40 亿美元），航空公司称 2002 年客运量只能达到原计划 80%，零件供应行业突然停业；政府补助金额未知。霍尼韦尔需要评估 2001 年第四季度与 2002 年的实际情况。
- **方法论的使用**: 收集大量信息、打很多电话，得出结论：销售额损失约 12 亿美元（大部分在配件市场）；推测商用航空来年早些时候会因飞行限制放宽而反弹，因而减小了商用与航空市场配件部门的削减幅度；综合后估计收益下降约 5 亿美元，并据此讨论如何把运营成本减少 5 亿美元；把收益目标定为 2000 年的水平，成本削减计划均摊到四个季度；向供应商提出延长支付期限（因航空公司要求延期付款）。
- **结论**: "毕竟，在制定计划的时候，我们还是应该从最坏的情况打算"——即便很多人认为 2002 年第二季度后半段经济恢复会加速，"我们并没有把这个因素考虑在计划当中"。
- **结果**: 公司以一组显性化、取证过的最坏情形假设重排了 2002 年计划（十天重订 2001 年度航空运营计划为同一应对的延伸）。

### 案例 2: 奥尔良小型供应商——沿客户链预判思科减速
- **问题**: 电信泡沫破灭后思科系统公司未能及时转型，其大多数供应商都因库存过多陷入困境。
- **方法论的使用**: 早在思科宣布削减原料需求之前，这家小供应商的 CEO 就要求董事会成员了解思科的客户情况（Verizon、AT&T、英国电信），并进一步观察这些公司的大客户（通用汽车、美国运通）的情况；收集完信息后判断"思科系统的乐观是盲目的"。
- **结论**: 需求假设必须沿客户链向上取证，而不是接受直接客户的乐观预期。
- **结果**: 该公司提前关闭自己的一家工厂，保持了产品流动性，避免了同行的库存灾难。

### 案例 3: AT&T 阿姆斯特朗——四个前提全部落空（反例）
- **问题**: 1000 亿美元光纤战略的四个前提是：收购光纤公司、捆绑式服务需求、尽快获得收入、电信条例被有效执行。
- **方法论的使用**: 作者用它作反面标本说明：战略"既没有对自己假设的那些条件进行验证，也没有预先制定有效的备选方案"。
- **结论**: 收购成本被长途价格下跌推高、消费者对捆绑服务的热情不足、执行周期超预期、政府执法力度不够——前提逐条落空。
- **结果**: 业务以 690 亿美元出售，股价从 44 美元跌至约 18 美元。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户要审一个海外建厂/新市场/大额投资提案，需要做压力测试。
2. 预算会上各部门数字打架、对不上，彼此用的假设不同。
3. 用户想给一份乐观计划"踩刹车"，把最坏情况摆到桌面上。
4. 组织面临突变（汇率、关税、需求、政策），需要决定要不要改计划、怎么改。
5. 用户发现某个部门的计划建立在"客户会按我们预期买"的假设上，但无人验证过。

### 语言信号 (用户的话里出现这些信号就应激活)

- "这个假设靠谱吗？/ 怎么做压力测试？"
- "预算数字对不上 / 各部门口径不一样。"
- "万一没好转怎么办？/ 最坏情况是什么？"
- "stress-test the plan" / "worst case" / "what if our assumptions are wrong"

### 与相邻 skill 的区分

- 与 `b1-f20 operations-plan-three-step` 的区别: 本 skill 是运营流程第一步（前提）的放大处理；b1-f20 负责从前提走向目标、行动计划、共识与跟进的完整三步。
- 与 `b2-f19 environment-three-variables` 的区别: 后者提供分析大环境的三个变量框架（册2）；本 skill 是计划评审场合下对前提的取证与应急设计程序。
- 与 `b3-f06 complexity-to-priorities` 的区别: 后者把复杂信息压缩为优先事项；本 skill 把计划背后的判断拆开核对，方向相反、可互补。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **把计划翻译成前提清单**
   - 完成标准: 列出不超过六个前提，覆盖客户与购买习惯、竞争反应、供应商、渠道、经济与汇率、政策法规；每条写成一个可判断真伪的命题。
   - 判停条件: 若列不出六个以内的核心前提，说明计划尚未想清，退回重写。

2. **逐条取证**
   - 完成标准: 每条前提标注证据来源（客户、供应商、第三方数据、现场走访），并记录"已核实/未核实"；对未核实项，明确取证对象与期限。

3. **穿透客户链**
   - 完成标准: 对关键需求前提，至少向上追两层（客户的客户），并写下终端需求的判断依据。

4. **标记最可能变化的前提并设计应急方案**
   - 完成标准: 挑出 2–3 条最不确定的前提，各写出：触发条件、应急措施、负责人；应急方案不必细化到细节，但必须可启动。

5. **以最坏情况设定目标并重算数字**
   - 完成标准: 用最坏情形（而非乐观预期）重算收益与现金流，给出对应的成本削减或资源调整方案。
   - 判停条件: 若最坏情形下企业无法承受，回到 `b1-f16` 或 `b1-f17` 重新审视战略本身。

6. **把"希望"从讨论中驱逐**
   - 完成标准: 会场上所有"希望/预计会好转"的表述都被替换为"若 X 发生则采取 Y"的条件句；并约定季度复核前提是否仍成立。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 紧急止损现场：先执行预案再补讨论，不能在危机中开会取证。
- 涉及未公开重大信息的场合：前提讨论的记录与用途须符合信息披露与保密规则，不得用于对外沟通。
- 把前提讨论变成"找借口"：作者要求的是取证与权衡，不是为不达标预留说辞。

### 作者在书中警告的失败模式

- **预算数字游戏与"从未来借债"**: 不讨论前提与执行方案、只看结果数字，会使"达成数字"成为唯一理性选择，压货、折扣、透支行为随之而来（b1-ce16）。
- **目标脱离执行能力（未做组织能力评估）**: 战略假设自己拥有其实不具备的人才、流程、文化，进入执行阶段才发现处处缺人缺能力（b1-ce17）。
- **忽视竞争对手反应 / 过高估计对手**: 竞争反应是前提清单中的必答项，漏掉它就会在行业价格战中损失最大，或用恐惧替代调查而错失机会（b1-ce15）。

### 作者的盲点 / 时代局限

- **前提讨论假设了"可取证且有人愿意说真话"**: 在供应链不透明、信息不对称或对方有意隐瞒时，取证结果会被污染；书中未讨论信息治理机制。
- **"不超过六个"是经验法则**，不是定律；在多重监管、多国运营的复杂业务中，六个上限可能掩盖关键变量。
- **事后归因风险**: AT&T"四前提全落空"是结果已知后的复盘，且作者未讨论治理结构、技术迭代等替代解释（BOOK_OVERVIEW 批判节）。
- **美国大公司语境**: 案例以制造业与电信业为主，对平台型业务与快速发展市场的适配需自行判断。

### 容易混淆的邻近方法论

- 与"敏感性分析"的区别: 敏感性分析算数字对变量的弹性；本 skill 先判断假设本身真伪与来源，再谈数字。
- 与"情景规划"的区别: 情景规划生成多个未来图景；本 skill 针对单一计划的假设做取证与应急设计。
