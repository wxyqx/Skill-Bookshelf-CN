# 模型必须按组织定制，严禁机械照搬

## R — 原文 (Reading)

> "最后，我们需要提醒的是，不要“机械地”运用领导梯队概念，换句话说，就是避免照搬领导梯队模型。我们发现很多公司将继任计划等同于领导力发展，实际上，领导梯队模型所建立的领导力标准与继任计划不同。我们希望读者能全面思考，时刻提醒自己人的复杂性。"
>
> — 查兰/诺埃尔/德罗特，导论（L9723）

> "用贵公司的职位结构替换我们在模式中所使用的名称，也可以将我们的六个领导阶段改为五个或七个，如果这样更适合贵公司的结构。……上述变动只是为了帮助你成功地为实际职位制定继任计划，并不是试图将该计划硬塞入一个通用的模式。"
>
> — 同上，第10章（L11977）

> "你必须使用企业自身的术语、领导力发展阶段和业务目标来界定你自己的领导梯队模型。……那些根据本企业的实际情况对领导梯队进行修改的企业相对于那些没有这么做的企业会获得更多的益处。"
>
> — 同上，第14章（L12838）

## I — 方法论骨架 (Interpretation)

领导梯队模型是"框架"不是"法律"：它提供的是"层级不同、要求不同"的思考方式与一套自检问题，而不是一份可以直接安装的现成制度。作者从头到尾反复提醒"不要机械地运用""不要照搬"。

定制的三项具体操作：

1. **层级数**：先验证本公司真实存在的领导层级结构（哪些层级真实存在、哪些被合并、哪些因人设岗），把六阶段改成五层或七层都可以——作者对小公司的观察是常常把公司高管层与 CEO 层合并，全球化公司则可能需要额外层级。唯一不变的是"层级之间在领导技能、时间管理能力和工作理念上的差别"。
2. **术语**：用公司自己的职位语言替换书中的名称，让模型能嵌入日常沟通，而不是另造一套只有 HR 会说的黑话。
3. **标准**：把绩效与潜能标准翻译成本地话语，在组织内公示并讨论，并随着商业环境变化而修订标准（环境变化→新行为→新标准）。

定制的目的不是降低标准，而是让标准"被本组织使用"。作者的原话逻辑是：这样做过的企业比没做的获益更多；反之，把框架当教条、强迫员工遵循，只会适得其反——框架一旦变成"当地法律"，人们就会应付它而不是使用它。

因此本 skill 的操作判据是"是否咬合"：模型必须与现有的计划、预算、考核、培训、招聘程序咬合，成为它们的共同参照系，而不是在它们之外再叠一套流程。同时保留对人的复杂性的敬畏——这也是全书最后一句提醒的落点。

## A1 — 书中的应用 (Past Application)

### 案例 1: 万豪国际——把模型长成"万豪的系统"
- **问题**: 万豪需要支撑快速全球扩张的领导人才储备，但任何外来模型都必须能在万豪的文化与业务中运转。
- **方法论的使用**: 万豪聘请外部专家，但"在吸收先前经验教训的同时也找到了最佳的实践方式。他们已经创建了一个既能反映万豪公司文化背景，又能应对全球经营挑战的系统"——核心工具"领导才能开发细则（LTDI）"是"一套程序，万豪可以使用这个程序来评估各领导层人才的实力，确定当前已经做好准备能够获得晋升的经理"，先在 250 名最高级经理试用，再推广到所有领导层级；配套人力资本执行委员会（总裁兼 COO 主持）、领导有效性模型、网络化人才信息与心理测量工具、深度面谈、组合管理式校园招聘等。
- **结论**: 定制的标志不是改了名字，而是模型与公司的治理结构（谁主持）、评价标准（用什么测）、人才制度（招聘/培训/选拔）全部咬合。
- **结果**: 数年内建立起宏大的管理人才储备，管理质量成为万豪资本市场叙事的一部分；作者在多年后仍将其列为最具参考价值的落地案例。

### 案例 2: 小公司并购贷款研究——50 家企业的失败都源于"没换模型"
- **问题**: 一家向小公司提供并购贷款的金融服务公司要求作者评估借款方能否在并购后管理变大的公司。
- **方法论的使用**: 作者调查约 50 家企业，逐家对照"创始人是否随公司规模改变工作方式"，而不是套用大公司模板去评分。
- **结论**: "在研究了大约50家贷款公司后，我们发现失败的公司都是源于它们的领导者没有改变原来的工作习惯，他们很难放弃事必躬亲，也很难信任一个新的管理层级。"小公司不需要六层结构，但凡新增一个管理层级，就出现一次转型断裂点——这就是为小公司定制的模型内核。
- **结果**: 结论被直接用于该公司的贷款评估标准，把"领导力转型"从 HR 议题变成信用风险议题。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户想直接复制某标杆公司的领导力模型/人才盘点体系，问"能不能拿来就用"。
2. 已经引入一套通用模型或咨询方案，但业务部门觉得"跟我们的实际不是一回事"，落地卡住。
3. 公司层级与书本模型不一致（有的层合并、有的层多设），用户不确定该不该硬套。
4. 要论证定制方案：层级数、术语、标准该怎么改，改到什么程度算够。
5. 正在设计制度咬合方案（与预算、考核、培训、招聘如何接），避免另起一套并行体系。

### 语言信号 (用户的话里出现这些就应激活)

- "这套模型我们能不能直接抄？/ 学 GE 那套怎么学？"
- "咨询公司给的方案很好，但我们用不起来"
- "我们只有五层/七层，跟书里对不上，怎么办？"
- "off-the-shelf model" / "copy a best practice" / "how much should we customize" / "tailor it to our company"

### 与相邻 skill 的区分

- 与 `b5-f01 leadership-pipeline-six-passages` 的区别: 那是模型内容（六个阶段各要什么）；本 skill 是使用纪律——先按公司实际改造模型，再谈应用；照搬内容而不改造是本 skill 明确反对的行为。
- 与 `b2-f03 performance-pipeline-interview-build` 的区别: 册2 建队六步骤本身含"留灵活性"，与本单元是姊妹主张（两册独立给出同一定制命令）；本 skill 聚焦"拒绝照搬"的判断与操作，不涉及业绩定义的具体步骤。
- 与 `b4-f01 apprenticeship-model` 的区别: 轮岗培养模式强调为每个人量身定制成长路径；本 skill 定制的是组织层级的模型与语言，两者是"个人定制"与"组织定制"的分工。
- 与 `b5-f27 succession-five-steps` 的区别: 五步骤中的第一步就是"调整模型适应组织"；本 skill 是这一步的展开与通用纪律，可独立用于任何模型/制度的引入决策。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **先验证公司真实的层级结构，而不是相信组织图**
   - 完成标准: 列出实际存在的领导层级与各层实际工作内容（访谈＋观察），标出被合并、被虚设、因人设岗的层级；产出"本公司层级清单"。
   - 判停条件: 若组织没有稳定的层级结构（如小团队、项目制组织），先说明本模型不适用或需大幅裁剪，不要强行推行。

2. **改造层级数与名称**
   - 完成标准: 决定采用几层（五、六、七均可）并全部换成公司职位语言；对每一层写出一句话的层级要求（技能/时间/理念）；写明与书本标准模型的差异清单及理由。

3. **翻译绩效与潜能标准，并公示讨论**
   - 完成标准: 标准全部使用公司自己的业务术语；通过培训/讨论会让员工理解并反馈；写明标准的修订机制（环境变化→行为变化→标准更新）。
   - 判停条件: 若标准只停留在 HR 文档、业务部门无法用自己的话说出来，不要进入下一步——这是"照搬"的典型症状。

4. **与现有制度咬合，拒绝另起一套**
   - 完成标准: 逐项列出模型与现有计划、预算、考核、培训、招聘程序的接口（哪个会、哪张表、谁负责），并明确"不新增并行体系"；能最小改动就最小改动。
   - 完成标准 (反教条检查): 明确写出"不强迫员工遵循"的应用方式——框架用于讨论与判断，不用来打合规分。

5. **小范围试用再推广**
   - 完成标准: 选择一个层级或一个业务单元先行试用（作者案例中万豪先在 250 名最高级经理试用），设定 3–6 个月的观察点与调整机制。

6. **定期回到"人的复杂性"**
   - 完成标准: 每轮修订都记录"哪些地方是标准失灵、哪些地方是人本身复杂"；在制度文本中保留对个体差异的处理说明，避免模型退化为贴标签机器。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户只是要理解模型概念本身（如"六阶段是什么"）——先讲内容，不必先讲定制。
- 把定制当拖延借口：反复调整语言而不推行，等于用"我们要定制"推迟任何改变。
- 公司尚无稳定层级或管理层不愿投入时强行引入：模型需要真实的层级土壤。
- 定制被理解为"只挑好做的做"：作者要求的是适配（层级/术语/标准），不是删掉难做的部分（如标准公示、评估节奏）。

### 作者在书中警告的失败模式

- **机械照搬与概念混用**: "不要'机械地'运用领导梯队概念，换句话说，就是避免照搬领导梯队模型。我们发现很多公司将继任计划等同于领导力发展……我们希望读者能全面思考，时刻提醒自己人的复杂性。"（导论 L9723）
- **官僚填表式人才流程：有形式无实质**: "有的公司在这方面虽然有规章制度，但主旨却错了。他们让员工循规蹈矩地填写表格，遵守程序，但识别和评估领导潜质的方法却很马虎、很官僚。有些公司模仿在领导力培养方面堪称楷模的通用电气公司，但它们大多只是按图索骥，并没有学到通用电气在这方面的严谨态度和专业方法。"（b4-ce09，册4 第1章 L7613）
- **只盯职能工作式的"照搬现成课程"**: 企业职能主管常见错误之一就是"不加变动地采用培训方提供的现成课程，该课程无助于员工在工作岗位上提升业绩"（b5-ce30，第12章 L12469）——培训采购层面的照搬同病。
- **把框架当教条**: 作者在册2 姊妹篇中明言要用"框架而非教条"推行（b2-p17 并入本主张）：强迫员工遵循会让框架变成"当地法律"，适得其反。
- **小公司照搬大公司结构**: 作者在 FAQ 中明确"很小的企业……不会从领导梯队中获得多少益处，除非这个企业正在快速成长"；小公司的定制方向是压缩层级（常把公司高管层与 CEO 层合并），而不是移植六层（第14章 FAQ L12852 附近）。

### 作者的盲点 / 时代局限

- **"定制获益更多"是自我报告**: "根据本企业实际情况修改的企业比没修改的获益更多"没有对照组与量化证据，属于咨询顾问的经验主张（BOOK_OVERVIEW 批判节：咨询顾问的样本与利益）。
- **定制缺乏判据**: 改到哪里算够、改过头会不会丢失模型内核，书中没有给出边界；实践中可能被用作"任意裁剪"的通行证。
- **模型内核仍绑定美国大公司科层范式**: 无论怎么定制，六阶段与"逐级历练"的假设来自 GE 式组织；对扁平化、平台型、敏捷组织，定制的空间可能超出框架自身承载力。
- **中文语境的本地化张力未被处理**: 国企干部管理、劳动关系与"公开评估/按业绩排名"等做法的适配问题，书中只在推荐序层面被提及（BOOK_OVERVIEW 批判节）。

### 容易混淆的邻近方法论

- **最佳实践标杆学习（benchmarking）**: 标杆学习容易退化为形式模仿（抄工具不学实质，参 b4-ce09）；本 skill 的方向是先看自己有什么层级与语言，再决定借鉴哪一部分。
- **变革管理中的"以试点先行"**: 试点是推广策略；本 skill 还包括"改层级数、改术语、改标准"的内容改造，不只是节奏安排。
- **全面质量管理/流程再造等管理时尚的引入**: 那些是具体方法；本 skill 提供的是"引入任何外来管理模型都要本地化"的元纪律，可与之组合。
