# 管理/技术双轨发展框架

## R — 原文 (Reading)

> "公司经常存在领导职位过多，但领导力不足的状况。我们发现领导梯队模型最大的好处就是能让人突出意识到“多领导综合征”的存在。……技术能力强的人应当获得一个头衔，领导几个人并获得加薪，但他们仍然应该把大多数时间用在技术性工作上。"
>
> — 查兰/诺埃尔/德罗特，第1章（L9942）

> "界定一个技术人才的发展轨迹，也是个很好的想法。……这个发展轨迹为那些没有领导能力或者不想做领导，同时又想接受更大挑战取得更多报酬的人，提供了一个很好的选择，它确实对领导梯队建设的畅通很有帮助。"
>
> — 同上，第1章（L9944）

> "工作调整　一些初任经理还没有为新岗位做好准备，他们需要重返员工岗位继续锻炼和准备。另外一些从本质上不具备领导潜质，不适合担任领导工作，应该被安排在能够发挥他们才能的专业岗位上（如从销售员到超级销售员）。"
>
> — 同上，第2章（L10123）

---

## I — 方法论骨架 (Interpretation)

组织的奖酬体系往往只有一条上升通道：想加薪、想被认可，就得当经理。结果是用管理岗奖励优秀个人贡献者，制造出大量有名无实的管理职位——作者称之为"多领导综合征"：领导职位过多、领导力不足，头衔满天飞而管理形同儿戏；被奖励者没学会管理，未来提拔建立在虚假的管理经验上，真正适合管理的人又被稀释在头衔体系里。

解法是开第二条轨道：技术/专业发展轨迹。它给"没有领导能力或者不想做领导，同时又想接受更大挑战取得更多报酬的人"一个正式出口——同样加薪、同等尊重，但不必改行做管理。

技术轨不是头衔安慰奖，它有严格定义（册2《业绩梯队》的姊妹版说得更细）：技术性业绩梯队提供"一系列越来越具有责任感的个人贡献者岗位，这些岗位会对职能部门、业务部门或者整个企业的效能和方向产生影响"；它以**实现业务业绩为目的**（而不是提升个人技术水平，那是技术性职业阶梯），其成员要**参加所服务业务/公司的员工会议**以获得影响力、管理公司范围专业技能的使用、把知识转移给组织。

双轨还承担一个修复功能：对"从本质上不具备领导潜质、不适合担任领导工作"的已提拔者，放回专业岗位是官方选项而非失败——"如从销售员到超级销售员"。作者把它明确写进初任经理转型失败的处置手段之一（工作调整）。因此在领导梯队理论里，双轨既是留人机制，也是修复错配的出口。

## A1 — 书中的应用 (Past Application)

### 案例 1: 巴里——销售明星升销售经理，挣扎两年辞职回去做销售
- **问题**: 巴里热爱高自主性的销售工作；升任八人销售团队经理后，不适应大量观察、招聘、培训、写报告的工作，也失去了签单带来的心理满足感。他无法有效辅导下属，"他的下属也在挣扎，因为当他们渴望得到指导时，巴里并没有给予他们有力的支持"。
- **方法论的使用**: 作者用这个案例说明问题不在巴里缺潜力，而在公司缺少评估与教练机制：如果有评估机制，本可把他放到"超级销售员"轨道，或专门设计一条兼顾销售与带教的培养方案，而不是让他硬扛一个不适合的管理岗。
- **结论**: 用管理岗奖励顶尖个人贡献者，会同时损失一名优秀专家和一个管理岗位；正确的做法是提供技术轨与真实的选择。
- **结果**: "最后，巴里辞去了销售经理职务，到另一家公司担任销售代表"——在另一家公司获得更高薪酬与自主性；管理岗与个人双输，组织还流失了他。

### 案例 2: "头衔化"趋势——管理岗成为地位象征
- **问题**: 作者观察到"一个正在出现的、令人不安的趋势：经理越来越多，直接下属却越来越少，这是对业绩突出的个人贡献者给予的回报"；大量新任经理手下只有一两个人，管理工作根本填不满时间，于是又退回去做技术活。
- **方法论的使用**: 用"职位是否有真实的管理工作要求"作判据——"如果管理职务代表的是地位而不是一系列的管理工作要求，公司的管理就变得'形同儿戏'"；据此应把奖励与真实职责变化对齐，并为专家设置独立通道。
- **结论**: 头衔可以发，管理能力不能随头衔自动发放；管理幅度过小的"伪管理岗"既培养不了人，又埋下未来提拔失败的伏笔。
- **结果**: 作者在多个客户案例中指出（如册2 记录的"直接下属太少造成伪管理岗"问题）：组织持续"随意增长"，最终要靠有纪律的组织建设与双轨设计来纠偏。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 团队里最好的工程师/设计师/销售不想转管理，想给他加薪却没有管理岗可给。
2. 已经把一个优秀专家提拔成经理，结果他管得很痛苦、团队也不满意，用户想知道怎么收场。
3. 公司出现"经理越来越多、直接下属越来越少"的现象，头衔膨胀、管理变形式。
4. 要设计或改革专家晋升通道（技术序列、首席专家、超级销售员等），需要判定标准与纪律。
5. HR 或高管要论证"为什么不能只用管理岗奖励高绩效员工"。

### 语言信号 (用户的话里出现这些就应激活)

- "最好的工程师不想做管理，怎么留住他？/ 技术大牛当经理反而毁了"
- "经理越来越多，管的人越来越少 / 头衔满天飞"
- "能不能给专家一条晋升通道？/ 不升官怎么加薪？"
- "dual career ladder" / "individual contributor track" / "super salesperson" / "how to reward experts without promoting them to manager"

### 与相邻 skill 的区分

- 与 `b5-f04 first-manager-three-transitions` 的区别: 后者帮助"已经上任的初任经理"完成三项转型（技能/时间/理念）；本 skill 处理"该不该让他上任、不上任怎么留、上错了怎么退"。
- 与 `b4-f02 concentric-learning-job-design` 的区别: 同心圆学习解决"为有领导潜质者设计挑战递增的岗位序列"；本 skill 服务的是不想做领导、不具备领导潜质的专家，方向相反。
- 与 `b5-f32 corporate-function-six-relations` 的区别: 后者是职能主管层的矩阵关系与角色重定义；本 skill 是个人贡献者层的通道设计。
- 与册2《业绩梯队》的技术性业绩梯队（候选 b2-f18，已并入本单元）的区别: 那是同一制度在业绩侧的完整版本（以业务业绩为目的的岗位序列定义）；本 skill 侧重领导梯队侧的通道接口与修复功能，两者互为姊妹。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **先判定"该不该转管理"，不做默认假设**
   - 完成标准: 对当事人给出两项证据——本人意愿（是否真的想做管理）与能力证据（是否已展现通过他人完成任务的行为，如辅导、授权、目标设定）；明确指出"业绩好"不在证据之列。
   - 判停条件: 若证据表明他不适合或不愿意，停止按管理岗培养，转入双轨设计（步骤 2）。

2. **定义技术轨岗位序列（吸收册2 的严格标准）**
   - 完成标准: 写出 3–5 级专家岗位及其"业务影响范围"（影响团队/职能/事业部/公司），并规定每一级必须以业务业绩为目的、必须参加所服务业务的员工会议、承担知识转移与专业标准管理责任——与"只提升个人技术水平"的职称阶梯明确区分。

3. **把报酬与头衔接到业务贡献上**
   - 完成标准: 确认技术轨各级的薪酬区间与头衔可与同层管理岗对标（不等于必须相同）；不得用"名义经理"作为加薪的中转站；头衔对应真实职责而非地位。

4. **为已错配者安排官方回退出口**
   - 完成标准: 对已提拔但不适合的管理者，给出"重返专业岗"的完整方案（岗位、薪酬、公开说法、心理支持），并明确这是组织认可的正式路径而非失败惩罚（如从销售员到超级销售员）。
   - 判停条件: 若涉及降职降薪或取消头衔，声明须遵守当地劳动法与公司政策，不得单方降薪；调整须依法协商（参 b5-ce05、b5-ce31 ethics_legal_note）。

5. **治理"多领导综合征"**
   - 完成标准: 盘点每一项管理岗的管理幅度与真实管理工作量，识别"只有 1–2 个下属或大部分时间做技术活"的伪管理岗；给出合并、撤销或转换到技术轨的方案，并说明头衔与职级体系的调整须经合法程序与员工沟通。

6. **定期检查通道是否真正可用**
   - 完成标准: 用三个指标验证——高绩效专家中主动选择技术轨的人数、技术轨上的人员流失率、管理岗新任者的失败率；若技术轨形同虚设（无人愿意去、去了就被视为"没前途"），回到步骤 3 检查报酬与话语权是否真正对标。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 小组织里专家只有一两个人、形不成序列——此时更现实的做法是弹性头衔与项目角色，而不是正式双轨。
- 把技术轨当安慰奖：如果技术轨没有真实影响力（不进决策、不参加会议、薪酬明显低），它只是延迟流失。
- 用户想借此规避管理岗应有的责任（把不合格管理者悄悄转岗了事）——技术轨是正视匹配问题，不是掩盖问题的通道。
- 技术轨不能替代管理轨自身的改进：管理岗也要能被恰当设计、评价与培养。

### 作者在书中警告的失败模式

- **头衔化/多领导综合征**: "经理越来越多，直接下属却越来越少，这是对业绩突出的个人贡献者给予的回报。……如果管理职务代表的是地位而不是一系列的管理工作要求，公司的管理就变得'形同儿戏'。"（b5-ce05，第2章 L10190）——伦理提示：诊断涉及取消头衔/调整职级时，须遵守当地劳动法与公司政策；不得以"头衔虚设"为由单方降薪（b5-ce05 ethics_legal_note）。
- **用管理岗奖励高绩效个人贡献者**: "把晋升作为对高绩效个人贡献者的一种回报，将给公司的管理带来巨大的麻烦。"（b5-ce31，第1章 L9942–L9943、第2章 L10190）——调整职级/头衔体系涉及既有劳动合同与员工预期，需依法协商，避免单方降职降薪争议（b5-ce31 ethics_legal_note；同源反例 b3-ce10 册3 L6878）。
- **被动晋升**: "许多人都会接受较高层级上的职位……但是，自觉或者不自觉地，他们可能并不想去做这份新的工作……他们只是尽可能做得最好，但是，他们并没有按该层级的要求去履行职责。"（b2-ce10，册2 第10章 L5432）
- **伪管理岗**: "最大的错误就发生在那些只有两个、三个或者四个直接下属的领导者身上……因为直接下属较少，他们没有足够的领导工作……因此他们会去做一些技术性的工作来为企业做贡献。"（b2-ce21，册2 第9章 L5313）
- **个人贡献者的三种有害表现**: 愤世嫉俗、抵制变革、自我陶醉——团队里这类专家如果不被正确疏导与安置，会成为通道失效的另一种代价（b2-ce18，册2 第8章 L5093）。伦理提示：这三类表现的处置要在管理权限与合法合规框架内进行（对个人态度问题应辅导为主，避免以"态度"为名随意处理）；书中明确"合理担忧可以表达，但要在决定前、以正当渠道提出"（b2-ce18 risk_note）。

### 作者的盲点 / 时代局限

- **双轨是补丁，未进入模型内核**: 作者自己承认"超级销售员/技术轨迹"只是对领导梯队模型的补充；整个系列仍以"通过他人完成任务"为成功定义，专家路线的地位与评价体系未获同等展开（BOOK_OVERVIEW 最强反对意见第 3 条）。
- **知识工作者与创意型组织的适用性存疑**: 当专业判断、创造力与自主性成为主要价值时，"要么管人、要么被管"的双轨仍可能不匹配；书中没有讨论自治团队、专业合伙制等形态。
- **技术轨的评价标准未给出**: 如何判定"越来越具有责任感的个人贡献者岗位"的履职水平，册2 有框架但缺少可操作证据规则。
- **美国大公司语境**: 以大型、多层级、内部培养为主的公司为原型；中小公司或高流动性行业的双轨设计需大幅调整。

### 容易混淆的邻近方法论

- **技术性职业阶梯（technical career ladder）**: 那以提高个人技术水平为目的（册2 明确区分）；技术性业绩梯队以实现业务业绩为目的——本 skill 采用后者，使用时要先分清是哪一种。
- **职称/职级体系改革**: 那是 HR 制度工程；本 skill 的核心是"用第二通道承接不受管理岗的专家贡献"，头衔只是其中一环。
- **继任计划**: 那是为领导岗位准备人选；本 skill 处理的是"不进入领导岗位的人如何被公平对待与留用"。
