# 领导力发展六阶段模型（领导梯队总框架）

## R — 原文 (Reading)

> "通常，在大型的、分权管理的公司中，工作层级包括六个职业阶段或六次领导力转型。……每一个转折点都代表了公司职位的变化——在领导层级和领导力复杂程度方面不同，这些重大变化包括新岗位的工作要求以及新的领导技能、时间管理能力和工作理念。"
>
> — 导论「领导梯队的各个阶段」（fulltext L9663）

> "在大公司，从员工成长为首席执行官，需要经历六个领导力发展阶段。每一个阶段都是一个重大的转折，不可能通过读一本书或者参加几天的培训课程就可以学会。"
>
> — 第1章 概述（fulltext L9732）

> "每家公司都有自己的特性，可能至少有一个领导力阶段与众不同。但是在领导梯队模型的六个阶段中，你可能会找到一个与之相匹配的阶段。"
>
> — 第1章 概述（fulltext L9738）

## I — 方法论骨架 (Interpretation)

这套模型回答一个问题：为什么"干得好的人升上去反而干不好"？作者的答案是，领导工作不是同一件事的放大版，而是**六个彼此不同、必须逐一穿越的工作层级**，每次晋升都是一次"换专业"。

1. **六个阶段（美国大公司版本）**：管理自我（个人贡献者）→ 管理他人（一线经理）→ 管理经理人员（部门总监）→ 管理职能部门（事业部副总经理/职能主管）→ 管理事业部（事业部总经理）→ 管理业务群组（集团高管）→ 管理全集团（CEO）。注意"六次转型"对应七个站位：起点是"管理自我"，不是一个管理阶段。
2. **转折点不是头衔**：每个转折点意味着工作要求、复杂度、以及技能/时间/理念三件套的整体变化；岗位名字变了而工作内容没变，等于没转型。
3. **相邻层级"总体相近、具体差别重大"**：这是全书最关键的判断——正是这种"看起来差不多"造成组织默认"他能做好现在就能做好下一个"，也正是差别最容易被忽略之处。
4. **定位器而非阶梯**：模型的用途是把人的**实际工作层级**找出来（对照岗位应有层级），从而暴露"在错误的层级工作"；一个公司里几乎所有层级都可能出现错位，尤其高频于一线经理、事业部总经理、集团高管三层。
5. **层级数可定制**：六个阶段是"大公司原型"（GE 式），小公司可能只有"管理自我→老板"一级，扩张后再逐层长出；公司可设 5 层或 7 层，关键是相邻层要求必须可界定、无重叠无空当。
6. **用法**：给公司定层级语言、给岗位定层级、给个人定位、诊断阻滞（哪一层卡住）、设计选拔与继任标准（不可越级；跳过阶段者要补课）。它是全系列的公共骨架：册2 用同一套层级讲"每层交什么结果"，册4 讲"怎么按阶段培养"。

## A1 — 书中的应用 (Past Application)

### 案例 1: 鲍勃与玛丽——两个"有潜能却被阻滞于系统"的领导者
- **问题**: 作者在导论中给出两位受阻的新任领导者：鲍勃（能力极强的工程师，刚被提拔为团队经理）仍坚持"自己找出工程解决方案"，在给下属分配任务前一直和下属直接竞争，"这让他的下属感觉很受压抑，双方都觉得在浪费时间"；玛丽（原销售经理，现事业部副总经理）看不懂跨部门矛盾，受挫后回到自己熟悉的客户关系领域"硬闯"，只做了新职责的一部分。
- **方法论的使用**: 用六阶段模型给两人定位——鲍勃处在第一转型（管理自我→管理他人）却保留着第一阶段的工作理念；玛丽处在第四转型（管理职能部门→管理事业部）却仍以业务型而非战略型方式思考。
- **结论**: 两人都"具备成为领导者的潜能，但是潜能却没有得到完全的发掘……已经被阻滞于系统中"，问题不是能力不足而是层级不匹配。
- **结果**: 作者以此论证：帮助这类领导者转型需要时间、资金、精力和情感投入，且必须在领导梯队框架内完成——单纯挖人或短期培训都补不上（L9702）。

### 案例 2: 约 50 家小公司的并购贷款评估——转型失败成了信用风险
- **问题**: 一家向小公司提供并购贷款、要求评估借款方能否管好并购后"变大"的公司的金融服务机构，请作者研究"新设管理层级后创始人能否适应"。
- **方法论的使用**: 把"创始人是否完成领导力转型（是否肯放弃事必躬亲和是否肯信任新增的管理层级）"作为判断标准，逐一评估约 50 家贷款企业。
- **结论**: "在研究了大约50家贷款公司后，我们发现失败的公司都是源于它们的领导者没有改变原来的工作习惯，他们很难放弃事必躬亲，也很难信任一个新的管理层级。"
- **结果**: 结论被用于贷款评估标准；作者据此把小公司模型并入六阶段框架——每新增一个层级都是一次失败高发点，领导力转型因此从 HR 议题变成可计量的经营风险（L9863）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户要**设计或校验公司的管理层级/晋升通道**："我们公司从员工到高管应该设几层""怎么给每一层定名字和职责"。
2. 用户观察到**某人升职后反而表现变差**，想判断是"人不行"还是"岗位要求变了"——需要一套定位语言而不是直觉。
3. 用户面临**越级提拔/快速提拔**决策（尤其年轻高潜、顶尖 MBA、咨询顾问背景），想知道风险在哪、要不要补课。
4. 用户想**给"领导力发展/继任"建立一套共同语言**，让选拔、培养、评价、继任对齐到同一套层级标准。
5. 用户在做**组织诊断**，发现"各部门都在做下一级的工作"，想定位阻滞发生在哪一层。

### 语言信号 (用户的话里出现这些就应激活)

- "领导梯队 / leadership pipeline / 六阶段 / six passages / 六次转型"
- "从员工到 CEO 要经过几个层级 / 管理层级怎么分 / 晋升通道怎么设计"
- "他升上去了反而干不好 / 提拔太快 / 越级提拔 / skip a level / 跳过了某个阶段"
- "我们公司各层都在做下一级的事 / 层级错位 / working at the wrong level"
- "该不该给这个岗位加一层 / 公司就二三十人还要不要设经理"

### 与相邻 skill 的区分

- 与 `three-dimension-transition`（本册）：六阶段回答"你在哪一层"，三维度回答"你在这一层缺什么"——先定位后体检，二者常连用但不要互相替代。
- 与 `performance-pipeline-interview-build`（册2，业绩梯队）：同一套层级的业绩侧——它回答"每层该交什么结果"，本 skill 回答"每层是什么角色"；用户问"考核标准"多属对方，问"角色/层级"多属本方。
- 与 `apprenticeship-model`（册4）：那是"怎么按阶段把人培养出来"的供给侧方法；本 skill 只负责定层级与定位，不含培养路径设计。
- 与 `diagnosis-five-steps`（本册）：本 skill 输出"层级定位"，那条输出"个体/组织诊断的操作流程"；若用户已经明确要"查一个具体的人"，直接用后者。
- 与 `potential-three-types` / `nine-box-actions`（本册）：那两条处理"潜能与绩效的盘点分类"，本 skill 处理"层级与角色定位"，用途不同。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **自上而下定位本公司真实层级**
   - 先看 CEO 的直接下属是职能主管还是事业部总经理，再逐层下推，画出实际存在的管理层级与每层人数（含"名不副实"的层级）。
   - 完成标准: 一张实际层级图；每个层级能说出"这一层的直接下属是什么角色"。
   - 判停条件: 若公司人数少于 20 或只有"老板—员工"一级，改用小公司版结论（每加一层即新失败点），不要硬套六层。

2. **把现有层级对应到六阶段语言（或自定名）**
   - 允许层数为 5~7；为每层写一句话角色定义，并检查相邻层定义"无重叠、无空当"。
   - 完成标准: 每层既有公司自己的名称，也有对应的阶段定位；相邻两层的差别能用一句话说出"具体差在哪"。

3. **对每个相邻断点写出三维度差别**
   - 逐对列：技能（新能力是什么）、时间（日程该给什么）、理念（什么该放弃、什么是成功）。
   - 完成标准: 每个断点至少各写 1 条技能/时间/理念差别；找不出差别的层级对，考虑合并。

4. **用它给人/岗位定位（本 skill 的核心用法）**
   - 对个人：对照其实际行为与时间（不是头衔），判断他"实际工作的层级"与"岗位所在层级"是否一致。
   - 完成标准: 给出"实际层级 vs 应有层级"的判断及依据（行为/时间证据），而非仅凭印象。

5. **输出动作：补课、调整或澄清**
   - 对跳过阶段者设计补课；对错位者先查组织因素（薪酬、职责、资源、上司）再谈个人；对职责断裂/重叠的岗位对做澄清。
   - 完成标准: 每条定位结论都配 1 个可执行动作与验收方式；结论只用于发展对话，不直接作为人事处置依据。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **扁平化/平台型/项目制/敏捷组织**：六阶段以"大型的、分权管理的公司"为原型（GE 式科层），作者未正面处理"中层消失"与自治团队；在矩阵制、平台型组织里，层级可能并不按此分层，套用会制造伪问题。
- **组织很小或根本没有中间层**：<20 人公司只有一级，把它当"缺了五个阶段"来补是误用。
- **只想解决某个人的具体表现问题**：那是诊断类 skill（`diagnosis-five-steps`）的活；本 skill 是定位框架。
- **据此对个人做标签化评判或人事处置**：层级判断须先排除组织因素（薪酬、职责、资源、上司），且不构成人力资源法律意见，涉及调岗/解聘须依当地劳动法与公司程序（系列级伦理边界）。
- **把模型当人才库名单或胜任能力清单**：作者明确区分——重点不是"有多少后备"，而是"每层角色要求不同"；他也批评"一刀切"的胜任能力模型。

### 作者在书中警告的失败模式

- **组织默认的晋升假设（b5-ce35）**："公司总是做出这样的推断：如果一个人能够出色地完成某个岗位的工作，那么他也会同样出色地完成下一个岗位的工作"——由此"几乎所有的组织都存在把人员配置在错误领导层级的问题"，这种错位有时还成为一种"沾沾自喜的文化"。
- **跳过发展阶段（b5-ce18）**：越级担任 CEO 者"将为缺乏必要的经验而付出代价"；作者特别指出"许多咨询顾问被选拔为集团高管，甚至担任首席执行官……表现往往比较糟糕，因为他们缺乏各个领导力发展阶段的历练"。
- **用旧阶段的方式干新阶段的事（b5-ce01）**："岗位是经理，思维却是业务员"；日程表被旧层级的事务占满，提拔后一年仍未完成新层级的关键动作。
- **层级错位（b2-ce01）**：拿 X 层级待遇做 X-1 层级工作——领导亲力亲为做技术性/事务性工作、关键战略与人才工作无人做。

### 作者的盲点 / 时代局限

- **"六个阶段是天然的"是修辞而非发现**：亚马逊式扁平化、华为式矩阵、平台型公司并不按此分层；书中对扁平化、敏捷、自组织的挑战没有正面处理（BOOK_OVERVIEW 系列级批判）。
- **科层制预设与 2000–2011 年美国大公司语境**：模型以 GE 为原型、以稳定的大公司节律为背景；对数字化/远程领导、算法管理、知识工作者自组织没有预见，对中国国企/民企的干部管理语境也未作本地化（中文版推荐序的对接存在未解决的张力）。
- **单因论与幸存者偏差**：把复杂的组织失败压缩为"层级错位"便于推销框架，对组织政治、股权结构、行业周期处理很薄；案例由作者自己参与背书，缺少失败企业与对照组。
- **层级本身可能是问题**：信息衰减、决策变慢、责任稀释——模型可能把过时的科层结构"合法化"；若团队自组织成为主流，"管理经理人员""管理职能部门"两层可能根本不存在。

### 容易混淆的邻近方法论

- 与 `three-dimension-transition`（本册）：本 skill 定位"哪一层"，它体检"这一层缺哪一维"。
- 与 `performance-pipeline-interview-build`（册2，业绩梯队）：同源作者、同一套七层级，但回答"每层交什么业绩结果"。
- 与 `role-clarity-gaps-overlaps`（本册）：本 skill 给出层级图，那条用层级图查"职责断裂/重叠"。
- 与 `apprenticeship-model` / `concentric-learning-job-design`（册4）：那是人才培养机制，不是层级定义。
- 与 `potential-three-types` / `nine-box-actions`（本册）：那是人才盘点分类工具。
