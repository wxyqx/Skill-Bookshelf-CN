# 人才评估会议机制（MRR）

## R — 原文 (Reading)

> "在霍尼韦尔，这些评估被称为管理资源评估（management resource review, MRR）。它们通常都是在春季和秋季举行，为期两天，而且一般是在战略和运营会议之间。"
>
> — 博西迪/查兰/伯克，第6章（L1759）

> "在进行会议的前一周，准备参加人才评估会议的人必须事先提交自己的评估报告，而且那些没有达到要求的评估还将被退还给个人，重写一遍"
>
> — 同上，第6章（L1763）

> "当你准备真正了解某个人的时候，最好的办法就是找五个认识这个人的人，把他们集中到一间屋子里，大家开诚布公，分享彼此对这个人的观点，直到最终达成共识。"
>
> — 同上，第6章（L1777）

---

## I — 方法论骨架 (Interpretation)

人才评估的价值不在表格，而在"结论被强制执行"。MRR 是一套有严格要件的会议机制：

1. **固定节律与咬合**：一年两次（春/秋），为期两天，安排在战略会议与运营会议之间——人才议题不是孤立的人力活动，而是战略与运营的中间站。
2. **会前书面评估（带退回重写规则）**：参与者须提前一周提交书面评估；两条退回理由——语言过于温和（如"很好"、培养需要填"无"），以及评估内容未与被评估者当面沟通。
3. **会中逐人讨论**：评估当前表现、潜在继任者、组织设计与技能需求；用"找五个认识他的人开诚布公地谈"的方式收集具体行为证据；允许保留异议，但由领导者做结论。
4. **会后固定结论**：给每位与会者写一封信，具体到人名、数字与行动（如"你有 1000 名工程师，其中 7 个人具有很高的潜力。这还不够！"），并明确后续跟进。
5. **产出三类决策**：培养（持续改进总结写明培养需要）、调岗、以及不胜任者的处置；同时兼顾继任深度与挽留风险两条线。

## A1 — 书中的应用 (Past Application)

### 案例 1: 沃尔特——20 分钟讨论推翻 CEO 的继任判断
- **问题**: 公司营销副总裁沃尔特（34 岁）聪明、和蔼、口才极好，被董事会列入未来 CEO 候选人，CEO 本人也相信他是最可能接班的人；正讨论把他安排去运营部门，作为接班的重要一步。
- **方法论的使用**: 小组几名成员此前观察过沃尔特，并从与其共事过的人那里收集了评估资料；讨论中浮现三点具体行为——他很少跟进自己所制定计划的实施、为获取大额订单忽视对公司资本投资的影响、偏爱大项目而忽视利润更丰厚的小项目。
- **结论**: 这些都是直接来自共事者的具体行为；"这次讨论的时间不到 20 分钟"，执行官们包括 CEO 很快得出结论：沃尔特既不适合接替运营部门，也不应成为 CEO 候选人。
- **结果**: CEO（原支持者）改变立场；公司为领导管道建立了更严格的标准。

### 案例 2: 韦尔评估——允许保留异议的集体判断
- **问题**: 四人小组评估入职三年的工程师韦尔（时任某部门主管）：他精通技术、了解客户、有创造力与亲和力，但不熟悉财务数据、经常无法达到预期目标、缺乏成熟商人头脑。
- **方法论的使用**: 一人提出反对意见，认为在克服技术与质量问题的形势下韦尔的表现已属不易；讨论数分钟后，多数人坚持"他没有完成任务……但事实是无法改变的"。
- **结论**: 结论是"韦尔具有非常大的潜力，但他仍需要更多的改进"；提出异议者并未改变想法，但这不影响最终结果——"在很多情况下，你不能要求每个人都同意你的观点，但只要能够听取更多方面的意见，你就能做出更为明智的决策。"
- **结果**: 会后博西迪给每位与会成员写信总结共识，这些信成为后续人才规划与领导输送渠道建设的基础，并随后跟进实施情况。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 公司每年做人才盘点，表格填完、会议开完，之后没有任何人事动作。
2. 用户要评估一位"呼声很高"的候选人，但收到的评价都是形容词，没有行为证据。
3. 用户想建立继任者名单，但不确定如何让评价足够诚实。
4. 用户发现评估会上一片和气：没人愿意说负面判断，结论都是"继续观察"。
5. 用户要把人才评估与战略/运营节奏咬合起来（一年两次、会前材料、会后跟进）。

### 语言信号 (用户的话里出现这些信号就应激活)

- "人才盘点做完就完了 / 盘完没人动。"
- "评估会开成走过场 / 评价都是温吞水。"
- "继任者名单没人信 / 怎么才能让评价诚实？"
- "talent review" / "succession review" / "how do I run a talent calibration"

### 与相邻 skill 的区分

- 与 `b5-f27 succession-five-steps` 的区别: 后者是继任计划的完整五步流程（含覆盖全员层级、90% 内部选拔等准则）；本 skill 是其中承载评估的那台会议机器。
- 与 `b5-f29 nine-box-actions` 的区别: 九格矩阵是分类工具，作者警告"只是面粉而非蛋糕"；本 skill 提供的是让分类有证据、有后果的程序。
- 与 `b1-f15 underperformer-tiered-handling` 的区别: 本 skill 在会上做出"谁需要培养、谁需要调整"的判断；具体如何分层处置一位表现不佳者，交给 b1-f15。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **把评估会排进战略/运营节奏**
   - 完成标准: 确定固定节律（如每年两次、每次两天）与时间位置（战略会与运营会之间），并公开全年日历。

2. **设定会前材料标准与退回规则**
   - 完成标准: 每位管理者提前一周提交书面评估，须含：关键业绩指标与未达标项、具体的培养需要（不接受"无"）、继任者判断；语言温和或未与本人沟通的评估退回重写。

3. **会中逐人讨论，用行为证据说话**
   - 完成标准: 对每位被评估者，至少收集 3 条来自共事者的具体行为事实；讨论当前表现、继任者、组织设计三件事；记录异议但由领导者收敛结论。
   - 判停条件: 若讨论停留在形容词层面（"很棒""还需要成长"），暂停并回到"请给出具体事例"。

4. **会后写信固定结论**
   - 完成标准: 24 小时内向每位与会者发出总结信，逐条写明共识、待办、责任人、时限与跟进方式（可参考书中示范：具体到岗位、人数、培养动作）。

5. **把结论转成人事动作并跟进**
   - 完成标准: 每项结论都落到一个动作：培养计划、岗位调整、继任准备或处置决定；约定下次复核时点。继任深度可用书中样板校准——GE 家电部门总裁 2001 年宣布离任当天即宣布继任者及该部门各级人员调动，说明其人才管道可随时补位（b1-c29）。
   - 判停条件: 若结论涉及降职或离开，转入 `b1-f15`，并先做合规与程序检查（见 B 段）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 管理幅度很小（如十余人团队）且没有独立的继任议题：轻量化的定期一对一更合适。
- 无法保证评价保密与程序公正时：公开评估会放大组织政治，应先解决信息保密、评价者构成与被评估者知情问题。
- 把本机制用作"秋后算账"或裁员工具：这会让评估材料失真，并带来法律风险。

### 作者在书中警告的失败模式

- **机械式（唯数字）业绩评估**: 只比对数字会奖励运气好的人、冷落在逆境中表现优秀的人、漏掉"从未来借债"的人，最终让真正优秀者灰心出走（b1-ce06）；跨册反例进一步指出，仅按业绩考核判断，几乎无法深入分析领导人才是在什么样的情况下完成目标，也几乎从未关注其天赋与潜质（b4-ce05）。
- **仅提拔忠诚者（心理舒适因素）**: 用"绝对忠诚"取代能力标准组建团队，关键岗位持续失能却拒绝替换（b1-ce08）。
- **未经历逆境者被推到关键岗位**: 履历漂亮、零过失但从没打过逆风仗的人被提拔，环境转恶时全盘被动；本机制正是发现这类问题的场所（b1-ce10）。
- **官僚填表式人才流程**: 照搬工具（表格/会议）而不学实质（真观察、真讨论、真反馈），流程走完、人才依旧没有成长，还制造"我们已在做"的错觉（b4-ce09，跨册反例）。
- **让基层主管负责识别人才**: 把最难的识人任务交给经验与视野最不足的层级，标准走样、名单同质化、漏掉真正的千里马（b4-ce07，跨册反例）——MRR 的参与者范围须覆盖到真正看得见行为证据的层级。

### 作者的盲点 / 时代局限（含风险提示）

- **风险提示（来自 b4-ce13，治理合规边界）**: 涉及董事会与继任议题的评估，须符合董事会决议合规、信息保密与内幕信息管理规定（书中亦提到接班人姓名须保密、发布信息阻谣言等）；评估会议的操作不得违反公司治理与证券监管要求。
- **"集体讨论能消除偏见"是未证假设**: 书中把"背后议论公开化"视为优点，但未讨论被评估者的知情权、程序公正与评估者群体偏差（同质化、政治联盟）；"本来是主观的评价也可能具有了一种表面上的客观性"（BOOK_OVERVIEW 未证假设 8）。
- **评估标准缺乏效度证据**: 潜能与继任判断的效度未被检验，须防标签固化造成事实上的歧视。
- **美国大公司语境**: MRR 的两天会期、多层级参与者等设置以 GE 式大公司为原型，中小组织须定制。

### 容易混淆的邻近方法论

- 与"绩效校准会"的区别: 绩效校准的目标是打分公平；本机制的目标是人才决策（培养/继任/处置）与责任落地。
- 与"360 度反馈"的区别: 360 度是数据采集工具；本机制是带着结论与跟进义务的会议制度。
