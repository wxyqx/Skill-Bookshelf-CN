# 公开创新，不偷偷摸摸

## R — 原文 (Reading)

> "在《精益创业》一书中，我强调过一点，经常有人说：'要保护创业团队不受居心不良的母公司伤害，'这其实是一种落后的思想。关键是如何说服母公司以及那些神经紧张的中层管理者，让他们知道创业团队的一切活动都是安全的。因此，偷偷摸摸搞创新很少能传来捷报。要想实现整个公司的转型改造，唯一的办法就是公开创新。"
>
> — 埃里克·莱斯，第 6 章

> "'我们不按标准流程办事，您介意吗？因为我们只是想生产样机让用户试用 60 天'。他问。工程部主管回答：'当然不介意。你们只是在实验，对吧？'"
>
> — 埃里克·莱斯，第 7 章（马汉冰箱案）

---

## I — 方法论骨架 (Interpretation)

"躲开母体、偷偷搞创新"听起来聪明，实际是死路：地下项目拿不到正式资源，成果没有合法性，做成了也无法落地，做黄了连学习都留不下。公开创新的意思不是天真透明，而是把实验的严谨性和风险控制亮出来，让神经紧张的中层看到"这些活动是安全的"，用透明换合法性。

作者并不天真：地下网络在公司里普遍存在，转入地下有时确实是项目存活的实际路径（火种保住了）。但地下只能是过渡态——在下个里程碑，必须带着可展示的结果公开出场，去换支持者、换特事特办的授权。长期地下等于资源与合法性双输。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 马汉冰箱——地下复活与公开转正（c08）
- **问题**: 马汉的 3D 打印冰箱团队项目被政治性取消；他选择转入地下，志愿者晚上接着干。但地下做不出结果：铰链测试按规定要耗资 50 万美元、费时 3 个月，比用户测试时间还长——"这跟多少台没关系，这是规定。"
- **方法论的使用**: 地下只用来保火种；团队在下一个节点争取到 CEO 支持后公开重启。面对死规定，马汉直接问工程部主管本人："我们不按标准流程办事，您介意吗？"——"当然不介意。你们只是在实验，对吧？"同时主动加装保障措施（UL 认证元器件）降低风险。
- **结论**: 真正让项目转正的不是地下坚持，而是"地下→公开争取支持者→特事特办"这条转换链；规定本身并不反对实验，只是没人问过。
- **结果**: 60 台冰箱完成 60 天真实用户测试；项目重新纳入试点，马汉获晋升。

### 案例 2: 作者对"保护性隔离"的否定（第 6 章）
- **问题**: 常有人建议把创业团队藏起来保护，免受"居心不良的母公司"伤害。
- **方法论的使用**: 作者称这是落后思想——正确做法是说服母公司，让人看到团队的一切活动是安全的（实验严谨 + 风险受控）。
- **结论**: 偷偷摸摸搞创新很少传来捷报；要实现整个公司的转型，唯一的办法就是公开创新。
- **结果**: 该论断成为转型第一阶段"公开试点+舞动宝剑"设计的政治前提。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 方案被管理层否了，正纠结要不要拉着同事私下继续做（影子项目）。
2. 团队在用个人设备/个人账号跑公司业务流程（影子 IT），讨论要不要继续瞒着。
3. 领导建议"先低调做，做出成绩再汇报"，需要判断低调的边界在哪。
4. 项目已地下运行一段时间，有初步结果，纠结怎么浮出水面而不被再次砍掉。

### 语言信号 (用户的话里出现这些就应激活)

- "偷偷做 / 先斩后奏 / 瞒着公司 / 别让 XX 知道"
- "影子项目 / 影子 IT / skunkworks / 地下创新"
- "被否了但我觉得方向是对的，要不要私底下继续"
- "innovate in the open / skunkworks project"

### 与相邻 skill 的区分

- 与同书 `three-tier-support-structure`（支持者三层结构）的区别: `innovate-in-the-open` 回答"为什么必须公开、地下最多多久"；`three-tier-support-structure` 回答"公开之后找谁支持"（发起人/支持者/教练的角色分工）。本 skill 是前半段，`three-tier-support-structure` 是后半段。
- 与同书 `wield-the-sword`（舞动宝剑）的区别: `wield-the-sword` 是公开出场的谈判结构（成果换清障）；`innovate-in-the-open` 是"要不要公开、怎么转正"的政治判断。
- 与同书 `one-page-preapproval`（一页纸预批文件）的区别: `one-page-preapproval` 把公开制度化——给公开实验修一条合规快车道；`innovate-in-the-open` 是在快车道存在之前的行为规则。
- 跨批提示: 与 ce08（"这是规定"）的解法直接衔接——公开+特事特办（直接问规则的主人）是 ce08 的出口之一。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **诊断当前状态**
   - 项目在公开场域还是地下？公开的真实障碍是什么（谁会否决、怕的是什么——合规、面子、还是政治）？
   - 完成标准: 一句话状态判断 + 障碍清单（区分"风险型障碍"与"政治型障碍"）。

2. **若在地下：设定转正里程碑**
   - 明确完成哪个实验节点就公开汇报；地下期间资源自担、范围自限。
   - 完成标准: 日历上有明确的公开日期与汇报对象；无日期的地下 = 判定为"永久地下"，进入第 4 步判停。

3. **公开时带三件东西**
   - 实验设计（可证伪假设/下一步/风险控制，对齐 `good-experiment-four-traits` 四特征）、风险控制承诺（限用户数、退款、不贴商标）、要的支持清单（少要钱、多要清障，对齐 `wield-the-sword` 宝剑结构）。
   - 完成标准: 一页公开材料 + 明确的请求清单。

4. **判停**
   - 判停条件: 公开后高层要求全胜/零风险，或障碍确属风险型且无法用实验设计化解 → 先解决期望（`one-team-success-is-enough`）或先合规（`one-page-preapproval`），不要硬闯；若两者都不成立，评估这个地下项目是否值得继续（有明确时限+愿意承担其成本）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 涉及真实法律/安全风险的实验: 公开 ≠ 免责，先走合规（`one-page-preapproval` 参数化预批），不要拿"透明"当通行证。
- 实验本身不严谨时抢先公开: 公开是政治动作，实验设计漏洞百出时公开只会授人以柄——作者的前提是"实验严谨 + 无极端责任风险"。
- 用保密保护真正需要保密的东西（知识产权、竞争情报）: 本 skill 处理的是"对母体隐瞒创新活动"的组织政治问题，不是商业机密管理。

### 作者在书中警告的失败模式

- "这是规定"（ce08）: 规则与触发条件脱钩后变成免责符号，公开也未必自动通——需要马汉式的"直接问规则的主人"+主动加保障措施。
- 永久地下 = 双输: 地下项目拿不到正式资源，成果无合法性；作者明确说"偷偷摸摸搞创新很少能传来捷报"。
- "只许成功"文化（ce02）下公开即危险: 失败会被政治化，此时公开前必须先谈好组合期望（`one-team-success-is-enough`）。

### 作者的盲点 / 时代局限

- 马汉案本身证明公开曾失败（项目被政治性取消才转入地下），作者把结局解读为"公开争取支持者"的胜利，但低估了公开触发否决的概率与公开失败后二次地下的无指导状态。
- "说服神经紧张的中层"依赖高层支持者存在这一默认输入；无 CEO 级支持的组织里，公开的成本被书中淡化。
- 案例均为作者深度合作的试点（GE 等），存在幸存者偏差与利益关联。

### 容易混淆的邻近方法论

- 与《精益创业》正传的区别: 正传面向独立初创公司，几乎不涉及母体政治；"公开创新"是对正传读者可能带有的"保护性隔离"直觉的否定，且承认地下网络的现实存在并给出转换条件——边界比口号精细，这是 2.0 的独有内容。
- 与开放式创新（open innovation, Chesbrough）的区别: 那是跨组织边界的协作创新；这里谈的是组织内部创新的透明度，两码事。
- 与经典 skunkworks（臭鼬工厂）传统的区别: 经典 skunkworks 主张隔离保密；本书立场相反——地下是过渡态，归宿是公开。
