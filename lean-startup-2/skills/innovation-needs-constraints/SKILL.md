# 没有制约的创新不是好创新

## R — 原文 (Reading)

> "如果团队认为让上面拨款不太难，就很难有创业团队的那种精力和专注度。没有制约的创新不是好的创新——资金过剩的项目往往有很高的创业死亡率，这种不光彩的例子很多。"
>
> — 埃里克·莱斯，第 7 章

> "优秀的创业者能够在工作中约束自己……比较大的公司必须更自觉地提出种种约束条件。'我告诉大家，我们的钱只够维持一个半月……但如果我们这段时间不能保证干好一件事，我们就完蛋了。'……但这也是一种解脱。这是我见过的效率最高的工作方法。"
>
> — 埃里克·莱斯，第 2 章

---

## I — 方法论骨架 (Interpretation)

直觉认为创新需要"要人给人、要钱给钱、少管多放"，本书给出相反判断：资源过剩不是福利而是风险，资金过剩的项目死亡率反而更高。

机制在于三点。其一，稀缺强迫专注：钱只够一个半月，团队就必须只做最重要的一件事，优先级不再是讨论题而是生存题。其二，约束是对付范围蔓延的武器：没有时间盒和资源上限时，每个利益相关者都有动机把计划加码得更宏伟，蔓延是系统的默认解。其三，约束改变汇报内容：资源宽裕的团队谈愿景和活动量，受约束的团队谈"这轮实验换回了什么学习"。

关键的分寸是"有限但可靠"：本书同时反对两个方向——既反对资源过剩，也反对审批过紧。约束必须在启动时一次性谈定、期内不追加干预、到期严格复审；它不是克扣，而是把"可失败次数"当作预算的真正计量单位。

## A1 — 书中的应用 (Past Application)

### 案例 1: 全球创新基金（GIF）的三阶段拨款与 SafeBoda
- **问题**: 非营利风投 GIF 给乌干达摩托车头盔项目 SafeBoda 等早期项目拨款，如何既防"水龙头式续命"，又不把种子掐死？
- **方法论的使用**: 把投资切成 23 万/230 万/1500 万美元三档，学习与成果的资金配比从 8:2 渐变到 2:8；第一阶段的钱只够回答"大家真的会戴头盔吗"这一条关键假设——稀缺被设计进了拨款结构本身。
- **结论**: 制约不是对创新的敌意，而是让每笔钱各司其职：早期只买学习，后期才买规模。
- **结果**: "阶段性投资让你关注正确的事情：风险、证据、影响"，该模式被证明适用于慈善部门。

### 案例 2: GE 印度可持续医疗方案的种子额度
- **问题**: 印度 6 亿人无保健覆盖，公司研发预算以 10 亿美元计；怀疑者断言低端产品削弱品牌、市场不够大。
- **方法论的使用**: 项目只拿到 650 万美元种子——与公司研发体量相比是刻意的"小钱"，团队据此聚焦母婴护理套件，把成本降四成并取得专利。
- **结论**: "钱只够一个半月"式的自觉约束，逼出了"20 美分一次的心电图机"这种大预算造不出来的专注。
- **结果**: 收入从 2012 年 3000 万美元增至 2015 年 2.6 亿，2016 年成立 3 亿美元规模的新公司；新用户中 35% 以上此前从未购买过 GE 产品。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 拿到一大笔创新预算（年度专项、孵化基金、高层特批），团队第一次手里宽裕，不知道怎么防止"慢慢做"。
2. 项目上了年度预算的"台面"，季度续费从无终止，上市日期持续后移而团队规模持续上升——疑似僵尸项目。
3. 产品范围持续蔓延：需求清单越来越长（"多种用户都要"），关键假设的验证排在开发完成之后。
4. 设计创新比赛/内部孵化规则，要决定给多少启动资金、给多久、何时收回。
5. 领导以"支持创新"为名要求撤掉所有限制（无限资源无限时间），团队反而失去方向。

### 语言信号 (用户的话里出现这些就应激活)

- "预算越足越好吧？我们刚拿了一大笔创新经费"（funding windfall / resource abundance）
- "这个项目做了三年还没上线，每年都能续上"（zombie project / 水龙头拨款）
- "需求越来越多，什么时候算做完"（scope creep / 范围蔓延）
- "要不要给创新团队更多时间和钱，让他们安心做"

### 与相邻 skill 的区分

- 与同书 `milestone-based-funding`（里程碑式资金拨付 vs 按指定用途拨款）的区别: `milestone-based-funding` 是资金机制设计（钱怎么给：里程碑结构、七项好处、铁律），`innovation-needs-constraints` 是资源纪律原则（团队与出资方共同的心智立场：约束本身是方法的一部分）。先有 `innovation-needs-constraints` 的立场，`milestone-based-funding` 的机制才立得住。
- 与同书 `growth-board-design`（增长委员会设计）的区别: `growth-board-design` 管"谁在什么节点裁决给不给下一笔"，`innovation-needs-constraints` 管"这一笔为什么要留缺口"。拨款结构的裁决者是 `growth-board-design`，自我设限的是团队自己。
- 与同书 ce04/ce11 反例的区别（对用户的表达方式）: 用户描述的是症状（蔓延/续命），本 skill 给的是病因与处方（无制约）。
- 跨批提示: 与 `organizational-experiment-loop`（精益实验循环五步法）的区别——`organizational-experiment-loop` 是实验怎么跑，`innovation-needs-constraints` 是跑实验的资源容器怎么造；容器先于循环。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **给项目立"不可展期"的约束一句话**
   - 完成标准: 一句话写全三项硬数字——本实验只有 X 人、Y 资金、Z 周，且到期不可自动续期。数字由团队与出资方当面确认，不是单方宣布。

2. **诊断当前资金机制属于哪一类**
   - 完成标准: 能明确指出项目是"水龙头"（季度滚动续费、取消要有人背政治责任）还是"里程碑"（下一笔取决于验证式学习），并说出对应的副作用（延迟推出最优 vs 稀缺带来的专注）。

3. **把"钱多"重定义为"可失败次数多"**
   - 完成标准: 列出本轮要测的假设数，给每次失败标出成本上限，资源总量被表述为"够失败 N 次"而不是"够做 M 个月"。

4. **判停（资源过剩侧）**: 若出资方坚持全额拨款且拒绝设终止条款，不要启动——先回到 `milestone-based-funding`/`growth-board-design` 争取"里程碑+严格复审"结构；无制约的项目按书中判据大概率进入高死亡率通道。
5. **判停（审批过紧侧）**: 若所谓"制约"已紧到连一次真实用户接触都无法负担，这不是制约是绞索——谈判目标是"有限但可靠"，必要时缩小项目范围而不是接受不可行的资源。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 成熟业务的确定性执行（财务月结、生产线品控）：那里的问题恰恰是消灭变异，六西格玛式纪律成立——创业管理不能替代传统管理。
- 以"设限"为名中途克扣已承诺资源：约束必须期初一次性谈定；风投不会在种子轮后打电话要回 20 万，期内追问用途只会培养汇报表演。
- 安全、合规等硬约束场景：红线不是"制约"的谈判对象，应走 `one-page-preapproval` 的预批参数化。

### 作者在书中警告的失败模式

- ce11 水龙头式拨款：项目立项即续命，取消反而要有人背政治责任；最优个人策略是延迟推出、把后果留给继任者。
- ce04 范围蔓延与"等造出来再建分销"：没有时间盒时，每个利益相关者都有动机把计划加码得更宏伟，成本由未来的自己承担。
- ce22 独角兽拨款失误：只给自由不给问责（给了钱没有任何预定检查点）同样失败——约束与问责必须同时设计。

### 作者的盲点 / 时代局限

- 案例来自作者深度合作或投资的试点（GE/财捷），"稀缺带来专注"缺少对照检验，存在幸存者偏差与推广动机。
- "有限但可靠"依赖组织真的会兑现下一轮复审；在政治内耗型组织，稀缺反而激励表演性汇报——正如 BOOK_OVERVIEW 强反对意见所指，创新核算类机制容易退化为新的表演性指标。
- 书中默认团队可以选择"要不要这笔大钱"；现实中内部团队往往无权拒绝资源，主动放弃预算的政治成本被低估。

### 容易混淆的邻近方法论

- 与《精益创业》正传"MVP 最小化"的区别: 正传讲单个产品的最小化（少造功能），本书讲组织给创新项目的资源约束设计（时间盒、拨款结构、"钱只够一个半月"式自设约束）——层级不同，别把 `innovation-needs-constraints` 讲成"把产品做简陋点"。
- 与"抠门文化/成本压缩"的区别: 约束的目标是买学习，不是省钱；压缩到无法实验就走到了作者反对的另一个方向。
- 与 ce20 砍光森林式短期主义的区别: 制约不等于季度 KPI 压榨——那是抽取长期资产，本书的制约是保护长期学习。
