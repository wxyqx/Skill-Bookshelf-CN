# 里程碑式资金拨付 vs 按指定用途拨款（对偶模型）

## R — 原文 (Reading)

> "这种体制我称为按指定用途的资金拨付……一旦上了台面，就成了大多数管理者所说的'水龙头'——不时有资金流出。……大多数项目在拿到资助的下一年还会继续拿，也许数量会有不同，但很少会被取消。"
>
> — 埃里克·莱斯，第 7 章（行 2771-2775）

> "里程碑式的资金拨付的原则是：钱你随便花，但要争取更多资金就必须达到极其严格的标准，关键是看你验证式学习的结果怎么样。"
>
> — 埃里克·莱斯，第 7 章（行 2787）

> "没有制约的创新不是好的创新——资金过剩的项目往往有很高的创业死亡率。"
>
> — 埃里克·莱斯，第 7 章（行 2779）

---

## I — 方法论骨架 (Interpretation)

一笔创新资金只有两种给法，它们塑造两种完全不同的行为：

- **按指定用途拨款**：年度预算"水龙头"——上台面极难、上台后极难断。理性反应是延迟推出（推迟失败、把后果留给继任者）、堆积"无限正当理由"、为续命而表演。作者指出其激励分析的荒谬处：把上市期推到很久以后，管理者照样晋升，还不用担责。
- **里程碑式拨款**：整笔预付、随意支配、团队承担全部成本；下一笔钱取决于"用这笔钱验证了什么学习"，而不是时间表或进度。它带来七项好处：稀缺心态（专注与优先级）、失败责任转移（团队自己算终止账）、组合管理、政治压力小、聚焦"我需要学什么"、跨职能合作（劳酬出自同一预算）、中层干预减少。

关键区别于"阶段预算"：里程碑是**学习里程碑**，不是日历节点或审批点。钱与复审必须同时设计——只给钱不设复审是 ce22 式失误，只设审批不给自由是另一种指定用途。

## A1 — 书中的应用 (Past Application)

### 案例 1：全球创新基金（GIF）与 SafeBoda——社会部门的里程碑拨款
- **问题**：慈善资本习惯一次性大额资助，项目死了钱也没了，资助方无法区分"真探索"与"烧钱"。
- **方法论的使用**：GIF 把投资切成三个阶段（23 万/230 万/1500 万美元），早期阶段的钱"是给你去学习用的，而不是要看你的成果"，学习与成果的资金配比从 8:2 渐变到 2:8；乌干达摩托车头盔项目 SafeBoda 在第一阶段只需回答一个假设——"大家真的会戴头盔吗？"
- **结论**：阶段性投入让双方聚焦正确的事情：风险、证据、影响。
- **结果**：该模式被证明适用于慈善部门，SafeBoda 按里程碑逐级获得放大投资（第 7 章，案例 c19）。

### 案例 2：GE 可持续医疗（印度）——小额种子长成新公司
- **问题**：印度 6 亿人无保健覆盖，但"低端产品会削弱品牌、回报率低"的质疑让常规预算流程不可能批大钱。
- **方法论的使用**：ICFC 项目只给 650 万美元种子（对比 GE 十亿美元级研发预算），按里程碑复审：团队先做 20 美分一次的心电图机验证市场，再聚焦母婴护理套件降本四成并获专利，逐阶段追加。
- **结论**：小钱+严格学习门槛能走通大企业不敢走的路。
- **结果**：收入从 2012 年 3000 万美元增至 2015 年 2.6 亿，2016 年成立 3 亿美元的新公司，由增长委员会拨款（第 8 章，案例 c23）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 给创新项目、内部团队、实习生甚至孩子设计预算：想要"培养自主判断"而不是"讨价还价与汇报表演"——整笔预付+里程碑复审，期内不追问用途。
2. 组织在用年度水龙头拨款，项目一上桌就死不了：延迟推出、团队膨胀、上市日年年后移，需要换资金制度。
3. 决定"要不要给某项目断供"：判断标准应从进度变成"这笔钱换回了什么学习"。
4. 非营利/资助方场景：如何分期资助探索型项目并设学习门槛（GIF 模式）。

### 语言信号 (用户的话里出现这些就应激活)

- "预算应该按里程碑还是按年度拨？"（milestone-based funding / annual budget）
- "团队拿到钱就不着急了/项目一直不出活，该断供吗？"
- "下一笔钱怎么给？看什么标准？"（tranche / follow-on funding）
- "这笔钱是给他学习的还是看成果的？"（funding for learning vs outcomes）

### 与相邻 skill 的区分

- 与 `growth-board-design`（增长委员会）的区别：milestone-based-funding 是**钱**的制度（怎么给、何时断），growth-board-design 是**人**的机构（谁来判）。先有里程碑制度，委员会才有可执行的支票；先有委员会无里程碑，委员会只是建议团。两 skill 通常组合交付。
- 与 `innovation-accounting-three-levels`（创新核算三层次）的区别：innovation-accounting-three-levels 提供复审时衡量"学到了什么"的记账语言；milestone-based-funding 提供钱与学习的挂钩机制。
- 与 `innovation-needs-constraints`（没有制约的创新不是好创新）的区别：innovation-needs-constraints 是原则（稀缺是方法的一部分），milestone-based-funding 是把稀缺制度化的资金载体。
- 与《精益创业》正传"计量供资"的区别：正传讲硅谷风投的轮次供资原型；本书增量为企业版对偶命名（指定用途 vs 里程碑）、七项好处清单、"延迟推出对个人最优"的激励分析——把公司金融问题翻译成行为设计。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **诊断现有拨款体制**：判定属水龙头式还是里程碑式。
   - 完成标准：能指出三种水龙头症状是否存在——项目年年滚动从不终止 / 上市日持续后移而团队扩张 / 汇报全是活动量。

2. **定义里程碑**：把阶段切分为学习里程碑，写明每阶段"必须验证什么才能解锁下一笔"。
   - 完成标准：每个里程碑对应一条可测假设与门槛（语言见 `value-and-growth-hypotheses`、记账见 `innovation-accounting-three-levels`）；没有日历式"阶段=季度"的假里程碑。

3. **授权与成本**：整笔预付，团队随意支配并承担全部成本（工资、设备、设施），期内不追问用途明细。
   - 完成标准：报销与审批流程已为团队开专用通道；无兼职成本转嫁。

4. **设复审**：到期复审只回答一个问题——"用这笔钱验证了什么"。
   - 完成标准：复审以仪表板证据为准（领导者两问格式）；铁律生效：不能证明验证式学习，休想再拿一分钱。
   - 判停条件：复审若被要求同时审查进度与用途明细，说明退回了指定用途体制，回到步骤 3 修授权。

5. **配比与放大**：随项目成熟，把"学习/成果"的资金配比从 8:2 渐推向 2:8（GIF 模式），成熟后并入常规经营预算。
   - 完成标准：各阶段配比与解锁条件成文；用户若需要常设裁决机构，转 `growth-board-design`。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 需求明确、按合同交付的执行类项目（工程、外包、ERP 交付）——里程碑=交付节点，传统预算更高效。
- 成熟业务的日常经营预算——有稳定现金流可预测，水龙头式拨款在此并无激励扭曲。
- 只想"给钱图省心"、不愿设复审——一笔了之+零问责是 ce22（独角兽式失误），比水龙头更糟。

### 作者在书中警告的失败模式

- ce11 水龙头式拨款与资金过剩高死亡率：拨款与学习脱钩后，预算延续性取代价值成为生存标准。
- "延迟推出对个人最优"的激励扭曲：推迟失败可保晋升，后果归继任者——指定用途体制的系统性风险。
- ce19 "收获特别大"式续命：复审若无法审计学习，裁决退化为讲故事比赛。
- ce20 砍光森林：资金与激励设计的边界——若上层激励是季度回报最大化，任何拨款制度都会被短期主义绞杀。

### 作者的盲点 / 时代局限

- "团队承担全部成本"在大型组织的财务分摊现实里很难干净执行（间接成本、共用设施），书中以 GE 情境默认可分摊。
- 七项好处是机制推演+个案佐证，无对照实验；里程碑过密也可能诱发"为复审而优化"的指标游戏，书中未展开。
- 给孩子/实习生设计预算属本 skill 对 V2 问题的自然外推，书中并无原生个人场景案例，使用时应说明这是机制迁移而非原书教导。

### 容易混淆的邻近方法论

- 《精益创业》正传"计量供资"（metered funding）：硅谷原型；本书的企业版对偶模型与七项好处是增量。
- 阶段门径预算（stage-gate budgeting）：阶段=日历与审批，里程碑拨款的阶段=学习；形似神异。
- 项目独立核算（project P&L）：是记账手段；里程碑是裁决标准——有独立核算无学习复审，仍是水龙头。
- OKR/预算目标制：以年初承诺值为考核锚，恰是"预测当问责"（ce01）的资金形态。
