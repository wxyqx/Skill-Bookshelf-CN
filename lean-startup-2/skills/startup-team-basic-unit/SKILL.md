# 创业团队作为基本工作单元（实验-执行连续体 + 落地预谈判）

## R — 原文 (Reading)

> "公司领导者必须理解创业团队是一个基本的工作单位，不同于公司经常任命的其他项目团队……内部创业团队必须同时拥有研发部门的科学精神与严谨性；销售与营销部门以用户为中心的原则；以及工程部门井然有序的规范。"
>
> — 埃里克·莱斯，第 2 章（行 713-716）

> "在一家举步维艰的知名公司内部成立一支创业团队，肯定会对现有秩序产生威胁。但更大的威胁其实来自取得成功的初创公司本身。"
>
> — 埃里克·莱斯，第 2 章（行 727）

> "每一个业务单元都是一个组合，是实验和执行的某种融合，这样理解更为恰当。……现有业务领域的创新团队同样是新创意的重要源泉，并且可以对新创意加以测试。"
>
> — 埃里克·莱斯，第 2 章（行 751）

---

## I — 方法论骨架 (Interpretation)

把"创业团队"从一种项目形式升格为组织的基本工作单元，有三个关键设计：

- **定义**：专职、跨职能的小团队，同时具备三种基因——研发的科学严谨、销售营销的用户中心、工程的规范有序；它把项目当实验经营，可申请转型，直接向增长委员会问责学习成果。临时项目组、跨部门委员会、特别工作组都不满足这个定义，也不该套用这套问责。
- **实验-执行连续体**：每个业务单元都是实验与执行的某种配比——一端是新产品的初创团队，另一端是稳步增长的成熟产品部门。配比不是标签而是随时间移动的量：项目成熟，执行占比上升；成熟部门重新投入创业基因，实验占比也能回升。所以"要不要创新"首先问"配比要不要调"，而不是"要不要另立山头"。
- **落地预谈判**：成功的威胁比失败更大——成功会打破当初为试点破的例，引发组织排异（各方认领、管辖不出资）。因此立项时就要谈好"成功后去哪"：被现有部门吸收还是生成新部门？由谁、按什么指标决定？这是一场艰苦的、必须由专人完成的谈判，不能等成功后再补。

## A1 — 书中的应用 (Past Application)

### 案例 1：爱彼迎"白雪公主"——先愿景后团队，成功即常设
- **问题**：公司进入稳定期，切斯基担心的不是失败而是滑入"管理期"——组织失去建设期的实验能力。
- **方法论的使用**：先重画公司故事（聘皮克斯艺术家做"白雪公主"分镜），再让格比亚带 6 人团队驻纽约 3 个月孵化实验，直接到渔人码头问路人"你为什么来这儿？最想做的是什么？"；用真实行为迭代出 Trip/体验业务。
- **结论**：实验团队是创意的载体——"爱彼迎绝不会进入管理期，会始终处于建设期"的组织解法就是让创业团队常设化。
- **结果**：Trip 业务线成型；2016 年设 Samara 内部工作室作为常设内部创新机构（第 8 章，行 2883-2898，案例 c20）。

### 案例 2：亚马逊 Fire 手机之后——组合式再配置，不解散团队
- **问题**：Fire 手机上市即败，市值一度蒸发 1.7 亿美元；惯常做法是解散团队、追责负责人。
- **方法论的使用**：把 Lab126 团队当作基本工作单元保留并再配置到 Echo、Alexa 等项目——贝索斯用"柠檬水摊→汉堡店"的比喻说明组合式尝试与风险预备：失败的单位是项目，不是团队。
- **结论**：创业团队承载的是能力与人才，项目证伪后团队转入下一个实验；"如果公司不持续实验，不接受失败，最终只能沦落到孤注一掷"。
- **结果**：Echo/Alexa 等后续产品成功，失败被转化为人才与能力的再配置（第 1 章，行 511-520，案例 c06）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 成熟产品线的老板想"成立一个创新小分队"，纠结要不要设、向谁汇报、怎么考核。
2. 内部实验成功了，现有部门、创新孵化器、业务线都想认领，不知道该被吸收还是长成新部门。
3. 做组织设计：要弄清创业团队与项目组/委员会/敏捷小队的本质区别，以及它在架构图上的位置。
4. 业务单元想平衡"做完这季度的活"与"试验新东西"，需要一个思考配比的框架。

### 语言信号 (用户的话里出现这些就应激活)

- "创新小分队" "内部创业" "intrapreneurship" "孵化个团队" "基本工作单元"
- "实验还是执行" "成功之后怎么办" "项目被谁认领" "组织排异" "落地路径"
- 英文：internal startup team / basic unit of work / experiment-execution continuum / where does it land after success

### 与相邻 skill 的区分

- 与 `unified-entrepreneurial-theory`（统一的创业理论）的区别：`unified-entrepreneurial-theory` 在公司层回答"四类活动归谁管"（创业部定位与七项职责）；`startup-team-basic-unit` 在工作单元层回答"团队怎么定义、放在连续体哪里、成功后去哪"。`startup-team-basic-unit` 的团队是 `unified-entrepreneurial-theory` 体系内的原子单元。
- 与 `dedicated-cross-functional-teams`（跨职能团队必须专职（缺编就借义工））的区别：`dedicated-cross-functional-teams` 是团队构成的构成规则（专职性、借义工、业务人员早期加入）；`startup-team-basic-unit` 是团队的存在方式与生命周期（连续体位置、成功后去向、问责对象）。
- 与 `growth-board-design`（增长委员会）的区别：`growth-board-design` 是团队的问责机构（审学习证据、拨里程碑资金）；`startup-team-basic-unit` 是被问责的对象的设计。问"要不要建团队"用 `startup-team-basic-unit`，问"怎么审它"用 `growth-board-design`。
- 与 `pivot-persevere-cadence`（转型/坚持会议节奏设计）的区别：`pivot-persevere-cadence` 是团队层面的决策节奏；当转型/坚持会决定"转型"时，常意味着连续体位置的移动（配比重调），两者在时序上衔接。
- 与《精益创业》正传的区别：正传里"团队"就是初创公司本身；本书把创业团队移植为大组织内的基本工作单元，并处理它与母体的一体化问题（成功威胁、落地谈判）——这是"2.0"的定义性增量。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **定位连续体位置**
   - 完成标准：为该工作对象写出当前"实验:执行"配比与目标配比，并指认连续体上的参照点（更靠近新品初创还是成熟部门）；配比判断需有证据（现有业务的创新团队同样是创意源泉——先确认是否真的需要新团队）。

2. **判断是否值得设独立团队**
   - 完成标准：只有当实验对象是新市场/新商业模式时才设独立团队；若只是成熟线想加创新，先调整其配比与问责（在现有业务里做实验），给出"设/不设"的书面结论。
   - 判停条件：若结论是"不设独立团队"，转而设计现有业务的实验配比与问责调整，本流程终止。

3. **按定义配齐团队**
   - 完成标准：专职跨职能（研发严谨+用户中心+工程规范三类基因各有其人）、有明确增长命题、直接向增长委员会汇报学习证据；兼职拼凑的"团队"不予立项（回到 `dedicated-cross-functional-teams` 解决构成）。

4. **落地预谈判（立项时完成，不许延期）**
   - 完成标准：书面回答"成功之后怎么办"——被哪个现有部门吸收，或长成什么新部门；决定人是谁、判据是哪些指标（临界规模、财务影响格）；发起人与现有部门负责人在立项书上签字确认。
   - 判停条件：若无法完成预谈判（无人愿意承诺承接成功），缩小实验范围或改用"自由岛+预先设定的责任约束"（g04），并明示这是有意的限制而非疏忽。

5. **随成熟度移动配比并移交**
   - 完成标准：按转型/坚持节奏（`pivot-persevere-cadence`）定期复查配比；当执行成为主旋律且落地判据达成时，按预谈判把团队移交给承接部门，团队骨干转入下一实验（组合式再配置）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 需求明确、路径清晰的执行型项目套"创业团队"名头——那会让执行项目逃避执行问责（里程碑、交付标准）。
- 把全公司每支团队都改成创业团队——书中明言"并不是说现代企业中的所有事务都一定要由创业团队打理"，它只在极端不确定条件下是最佳组织形式。
- 只建团队、不做落地预谈判——等于埋雷：成功即排异开始。
- 以为再建一个创新实验室就等于有了创业能力——书中明言"现代企业需要的不仅仅是再建一个创新实验室"；实验室是项目集合，创业团队是基本工作单元。

### 作者在书中警告的失败模式

- ce16 无代表权税收：现有部门要管控权却不投资源；"成功后突然各方认领"——正是"更大的威胁来自成功的初创公司本身"的组织表现。
- ce22 独角兽拨款失误：以"创业情怀"拨款后放任自流、无检查点——有自由没问责的团队半年零用户，失败被解释而非被纠正；创业团队必须配增长委员会式问责。
- 第 2 章的观察：创新实验室负责人"很少对这种情况（成功后怎么办）做出规划"——强烈反应"来得很快（也会很致命）"，不能等出了问题再考虑对策。
- ce01/ce03 背景下的提醒：团队不等于护身符——把项目理解为实验才是定义核心；没有验证式学习的"创业团队"只是换了名字的项目组。

### 作者的盲点 / 时代局限

- "既要又要"假设未被机制化：企业同时稳定运营核心业务并孵化颠覆业务，书中靠组织隔离（自由岛）保证，但对隔离失效、资源被核心业务反向抽走的场景缺乏讨论（BOOK_OVERVIEW 未被证明的假设）。
- 对团队成员的个人代价着墨少：绩效悬置期、失败污点、"职业资产净值"受冲击（g28 提出概念但未展开解法）。
- 案例多来自作者深度合作的组织（GE、爱彼迎、亚马逊），存在幸存者偏差与利益关联；GE 的后续崩塌削弱了"基本工作单元拯救巨头"的叙事。

### 容易混淆的邻近方法论

- 创新实验室/内部孵化器：项目集合与空间概念；创业团队是工作单元+独立问责+转型权。书中明确反对把二者混同。
- 敏捷小队（squad/feature team）：以交付节奏定义的执行单元；创业团队以实验定义项目、可申请转型、向增长委员会汇报学习——一个优化路径，一个审查方向。
- 双元组织（ambidextrous organization，探索/利用分区）：学术上同源（连续体思想相通）；本书的可区分增量在"落地预谈判"——把成功后的组织排异当作立项时必须谈判的合同条款，而非事后再议。
