# 直觉设计三步循环（假设→尝试→高兴）

## R — 原文 (Reading)

> "1. 假设 自发建立'要××吗？'的假设。……2. 尝试 自发决定'试试××'，然后行动起来。……3. 高兴 自发确认'××是正确的'。" / "玩家不是因为游戏有趣才玩，是因为'不由自主就想到了，不由自主就做了'才玩的。"
>
> — 玉树真一郎，第1章《直觉设计的结构》/《比有趣更重要的事情》

---

## I — 方法论骨架 (Interpretation)

想让对方做一件事，不要告诉他，而是布置环境信息让他**自己**走完三步：①自发产生"要做××吗？"的假设（此时他不知道对不对，带着轻微不安）；②自发去试；③自发确认"猜对了"，高兴。三步必须全部是"自发"的——命令和指示制造不出自发性，它们只能被环境诱导出来。

这个结构的威力来自一个机制：**自己经假设→尝试→高兴学到的东西，一辈子无法否定**（如同骑车），因为怀疑它等于怀疑自己的五感和努力；而别人口头告知的知识很难被真正相信。附带的收益是"能让人直观理解的东西就很有趣"——易懂与有趣不是取舍关系。

要把三步串成长体验，有三条连接规则：①从开始到用户意识到"有趣"之间有几分钟到几十分钟的空窗，必须用一连串微循环填满；②每个微循环必须短——假设未确认的不安约 10 秒就到上限，超时人会放弃；③提高每个循环"猜对"的概率（靠简单、容易的假设和明确的线索），让高兴逐次累积，直到用户自己说出"这很有趣"——那一刻才是设计目标，且无法被直接给予。

## A1 — 书中的应用 (Past Application)

### 案例 1: 《超级马里奥》开场几秒钟
- **问题**: 不用文字说明，如何让全世界玩家瞬间知道"最重要的规则"？
- **方法论的使用**: 用马里奥的朝向、左边的山、右边的草和云布置"向右前进吗？"的假设；玩家按下十字键（尝试）；酷栗宝从右边出现，确认假设正确（高兴）——敌人都从右边来，说明向右是对的。
- **结论**: 玩家"冒死也相信"向右前进，因为这是他自己发现的。
- **结果**: 全球最畅销游戏，且孩子看开始画面会自发喊出"向右前进"。

### 案例 2: 《勇者斗恶龙》国王房间
- **问题**: RPG 指令系统复杂（8 个指令），怎么让人学会？
- **方法论的使用**: 故意把国王的房间从外面反锁——玩家必须对站着的勇者用"对话"指令才能出门；假设（跟他说话试试？）→尝试→"果然猜对了"（高兴）。5 个指令在出门前一口气学齐。
- **结果**: 被称为"游戏教科书"的指令教学，全程没有一条说明书。

### 案例 3: Wii Sports 的挥拍
- **问题**: 全新体感操作如何让人第一次就挥对？
- **方法论的使用**: 控制器形状本身引发"像球拍一样挥挥看"的假设；挥动时控制器发声，立刻确认"猜对了"。
- **结果**: 从《超级马里奥》手里夺走"家用机最畅销游戏"称号。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 设计新手引导/教程/onboarding，或现有教程完成率低、被跳过。
2. 写教学步骤、操作文档、课程设计——想让读者"跟着做"而不是"看完就忘"。
3. 让孩子/下属/用户主动做某事，命令和催促已经失效。
4. 评审一个功能的引导流程，怀疑"信息都给了但没人动"。
5. 设计谜题、彩蛋、互动环节，想让对方有"我自己想出来的"的成就感。

### 语言信号 (用户的话里出现这些就应激活)

- "怎么让他们**自己**发现/想到/去做"
- "教程没人看 / 引导被跳过 / 讲了等于没讲"
- "孩子（下属/用户）不肯做，怎么说都没用"
- "想让他有成就感 / 自己动手 / 不由自主"
- "onboarding / tutorial / let them discover / guided discovery"

### 与相邻 skill 的区分

- 与 `fatigue-timing-management` 的区别：本 skill 解决"如何产生行动"（单个循环怎么设计）；那个解决"连续行动之后累了怎么办"（节奏问题）。教程没人看→本 skill；看了一半弃坑→那个。
- 与 `comprehension-first-affordance` 的区别：本 skill 是心理过程编排（三步循环）；那个是信息取舍决策（第一秒传达什么、牺牲什么）。通常先用那个决定"该做什么"的线索，再用本 skill 编排确认过程。

## E — 可执行步骤 (Execution)

1. **写出目标行为与目标信念**
   - 完成标准：一句话说清"我希望对方自发做出××，并因此相信××"。
2. **拆成微循环序列**
   - 完成标准：列出 3-8 个"假设→尝试→高兴"单元；每个单元能回答"对方会从什么线索产生什么假设、怎么试、怎么确认"。判停条件：若某单元想不出自然线索（只能靠直接指令），回到步骤 2 重新拆或先做 `comprehension-first-affordance` 的信息取舍。
3. **给每个单元做三个体检**
   - 完成标准：①单循环 ≤10 秒内可得到确认（教学/阅读场景可放宽到 1-2 分钟，但确认必须明确）；②"猜对"概率高（线索明确、难度低）；③对方无法从你的措辞里直接读出答案（没有命令感）。
4. **排布顺序并埋首循环**
   - 完成标准：第一个循环放在对方接触后 10 秒内；连续循环之间情绪递增；最后标出"用户自己说出'有趣/我会了'"的目标时刻。
5. **试跑并只修线索不修人**
   - 完成标准：找 1-3 个目标用户观察：卡住的循环修线索（更明确、更简单），而不是加说明文字。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **合规、安全、法律类指令必须明示**——"让用户自己发现退货流程"会造成真实损失；自发性适用于学习与行动意愿，不适用于必须一次做对的规程。
- **对方缺乏前提记忆时**——塞尔达的谜题成立是因为"木柴会燃烧"人人知道；你的线索若嫁接在目标人群没有的共同记忆上，循环直接失效。
- **时间压力极高的紧急场景**——10 秒不安上限等不起三步循环。

### 作者在书中警告的失败模式

- 假设悬置超过约 10 秒，用户放弃（马里奥如果一直只看到平地，10 秒就关机）——ce07。
- 问题复杂到"39271÷23"的程度，人连试都不试——简单、容易是绝对条件（ce08）。
- 显示了信息却不显示方法（有分数没有得分法），用户走投无路（ce04）。

### 作者的盲点 / 时代局限

- "自发性学到的东西一辈子无法否定"是经验断言——自发习得的**错误**同样坚固，本 skill 需要配一条纠错回路（第 4 步试跑）。
- 案例来自单机游戏时代的低风险环境；现实行动有真实代价时，"猜错"的挫败要被设计得更轻。

### 容易混淆的邻近方法论

- 游戏化（点数/徽章/排行榜）：那是外部激励，本 skill 制造的是内在的"我发现的"确信；先发徽章后发整体感的做法恰恰破坏空缺识别（见 `gap-collection-engine`）。
- 建构主义/discovery learning（教育学）：同源但本书给出可操作的硬参数（10 秒上限、成功概率、填满空窗），按参数执行。
