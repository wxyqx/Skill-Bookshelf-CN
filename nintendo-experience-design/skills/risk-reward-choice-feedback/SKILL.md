# 风险回报选项与反馈闭环（选择和斟酌）

## R — 原文 (Reading)

> "从设计师的角度来看，就是准备风险和回报不同的几个选项，设计让人自由选择斟酌的体验。" / "游戏让玩家觉得'失败是你的错'是必要的。……为让玩家真心'想变得更好，想成长'，只能让玩家在失败的基础上后悔自己的操作。"
>
> — 玉树真一郎，第3章《成长的主题2：选择能得到的东西》/《带来成长的最佳体验》

---

## I — 方法论骨架 (Interpretation)

成长的第二个主题是"选择和斟酌"：给每个选项配置不同的风险与回报（走，稳但慢；B 冲刺，快但会被最弱的敌人打败），让用户凭直觉自行斟酌，走出属于自己的路径。这个结构有两个隐藏功能：**选项就是自定难度器**——放任不管，用户也会自动调到"对自己难度适中"的程度并全力以赴，所以一款产品能同时给无数人带来最大成长；收集、选项等主题都兼任难度调节。

反馈是选择的前提：对用户的行为分别给予好坏评价，让他产生"我做得很好/我做错了"这种**以自身为主语**的感受。最反直觉的一条是归因设计——失败必须被归因于用户自己的操作（而不是运气、网络、设计），成功时明确表扬。主流产品习惯抢先替用户开脱，但那样成长欲望就死了：只有"是我的错"，才有"我想变得更好"。无法选择、或无论怎么做反馈都一样的产品，不可能有趣。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: B 冲刺
- **问题**: 马里奥走太慢，一直跑又太难，怎么平衡？
- **方法论的使用**: 两个选项并存——走（低风险低回报，沉着应对）与 B 冲刺（高风险高回报，又快又险）；玩家自己斟酌，得意忘形会被最弱的酷栗宝打败——失败是"我的错"。
- **结果**: 同一款游戏覆盖从孩子到高手的全谱系玩家。

### 案例 2: 刀与手枪
- **问题**: 《最后生还者》与《风之旅人》如何让玩家"有自己的冒险"？
- **方法论的使用**: 刀（稳妥但消耗大）与手枪（强但弹药稀缺）、能量元素与同行者的取舍——每个选项都有代价与收益，玩家斟酌出属于自己的打法。
- **结果**: 两部作品均获年度级评价，玩家叙事高度个人化。

### 案例 3: 作弊选项（第5章应用4）
- **问题**: 要不要给卡关的玩家跳过手段？
- **方法论的使用**: 马里奥的"移动区域"——把"是否作弊"留给用户；每次选择都确认"这是我自己决定的"，自由反而是回来的力量。
- **结果**: 越用越能感到自身成长（与 u13 的立场衔接）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 统一培训/教学后学员水平参差，在"分层教学"还是"统一进度"间纠结。
2. 产品难度无法兼顾：新手骂难、老手骂浅。
3. 设计反馈机制：要不要在用户失败时安慰/免责，怎么表扬才有效。
4. 方案只有一条路径，评审时被挑战"为什么没有备选"。
5. 设计通关路线/套餐/策略选项，想加"值得斟酌"的深度。

### 语言信号 (用户的话里出现这些就应激活)

- "给用户选择 / 让他自己选 / 备选方案"
- "风险回报 / 权衡 / trade-off"
- "难度分层 / 自定难度 / 简单模式和困难模式"
- "反馈怎么做 / 表扬 / 归因 / 怪谁"
- "meaningful choice / risk-reward / difficulty options / feedback loop"

### 与相邻 skill 的区分

- 与 `gap-collection-engine` 的区别：成长的两条主题——那个管"重复的粘性"（收集），本 skill 管"路径的斟酌"（选项与反馈）；书中明确可组合（收集选项兼任难度调节）。
- 与 `story-design-user-growth` 的区别：本 skill 是"成长"步的施工法；同时"意志"级终点决定（生命交换/未知体验）不属于本 skill——那是 `story-design-user-growth` 的领域，选项设计只到"策略斟酌"为止。
- 与通用 UX"减少用户认知负担"：方向相反处要警惕——本 skill 主张保留有价值的斟酌（选项对比清晰），不是无限给选择。

## E — 可执行步骤 (Execution)

1. **列出决策点**
   - 完成标准：找出用户在体验中真正做决定的位置（路线/策略/强度/投入），标注当前是"唯一最优解"还是"可斟酌"。
2. **配置风险回报对**
   - 完成标准：每个决策点给出 2-3 个选项，各自写明风险与回报（稳慢/快险/中间态），且差异真实可感——没有代价的"选择"是装饰。判停条件：选项间无真实代价差异 → 砍掉伪选项，宁少而对比清晰。
3. **接反馈闭环**
   - 完成标准：每个选择的结果都有以用户为主语的评价（"你这把选了冲刺，第 3 关翻车了"），失败归因于操作、成功明确表扬；检查没有"怎么做都一样"的死区。
4. **难度自检**
   - 完成标准：确认选项结构能让新手与高手各得其所（自动调档），无需额外做难度开关；若必须加开关，把它也设计成风险回报选项而非数值菜单。
5. **守住"斟酌"与"意志"的边界**
   - 完成标准：本 skill 的选择停留在策略层；涉及用户珍视之物的终点级决定，移交 `story-design-user-growth` 的意志时刻设计。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **安全关键与合规操作**——支付、医疗剂量、删除数据不允许"用户自己斟酌风险"，必须收窄为单一安全路径。
- **纯运气结果**——无可斟酌性时给选项是伪选择。
- **无限自由**——选项爆炸（几十个设置项）不是斟酌是负担；本 skill 的选项宁少而对比清晰。

### 作者在书中警告的失败模式

- 无法选择斟酌、或无论怎么做反馈都一样——"这样的游戏，怎么可能有趣呢"（ce23）。
- 得意忘形一直 B 冲刺被最弱敌人打败——这是特性不是缺陷：失败归因于用户是成长的前提（ce22）。
- 把失败责任推给别人（"都怪网络/怪队友"）——憎恨归因同时杀死反馈与成长（ce24）。

### 作者的盲点 / 时代局限

- "失败是你的错"建立在游戏的重来成本近乎为零之上；高代价现实场景（一次失误即重创）需要把"失败"拆解成小步可重试，否则归因设计变成纯挫败。
- 书中反馈即时且明确（游戏引擎天然如此）；弱反馈媒介（文字服务、线下培训）需要自行设计反馈通道，作者未展开。

### 容易混淆的邻近方法论

- 自我决定论（SDT）的自主需求：同源（自主促动机）；本书增量是"选项=难度调节器"的功能定义与"失败归因于用户"的硬规则。
- 无障碍/容错设计（error tolerance）：与"失败是你的错"表面冲突——容错针对系统故障与不可逆损失，本 skill 针对可重试的技能失败；先分清失败类型再选用。
