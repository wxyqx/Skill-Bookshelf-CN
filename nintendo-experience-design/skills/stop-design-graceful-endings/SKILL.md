# 让体验停止的设计（用户人生是主角）

## R — 原文 (Reading)

> "这里需要的是，在了解惊喜设计原理和效果的基础上，刻意让体验停止的体验设计。……通过回归日常的情节设计，将用户从产品中抽离。" / "对用户来说，重要的不是产品，而是用户自己的人生。用户的人生才是主角，产品只是衬托主角的配角。"
>
> — 玉树真一郎，第5章《应用4 设计/产品设计》

---

## I — 方法论骨架 (Interpretation)

整个增长行业的直觉是"延长停留、防止流失"，本书给出一个立场先行、然后一路反着走的框架。立场：**用户的人生才是主角，产品只是配角**——对产品的执着（"希望它被一直使用"）会让开发者堆功能、加钩子，最终做出让用户望而却步的东西。

从这个立场推出三条设计规则。①**在停止点禁用惊喜**：惊喜设计的唯一功能是延长体验（它靠打破坚信重新激活人），把它用在收尾处，产品就变成时间黑洞；想让用户走，就要在结束前后刻意不用它。②**用回归日常收尾**：老动画片的结尾为什么是夕阳下堤坝上回家的宁静画面？设计师在说"这个体验到此结束了"——孩子们心情愉快地关掉电视。给退出设计同样的宁静情节，宣告"结束了"而不是"明天还有更多"。③**把自由还给用户**：随时可停、甚至"作弊"（马里奥的跳关区域）。每次自由选择都在确认"这是我自己决定的"，这份自由恰恰是用户反复回来的力量；断签焦虑服务的是产品的存续，不是用户的人生。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 动画片结尾的宁静
- **问题**: 孩子看完一集还想看，怎么让他平静关掉电视？
- **方法论的使用**: 结尾播放轻松主题曲、描绘主人公在夕阳堤坝上走回家——用回归日常的情节宣告"体验结束了"，且停止点前后不用任何惊喜设计。
- **结果**: 孩子心情愉快地结束，明天还想看（作者的分析：这是"让体验停止的设计"）。

### 案例 2: 马里奥"移动区域"
- **问题**: 卡关的玩家会不会流失？
- **方法论的使用**: 提供跳关的"作弊"选项但不推荐——是否作弊由用户每次自己决定，每次决定都确认自身成长。
- **结果**: 自由成为重新使用产品的力量（与 `risk-reward-choice-feedback` 的选项设计衔接）。

### 案例 3: DQ4 赌场（战略暂停的近亲）
- **问题**: 20-30 小时的冒险疲劳累积。
- **方法论的使用**: 设计"暂时停止冒险"的段落，让玩家痛快玩赌场、拿强装备，心情愉快地回归主线。
- **结果**: 停止不是流失，是节奏（证明"停下来"可以是被设计的正面体验）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 数据看板显示停留时长下降，团队在焦虑要不要加钩子。
2. 设计关服/结课/完结/毕业/退出的流程与文案。
3. 争论"连续签到 100 天"徽章、断签提醒、防沉迷功能该不该做。
4. 每次退出前要不要再弹"再多看一条？"的自检。
5. 长体验（课程/剧/游戏）的收尾节奏设计。

### 语言信号 (用户的话里出现这些就应激活)

- "怎么让用户体面地离开 / 结束"
- "防沉迷 / 防上瘾 / 别让用户泡在里面"
- "要不要提醒他回来 / 断签了要不要push"
- "停留时长掉了，慌不慌"
- "offboarding / graceful exit / digital wellbeing / end gracefully"

### 与相邻 skill 的区分

- 与 `surprise-design-two-beliefs` 的区别：本 skill 的前提是**理解**惊喜设计的原理，然后在停止点**禁用**它——两者是"知道怎么用，所以知道哪里不能用"的关系，不是竞争关系。
- 与 `fatigue-timing-management` 的区别：那个回答"怎么撑过疲劳让体验继续"，本 skill 回答"什么时候该让它体面地停"；两者覆盖同一坐标（疲劳轴）的两端动作。
- 与 `risk-reward-choice-feedback` 的区别：作弊选项在本 skill 中是"自由"的体现，在那边是"难度自调"的机制——同一手法，两个视角。

## E — 可执行步骤 (Execution)

1. **立场审计**
   - 完成标准：对当前产品/体验写下"这个设计服务的是用户的人生，还是产品自己的存续"；标记所有存疑项（挽留弹窗、断签惩罚、无限推荐流）。判停条件：全是服务产品存续的设计且业务方拒绝调整 → 本 skill 无法推进，先解决立场问题。
2. **标记自然停止点**
   - 完成标准：找出体验中用户任务完成/一集结束/一次练习结束的节点，列为"体面终点"候选。
3. **停止点禁用惊喜并设计宁静收尾**
   - 完成标准：审计停止点前后无任何延长钩子（自动播放下一条、未读红点、倒计时优惠）；设计一个"回归日常"的收尾元素（总结画面、平静的完成页、明日再见的文案——注意是"再见"不是"快回来"）。
4. **发放自由**
   - 完成标准：用户可随时停止、可跳过、可"作弊"（跳关/降级模式/跳过剧情），且不惩罚（无断签恐惧）；自由入口清晰可见而非藏在深层。
5. **换指标复查**
   - 完成标准：把"停留时长/日活"类指标补充为"完成质量/用完即走的满意度"；数据复查时先问"下降发生在任务完成处吗"——是，则是收尾设计的成功。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **必须连续的安全流程**——麻醉监护、驾驶辅助等"中途体面退出"会出人命。
- **把"让用户停止"当免责话术**——本 skill 是设计能力，不是放弃留存管理的借口；停止点之后仍然要有值得回来的内容。
- **任务中断场景**——用户是被迫中断（断网、来电）时，他需要的是"继续点"，不是收尾仪式。

### 作者在书中警告的失败模式

- 滥用惊喜挽留用户——每次退出前再弹一个钩子，抢夺用户时间、降低其人生质量（ce35）。
- 开发者的自我焦虑——"担心用户不回来"被作者诊断为设计师的焦虑，不是用户需求（第5章原文立场）。
- 为"被一直使用"堆功能——产品变主角，内容乱七八糟，用户望而却步（ce34 的另一面）。

### 作者的盲点 / 时代局限

- 全书善意前提（设计者为用户消除疲劳）在把疲劳当变现工具的商业模式下不成立——本 skill 与成瘾设计一线之隔，落地必须写明红线并接受业务审视。
- 书中案例是单机买断制（停止无成本）；订阅制/社交产品的"停止"牵涉商业模式生存，作者未给出商业适配方案，需要团队自行定价"体面"的代价。

### 容易混淆的邻近方法论

- Digital wellbeing / 数字健康（屏幕时间管理）：同方向的社会运动；本书增量是给出**设计规则**（停止点禁惊喜/回归日常收尾/作弊自由），而非功能开关。
- 留存漏斗优化：直接对立的目标函数；本 skill 要求先做立场审计（步骤 1）再谈留存手段。
