# 故事设计：虚构只是手段，用户成长才是目的

## R — 原文 (Reading)

> "1. 吸引 吸引想要理解故事的玩家，让他们叙述故事。2. 成长 让玩家和故事中的主人公一样成长。3. 意志 玩家用自己的意志开启自己的命运。" / "游戏设计师真正想要描绘的，不是在游戏中展开的'虚构故事'，而是玩家自身成长的'故事'。"
>
> — 玉树真一郎，第3章《故事设计的结构》/《体验的意义》

---

## I — 方法论骨架 (Interpretation)

游戏告诉了我们"体验的意义"在哪：主人公怎么成长毫无意义——他只是虚构角色；**玩家（用户）的成长才是意义**。所以情节、角色、世界观都是装置，评估一个长体验要问的是：用户离开之后，现实中的他哪里不一样了？如果没有任何变化，再精美的体验也会"瞬间被抛弃"，还会招来"浪费时间"的敌意。

施工分三步。**吸引**：不把故事说完，用碎片、节奏、伏笔刺激叙述本能，让用户自己拼出"发生了什么"——自己叙述出的故事才有充实感。**成长**：让用户（不只是主人公）真实变强，可用三个成长主题施工——空缺驱动的收集重复（`gap-collection-engine`）、风险回报的选择斟酌（`risk-reward-choice-feedback`）、麻烦同行者的共鸣（`engineered-empathy-companion`）。**意志**：把终点交给用户——在毫无先例的处境里，让他亲手为珍视之物做决定（生命交换/未知体验两类主题），并刻意保留解释余地，让每个用户带着"我自己怎么想"离开。得到无数种解释的作品会被评价为"深刻、引人深思"。

## A1 — 书中的应用 (Past Application)

### 案例 1: 《最后生还者》手术室
- **问题**: 故事讲完了，怎么把终点交给玩家？
- **方法论的使用**: 疫苗要用艾莉的生命换——乔尔杀入手术室，面对麻醉的艾莉与乞求的医生：开枪还是收枪？设计师不给道德答案。
- **结果**: 玩家在网上大量叙述"自己采取了什么行动"，争论至今——用户开始书写自己的故事。

### 案例 2: 《风之旅人》无文字获奖
- **问题**: 没有文字、没有语音，连"故事"都无法直接讲，怎么讲故事？
- **方法论的使用**: 全部信息用环境碎片+波浪节奏+伏笔呈现，玩家自己叙述"发生了什么"；结尾进入无人知道结局的光谷。
- **结果**: 在多个奖项中被评为"优秀故事"。

### 案例 3: 《旷野之息》等待成长
- **问题**: 开放世界自由与引导怎么兼容？
- **方法论的使用**: 宿敌加农放在世界中心**等待**——初始台地的教程与自发性冒险交替重复，让玩家成长到"以自己的意志"踏入世界中心。
- **结果**: 引导与自由兼容的历史性杰作（附录案例）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 产品/课程/活动体验流畅、口碑不差，但用户"用完就走"、没有留恋。
2. 复盘内容"为什么我们的故事没人记得"，或争论要不要把叙事讲完整。
3. 设计结业/毕业/结项/结局环节，想让用户带走"意义"。
4. 评估作品深刻还是肤浅，需要可操作的判断标准。
5. 给用户设计"由他决定"的时刻（盲盒结局、自选路线、公开表态）。

### 语言信号 (用户的话里出现这些就应激活)

- "没意义 / 用完就走 / 没有留恋 / 不深刻"
- "让用户当主角 / 用户的成长 / 自己的故事"
- "结尾怎么设计 / 让他自己决定 / 开放式结局"
- "要不要把故事讲完整 / 留白"
- "meaningful / user growth / sense of agency / 开放式 ending"

### 与相邻 skill 的区分

- 与 `foreshadow-payoff-homecoming` 的区别：那个是具体手法（伏笔/回到起点怎么施工）；本 skill 是评估框架（意义缺在哪一步：吸引/成长/意志）。先诊断缺哪步，再调手法。
- 与 `engineered-empathy-companion` 的区别：那个是"成长"步的施工法之一（共鸣主题）；本 skill 是全局框架。把它误当全局框架会只见情感不见结构。
- 与 `intuition-design-loop` 的区别：三步循环管"行动"，本 skill 管"意义"——行动问题（不会用/不去做）用前者，意义问题（用完就走）用本 skill。

## E — 可执行步骤 (Execution)

1. **三步诊断**
   - 完成标准：对现状逐项回答——①吸引：用户有没有"自己拼出什么"的机会（还是全被喂）？②成长：用户离开后现实中哪里不一样了？③意志：有没有一个"由他自己决定"的时刻？写明缺失项。判停条件：三步全过但仍"用完就走"→ 问题可能在疲劳节奏（转 `fatigue-timing-management`），不在意义层。
2. **吸引补课**
   - 完成标准：找出至少一处"全盘托出"的信息，改为碎片+留白（环境故事手法），并确认留白嫁接在用户的叙述本能上。
3. **成长施工**
   - 完成标准：从三个成长主题中选定适配的施工法（收集重复/选择斟酌/共鸣），给出把"用户现实变化"设为指标的评估口径（替换"满意度/时长"类指标）。
4. **意志时刻设计**
   - 完成标准：设计一个无先例、由用户亲手决定的时刻（对珍视之物做选择/面对未知状况），并保留解释余地——不给标准答案，允许多种解读并存。
5. **收尾可见化**
   - 完成标准：用回到起点/伏笔回收让成长被用户自己看见（调用 `foreshadow-payoff-homecoming`）；确认用户能用自己的话转述"我经历了什么、我变了什么"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **纯工具型单次任务**——计算器、查词典没有成长叙事预期，强加"意义层"是负担。
- **把本 skill 当编剧指南**——它不教你写好剧本；内容工艺（文笔、表演、关卡设计）是另一门学问，本 skill 只保证"装置服务于用户成长"。
- **意志时刻滥用**——不是所有决策都该交给用户；高频小选择用 `risk-reward-choice-feedback`，"意志"只留给终点级的珍视决定。

### 作者在书中警告的失败模式

- 只做持续、不做意义——"如果游戏提供的持续体验毫无意义，人们很快就会离开"（ce19）。
- 读完/玩完没有任何变化——瞬间被抛弃（ce20）。
- 把主人公的成长当卖点——"游戏中的主人公怎么成长，毫无意义"（ce21）。

### 作者的盲点 / 时代局限

- "意志"主题（生命交换/未知体验）在游戏的安全虚构里可行；现实产品让用户"决定命运"的责任设计要极克制，避免把重大代价推给用户。
- 案例都是叙事型作品；强功能型产品（B 端工具）的意义层要落在"用户工作方式改变"上，套游戏叙事会违和。

### 容易混淆的邻近方法论

- "Customer is the hero"（StoryBrand 式营销）：措辞相近；本书增量是反方向纪律——反对把工艺投入虚构故事本身（角色弧光、剧本），主张情节只是装置，且"意志"是终点步骤而非全程撒选择权。
- 开放式结局/多结局设计：形式相近；本书的"解释余地"目的是让用户带着自己的解读叙述，不是内容量技巧。
