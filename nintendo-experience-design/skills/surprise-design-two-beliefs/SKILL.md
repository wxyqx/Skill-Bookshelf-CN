# 惊喜设计：误解→尝试→惊讶与两种坚信

## R — 原文 (Reading)

> "1. 误解 自发做出'要做××吗？'的错误假设。2. 尝试 自发尝试……3. 惊讶 自发发现'××是错误的'，然后大吃一惊。" / "1. 对前提的坚信→'这个游戏是××'　2. 对日常的坚信→'应该不会出现禁忌'。有意识地背叛这两种坚信，才是设计师应采取的战略。"
>
> — 玉树真一郎，第2章《惊喜设计的结构》/《契机是两种坚信》

---

## I — 方法论骨架 (Interpretation)

惊讶的物理来源只有一个：**坚信崩塌**。没有铺垫的意外只是混乱，不是惊喜——必须先花时间让用户自发建立错误假设并坚信其正确（坚信越深，崩塌越惊人），再让现实暴露"错了"。结构与直觉设计同构（误解→尝试→惊讶），只是第三步的高兴换成了惊讶；且用户不会生气，反而开心——前提是这是安全的虚构游戏，"被骗"没有真实代价。

惊讶只有两个杠杆，成本不对称：**对前提的坚信**（"这个游戏是严肃冒险"）要长期铺垫"说谎"，惊讶最强但实施成本极高；**对日常的坚信**（"日常生活里不该出现的东西不会出现"）只需让禁忌主题登场，惊讶稍弱但便宜、够用。所以实施的顺序是：①定位用户疲劳厌倦的顶峰（交给 `fatigue-timing-management`）；②选择杠杆——有长期铺垫条件就颠覆前提，否则用禁忌主题打破日常；③设计暴露误解的剧情，让坚信当众落空。

还要接受两个约束：惊喜是一次性资源（同一个惊喜用第二次归零）；它是"让体验持续下去的必要之恶"——如果用户永不疲倦，你根本不需要它。

## A1 — 书中的应用 (Past Application)

### 案例 1: DQ 系列的"惊喜刺激"
- **问题**: 严肃的勇者屠龙故事里，为什么塞进一个不该存在的怪话题？
- **方法论的使用**: 前几小时全力铺垫"这是严肃冒险"（对前提的坚信）+"这是正经游戏"（对日常的坚信），在学完全部指令的疲劳顶点让禁忌话题登场——两种坚信同时落空。
- **结果**: 成为系列玩家几十年念念不忘的桥段，玩家被"骗"却不生气。

### 案例 2: DQ 的三大背叛
- **问题**: 教科书式的经典游戏如何持续让人惊讶？
- **方法论的使用**: 龙王提议"把世界分你一半"、逃犯躲在牢房里、DQ3 的异世界竟是 DQ1 的世界——全部是对"这类游戏应该怎样"的前提背叛。
- **结论**: "非教科书式设计才恰恰是教科书式的"。

### 案例 3: 牙刷柄刷牙（日常微缩版）
- **问题**: 孩子每天刷牙感觉不到效果，厌倦了。
- **方法论的使用**: 故意用牙刷柄刷牙——打破"刷牙用刷毛"的日常坚信，孩子在"错了！不行！"的惊讶和高兴中重新认真刷牙。
- **结果**: 孩子开始认真刷牙（作者亲测）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 策划活动/年会/课程/直播里的"爆点"环节，想让参与者记住。
2. 长期产品或内容需要彩蛋、反转、周年惊喜。
3. 营销传播想制造"没想到你是这种品牌"的话题性。
4. 团队日常（会议、复盘）陷入沉闷，需要打破预期。
5. 个人习惯重复倦怠，想给自己制造重新出发的瞬间。

### 语言信号 (用户的话里出现这些就应激活)

- "制造惊喜 / 惊喜感 / 出乎意料 / unexpected"
- "反转 / twist / 彩蛋 / 爆点 / 惊艳一下"
- "打破预期 / 让用户wow一下"
- "周年庆/发布会想让人记住"
- "surprise design / delight moment"

### 与相邻 skill 的区分

- 与 `fatigue-timing-management` 的区别：那个回答"什么时候放惊喜"（饱和点坐标）；本 skill 回答"惊喜怎么造"（结构+杠杆选择）。没有疲劳诊断就上惊喜，往往砸在新用户身上（没有坚信可打破）。
- 与 `taboo-theme-toolkit` 的区别：本 skill 是施工框架（三步+两种杠杆）；那个是原材料库（10 种主题+4 问检验）。选杠杆②时去那个仓库取料。
- 与 `intuition-design-loop` 的区别：方向相反——直觉设计建立"猜对了"的确信，惊喜设计打破"猜对了"的确信；长体验里两者交替。

## E — 可执行步骤 (Execution)

1. **盘点用户的坚信**
   - 完成标准：写出目标对象此刻对"这件事"的前提坚信（"这个课程很严肃"）和对"日常"的坚信（"职场里不会出现××"）各 1-3 条。判停条件：两条都列不出（对象对你没有既有认知）→ 停止，这不是惊喜场景，先建立认知。
2. **选杠杆**
   - 完成标准：明确打破哪一种——有长期铺垫条件选"前提"（惊讶最强），没有就选"日常"（用禁忌主题，调用 `taboo-theme-toolkit`）；写明选择理由。
3. **设计暴露方式**
   - 完成标准：暴露发生时用户"自发发现错了"而非被你告知错了；暴露前用户确实按错误假设行动过（误解→尝试→惊讶的完整链）。判停条件：暴露点无法安排"用户的行动"→降级为单靠禁忌登场（惊讶减弱但成立）。
4. **校准安全与尺度**
   - 完成标准：确认"被骗"无真实代价（不涉及金钱、健康、信任承诺）；职业场景主动绕开死亡/肮脏/暴力等高风险禁忌。
5. **一次性原则与回程**
   - 完成标准：确认该惊喜不会在同批对象上重复使用；设计暴露后的回程（惊讶之后用什么把人送回主线——DQ 用强装备，会议用回到议题）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **新用户/首次接触**——没有坚信可打破，惊喜只是错位信息，甚至违反"了解优先"。
- **重复暴露场景**——同一个惊喜第二次归零（重读本书的人对"惊喜刺激"只会说"是的是的"），高频产品靠它维持新鲜感是死路。
- **信任型关系**——医疗、金融、家长对子女等承诺场景，"善意的骗"的代价由对方真实承担，游戏的安全虚构不成立。

### 作者在书中警告的失败模式

- 没有铺垫的意外只是混乱，不是惊喜——必须先让对方坚信（ce15 颠覆前提成本极高的反面警示）。
- 惊喜用第二次就失效（ce14）。
- 心软不敢用消极主题——反派和禁忌是必要原料，但要以"不引起怀疑的程度让用户赢"做补偿（ce16/p30）。

### 作者的盲点 / 时代局限

- 全书把"用户被骗不生气"当作默认，这在单机游戏的安全虚构里成立；把本 skill 迁移到有真实利益的关系（管理、教育）时，伦理边界必须自设——BOOK_OVERVIEW 批判明确点名此风险。
- 案例均为一次性大事件；高频产品场景缺少作者给的方案（书的答案其实是"让体验停止"而非无限惊喜）。

### 容易混淆的邻近方法论

- Delightful design / delighter（Kano 模型的魅力属性）：泛指超出预期的愉悦；本 skill 强调**先坚信后崩塌**的结构与两个杠杆的取舍，"无铺垫的惊喜"在本书体系里是伪惊喜。
- 恐怖/悬念创作技巧：同为情绪工程，但目标不同——悬念延长期待，惊讶结束期待；不要混用节奏。
