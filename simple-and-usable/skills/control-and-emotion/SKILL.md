# 掌控感与感情需求

## R — 原文 (Reading)

> "从简单这个角度来看，最重要的是让用户感到自己在掌控一切。"（第2章）
>
> "他们希望自己能做完很多工作，感觉一切尽在掌握。"（第2章）
>
> "这部电梯并没有给人简单的感觉，而是让人觉得它神经错乱。"（第4章）
>
> — Giles Colborne，《简约至上：交互式设计四策略》第2章、第4章

---

## I — 方法论骨架 (Interpretation)

作者主张：用户说一个产品"简单"，首先是指**对结果的掌控感**——响应在意料之中、没有后顾之忧，而不是指拥有多少精确控制和定制选项。

这层需求藏在功能诉求底下。用户口中的"我想要一个任务列表"是表层方案，底下是感情需求："做完很多工作、感觉一切尽在掌握"。停留在表层只能得到功能清单；下钻到感情需求层才能得到设计重点。

配套一个固定的下钻问法——**"然后呢"连环追问**：从感情需求出发（需要掌控→怕账目失控→那需要看到什么→一次只想看本周→默认周视图），每问一次"然后呢"就向功能层逼近一步，直到出现可以动手的方案。

最后用**控制感两端**校验方案：控制太少（比如删光所有操控装置）让人无助焦虑；控制太多（一堆设置项）让用户因选择浪费时间。目标是"足够多的控制消除焦虑"，不多不少。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: Things 应用的感情需求
- **问题**: 待办应用几百个，表面看都是一个带复选框的列表，Things 靠什么脱颖而出？
- **方法论的使用**: 开发者先回答感情需求——用户要"做完很多工作、感觉一切尽在掌握"；据此把设计重心放在容纳上千条任务却翻阅不费事、始终只呈现少数最重要的工作、随手记任务时不强制归类不打断。
- **结论**: 挖到感情需求层才有设计重点：让用户自信"无论怎么创建任务，将来都能轻松找到它"。
- **结果**: Things 获 2009 年度最佳苹果应用奖，从几百个同类中胜出。

### 案例 2: 东京苹果店无按钮玻璃电梯
- **问题**: 把电梯精简到极致——没有任何按钮，每层自动停靠，够简单了吗？
- **方法论的使用**: 作者亲测发现体验是迷惑、沮丧、无助：不知道会不会在要去的层停、看不到任何人在操作、没有按下按钮的反馈——删掉操控装置等于把掌控感一起删掉了。
- **结论**: 掌控感是简单的必要成分，"删光控制"不等于简单。
- **结果**: 无按钮电梯让人心烦意乱，成为"控制感不可删"的反例标尺。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户研究/访谈中，用户抱怨"难用""别扭"却说不清具体哪里，常规追问失灵。
2. 需求评审争论"要不要加更多设置项/自定义"，需要判断这是不是真的掌控感。
3. 设计自动化、默认值或"智能"功能时，要决定哪些控制必须留给用户。
4. 产品同质化、功能对齐竞品，需要从感情需求层找差异化切入点。

### 语言信号 (用户的话里出现这些就应激活)

- "用户说难用但说不出哪里 / 访访谈不出东西 / 不知道用户到底要什么"
- "要不要给用户更多选项/设置 / 是不是自动化太多了 / 掌控感"
- "感情需求 / 用户真正想要的是什么 / 怎么继续往下挖 / 然后呢"
- "users can't articulate what's wrong / sense of control / emotional needs / more options?"

### 与相邻 skill 的区分

- 与 `field-observation` 的区别：那是去真实环境**看**用户（观察法）；本 skill 是访谈与讨论中**问**的下钻工序，产出需求而非环境约束。
- 与 `mainstream-user-lens` 的区别：那是"为谁设计"的立场（三分类）；本 skill 是"挖什么、怎么挖"（从感情需求下钻）。
- 与 `simplicity-baseline` 的区别：那是把认识写成可判断的基准；本 skill 的产出常作为基准的原料。
- 与 `four-strategies` 的区别：四策略回答"怎么简化"；本 skill 在简化之前回答"用户要的简单到底是什么"。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **分离表层诉求与需求**
   - 把用户原话里的"方案"（功能词）标记出来，逐条翻译成"在什么情境下想完成什么"
   - 完成标准: 每条原话都改写成不含功能词的情境化需求
2. **下探感情需求层**
   - 追问"用完之后你希望是什么感觉？"，定位到掌控感/成就感/安心等感情需求
   - 完成标准: 用一句话说出感情需求（如"感觉一切尽在掌握"），且有用户原话支撑，不是设计师替用户说的
3. **"然后呢"连环追问下钻**
   - 从感情需求逐层追问到功能层（怕失控→需要看到什么→一次想看多少→什么时候看）
   - 完成标准: 追问链每一环都有用户证据；产出 1-2 个具体功能方案
   - 判停条件: 用户开始直接索要新功能而非描述感受时停下——疑似伪需求，回到第 2 步换角度验证
4. **控制感两端校验**
   - 检查方案：让用户更无助（控制太少）还是选择更多（控制太多）？
   - 完成标准: 明确列出"保留给用户的控制"与"交给默认值/自动化的部分"，两端都有理由且不越界

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户已经能明确说出要什么——直接记录需求即可，下钻是多余工序
- B2B 场景中"用户"是采购方而非实际操作者——先找准掌控感的主体，否则挖到错误的人身上
- 需要的是环境约束（物理场景、干扰因素）而非需求动机——转 `field-observation`

### 作者在书中警告的失败模式

- **删光控制装置**：东京苹果店无按钮电梯删掉操控装置，体验"神经错乱"——没有掌控感就没有简单（第4章）
- **把"更多选项"当掌控感**：选择超过界限变成负担；主流用户要的是掌握结果，不是精确控制与定制（第2章）
- **让机器替用户做主**：智能旅行规划程序"不断地评判"用户的安排，剥夺决定权，产品最终未上线（第7章）

### 作者的盲点 / 时代局限

- 掌控感的结论来自大众消费产品；专业工具用户的"掌控"恰恰是精确控制，照搬"少给控制"会做错
- 感情需求依赖小样本访谈获得，自我报告与真实行为存在差距（行为科学对访谈法的后续批评）
- 成书于 2011 年，未讨论用"掌控感幻觉"做暗黑模式的伦理边界——本 skill 不得用于诱导用户放弃控制权

### 容易混淆的邻近方法论

- 泛泛的"用户共情 / 以用户为中心"：本书给的是固定追问工序与两端校验，不是态度倡议
- 自我决定论等动机心理学：那是理论框架；本书是可直接执行的设计问法
