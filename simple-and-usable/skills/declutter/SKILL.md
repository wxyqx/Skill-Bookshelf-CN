# 减速带清理

## R — 原文 (Reading)

> "界面中的各种小细节会增加用户的负担，会像公路上的减速带或坑坑洼洼一样降低用户的效率。"（第4章）
>
> "如果你选择了将来的日期，就会有一条错误消息提示你，意思就是说你很白痴。"（第4章）
>
> — Giles Colborne，《简约至上：交互式设计四策略》第4章

---

## I — 方法论骨架 (Interpretation)

功能范围定下来之后，界面仍可能让人"说不上来就是累"。作者把这类小细节叫**负担**：像公路上的减速带，单个不起眼，但每一个都对每次使用收费。

为什么常识会漏掉它：减速带不进功能清单，评审里显得无害（一条装饰线、一个补充链接、一句客套话），也没人为它负责。本书把它们重新定价为认知税——人处理信息、学习规程、记忆细节的能力有限，多余的文字、选项、干扰和视觉杂乱都在花用户的注意力预算。而且它们有乘数效应：单次小负担 × 用户数 × 使用次数，规模惊人。

清理工序按四类藏身处逐一排查：

1. **视觉混乱与装饰**：删没人看的口号、装饰线条、色块、重复链接、多余按钮样式。研究显示文档里的超链接即使不被点开也会降低理解力——干扰本身就有成本。
2. **选项与链接**：选择超过界限就变成负担；在接近完成任务的节点，"再看一眼"的链接会动摇决心。收敛选项，用聪明的默认值替空表。
3. **错误**：好的设计消除错误来源，让错误消息根本不需要出现，而不是把消息措辞写得更友好。"你确定要这样做吗"式的确认同样在惩罚没犯错的人。
4. **文字**：删一半，再删一半——无效的客套和解释都在收注意力税。

它与删除功能的关系：这是删除策略在感知层的延伸——功能该不该整个删看 remove-strategy；功能留下后的每次使用体验，由这里的减速带密度决定。

## A1 — 书中的应用 (Past Application)

### 案例 1: 合作银行主页减负
- **问题**: 银行想提高主页点击量。常规思路是加内容、加推广位。
- **方法论的使用**: 反着来——从减轻访客负担入手：删没人看的口号、删右侧垂直边栏、去掉重复链接（可点击项减少 20%）、精简按钮样式、减广告位、去掉黄色背景条。
- **结论**: 去掉干扰元素让用户感觉更快、更有安全感，注意力回到真正重要的内容。
- **结果**: 几周完成的小项目让主页点击量明显提高，填写申请表单的人数随之增加。

### 案例 2: 网上银行对账单控件：消除错误来源
- **问题**: 用户从月、年两个下拉菜单选日期查对账单：选将来日期被讥讽般报错，选超过 12 个月又提示不存在——匆忙的客户极易选错，错误消息怎么措辞都不友好。
- **方法论的使用**: 看出问题在"用户只需从过去 12 个月里选，却被要求输入日期"——把两个日期控件换成可用对账单的下拉列表，用户只能选有效项。
- **结论**: 消除错误来源好过设计错误消息；错误被当成了用户的问题，其实是设计的问题。
- **结果**: 错误消息被整体消除，系统维护也更简单。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户反馈改版后"说不上来哪里不对，就是觉得累/乱"。
2. 错误提示反复出现，措辞改了很多版还是不友好。
3. 关键动作（注册/结账/提交）转化率莫名低，页面本身"看不出毛病"。
4. 文案冗长、客套话多，用户不看说明。
5. 界面装饰、按钮样式、颜色太花，到处都在抢注意力。

### 语言信号 (用户的话里出现这些就应激活)

- "页面太乱 / 说不上来就是累 / 视觉噪音 / 太花哨"
- "错误提示太多 / 老是报错 / 确认弹窗烦人"
- "太啰嗦 / 文案精简一下 / 链接太多 / declutter / visual noise / cognitive load / too wordy"

### 与相邻 skill 的区分

- 与 `remove-strategy` 的区别：功能层 vs 感知层——"这个功能要不要整个砍掉"归 remove-strategy；"功能都留下了但界面还累"归本 skill。
- 与 `visual-organization` 的区别：本 skill 做减法（删元素）；视觉组织不删元素，用网格、分层、大小重新呈现。
- 与 `four-strategies` 的区别：总纲是策略选择；本 skill 是删除策略落在感知细节上的清扫工序。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **走查并标记减速带**
   - 逐个元素问"这是减速带吗"
   - 完成标准: 每个元素标注类型（视觉混乱/干扰链接与选项/错误处理/冗余文字），并按"单次负担 × 使用频次"排出清理顺序
2. **清视觉与干扰**
   - 完成标准: 装饰性线条色块、重复链接、没人看的口号已删；行动按钮附近不再有竞争性链接；补充性说明移到任务完成点之后
3. **消错误与收敛选项**
   - 完成标准: 每条错误消息都追问"能否让这个错误不可能发生"（约束输入、聪明默认值、列表化选择），能消除的已消除；仅剩的确认与报错只针对真正的错误，不惩罚没犯错的人
4. **删文字并判停**（判停条件：清理后若仍显复杂，说明是功能或结构问题，转 remove-strategy / organize-strategy）
   - 完成标准: 关键文案删一半再删一半后仍保留行动信息，无客套填充；眯眼走查不再发现减速带即停

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 问题其实是功能太多或结构混乱——减速带清理救不了错误的分组和多余的流程
- 为了"干净"删掉用户依赖的信息或产品的特征与个性——负担是认知税，不是内容本身
- 只有审美动机、没有使用证据时，先用真实环境观察确认再动手

### 作者在书中警告的失败模式

- **一个链接毁掉全部注册**：登记按钮旁的"查看详细说明"很有诱惑力，每位测试者临登记都先点开它，结果无一人登记成功——在接近完成的节点，一个多余选项都嫌多
- **错误消息式设计**：银行日期控件让选将来日期的用户被报错羞辱——把错误当用户的问题而非设计的问题；正确做法是让错误根本无法发生
- **选项过载**：24 种果酱的摊位成交率 2%，6 种时升到 12%——选择超过界限（尤其选项相似时）变成负担
- **"两种都给"的折中**：团队对方案不分伯仲时把两种导航都加上，恰恰在制造选择负担

### 作者的盲点 / 时代局限

- 作者依赖小样本可用性测试与自我报告，行为科学指出自我报告与实际行为有系统差距——"觉得累"的归因需要结合行为数据复核
- 成书于 2011 年，未覆盖移动端弹窗、推送、暗黑模式等新型减速带的形态与伦理问题

### 容易混淆的邻近方法论

- `visual-organization`：删（本 skill）与重排（网格/分层）是两种动作，先删后排
- `remove-strategy`：整个功能该不该留是功能层决策，不是细节清扫
- 极简主义：清理负担不等于极简审美，特征与个性应保留 → simplicity-boundaries
