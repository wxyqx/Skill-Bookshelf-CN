# 组织策略

## R — 原文 (Reading)

> "按照有意义的标准将按钮划分成组。"（第3章）
>
> "这些不起眼的'期望路径'通常都与铺好的路不一样。"（第5章）
>
> "功能、选项和配件的分类法表示内容是否符合某种标准——只有内部人才可能知道。"（第5章）
>
> — Giles Colborne，《简约至上：交互式设计四策略》第5章

---

## I — 方法论骨架 (Interpretation)

组织是四策略中唯一"不减功能也能降复杂"的手段：功能删完剩下的所有东西，按什么逻辑摆，决定用户找不找得到。作者强调最重要的一点是只强调一两个最重要的主题——随随便便的多彩分组只会让人眼花缭乱。

**分类标准的三重判定**：好的分类对用户是"是非分明"的——每个东西明显属于某一组，界限清晰用户才知道去哪找。选标准时问多位用户他们的分法，取众口一致、且重复交叉最少的那个。"空调算技术还是舒适度"这类众口不一的标准，本身就是麻烦信号。

**两条反直觉规则**：别按字母表——用户不知道东西叫什么就完蛋（字典里 finish 排在 start 前面）；别按格式（文字/图片/视频）分——用户读文字时想看的可能正是图片，按格式拆内容把同一主题撕到多处。内部组织架构更不能当分类标准。

**围绕行为组织**：按用户做事的顺序排（查找 → 比较 → 完成），而不是按内容属性或部门结构；能推迟的步骤（如注册）尽量推迟。

**期望路径检验**：公园里行人踩出的土路总比设计师铺的笔直路更真实——观察用户实际怎么走，简单的组织是"用起来感觉不错"，不是"规划图上看起来合理"。

**搜索与组织的关系**：对 30 名用户 120 多次购物测试显示，没有人始终首选搜索，用户只在导航失效时才用搜索。先有效组织，再考虑搜索——搜索好用是内容被组织好的结果，不是搜索框的功劳。

## A1 — 书中的应用 (Past Application)

### 案例 1: 标致汽车网站：从内部标准到用户标准
- **问题**: 作者接手标致汽车网站，信息按"功能（行业标准）/选项（适合经销商）/配件（适合公司自己）"组织——只有内部人才懂的分法，用户无从查找；改提"舒适度、技术、载客量"又因人而异（空调算技术还是舒适度？）。
- **方法论的使用**: 找一个所有人都"是非分明"的标准。汽车看得见摸得着，于是用汽车本身的布局组织信息：内饰、外观、性能——任何人都知道 CD 机和后视镜在哪。
- **结论**: 分类标准必须来自用户的心智模型，最简单的分类是重复交叉最少的分类；重叠类别有时无法避免（超市把西红柿放蔬菜区）。
- **结果**: 重组后任何用户都能明确知道到哪里去找想要的东西。

### 案例 2: 公园里的期望路径
- **问题**: 设计师从天空俯视的角度规划笔直的几何小路，行人却总是横跨草地踩出近路。
- **方法论的使用**: 把"期望路径"当检验工具——描述用户路径时别被规划图清晰的线条迷惑，要不断重复使用流程、观察哪里总抓住眼球、看其他人怎么做。
- **结论**: 真实行为的沉淀胜过规划逻辑；简单的组织"用起来感觉不错"，而非"规划中看起来合理"。
- **结果**: 提供了一个零成本自查方法：用眼光"瞟"屏幕布局，代替逻辑推演。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 商品/内容分类改了几版用户还是找不到东西，分类标准定不下来。
2. 导航、菜单、标签怎么分组争论不休（按业务线？按主题？按用户类型？）。
3. 有人说"不用花力气做导航，加个搜索框就行了"。
4. 排序方式待定：字母表 / 时间 / 格式 / 主题。
5. 新页面、新功能不知道往现有结构里哪放。

### 语言信号 (用户的话里出现这些就应激活)

- "分类标准 / 信息架构 / 导航分组 / 菜单怎么分 / 标签体系"
- "用户总找不到 / 找不到东西 / 跳来跳去 / 找不到北"
- "加个搜索就行了 / 站内搜索 / IA / taxonomy / navigation / wayfinding / 期望路径"

### 与相邻 skill 的区分

- 与 `visual-organization` 的区别：本 skill 定"按什么逻辑分组"（分类标准、行为顺序、期望路径）；视觉组织定"分组之后视觉上怎么呈现"（网格、大小、颜色、分层）。
- 与 `declutter` 的区别：组织不删元素，只重排逻辑；元素本身多余先走减速带清理。
- 与 `hide-strategy` 的区别：组织把所有项摆成用户可理解的组；隐藏是把非核心项收起防分散注意力。
- 与 `four-strategies` 的区别：总纲回答"该走哪条策略"，本 skill 是组织这一条的执行细节。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **向用户收集分法**
   - 访谈或测试多位目标用户："你会去哪找 X？你会管它叫什么？"
   - 完成标准: 拿到用户自己的分类词汇与查找路径；没有用户输入时不产出标准（判停条件：拿不到用户信息且不允许假设，先转 field-observation / 用户研究）
2. **三重判定筛标准**
   - 完成标准: 候选标准逐一过"是非分明 / 多数一致 / 重叠最少"三关；字母表、内容格式、内部组织架构已被明确排除并说明理由
3. **围绕行为排布并分块**
   - 完成标准: 主流程按用户行为顺序排列（查找→比较→完成）；可推迟的步骤（注册等）已推迟；顶层分块数量少且只强调一两个最重要的主题
4. **期望路径检验与搜索定位**
   - 完成标准: 观察或走查中用户实际路径与设计路径一致（不一致处回步骤 1 重修）；搜索定位为导航失效的兜底——若测试中用户首选搜索，视为组织失败的信号而非搜索的功劳

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 拿不到用户分法且不允许观察真实行为——先做研究，否则产出的只是内部逻辑的投影
- 内容极少（三五项）——组织成本高于收益，直接平铺
- 用户是专家本人且行业已有强惯例（专业工具照行业惯例走，别发明新分类）

### 作者在书中警告的失败模式

- **内部分类法**：按"功能/选项/配件"或公司架构分组，只有内部人才懂，用户无从查找（标致网站原状）
- **字母表与格式排序**：字典里 finish 排在 start 前面；按格式拆内容让"读文字时想看图"的人来回跳
- **"加个搜索就行了"**：用户只在导航失效时才用搜索，搜索把"构造关键词 + 甄别结果"的成本转嫁给用户；设计好搜索本身比组织链接难得多
- **规划图逻辑**：设计师俯视铺的笔直小路，敌不过用户踩出的期望路径

### 作者的盲点 / 时代局限

- 信息架构重组的迁移成本（老用户重新学习、内容重标、链接失效）基本未讨论——组织的代价主要从"用户感觉"一侧论证
- 多个用户群体分法冲突时怎么办，书中只以超市放西红柿一笔带过，实操指引弱
- 2011 年成书，未覆盖个性化推荐流、移动端底部导航等新组织形态

### 容易混淆的邻近方法论

- `visual-organization`：分组逻辑 vs 视觉呈现——先定标准，再做网格与分层
- `hide-strategy`：分组后仍显杂乱的非核心项才考虑隐藏；隐藏不解决分类标准错误
- 站内搜索产品化：本 skill 只回答"组织与搜索谁优先"，不涉及搜索引擎实现
