# 视觉组织

## R — 原文 (Reading)

> "人们在无意的状态下，只会感知到自己关心的那条线路的颜色，将其他线路排除在意识之外。"（第5章）
>
> "没动一个标签，没多编写一行代码，就得到了一个让人感觉用起来简单的布局。"（第5章）
>
> — Giles Colborne，《简约至上：交互式设计四策略》第5章

---

## I — 方法论骨架 (Interpretation)

分组逻辑定了之后，"复杂感"还取决于视觉呈现。本书的立场反常识：大小、位置、颜色、对齐不是美化，而是**信息架构工具**——它们决定用户每次感知到几层信息。组织得好，读者会无意识中只感知自己关心的那一层，把其余排除在意识之外。

四件工具，按成本从低到高：

1. **网格对齐**：不可见的网格线引导注意力，对齐本身就能让界面"感觉简单"，甚至不用改一个字、一行代码。网格越简单效果越明显；局部破例会让全局引导失效。
2. **大小与位置**：重要性减半的元素，大小可以减到约四分之一。起头总是最难的，每屏要有一个明确的视觉起点（Flip 九个键里只有大红录像键突出——它在说"从这里开始"）。
3. **感知分层**：伦敦地铁图在巴掌大的地方塞下 13 条线路 300 多个站点，靠的是每条线一种颜色——用户每次只专注一条线。用颜色、阴影、大小、形状把页面分成 2-3 个感知层，层间差别拉到最大，让用户每次只处理一层。这几乎零学习成本。
4. **色标系统**：与感知分层有本质区别——色标是需要学习记忆的符号系统，只适合会天天重复使用的用户；颜色越多、含义越不一致，学习成本越高。

两个自检动作：眯眼测试（层还分得出来吗）、数强调（强调越多，越等于没有强调）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 火车票搜索表单的网格对齐
- **问题**: 表单功能上没问题，但用户测试中参与者使用时多少有些踌躇；原始设计 17 个字段里只有 3 个位置不合适，却足以毁掉整体网格的引导效果。
- **方法论的使用**: 从假想的水平网格线着手：对齐字段、去掉区分字段块的背景颜色，改用空白间距和想象中的网格线来对齐与分组。
- **结论**: 不可见的网格是引导注意力的有效方式，网格越简单效果越明显；少数元素错位即破坏全局。
- **结果**: 一个标签没改、一行代码没写，表单就用起来简单了。

### 案例 2: 伦敦地铁图 vs 红绿灯食品标签
- **问题**: 地铁图要在极小空间里呈现 13 条线路 300 多个站点；英国食品标签则想借交通红绿灯标示盐/脂肪含量。
- **方法论的使用**: 前者用感知分层——每条线一种颜色，读者无意间只感知自己那条线；后者是色标——红绿灯对司机司空见惯，对购物者却需要全部重新解释，色盲还分不清红绿。
- **结论**: 分层利用记忆原理、几乎零负担；借用的色标系统需要学习，临时使用者来不及。
- **结果**: 地铁图让复杂网络可读；食品红绿灯标签证明脱离原环境的色标行不通。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 字段/内容多但都得保留，页面"挤在一起显得复杂"。
2. 颜色越用越多，处处强调反而没有重点。
3. 要设计颜色语义系统（状态色、风险等级、健康分级）。
4. 界面"大体对齐"但总感觉不齐，说不出哪里不对。
5. 要决定元素的视觉层级：谁大、谁先、谁突出。

### 语言信号 (用户的话里出现这些就应激活)

- "视觉层次 / 分层 / 没有重点 / 眼花缭乱 / 太挤"
- "对齐 / 网格 / 排版 / 布局怎么调"
- "颜色怎么用 / 色标 / 状态色 / 眯眼测试 / visual hierarchy / grid / perceptual layering / color coding"

### 与相邻 skill 的区分

- 与 `organize-strategy` 的区别：本 skill 管"分组之后视觉上怎么呈现"（网格、大小、位置、颜色、分层）；organize-strategy 管"按什么逻辑分组"（分类标准、行为顺序、期望路径）。
- 与 `declutter` 的区别：本 skill 不删元素，靠重排降复杂感；元素本身多余（装饰、干扰链接）先走减速带清理。
- 与 `four-strategies` 的区别：组织策略的视觉执行层，不是策略选择。
- 与纯美学/品牌视觉规范的区别：这里只关心一件事——视觉编码信息、降低感知负担。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **网格对齐**
   - 完成标准: 所有元素落在简单网格上、无零星错位（少数错位会毁掉整体引导）；优先做"不改文案不改代码"的对齐调整
2. **编码重要性**
   - 完成标准: 每屏有一个明确的视觉起点；重要性比例在大小/位置上成立（重要性减半 → 大小约减到 1/4）；同时强调的主题不超过一两个
3. **感知分层**
   - 完成标准: 页面分为 2-3 个感知层，层间差别最大化，眯眼测试能分出层；颜色优先用于分层而不是装饰；去掉区分块用的背景色、改用空白与网格线的做法已评估
4. **色标条件判定**（判停条件：色标条件不满足就撤色标，改用位置/形状等冗余编码）
   - 完成标准: 若使用色标，已确认用户会长期重复使用、含义无需图例解释、对色盲用户有形状/位置等冗余编码；颜色数量没有持续膨胀

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 内容本身没有分组逻辑——先把 organize-strategy 做完，视觉分层救不了乱的分组
- 想用视觉掩盖必要信息缺失——巴黎地铁应用视觉再好，漏掉"方向"一行字整个体验就崩塌
- 纯审美或品牌诉求驱动——先确认要解决的是"复杂感"问题

### 作者在书中警告的失败模式

- **撞珠色球遥控器**：同时用尺寸、颜色、位置、形状到处强调，像镶满撞珠游戏的色球——强调越多等于没有强调，用户眼花缭乱而非聚焦
- **网格局部破例**：17 个字段里只有 3 个位置不对，整体布局的引导效果就被严重破坏——网格越简单越有效，破例即失效
- **色标移植失败**：交通红绿灯搬到食品标签上，购物者要全部重新学，色盲被直接排除——借用外部颜色系统等于把学习成本走私进界面
- **颜色通货膨胀**：颜色越多、各页面含义越不一致，学习成本越高；不必要地添加颜色只会造成困惑

### 作者的盲点 / 时代局限

- 结论依赖小样本可用性测试；"感觉简单"是自我报告，与实际行为有差距——视觉改版后应以行为数据（点击、完成率）复核
- 无障碍（色盲、低视力）只在色标反例中顺带提及，未展开为设计准则；暗色模式、响应式断点等现代视觉语境未覆盖

### 容易混淆的邻近方法论

- `declutter`：重排元素（本 skill）vs 删除元素（减速带清理）——先删后排
- `organize-strategy`：视觉呈现 vs 分组逻辑
- 品牌视觉/设计规范系统：本 skill 只关心视觉如何编码信息，不定义品牌风格
