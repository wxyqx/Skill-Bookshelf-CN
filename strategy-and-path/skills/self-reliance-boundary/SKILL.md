# 自主可控的边界

## R — 原文 (Reading)

> 绝不追求任何技术 100% 自给；日用消费品"形成一定的自主保障能力即可，并不一定要追求大包大揽、完全国产"。
>
> — 黄奇帆，《战略与路径》第九章

---

## I — 方法论骨架 (Interpretation)

自主化是成本递增的军备竞赛：自给率越接近 100%，边际成本指数上升，还会削弱国际分工收益与朋友圈。所以自主可控必须有边界，边界由两个判据划出：

1. **封喉判据**：用兵棋推演筛出"被断供后一剑封喉"的环节（无替代、无备份、业务立即瘫痪）——只有这些环节值得倾力自主化（作者清单：高性能芯片、工业软件、高端仪器、操作系统等六大短板）。
2. **备胎先行判据**：自主化的正确形态是"备胎"——平时不用或小规模用（CIPS 之于 SWIFT），但保持随时可切换的能力；不是把所有订单都搬回自研线。
3. **其余开放**：非封喉环节保持全球采购与分工，"形成一定的自主保障能力即可"。

反向红线：把资源撒满全部环节的"小而全"，会让真正的封喉环节反而投入不足——这是安全焦虑最常见的自我伤害。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 六大短板的筛选（第四章）
- **问题**: 数字技术哪些环节必须自主？
- **方法论的使用**: 用封喉判据筛出高性能芯片、工业软件、操作系统、仪器仪表等六项（EDA 三巨头占 80%、工业软件海外占 95%），其余保持开放。
- **结论**: 自主化清单收敛到六大短板，不是全部。

### 案例 2: CIPS 备胎逻辑（第十二章）
- **问题**: 金融清算要不要自己另建一套？
- **方法论的使用**: SWIFT 全面脱钩是低可能性高危害——正确姿势是建 CIPS 备胎（40 多国 900 多家银行）保持威慑与切换能力，而非追求替代 SWIFT 全部流量。
- **结论**: 备胎的价值在"可切换"，不在"替换"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 技术团队争论"该自研还是该采购"（中间件、数据库、框架）
2. 企业制定供应链备份与国产替代清单
3. 评估"全面国产化""去 A 化"类口号方案
4. 政策讨论中的自主可控范围划定

### 语言信号 (用户的话里出现这些就应激活)

- "要不要自研""哪些环节会被卡脖子""国产替代清单"
- "build or buy" / "self-reliance" / "供应链备份"

### 与相邻 skill 的区分

- 与 `war-game-scenario-analysis` 的区别：兵棋推演产生"哪些环节会被打"的清单（投入前置），本法决定"清单上的环节投多少、以什么形态投"（备胎 vs 全量自研）。
- 与 `snowball-alliance-strategy` 的区别：自主化防"被卡"，联盟防"被孤立"，反"小而全"正是为了让朋友圈不被自主化挤掉。

## E — 可执行步骤 (Execution)

1. **画依赖清单**：列出全部外部依赖（技术/部件/服务）及其供应商集中度
   - 完成标准: 清单含每项的替代性与切换时间
2. **封喉筛选**：标出"断供即业务瘫痪"的封喉环节
   - 完成标准: 封喉清单通常 ≤ 全部依赖的 20%；若超半数被标封喉，重新审视判据是否过松
3. **分级投入**：封喉级→自主化+备胎并行；重要级→双供应商；一般级→开放采购
   - 完成标准: 每项依赖有明确的投入级别与形态（备胎/双源/开放）
   - 判停条件: 某项自主化成本超过断供损失现值 → 降级为双源或接受风险
4. **定期复核**：威胁与替代格局变化时重新过筛
   - 完成标准: 复核周期与触发条件成文

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用自主化当营销卖点（"全栈自研"宣传）而非风险管理——判据是封喉程度不是宣传口径
- 供应商关系稳定且无地缘/断供风险的常规采购

### 作者在书中警告的失败模式

- "小而全"的全面自给（ce06）：资源稀释、效率损失、朋友圈流失三重代价
- 备胎建成即束之高阁、从不演练切换（作者强调 CIPS 需要持续推广使用）

### 作者的盲点 / 时代局限

- 封喉判据以断供情景为前提；对"标准与生态封锁"（不用你的标准而非断你的货）类威胁覆盖不足，评估时补充生态维度

### 容易混淆的邻近方法论

- 与"国产替代"产业政策：政策常按行业清单推进，本法按"封喉程度"逐项过筛——清单式推进容易变成新的小而全
